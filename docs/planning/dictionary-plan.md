# 离线词典实施计划

制定日期：2026-10-23。本文维护方案范围、阶段依赖和未完成候选；合并、发布与验收状态统一见[开发状态](../development-status.md)。用户要求以 KOReader 的体验为目标，兼容其主要词典格式，并使用已有个人词典验证。本计划细化 [路线图](roadmap.md) R15，不修改现有首版验收，也不表示已授权发布或设备操作。性能与资源目标统一见 [词典验收](../development/acceptance.md#离线词典开发中)，实际结果写入 [开发状态](../development-status.md)。

## 1. 交付目标与范围

第一批可用版本完成以下路径：用户将 StarDict 词典目录复制到 TF 卡，在设备中启用并排序；阅读 EPUB 或 UTF-8／GB18030 TXT 时，长按正文取词、调整选区并查看释义；可切换词典、翻阅长释义，关闭后回到原正文。准备、查询和失败均有明确状态，查词不改变正文锚点、进度修订或同步候选。

以 KOReader 的「选得准、查得到、释义可读、方便返回」为目标，不以设置项数量衡量兼容性。第一批应覆盖现有九套词典的文件形式及字段类型；不能只完成一个英文纯文本词典就宣称支持 KOReader 词典。

| 能力 | 第一批可用版本 | 后续完善 |
|---|---|---|
| 来源与导入 | 原始 StarDict 文件夹；USB 或读卡器复制；设备按需准备 | Wi-Fi 整套词典上传、在线下载 |
| 阅读入口 | EPUB、两种已有 TXT 路径；当前页文字长按、跨行选词 | 跨页选区、独立词典首页 |
| 中文 | 触点附近的词典候选匹配、单字回退、手动调整 | 分词模型、额外词频库、自动简繁转换 |
| 英文 | 原词、大小写候选、同义词、常见屈折形式 | 用户可触发的有界拼写建议、其他语言规则 |
| 释义 | 多词典切换、音标、基础结构与强调、长释义分页 | 复杂 CSS、图文资源、音频 |
| 连续查词 | 数据与状态边界预留，首批可用版本不依赖此功能 | 释义内取词和有限返回历史，作为下一小批 |
| 用户数据 | 启用列表和词典顺序 | 生词本、持久查询历史、导出或同步 |

不引入 MDX／MDD、dictd、Yomitan 等平行运行时格式，不执行词典附带 Lua 或脚本，不移植整个 sdcv／MuPDF／KOReader。日语去屈折和注音不按英语规则兼容；需要时另行规划。当前不创建生词本、历史或插件的空组件。

## 3. 文件与数据兼容

| 项目 | 第一批处理 |
|---|---|
| `.ifo` | 校验 magic、2.4.2／3.0.0、词条数、索引大小、字段类型和整数范围；未知非必需元数据忽略 |
| `.idx` | 按字节流读取 NUL 结尾 UTF-8 词头、大端偏移和长度；核对实际记录数量、排序、文件边界与重复词头 |
| `.dict` | 只读取所选词条范围；计算、定位及实际读回均检查边界 |
| `.dict.dz` | 校验 gzip extra 中的 dictzip RA 表，按需读取一个或多个压缩块；处理跨块词条、短读、坏块和取消 |
| `.syn` | 读取别名及指向 `.idx` 的词条序号；检查序号范围，保留同名别名的多个目标 |
| `.syn.dz` | 检查 RA 表；首选使用同一有界随机读取器，若目标性能不合格则流式展开到缓存，原文件不改 |
| `.ifo.gz`、`.idx.gz` | 元数据有界解压；索引在准备阶段流式展开到缓存，完整校验后发布；无空间时明确说明，允许电脑解压后重新导入 |
| `.idx.oft` 等现有缓存 | 不直接信任或修改；生成本项目可重建索引，避免架构、版本和字节序耦合 |
| 64 位偏移 | 识别 `idxoffsetbits=64` 并明确报告首批不支持，不按 32 位错读；后续由目标文件定位范围和大文件证据决定 |

普通 gzip 文件不能只因扩展名为 `.dict.dz` 就当作可随机访问的 dictzip。没有 RA 表时显示原因，可显式展开到缓存后使用，不在每次查词时从文件头解压。多成员或其他扩展布局若未验证，明确拒绝，不仅检查首个成员便宣称支持。部分块读取不能证明整包 CRC 正确；准备阶段的结构校验、实际块解压和可选完整检查分别报告。

字段解析遵守 `sametypesequence`，也处理未声明该字段时逐字段携带类型的记录；最后一个字段的长度规则不可与中间字段混用。支持 `m/t/h/g` 及其组合；基础 `x` 在释义渲染阶段补齐，使用公开合成样本。未知字段按格式规则安全跳过并提示；无可显示文本时说明类型不支持。二进制字段不作为文本读取。非 UTF-8 的旧 `l` 字段不猜编码。

`m` 是纯文本，尖括号保留；`t` 单独显示音标；`h/g/x` 经过对应的有界解析和语义转换，不能共用无条件去标签。保留段落、释义序号、例句、列表、基本强调和文字交叉引用，颜色映射到既有灰阶。未知标签保留其文本，脚本和样式内容不执行、不显示；外部资源不联网。格式无法安全解析时给出纯文本降级提示，原内容不可恢复时报告错误，不展示乱码或一半标签。

## 4. 查询与索引

### 4.1 最小核心

建立一个共享 `reader_dictionary` 组件，包含 StarDict 元数据／记录读取、稀疏索引、dictzip 范围读取、查询和释义字段解码；按实际职责拆少量文件，不预建多格式后端接口。host 和固件编译同一实现。接口传递查询、候选和有界的结果描述，结果区分找到、未找到、部分完成、需准备、取消、格式不支持、数据损坏、读卡失败与内存不足。

请求只复制必要的短文本、当前选区偏移、词典标识及代次；不复制整章、整本书或正文画布。结果先返回词典、词头和数据位置，正文只加载当前显示的释义；不一次持有所有词典的释义全文。同一结果中的多义项按需遍历，达到页批次上限时提供继续入口，不能静默只显示首条。

### 4.2 磁盘稀疏索引

顺序扫描原 `.idx`，每固定数量记录保存一个源文件偏移，并同步计算摘要和检查排序。查询先二分稀疏记录，再向前定位目标词头的完整起点，读取全部同名记录的有界一批；不能因为重复词头跨越采样边界而漏项。`.syn` 使用同类索引，ordinal 通过 `.idx` 的采样位置定位，避免从头扫描词库。

排序按 StarDict 比较规则：ASCII 不区分大小写比较，相等后按原字节排序。查询候选的大小写处理与磁盘排序分开，不以通用 Unicode casefold 替换排序比较器。损坏、未完成或失效的索引进入准备／错误状态，不在 UI 回调或普通查询中退化为全文件扫描。

小型 dictzip 块定位表可有界缓存；超过预算时采用卡上定位表与小块读取，或明确拒绝该资源规模，取舍在第一阶段用真实数据决定。不能按文件宣称的块数直接无限分配。首次准备和缓存重建可取消，有可见状态；清缓存后能够使用原文件离线重建。

### 4.3 词语与多词典

英文依次查询原词、规范化引号／边缘标点后的词、大小写候选、同义词和有限屈折候选。词形规则产生候选后必须真实命中词典，显示原选词与实际命中词；不把简单截去后缀当作确定词根。先处理复数、所有格、常见过去式和进行式；不规则形式主要依赖词典的同义词数据。软连字符和排版换行与原书实写的连字符区分，不无条件拼接跨段文本。

中文在当前可见页内，以触点字符为中心生成包含该字符的连续候选，按较长候选优先、词典顺序其次查询；不只向右截词，以免点到词中间时漏查。候选窗口和总数有上限，命中的完整候选才高亮；无多字命中回退单字。简繁原文保持不变，繁体／异体匹配先依赖原词条与 `.syn`，自动简繁转换后置。选区始终可以手动收缩或扩展；不宣称等同于语言模型分词。

多词典按用户顺序逐个查询，先显示最高优先级已命中的结果；余下词典按需或低优先级继续，显示仍在查询的状态，不等待全部结果才出现第一条。英文原词轮优先于词形回退轮；若展示的是回退命中，应标明实际词头。中文候选查询可复用同一词典内的文件游标与缓冲，避免每个候选重复打开文件。关闭、重新选词或切书时取消旧请求；旧结果不得改新面板。

## 5. 用户操作与触摸状态

### 5.1 导入和管理

候选目录为卡根 `Dictionaries/<词典目录>/`，原有 KOReader `data/dict` 内的词典子目录可原样复制进来。按 `.ifo` 的基名关联配套文件，不按目录名猜语言；递归深度、目录数、词头和路径长度均有上限，跳过 `res/`、临时文件及不安全路径。只在进入管理、用户重新扫描或挂载变化后按需发现，不在每次翻页或每次启动时扫描全卡。

设置中增加「词典」入口，显示名称、启用状态、顺序及不可用原因。支持启用、停用、上下移动和重新扫描，先使用全局顺序；没有可靠语言元数据时不自动猜测。校验与索引缓存由系统在查词时按需处理，不提供手动准备入口，不显示「待准备／已准备」等内部状态。等待期间显示查词提示并保留关闭入口，失败说明原因并按现有重试路径恢复。没有词典时说明导入目录，不弹联网下载流程。

建议在 `PicoPage/settings.toml` 增加全局 `[dictionary]` 配置，保存按顺序排列的已启用词典相对标识；不存在该段时保持默认未配置，不生成空文件。配置由现有 TOML 快照比较、tmp／回读／备份协议提交；若现有数组编辑入口不支持，则在该入口做最小扩展，不另建配置系统。失败保留旧生效配置，停用状态不能显示为已保存。词典被移走时保留用户选择但显示缺失，不自动启用另一本同名词典。单书覆盖与语言预设后置。

### 5.2 阅读与释义

| 用户操作或事件 | 计划行为 |
|---|---|
| 正文文字长按 | 使用既有长按阈值；先高亮触点字符或英文单词，松手后自动查询并调整为实际命中的词；长按文本链接时不同时跳转，普通点击链接仍按原行为 |
| 正文图片长按 | 保持图片查看入口；图片、文本和链接按动作类型明确命中优先级 |
| 拖动选区端点 | 在当前页内调整，可跨行；过程中只更新选区预览，松手后提交一次查询；不自动翻页 |
| 点按「查词」 | 用当前选区查询；为手动修正和查询失败后重试提供明确入口 |
| 英文或中文未命中 | 保留选区和查询词，可调整后重查；不把格式、内存或 I/O 错误显示成未收录 |
| 查看结果 | 先用避开选区的上／下方释义面板；可展开为全屏；长释义逐页加载，显示词典和实际词头 |
| 切换词典 | 保留选词，切换已命中或按需查询的词典；不切换书籍、不丢当前正文 |
| 默认 K1／K3 | 选区活动时不触发正文翻页；释义面板中仅翻释义页，首尾不切书或穿透 |
| 默认 K2 | 全刷当前选区或释义面板，不重查、不取消、不修改进度；休眠准备仍按 D43 忽略 |
| 点按关闭 | 清除选区与面板，恢复同一正文页；消费原触摸序列后才允许下一次正文操作 |
| 短按电源键 | 按既有休眠流程反馈、取消查询并等待文件交还；唤醒回正文，第一批不恢复词典临时状态 |
| 长按电源键 | 沿用电源菜单及保存／收尾规则，不将查词失败升级为关机阻塞条件 |

第一批不支持跨页拖选，也不隐式加载下一章补词。当前页边缘无法选全时保持已选文字，可通过正常翻页后重选；如增加手动编辑查询，应复用现有键盘，不另造输入组件。无字形、页脚、空白和图片不能被当成文字坐标。

### 5.3 输入序列与绘制

`EventPhase` 已增加 Move；连续文本选区保留接触所有权，直到真实松手或取消。移动采样合并为一个待处理槽，按下、松手和取消保持顺序；InputReset、换书和休眠可终止选区。主循环、host 模拟输入和既有手势测试使用同一接触生命周期，选区自身的预览刷新不释放接触。

自动中文取词在松手后执行，长按阶段的单字高亮只表示触点，不伪称已经找到词。发生手动拖选后按用户选区精确查询，旧的自动候选不得覆盖手选范围；查询词与选区代次一起提交。释义结果不能在尚未结束的接触中抢占输入。

正文普通点击和轻扫保持现状；进入选区后该接触不再参与轻扫或点击判定。绘制在途只更新待处理的逻辑端点，面板完成后呈现最新选区，不为每个移动采样排队刷新。选区的预览帧不能被当成新的正文呈现，也不能把自身刷新误判成书页已变。沿用 display 对画布的独占，复用已有正文底图恢复，不增加长期保留的整屏快照。

布局须先用现有 host 渲染器输出长词、长词典名、音标、中文释义、多结果、错误和空状态截图到 `artifacts/`；沿用现有字体、边框、按钮和灰阶。原始设计稿保持不变，实际差异在开发记录说明。

## 7. 缓存、失效与失败恢复

候选缓存目录为 `PicoPage/cache/dictionaries/<标识>/`。存放稀疏索引、解压后的索引和必要的块定位数据，原始词典与启用顺序均不放缓存。索引使用固定宽度、明确字节序和版本，记录源文件身份、条目数与校验信息；通过 FileStore 的临时写入、同步、验证及发布流程提交。失败不发布半成品，重试不无限累计临时文件。

挂载／USB 返回／重新扫描后，先以路径、大小和修改时间判定明显变化；这些信息不作为内容相同的证明。首次使用某套词典时，在 worker 中分段校验当前 `.idx/.syn` 与缓存记录的摘要，或在同次扫描重建索引，验证完成前不使用旧索引。只准备当前需要的词典，不在开书前验证九套。`.dict.dz` 的文件大小、当前 RA 头与词条边界在打开及读取时验证，持久块定位表必须绑定当前 RA 头；不强制每次查询完整扫描压缩正文。

同一已验证挂载会话内复用索引，查词时仍读回真实词头、序号、偏移和长度。发现不一致先废弃缓存，不能返回旧释义。电脑外部修改发生在 USB 独占期，返回后所有验证状态失效；不支持同时由电脑与设备写同一文件系统。首次使用、重启后验证、清缓存重建、热查询分别计时；若完整索引验证的首次延迟不达标，应提交有证据的简化候选，不能把抽样指纹写成强校验。

| 失败 | 用户结果与资源处理 |
|---|---|
| 无词典／未启用 | 导入或启用提示；仍可关闭回正文 |
| 一套损坏或格式不支持 | 显示该套的具体原因；其他可用词典继续查询；有释义时不显示跨来源警告，前后导航跳过无结果来源，具体故障保留在管理页 |
| 内存不足／文件句柄不足 | 结束本次可选工作，释放词典资源；保留正文和关闭入口，不自动扩大系统资源 |
| 索引过大、释义超出当前分段能力 | 明确超限或提供分段继续；不得静默截断并显示为完整释义 |
| 缓存不可写／卡满 | 已有且验证有效的缓存可继续只读；没有可用索引时停止准备并说明所需空间，不同步扫描整库补救 |
| 移卡／读取失败 | 取消并等待访问退出；沿用存储卡错误与正文恢复路径；不把 I/O 失败当作未收录 |
| 显示失败 | 基准失效并按既有恢复机制处理，保留已成功呈现正文的位置 |
| 设置写回冲突／失败 | 原设置继续生效；显示未保存，重新读取后才能重试 |

文件句柄按阶段打开并尽早关闭：`.ifo` 验证后关闭，同义词定位完成后关闭其输入，再读正文；不能在正文、字体、缓存提交同时存在时假设可额外打开所有词典文件。最大同时打开数与最低可用余量作为第一阶段结果记录，不用提高全局上限掩盖泄漏。

## 8. 资源与响应预算的执行方法

预算表统一放在验收矩阵，全部是待测候选目标。分别核算内部 RAM、PSRAM、最大连续块、既有 worker 栈和文件句柄；不把 PSRAM 总余量当作还能创建任务或满足大块分配的证明。

峰值包括当前正文／字体／既有底图、请求与结果短暂重叠、索引页、dictzip 解压环、释义原文、结构化文本、UTF-32 转换、排版和新增字形。不能只报告压缩缓冲大小。每次仅持有当前显示词条及有界结果描述；长释义按固定大小分段，保留解码及排版游标，不在每次翻释义页时重排全部词条。

按阶段记录单调时钟：接触开始、长按成立、选区帧提交／完成、索引准备、查询定位、解压、释义排版、结果帧完成、取消提出／文件交还。输入到反馈包含长按阈值和面板耗时，同时另报阈值成立后的软件耗时；不能拿 worker 完成时间代替可见时间。

中文候选、英语词形、索引验证和解压都在有界计算片段间检查取消与暂停，并按现有方式让 Idle 获得执行机会。检查间隔不构成 SD I/O 或整条用户路径的固定时限。超预算优先减少预取、附加词典的提前查询和可选样式，不牺牲源位置、完整字段边界或必要保存。

## 9. 实施批次与退出条件

批次按依赖顺序推进，不等于发布版本或已承诺的工期。每批保持可编译；可以在第一批窄路径上继续扩展，不另写随后丢弃的第二套解析器。设备维修期间可完成 host、固件构建和视觉验证，但不得把设备资源门槛标成通过。

| 批次 | 工作内容 | 完成条件与依赖 |
|---|---|---|
| P0 · 词典核心窄路径与基线 | 建立合成样本和私有样本清单；实现一个精确词的索引定位与跨块解压探针；复用 miniz；核对实际句柄和目标整数范围 | 九套样本各有可复现查询；最大两套的首次／热路径有 host 数据；标准固件能编译；有设备时先测小路径。原始统计放忽略目录，无完整 UI |
| P1 · 完整文件与缓存路径 | `.ifo/.idx/.dict/.dict.dz/.syn/.syn.dz`、压缩索引准备、字段解码、重复词头、坏文件及有界资源；配置与缓存提交 | DICT01–DICT04、DICT08 的适用 host 项通过；与固定版本 sdcv 对照结果；取消、坏索引和写失败不得假成功；依赖 P0 |
| P2 · 当前页取词与手势 | 命中几何、中文／英文候选、当前页跨行选区、移动事件与接触所有权；先用合成释义检查面板状态 | DICT05–DICT06 的 host／截图项通过；原轻扫、图片、页脚、链接、K2 和唤醒输入回归通过；依赖 P0 的结果接口 |
| P3 · 可日常使用版本 | 真实 worker 查询、管理与排序、基础富文本、音标字体、分页、多词典、加载／取消／错误、休眠与 USB 交还 | P1/P2 整合；九套词典均可查询及阅读，适用 Debug／sanitizer／固件／截图通过；设备完成 DICT07–DICT11 才标可用验收；第一批功能范围到此 |
| P4 · 连续查词与体验完善 | 释义内取词、有限返回历史、返回原释义页、文字交叉引用；按结果决定是否加入主动拼写建议 | 历史只保存查询和位置，不堆积释义／画布；失败返回当前释义，关闭全部返回正文；依赖 P3 的资源结果，不扩大到生词本 |

P0 若显示资源或等待不可接受，先调整索引粒度、文件打开生命周期或单次处理量；不直接加入更重的语言引擎。P3 的真机门槛失败时，交付本地候选并保留明确未测／失败项，不提前宣称达到 KOReader 的响应。

开始实现时，将已采用的产品行为补入 `decisions.md`，目录与配置补入 `storage.md`／`store-implementation.md`，输入与面板补入 `ui-implementation.md`，worker／所有权补入 `architecture.md`，专项保留在 `acceptance.md`；不将本规划全文复制到多份权威文档。每批在开发状态追加证据，实际能力变化后再更新当前摘要。

## 10. 验证方法与交接

新增一组必要的词典核心测试，复用现有 app／graphics／store／content worker／released tap 测试覆盖接入点；不为每个字段、每套词典或每种错误各建一套测试框架。合成词典覆盖排序、重复词头、采样边界、跨块字段、组合类型、32 位溢出、坏 RA、损坏长度和取消。解析及生命周期改动运行 ASan／UBSan；固件必须覆盖 `ESP_PLATFORM` worker 路径，host 64 位通过不代替目标边界。

私有九套词典采用确定的命中、不命中、中文词中间触点、屈折、别名和长释义查询集；记录词典文件摘要及参考引擎版本。参考 sdcv 需从当前 KOReader 构建清单核对并锁定，不使用同名旧 fork 代替。比较词典、实际词头、全部义项和规范化后的字段内容；渲染差异独立记录。对于参考端不识别的 `.syn.dz`，可在临时副本解压后作辅助对照，并单独标明，不声称原客户端已验证压缩别名兼容。

实际 KOReader 客户端用于核对选词、切换和释义可读性，sdcv 输出只证明检索结果，不能替代客户端体验。公开 CI 不依赖用户词典；本地真实样本结果与 CI 合成测试分别报告。

代码批次按仓库标准入口配置 Debug、检查实际注册的 CTest 并运行完整测试、运行适用 sanitizer、执行标准固件构建、`python3 tools/check_handoff.py` 和 `git diff --check`。性能探针复用 `tools/summarize_reader_perf.py`，必要时仅增加词典阶段识别；报告完整样本与 P50／P95／最大、冷／热条件、配置和内存，不过滤慢样本。授权设备操作前先完成可复现构建和私有样本准备。

当前仍需由实现和实测确定的事项：miniz 随机块解压的目标开销、首次索引验证时间、现有字体对音标与生僻字的覆盖、拖选刷新节奏、长释义分段后的样式连续性，以及所有词典启用时的尾部延迟。遇到这些问题先收集证据，不预设扩大资源、替换阅读引擎或降低验收要求。
