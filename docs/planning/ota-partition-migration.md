# OTA 双 7 MiB 分区与重装

Read Pico 的 16 MiB 内部 Flash 使用双 7 MiB 应用槽，保留双槽 OTA 和启动失败回滚（D50）。双 4 MiB 布局的设备须通过电脑完整重装一次；旧 OTA 清单固定提供 0.6.2。设备端升级规则见[固件更新实现](../development/platform-runtime.md#固件更新)。

## 分区布局

| 区域 | 偏移 / 大小 |
| --- | --- |
| Bootloader | `0x0` / 至多 `0x8000` |
| 分区表 | `0x8000` / `0x1000` |
| `nvs` | `0x9000` / `0x6000` |
| `phy_init` | `0xF000` / `0x1000` |
| `ota_0` | `0x10000` / `0x700000` |
| `ota_1` | `0x710000` / `0x700000` |
| `otadata` | `0xE10000` / `0x2000` |
| 未分配 | `0xE12000` / `0x1EE000` |

权威定义是 `firmware/partitions.build.csv`，板级构建、镜像校验和发布工具都从它读取地址与容量；`tools/ota_manifest.py` 校验分区条目的类型、子类型、地址、大小和标志，拒绝重叠、缺项或多项。书籍、设置和进度保存在 TF 卡，没有另设 Flash 数据分区。

正式镜像距槽上限剩 1 MiB 时作为复核点，按链接 map 复查新增资源和组件。内置回退字体是最大的单项资源；改用 `-Os`、缩减字库或证书包都须在同一设备、书籍和缓存条件下比较打开、翻页、刷新与内存后再决定。

## 为什么必须完整重装

新 `ota_0` 覆盖旧 `ota_1` 的一部分，旧 `otadata` 落入新 `ota_1`。只换分区表会留下错误槽位的应用和启动元数据，而应用 OTA 按设备当前分区表选槽，因此布局切换走 D41 的整片安装路径：由电脑写入配套的 bootloader、分区表和应用。

## 渠道隔离与镜像身份

- 旧固件内置的 `/firmware/manifest.json` 固定提供 0.6.2；新布局使用 `/firmware/ota-v2/manifest.json`。部署工作流支持渠道隔离，新安装包缺失或无效时停止部署，旧作业不得覆盖已切换的站点。
- 新渠道清单使用 `manifest: 2` 并声明布局。旧固件只接受格式 1，并在擦除前比较 `esp_app_desc.project_name`；新布局使用独立的项目名 `pico_page_ota7`，因此即使新镜像小于 4 MiB，被错误配对时也会被旧端拒绝。
- 新固件核对清单布局、镜像项目名、版本和摘要，并在提供更新、擦除目标槽和确认待验证启动前核对设备上的实际分区。TF 卡上的更新缓存和安装记录按布局识别。

## 安装、备份与恢复

| 初始状态 | 安装路径 |
| --- | --- |
| 全新安装 | 使用新布局的全量镜像，擦写后从 `0x10000` 启动 |
| 运行旧布局的 Pico Page | 保存阅读位置，用电脑或网页安装器完整重装，无需先 OTA 到旧渠道的最后一版 |
| 原厂固件，或 Pico Page 仍在原厂分区表上 | 先核对实际 Flash 与安全状态并保留原系统恢复材料，再按相同路径完整安装 |

网页安装器在擦除前检查 ESP32-S3、16 MiB Flash、Flash 加密和 Secure Boot 状态及全量镜像 SHA-256，并要求用户确认连接的是 Read Pico；随后擦除整片 Flash，从 `0x0` 写入并校验，再请求重启。浏览器显示成功只覆盖擦写校验，设备实际启动需要单独确认。实现见 [InstallPage.astro](../../web/src/components/InstallPage.astro)。

整片擦除会清除旧系统、NVS、应用和选槽记录。需要恢复原厂或其他系统时，先准备该设备的可信恢复镜像或完整 Flash 备份并核对摘要；原厂固件的内部数据不一定能从通用镜像恢复。安装只操作内部 Flash，TF 卡上的书籍、伴随目录、`PicoPage/`、字体和网络设置不受影响。面板 VCOM 由独立 PMU 提供，擦写路径不得调用任何校准写入。写入边界见[固件开发指南](../../firmware/README.md#硬件与写入边界)。

整片安装中断时，按安装页指引进入 ROM 下载模式，重新完整安装同一套已校验镜像。全量镜像在 `ota_0` 放置一份可启动的应用；固定 ESP-IDF 的 bootloader 在成功启动初始 `ota_0` 时写入有效选槽记录，其后的 OTA 向另一槽写入，由首次启动自检决定是否接受。

需要返回旧分区布局的设备，通过电脑完整安装匹配的旧包，并按 TF 数据格式核对所需备份。验收项见 [OTA01–OTA07 和 INST01–INST04](../development/acceptance.md#固件更新)。
