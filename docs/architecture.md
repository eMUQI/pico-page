# Pico Page 程序架构 · 当前实现基线

版本：handoff v0.2。首先服从 [当前决定](decisions.md)。本文件替代历史 v0.1 的冲突决定，保留其职责划分。内容是设计契约，不是已完成代码。

## 1. 结构

模块化单体固件 + 按需使用的主机内容工具。单仓库，先只支持 Read Pico。正文、排版、位置、同步策略的纯逻辑可在 host 编译；平台与 UI 是适配层。

```text
用户输入（屏幕 / 电容键）
           ↓
上下文输入映射 → app / reader_session（唯一阅读状态所有者）
                   ├─ reader_document：原书 / 派生内容 → 内容块、资源、锚点
                   ├─ reader_layout：内容 + 排版参数 → PageLayout
                   ├─ reader_display：合成、刷新 → Presented / Failed
                   ├─ reader_store：读写文件、提交确认、缓存与索引
                   └─ reader_sync：位置编解码、网络传输、远端候选

reader_ui：渲染只读状态 + 提交语义动作；不是上述业务的所有者
reader_system：网络生命周期、时间、休眠协调、诊断
platform_read_pico：官方 BSP / PMU / 屏幕与输入驱动的受控适配
```

这是职责图，不表示任意模块可以互相调用。外部 KOSync 是进度服务，不是书籍存储或完整备份服务；Karakeep 是后续来源，不是设备内浏览器。

## 2. 模块与所有权

| 模块 | 拥有/负责 | 禁止 |
|---|---|---|
| `app` | 启动、导航、用例编排 | 堆入 EPUB/驱动实现 |
| `reader_contracts` | 小型公共值类型与端口声明 | 杂项工具和全局可变状态 |
| `platform_read_pico` | BSP、PMU、原始输入、硬件能力 | 用户排版/同步策略；篡改工厂校准 |
| `reader_system` | 网络、电源协调、时间可信度、诊断 | 绕过保存/显示直接切断电源 |
| `reader_display` | 合成、刷新调度、缓冲生命周期、基准帧状态 | 决定阅读位置、直接保存进度 |
| `reader_document` | 书籍身份、目录、内容块、资源、源位置映射 | 以本机页码作为永久位置 |
| `reader_layout` | 字形、换行、段落、分页、命中区域 | HTTP、持久化或面板控制 |
| `reader_session` | 当前书、期望/已显示位置、短历史、排版会话 | 持有 GUI 控件、绕过 store 写文件 |
| `reader_store` | 普通文件权威、提交、书库扫描、可重建索引、同步记录 | 选择哪个冲突进度获胜 |
| `reader_sync` | 身份/位置编解码、协议、冲突策略 | 网络回包直接切页；上传未保存位置 |
| `reader_ui` | 页面、控件、状态呈现、语义输入 | 直接访问 SD/NVS/HTTP/EPD |

先按目录/组件建立边界，不要求每个模块都成为任务或有独立仓库。首轮可以只实现 contracts/session/store 与 recording display，不生成十套空框架。

### 2026-10-07 阅读响应性实现

固件启用 `ReaderApp` 的受控存储与异步内容模式。host 保留同步模式用于既有行为对照；异步回归单独启用与固件相同的调度入口。以下为当前代码事实，不代表真机延迟验收完成。

- 主应用仍独占 Session、当前正文、主字体和显示画布。`ContentJob` 每项工作拥有独立解析器、字体和输出缓冲；只在完成标记发布后转移结果，工作任务不修改在途显示缓冲。固件在应用初始化、网络启动前预留一个内容 worker：内部栈 32768 字节、优先级 1、无绑核，指针请求队列容量 1、非阻塞入队，满时返回启动失败；最多一项运行、一项排队。worker 与队列保留至固件复位，空闲时阻塞等待，不持有书籍或 TF 句柄；每项工作完成后释放其局部资源，发布完成后不再访问该 `ContentJob`。取消仍需等完成，必要保存继续执行既有不可中断提交。初始化失败释放队列，后续请求可重试。可选任务的内部余量检查扣除已经预留的栈，不重复计入栈预算。
- 前台开书、详情、跨章/分段跳转、图片及位置换算使用可取消请求。正文图片未准备好时先呈现文字和固定占位，保持阅读输入可用；已准备好的当前页/预取位图直接显示。新请求先取消旧工作，等旧任务退出再启动；结果依任务代次校验。同步另校验账户和已保存快照。位置映射任务启动失败时最多尝试 3 次，后两次通过主循环轮询间隔至少 50 ms；不阻塞输入、不重发 HTTP，也不保证能解决持续内存不足。耗尽后留在同步面板，区分内部内存不足与任务创建失败，清除可用候选及上传资格，重新检查和明确确认后才能上传。
- 进度提交持有不可变的已显示版本快照，完成只确认该版本。切书等待保存成功；失败保留旧会话。USB、休眠等存储所有权交接仍先等待任务退出和进度提交，不能在写入中卸载卡。
- 空闲时先完成必要保存，再为当前 EPUB 准备锁屏封面，随后准备一页布局、字形和正文位图，必要时包含相邻分段；随后读取/保存分页索引、统计当前章及全书。预取完成即停止扩展；全书统计仍可低优先级增量推进，输入会取消在途统计。锁屏封面在当前页保存完成后复用内容 worker 与缓存，不依赖全书统计成功；准备前释放已交还的分页会话，内存不足时释放下一页预取。仅命中有效缓存或成功提交封面/无封面缓存才确认准备完成；启动、读取、分配或提交失败与取消后延后重试。首次开书立即休眠时，先保存已呈现进度并释放预取/统计资源，再由同一 worker 准备原封面。已在生成的原封面直接接入轮询，交还后再执行保存与清理，不同步销毁；显式休眠同样遵守失败重试间隔。主循环轮询交接，任务完成后才绘制锁屏并进入休眠；等待期间的新输入取消休眠请求，K2 仍执行全刷。准备阶段达到 PW05 的预算后请求取消，仍须等任务停止访问文件才休眠；失败或无可用封面时采用书名回退。绘制回调只读取缓存，不现场解码，不放大书库缩略图。TXT 不调度封面任务。字体摘要每次最多读取 64 KiB，与每批最多 8 页的统计交替执行；输入取消后保留摘要游标和已完成的页边界。各批统计共用一个统计会话，其中保留已打开的书籍、统计专用字体和当前分段；会话在计数代次变化、离开正文、其他内容任务需要文件或内存时结束，普通翻页不结束会话。首次解析被取消时没有可保留的结果，需重新解析。新分页不等待字体摘要；摘要只用于验证持久分页缓存，稍后读入的缓存不得覆盖本会话已完成的章节。可选分页缓存无法分配或启动时跳过缓存，继续统计；统计遇到暂时内存不足时延迟 1 秒重试。
- 内容块以强书籍身份和规范化版本定位，保留源锚点、图片、链接和片段目标；源结构精确换算仍使用原 EPUB。分页索引包含强字体身份、算法版本和几何条件，短期访问页历史独立保留非标准入口与返回栏高度。
- 当前正文像素、下一页像素与按目标几何缓存的图片分别复用。书库封面按可见批次准备后合并更新。正文补图复用单个内容任务槽，结束后校验书籍、请求代次、章节/分段、页起点和排版；只更新图片矩形，以带区域的 Overlay 帧提交，不增加阅读修订。输入待处理时不启动或应用补图；正在显示的帧保持不可变。菜单打开后取消正文补图，恢复未完成的正文页时重新调度；旧任务确认结束后才释放和启动新任务。图片预览也在工作任务中解码；面板缓存缺失时允许显示原有图片不可用状态，不在 UI 绘制中重启解码。
- 可选驻留载荷采用 4 MiB 目标及 PSRAM 空闲/连续块门槛，优先回收远处索引、不可见封面、预取与低价值字形。此目标不包括分配器、FreeType 内部对象和工作任务临时副本，不是全系统内存硬保证。

解压/XML、分页和图像处理均有取消检查，但单次阻塞 SD 调用不能被抢断，缓存摘要计算也仍是有界整块操作。首个未命中文本页的字体打开、单页排版/绘制和配置提交仍有主任务工作；不能仅据工作任务存在就承诺所有输入都在 10–20 ms 内完成。阶段日志与[验收矩阵](acceptance.md)用于确定设备上的剩余最长等待。正文补图通过既有 BSP 的 `epd_hl_update_area` 提交区域；其他正文帧沿用整屏更新，K2 与基准失效仍全刷。波形和电源窗口保持原值；区域刷新的灰阶、残影、时延及能耗须真机测量。

## 3. 关键数据

### BookIdentity

内部内容身份基于未修改原书文件的强摘要。另存原文件名、来源、内容规范化版本。KOSync 的文档标识单独保存/生成，不能拿 SHA-256 或阅读包摘要冒充其部分 MD5。路径是当前位置，不是内容身份；同名不同内容必须隔离。同内容的多个路径可共享可重建缓存，但各自伴随记录不静默合并；KOSync 可能仍把它们视为同书。

### DocumentAnchor

与字号/视口无关：阅读顺序中的资源标识 + 稳定源块/节点 + 有明确单位的文本偏移。当前偏移工作默认是 Unicode 标量值；接入现有引擎时必须说明 UTF-8 字节、UTF-16 单元、标量值与空白规范化的转换。格式在 G1 真实位置对照前不宣称冻结。原始 EPUB 结构映射、规范化规则和版本是位置兼容的一部分，不只复制某一个 XPath 函数。UTF-8 与 GB18030 TXT 使用固定字节目标、字符边界分段和段内 Unicode 标量偏移保存本地位置；编码分别使用独立的内容修订。当前没有 KOReader TXT 位置适配。

固定页文档以后使用源页索引与视口/裁切信息，不强行借用 EPUB 的段落偏移。页面编号、百分比属于派生显示，允许未知，不承担唯一身份。

### LayoutSpec / LayoutKey / PageLayout

LayoutKey 包含内容与引擎版本、字体摘要/样式、字号、行距、边距、视口和影响几何的设置。灰阶/刷新偏好单独作为 RenderProfile；仅颜色策略改变不必重分页。PageLayout 包含起止锚点、绘制指令和与绘制共享的链接/图片命中区。正文在完整行之间分页；末行放不下进入下一屏，不裁半行、不重字漏字。总页数未完整计算时显式未知或标注估计。

### OperationContext / FrameToken

每次异步操作带 `book_id`、会话代次、排版代次、请求 ID；必要时再加存储挂载代次和账户作用域。旧结果不因「任务成功了」就被采用。FrameToken 区分正文与纯 UI 更新。

### ReadingRecord / SyncRecord

ReadingRecord 包含最后成功呈现的锚点、内容版本、写入者及本地修订、保存确认。本地计数只在同一写入者/会话规则内比较，不能跨设备直接按计数大小裁决。SyncRecord 按设备、账户/服务和书籍隔离，含基线、待上传的已保存版本、远端候选、确认版本。本地保存、传输、远端记录存在性、定位质量分别建模。原稿 `last_ack` 需补 `book_id`、`local_revision`、`account_scope`、对应锚点/摘要。

## 4. 一次正文翻页

```text
ReaderAction::TurnPage
→ session 请求目标
→ worker 返回有效 PageLayout
→ display 呈现并确认对应 FrameToken
→ session 更新 visible_anchor
→ store 提交并确认 saved_revision
→ sync 合并该已保存版本的待办
```

排版成功但刷新失败：不推进已显示位置。显示成功但保存失败：可以继续显示，明确「尚未保存」，不上传此版本。菜单、状态条、样文预览和 K2 全刷不会推进正文锚点或增加正文修订号。目录/脚注跳转先暂存起点，目标正文呈现成功再提交返回历史；失败或取消不污染历史。

## 5. K2 与输入路由

`MapInput(context, input) -> Action` 是唯一映射入口。正文：K1/K3 翻页，K2 ForceRefresh；工具通过中部触摸打开。所有可交互页面的 K2 均发 ForceRefresh，只重刷当前画布；关闭、取消、确认由屏幕控件承担。自定义按键按 [功能路线图](roadmap.md) R7 实现；开工前保持静态默认表。K1/K2/K3 不增加组合键或长按；电源键长按菜单按 R1、D34 实现，真机时序待测。

全刷是明确用户操作：即使帧缓冲与上次相同也必须执行有效清理刷新，不能被差分优化跳过。刷新事务忙碌时按原稿忽略重复 K2，不中断在途波形，也不积累无限请求。触发面板打开/关闭/唤醒的一次输入序列有唯一所有者，不将尾部抬手交给下一层。

## 6. 内容路径与组件复用

G1 先验证普通中文 EPUB、换字号恢复和 KOReader 源位置往返。优先研究 CrossPoint/PapyriX 的章节/位置/缓存代码，记录平台耦合与许可，再确定最小路径。原生解析或配套预处理先做一条，不同时做两套完整引擎。保留原书；规范化/转换不得丢失同步需要的源映射。必须预处理才能离线读时，其产物属于必要资源，不是可随意删除的缓存。

首版范围：正文、标题、基础强调/列表、目录、基础中英混排、字体/字号/行距/边距；插图和脚注在有界资源内提供基础路径或明确降级。复杂样式不承诺完整还原。PDF、Karakeep、词典/批注/脚本等后置，不用「格式已识别」冒充可阅读。

## 7. 同步契约

identity / locator / transport / policy 四部分分开。优先原生 KOSync；参考的源码入口见 references.md。不要只实现 HTTP 然后把核心定位列为以后补。

打开书只恢复本地，不自动联网或查询。首版同步仅由用户明确触发，远端回包只给候选，不强跳。断网先保存；联网先拉远端并与上次基线比较，不盲推旧 outbox。两边都改变时提示；不按最大百分比或不可信时间戳自动覆盖。没有远端记录不等于原书不匹配。mapping=unsupported 不提供「跳到附近」。近似定位先说明并确认，失败保留本地；不得退到第一页后报告成功。

「继续此处」仅保留本地，并记录对该候选的处置；不能随后由休眠上传暗中覆盖同一冲突。显式「上传并替换」走单独确认，服务器未实现条件写入时仍要承认竞态并保留恢复信息。取消在途上传不能保证服务端未变化，记录结果待确认，再拉取核对。确认成功只对应发送时的版本；期间又翻页则当前版本仍待上传。同步服务成功不等于其他设备已经接续，UI 显示「远端记录」，不推断对方实时状态。

## 8. 显示、内存与任务

Display 提供意图（翻页/UI/图片/手动清理/恢复）而不是把波形常量散布各页面。灰阶与更新范围是两个维度；用户模式名称不等于 Palma 的已验证效果。板级初始化、工厂 VCOM、供电时序沿用锁定且已核查的路径，不盲用别的屏幕实现。

维护基准帧 valid/unknown；刷新失败保留软件已确认锚点，但物理屏幕可能部分更新。Read Pico 的行队列欠载在电源状态正常时，等待驱动结束供数并解除扫描回调后，保留目标画布，执行一次完整清屏和从白底重画；清屏与重画均成功才确认显示，重试失败仍使基准失效并进入错误页。恢复复用既有驱动画布，不新增任务或图像缓冲；恢复期间不能抢断波形或改写在途目标。同步面板在网络等待期间保留一次等待画面，网络阶段通知只更新状态，不触发额外刷屏；完成/失败、明确取消和 K2 仍沿用各自显示事务。错误提示只能在屏幕能恢复呈现后显示；不能承诺坏屏一定能显示自身错误。同一时刻只有一个面板刷新；在途 buffer 不可变。减少重复整屏复制，优先复用驱动现有缓冲。

684×1216×4bit = 415872 bytes，约 406.1 KiB，仅是一个像素缓冲计算，不是总内存预算。实际内部堆、PSRAM、DMA 能力与最大连续块需分别测量，网络/字体/图像峰值要单测。正文/图片/字体缓存有上限，不整书解压或一次缓存所有中文字形。

任务先按工作类型安排：app/UI、阅读计算、显示、文件 I/O、网络；不预设每模块一任务。解析器/缓存对象在后台工作时只有一个拥有者；协作式取消并等待退出，不能强删后复用。前台当前页优先于未读章节预计算，进度保存优先于长导入；所有队列有界。

## 9. 休眠、恢复与诊断

休眠协调器冻结非必要请求，等待/取消有界工作，确认必要呈现与保存，保存待办，结束网络并通过 BSP 设置真实唤醒来源。网络失败不能无限阻止休眠。保存失败有独立分支；不能因低电量就声称已保存。深睡按重新构造对象处理。无卡时仍能使用内置错误字体呈现提示；不自动格式化挂载失败介质。未授权不刷写；分区/OTA 空间是 G0 要核对的硬件事实，不预生成虚构 CSV。

## 10. 预期工程组织与验收
