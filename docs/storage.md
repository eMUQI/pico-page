# 文件式存储设计 · Pico Page

版本：handoff v0.2。用户数据以 TF 卡的普通文件为主要来源，配置可读、可改、可备份。
这不是数据库中心式书库，也不是固件内部配置导出的一个镜像。
本文件的详细目录与格式是开工默认；尚无实际数据迁移或存储实现。

## 1. 命名与目录

项目改名后，建议统一使用 `PicoPage/` 与 `.picopage/`，而非硬件名 ReadPico。
原方案的路径是提案，不能据此假设用户已经有旧数据；如实际存在则显式兼容/迁移。
固件内部统一使用“卡根目录相对路径”，不得把 host 的 `/mnt/...` 编入数据。

```text
TF 根目录/
├── Books/                            # 可自行分类，默认扫描根之一
│   └── 文学/
│       ├── 示例.epub                  # 原书保持原样
│       └── 示例.epub.picopage/        # 完整文件名 + 产品后缀
│           ├── book.json             # 原书身份、来源、元数据覆盖
│           ├── settings.toml         # 本书覆盖项
│           ├── progress.json         # 正式本地阅读位置
│           ├── annotations.json      # 后续：书签/批注
│           ├── cover.png             # 可选：用户指定封面
│           └── prepared/             # 若必要：离线阅读所需派生产物
├── Articles/                         # 后续文章来源，目录可配置
│   └── Karakeep/
└── PicoPage/
    ├── settings.toml                 # 全局阅读/UI/刷新配置
    ├── integrations.toml             # 服务地址等非敏感配置
    ├── fonts/                        # 用户自行提供的字体
    ├── data/                         # 用户数据，不是缓存
    │   ├── collections.json          # 后续：自定义收藏集
    │   ├── history.jsonl             # 有界维护的阅读历史
    │   └── devices/<device-id>/
    │       ├── session.json          # 最近书籍/目录等本机恢复上下文
    │       └── sync/                 # 按服务/账户/书籍隔离基线与待办
    ├── cache/
    │   ├── library-index/            # 文件扫描派生索引
    │   └── books/<book-id>/           # 可重建元数据/缩略图/布局
    ├── inbox/                        # 可选接收入口，非唯一导入路径
    ├── tmp/                          # 未发布内容与中间写入
    └── logs/                         # 有配额、可轮转
```

Books、Articles 不是强制名称，也不以“登记进数据库”作为文件存在的前提。
扫描配置根，跳过产品数据、伴随目录、临时文件与缓存。目录不可读不是空书库。
索引丢失时扫描恢复；支持直接复制原书。尚需处理的文件仍可见并有原因。
以内容 ID 区分同名书，以当前路径定位文件；中文长文件名与大小写行为须在实际 FAT 配置测试。

## 2. 数据等级

| 类别 | 权威/是否可删除 | 例子 |
|---|---|---|
| 原始内容 | 用户文件，删除须明确确认 | EPUB，未来 PDF |
| 必需派生资源 | 设备不能重建时不可当缓存清理 | prepared、必要源位置映射 |
| 用户记录 | 不可由索引重建，不随清缓存删除 | 设置、进度、收藏、手动封面、未来批注 |
| 可重建数据 | 可以通过本机重建后继续使用 | 搜索索引、自动封面缩略图、布局与字形缓存 |
| 设备级私密数据 | 单独管理/显式导出 | 设备身份、Wi-Fi 密码、同步令牌 |

如果固件无法在没有电脑/网络时重建 `prepared/`，其删除必须叫“移除必要阅读资源”，
明确会需要重新处理。不能放进“清理全部缓存”。
缓存目录本身可采用二进制索引或以后采用数据库，但绝不能存唯一一份设置/进度。

## 3. 单书记录

`book.json`：schema_version、原书强摘要、格式、内容/映射版本、来源及用户覆盖的元数据。
原始元数据可重提取；用户覆盖项不能当可重建元数据删除。
`settings.toml`：只写与全局不同的覆盖项。
`progress.json`：schema_version、book_id、content_revision、writer_id、local_revision、
实际可定位的 anchor、可选展示值/可信度；具体锚点编码在 G1 冻结。
机器修订号只在明确作用域内比较，不把两台设备的计数直接排序。

`annotations.json`、collections 和完整历史界面后置；先留格式边界，不创建无用途空文件。
没有 `.picopage/` 时在首次需要保存后惰性创建，而不是扫描全卡就生成大量空目录。
只读/满卡允许显示可读内容，但明确不能保存，不能依赖隐藏内部进度伪装成功。

伴随数据不使用 KOReader 的 `.sdr`，不执行/覆盖 `metadata.epub.lua`。
KOReader 兼容通过同步/位置适配实现，不等于共享内部配置文件。

## 4. 身份、移动、删除

固件内移动/改名若实现，必须同时处理书与伴随目录；首版可以只浏览，不做写管理。
电脑端移动时建议一起移动。遗漏伴随目录可扫描仍存在的记录尝试按摘要关联；
不能承诺找回已删除或不在该介质中的记录。
原文件发生变化、同名替换时重新验证身份，不按路径+大小沿用旧进度。
同内容多副本的本书设置/位置不静默合并；缓存可以共享，KOSync 身份可能相同，要如实说明。

默认“删除书籍”：在确认后删除原书、相应不再需要的派生资源与可重建缓存，保留伴随目录内用户记录。
删除操作不触碰远端、不删除其他副本共享的在用缓存。孤立伴随目录可由明确操作清理。
“清除阅读记录”单独确认。重置应写入新的有效空状态/重置标记并同步处理备份，
不能删主文件后又从 `.bak` 自动复活旧进度。它也不能立即被旧会话/outbox 回写恢复。
“使用阅读默认”提交新的无覆盖状态，避免旧设置备份在下一次启动时重新覆盖。

## 5. 配置与手改

UTF-8 TOML 用于常改设置；JSON 用于机器维护的结构化状态。格式带 schema_version。

```text
固件默认 → 全局 settings.toml → 本书覆盖 → 本次面板尚未保存的预览
```

最后一层不持久化。关闭/取消回到已应用状态；应用时当前内容优先重新排版。
“设为阅读默认”仅接受已验证有效的参数，作用范围明确；不因字体缺失就偷偷改用户偏好。
区分偏好字体与实际回退字体。

示例见 [examples/sdcard/PicoPage/settings.toml](../examples/sdcard/PicoPage/settings.toml)。
该示例只有读取规则提案，不是已实现接口；不包含真实字体文件。

### 读写要求

界面和外部编辑都使用同一文件，不另有 NVS 配置在重启/休眠时覆写。
全局文件缺失采用内置默认；已有但语法错误时保留原文件，报告路径、行/字段与原因，
本次使用上次有效配置或默认。失败不触发自动“恢复出厂”。
版本高于支持范围时保护原文件，不能按旧 schema 重写删除未知内容。
界面只更新变更字段，尽量保留注释、其他字段与顺序；保注释写回需要专门验证。
不能因为选择 TOML 就声称天然支持无损编辑。若库达不到，先记录限制并实现可靠最小写回，不默默丢注释。
用户配置不要求手工更新校验和或机器修订号；检测外部更改使用实际文件摘要/版本。
保存前检测从加载后是否被外部改变，冲突时重新读/合并或提示，不写回过期内存副本。

首版用“重新加载配置”，不需要持续监视热更新。
配置变更对当前页面的应用可以是显式动作；成功加载和成功保存不能混为一件事。

## 6. 保存、备份与恢复

唯一写入口在 store。位置变化后有界合并写入；主动关书、休眠、交出文件系统前提交必要记录。
只保存成功呈现的正文位置；提交确认返回具体版本，超时/失败不宣称已保存。

小型文件：同文件系统写临时内容 → 检验/flush/适用同步 → 保留有限上一份有效版本 → 发布 → 确认。
也可使用带序号/校验的日志或双槽，选型先故障注入验证；不要为所有文件上复杂日志系统。
rename 不是跨文件/任意掉电的绝对事务。断电只承诺尝试恢复最后有效已提交记录，不承诺最后触摸绝不丢失。
临时文件不能无条件因 mtime 最新就胜出；记录恢复结果，外部手改与机器恢复规则要分开。
多个文件的操作通过可恢复标记/顺序完成，避免“一半改名、一半还在”且无修复路径。

备份数量、日志大小、缓存配额有界。删除缓存前取消在用布局任务，不能删仍打开的共享文件。
卡移除后停止新 I/O，挂载代次变化使旧返回失效；保存成功后移卡与未提交后移卡使用不同状态。
卡回来后重验原书身份与文件内容。挂载失败不得自动格式化。

## 7. 多端访问与隐私

USB MSC 若以后实现，固件与电脑不能同时各自挂载同一可写 FAT 卷；先提交/关闭、移交所有权，
退出后再挂载/扫描/加载。局域网修改也经 store，使用文件变更冲突检查。
传输只在用户开启的会话运行；未完成文件不加入正式书库，失败保留原文件。

NVS 仅用于设备身份、凭据、必要硬件绑定等小型例外，不是隐藏配置权威。
是否加密需实际配置验证，存 NVS 不自动等于加密。
integrations.toml 放非敏感服务信息和 credential_ref，常规备份不含令牌；显式导出另做。
不得将 Wi-Fi 密码、令牌、用户 EPUB 或 Flash 备份提交 Git。

## 8. 同步与备份

progress.json 描述本地正式位置；devices/<id>/sync 记录该设备/服务/账户确认过的版本与待办。
复制卡到其他设备不直接继承上一台设备的上传确认。切换账户也不继续发送旧队列。
远端回包不直接改文件，先经 session/policy；“保留本地”不隐式触发覆盖远端。
未来按目录同步工具搬运文件时同样可能冲突，不能把文件复制视为自动合并算法。

备份单书：原书 + 伴随目录；必要时另带用到的用户字体。
备份阅读环境：所有配置扫描目录 + PicoPage，通常可排除 cache/tmp/logs；凭据单独处理。
字体缺失时保留配置并回退。恢复旧版本资料先校验/迁移，不覆盖更新格式。

## 9. 首版存储模块建议子目录

`config`：解析、校验、覆盖合成、保注释写回。
`sidecar`：身份/设置/位置与必要资源。
`library`：扫描、搜索/排序派生索引。
`commit`：临时写、确认、恢复。
`cache`：有效性与配额。
`sync_state`：本机账户作用域的基线/待办。
这些是一个 reader_store 内部职责，不是六个线程。
具体测试见 acceptance.md 的 ST/CFG 系列。
