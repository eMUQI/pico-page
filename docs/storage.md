# 文件式存储设计 · Pico Page

用户数据以 TF 卡的普通文件为主要来源，配置可读、可改、可备份。这不是数据库中心式书库，也不是固件内部配置导出的一个镜像。当前固件已实现书库、字体、配置、单书进度和缓存的基本路径；以下标明后续功能。

## 1. 命名与目录

卡根目录分成用户自行放置的文件与固件管理的数据。`PicoPage/` 用于设备数据，`<原书完整文件名>.picopage/` 用于该书的设置和进度。固件内部统一使用「卡根目录相对路径」，不得把 host 的 `/mnt/...` 编入数据。

默认配置下，用户把 EPUB、TXT 放入 `Books/` 或其子目录；若已自定义书库扫描根目录，则放入配置的目录。TTF、OTF 及对应许可文本放入 `Fonts/`。`PicoPage/` 由设备管理，手工编辑配置时只修改需要的 TOML 文件；清理缓存使用设备上的「清理全部缓存」。移动书籍时一并移动同名的 `.picopage/` 目录，才能保留该书的进度和单书设置。`LockScreens/` 保存用户管理的 PNG/JPEG 休眠图片；在电源与休眠设置中启用「自定义图片」后使用。转换缓存放入 `PicoPage/cache/lockscreens/`，轮播记录放入 `PicoPage/data/last-lock-screen.txt`；清缓存不删除原图和轮播记录。格式与大小限制见 [自定义锁屏](roadmap.md#r4--自定义锁屏)。

```text
TF 根目录/
├── Books/                            # 默认书库根目录；EPUB、TXT 可自行分类
│   ├── Articles/                     # 用户放文章类书籍的建议位置
│   └── 文学/
│       ├── 示例.epub                  # 原书保持原样
│       └── 示例.epub.picopage/        # 完整文件名 + 产品后缀
│           ├── progress.json         # 正式本地阅读位置
│           └── settings.toml         # 本书覆盖项
├── Fonts/                            # 用户自行添加的 TTF、OTF 和许可证文本
├── LockScreens/                      # 用户自定义休眠图片：PNG/JPEG
└── PicoPage/
    ├── settings.toml                 # 全局阅读/UI/刷新配置
    ├── network.toml                  # 可选：最多 5 个 Wi-Fi 凭据，明文保存
    ├── sync.toml                     # 可选：KOReader 同步账户，明文保存
    ├── data/last-book.txt            # 上次打开的书
    ├── data/recent-books.txt         # 最多 128 本的最近打开顺序与可选日期
    └── cache/                       # 可重建内容
        ├── covers/                  # 书籍及休眠封面缩略图
        ├── positions/               # 书库显示的章节和百分比
        ├── pages/                   # 全书页数与分页结果
        └── update.json              # 固件更新：上次读到的清单、安装记录、已跳过的版本
```

默认扫描 `Books/`；书库首页直接显示其中的书和子文件夹，不显示额外的 `Books` 入口。文章放入 `Books/Articles/` 后，首页显示 `Articles` 文件夹；进入后可查看其中的书。若配置单个其他扫描根，同样直接显示其内容；配置多个扫描根时，首页显示各根目录入口。全局设置仍可更改书库扫描根目录，但固件不再默认扫描卡根的 `Articles/`。若存储卡仍采用旧目录，安装新固件前先备份，再把卡根 `Articles/` 中的书籍及同名 `.picopage/` 伴随目录移到 `Books/Articles/`，把 `PicoPage/fonts/` 中的字体和许可文本移到 `Fonts/`。若 `PicoPage/settings.toml` 中的 `library.roots` 仍指向旧目录，按书籍移动后的实际位置修改；使用默认书库时写 `roots = ["/Books"]`。若全局 `reader.font` 指向旧字体目录，改为 `font = "Fonts/<字体文件名>"`。再检查每本书旁的 `<原书完整文件名>.picopage/settings.toml`：其中若有指向旧目录的 `reader.font`，也改为 `Fonts/<字体文件名>`，或删除该覆盖项以继承全局字体。核对新路径和阅读进度后再清理旧目录；固件不自动迁移。扫描配置根时跳过产品数据、伴随目录、临时文件与缓存。目录不可读不是空书库。索引丢失时扫描恢复；支持直接复制原书。尚需处理的文件仍可见并有原因。以内容 ID 区分同名书，以当前路径定位文件；中文长文件名与大小写行为须在实际 FAT 配置测试。

## 2. 数据等级

| 类别 | 权威/是否可删除 | 例子 |
|---|---|---|
| 原始内容 | 用户文件，删除须明确确认 | EPUB、UTF-8/GB18030 TXT，未来 PDF |
| 必需派生资源 | 设备不能重建时不可当缓存清理 | prepared、必要源位置映射 |
| 用户记录 | 不可由索引重建，不随清缓存删除 | 设置、进度、收藏、手动封面、未来批注 |
| 可重建数据 | 可以通过本机重建后继续使用 | 搜索索引、自动封面缩略图、布局与字形缓存 |
| 设备级私密数据 | 单独管理/显式导出 | 设备身份、Wi-Fi 密码、同步令牌 |

如果固件无法在没有电脑/网络时重建 `prepared/`，其删除必须叫「移除必要阅读资源」，明确会需要重新处理。不能放进「清理全部缓存」。缓存目录本身可采用二进制索引或以后采用数据库，但绝不能存唯一一份设置/进度。

## 3. 单书记录

`book.json` 为预留设计，当前尚未作为运行时权威文件实现：schema_version、原书强摘要、格式、内容/映射版本、来源及用户覆盖的元数据。原始元数据可重提取；用户覆盖项不能当可重建元数据删除。`settings.toml`：只写与全局不同的覆盖项。`progress.json`：schema_version、book_id、content_revision、writer_id、local_revision、实际可定位的 anchor、可选展示值/可信度；当前编码与兼容范围见 store-implementation.md、document-runtime.md 和 sync-runtime.md。机器修订号只在明确作用域内比较，不把两台设备的计数直接排序。

`bookmarks.json`（[功能路线图](roadmap.md) R9）：schema 1，字段为 `schema_version`、`book_id`、`content_revision`、`next_sequence` 和 `bookmarks` 数组。每条书签有 `sequence`、与 `progress.json` 同格式的 `anchor`、创建时的 `chapter` 与 `excerpt`，以及可选的 `percent`；`created_at` 与 `time_source` 只在有可信时间时成对出现。序号与 `next_sequence` 用十进制字符串保存，删除后不复用。文件缩进输出，便于在电脑上查看。提交前比较主文件和 `.bak` 是否与读取时一致，再按 tmp、回读、备份、发布的顺序写入。主文件缺失时从有效 `.bak` 恢复；主文件或此时的 `.bak` 损坏、schema 较新时不使用、不覆盖，也不允许修改；主文件有效或属于其他内容、而 `.bak` 为较新 schema 时，同样不允许修改。身份不符时不显示这些书签；为当前书第一次加书签时，先把旧文件改名为 `bookmarks.<旧 book_id 前 8 位>.<n>.json`（旧备份为同名加 `.bak`），n 取不与已有文件冲突的最小值，再创建新文件。清理缓存、保存进度和「清除阅读记录」都不修改书签文件。`annotations.json`、collections 和完整历史界面后置；先留格式边界，不创建无用途空文件。没有 `.picopage/` 时在首次需要保存后惰性创建，而不是扫描全卡就生成大量空目录。只读/满卡允许显示可读内容，但明确不能保存，不能依赖隐藏内部进度伪装成功。

伴随数据不使用 KOReader 的 `.sdr`，不执行/覆盖 `metadata.epub.lua`。KOReader 兼容通过同步/位置适配实现，不等于共享内部配置文件。

## 4. 身份、移动、删除

固件内移动/改名若实现，必须同时处理书与伴随目录；首版可以只浏览，不做写管理。电脑端移动时建议一起移动。遗漏伴随目录可扫描仍存在的记录尝试按摘要关联；不能承诺找回已删除或不在该介质中的记录。原文件发生变化、同名替换时重新验证身份，不按路径+大小沿用旧进度。同内容多副本的本书设置/位置不静默合并；缓存可以共享，KOSync 身份可能相同，要如实说明。

默认「删除书籍」：在确认后删除原书、相应不再需要的派生资源与可重建缓存，保留伴随目录内用户记录。删除操作不触碰远端、不删除其他副本共享的在用缓存。孤立伴随目录可由明确操作清理。「清除阅读记录」单独确认。重置应写入新的有效空状态/重置标记并同步处理备份，不能删主文件后又从 `.bak` 自动复活旧进度。它也不能立即被旧会话/outbox 回写恢复。「使用阅读默认」提交新的无覆盖状态，避免旧设置备份在下一次启动时重新覆盖。

2026-10-06 实现：普通进度保持 schema 1；清除状态单独使用 schema 2，字段为 `schema_version`、`state: "cleared"`、`book_id`、`content_revision`。先提交清除备份，再提交主记录，两者均通过同步写入和回读比较后才报告成功。主记录缺失或损坏时，清除备份返回无阅读位置，不恢复旧记录。下一次成功显示正文后可保存新的 schema 1 记录。旧固件会将 schema 2 视为不支持并停止开书，不会从旧备份恢复位置；降级兼容性须明确告知。若第二次提交失败，主记录可能仍是原位置；界面报告未完成，重新读取文件后才能重试。

管理确认捕获原书大小/CRC32 和两个进度文件的完整内容，提交前再次比较，发现外部修改即拒绝。操作当前书籍前结束其会话并取消异步请求，阻止旧回包恢复已清除的位置。「删除原书文件」仅删除选中的 EPUB 或 TXT，并清理该路径的内存封面缓存；伴随目录保留。「清理本书缓存」目前只清理内存封面和当前书分页起点，不声称回收 TF 空间。

封面缓存位于 `PicoPage/cache/covers/`，每个尺寸一个文件：书库缩略图 184×250（裁切铺满）、详情 120×160、休眠封面 684×1040。文件名为书籍相对路径的 FNV-1a 64 位摘要加尺寸；文件头记录路径、原书大小和修改时间，其后是 4 位灰度像素。只有文件头的条目表示该版本没有可用封面，不再重复解码。文件头不符、长度不符或读取失败时按未缓存处理并重新生成；原书大小或修改时间变化后旧条目失效。这些文件只由「清理全部缓存」删除，目前没有配额；删除或移动原书后会留下不再使用的条目。大小和修改时间都不变的原书替换不会被发现，清理全部缓存后恢复。

书库位置缓存位于 `PicoPage/cache/positions/`，每本书一个文件，文件名为书籍相对路径的 FNV-1a 64 位摘要。文件头标识为 `PPPOS1`，记录路径、原书大小和修改时间；其后两行是离开该书时显示的章节名和全书百分比。返回书库、换书和休眠时写入，且只在该位置已成功显示并确认保存后写入；换书时尚未保存的位置，等它的保存确认后再写入，保存失败则不写。它只用于书库卡片和「继续阅读」卡片的显示，不参与恢复阅读位置；进度文件仍是唯一依据。没有条目时，书库按进度文件是否存在显示「在读」或「未读」。清除本地进度时同时清空该条目。旧尺寸 164×184 的书库缩略图不再使用，由「清理全部缓存」删除。

全书分页缓存位于 `PicoPage/cache/pages/`，每本书一个文件，文件名为书籍相对路径的 FNV-1a 64 位摘要。文件头记录内容版本、书籍路径、原书大小和修改时间、正文字体的路径、大小和修改时间，以及版心和排版参数、原书内容标识和字体内容摘要；其后按书脊顺序记录每章的段数，再逐段记录页数和各页起点（32 位小端整数），尚未统计的章节记为 `0xFFFFFFFF`。文件头标识为 `PPPAGES3`，旧格式按未缓存处理。文件头或长度不符时按未缓存处理并重新统计。全部统计完成时写入；离开书籍、休眠或进入 USB 传输时写入已完成的章节。内容上限 1 MiB，超过时不写入，每次开书重新统计。这份缓存只用于页码显示，不参与阅读位置的保存或恢复。

固件更新状态位于 `PicoPage/cache/update.json`，上限 24 KiB。内容包括上次读到的更新清单（更新日志只保留前 8 KiB）、检查时间、重启安装前写入的安装记录（安装前后的版本）和启动失败后被跳过的版本。清单可以重新读取；安装记录只用于重启后显示一次结果。「清理全部缓存」会删除这个文件：尚未显示的安装结果不再显示，已跳过的版本会重新提供。文件内容无效时按不存在处理。它不含凭据，不影响阅读进度。


## 5. 配置与手改

UTF-8 TOML 用于常改设置；JSON 用于机器维护的结构化状态。格式带 schema_version。

```text
固件默认 → 全局 settings.toml → 本书覆盖 → 本次面板尚未保存的预览
```

最后一层不持久化。关闭/取消回到已应用状态；应用时当前内容优先重新排版。「设为阅读默认」仅接受已验证有效的参数，作用范围明确；不因字体缺失就偷偷改用户偏好。区分偏好字体与实际回退字体。

示例见 [examples/sdcard/PicoPage/settings.toml](../examples/sdcard/PicoPage/settings.toml)。示例不包含真实字体文件。

全局 Wi-Fi 开关使用 `[network]` 下的 `wifi_enabled = true`，默认开启，只允许布尔值。该项不允许单书覆盖；界面修改沿用保注释、比较原文和验证提交流程，不改 `network.toml` 或 `sync.toml`。

### 读写要求

界面和外部编辑都使用同一文件，不另有 NVS 配置在重启/休眠时覆写。全局文件缺失采用内置默认；已有但语法错误时保留原文件，报告路径、行/字段与原因，本次使用上次有效配置或默认。失败不触发自动「恢复出厂」。版本高于支持范围时保护原文件，不能按旧 schema 重写删除未知内容。界面只更新变更字段，尽量保留注释、其他字段与顺序；保注释写回需要专门验证。不能因为选择 TOML 就声称天然支持无损编辑。若库达不到，先记录限制并实现可靠最小写回，不默默丢注释。用户配置不要求手工更新校验和或机器修订号；检测外部更改使用实际文件摘要/版本。保存前检测从加载后是否被外部改变，冲突时重新读/合并或提示，不写回过期内存副本。

首版用「重新加载配置」，不需要持续监视热更新。配置变更对当前页面的应用可以是显式动作；成功加载和成功保存不能混为一件事。

## 6. 保存、备份与恢复

唯一写入口在 store。位置变化后有界合并写入；主动关书、休眠、交出文件系统前提交必要记录。只保存成功呈现的正文位置；提交确认返回具体版本，超时/失败不宣称已保存。当前实现：翻页后不立即提交，页面停留 2 秒且没有输入时提交一次；连续翻页只提交最后停留的页。打开工具（页眉显示保存状态）、返回书库、开另一本书、休眠、USB 文件传输、上传同步和书籍管理确认前立即提交。翻页后 2 秒内断电或复位时，重开回到上一次已提交的位置。提交失败的处理与原先相同。

小型文件：同文件系统写临时内容 → 检验/flush/适用同步 → 保留有限上一份有效版本 → 发布 → 确认。也可使用带序号/校验的日志或双槽，选型先故障注入验证；不要为所有文件上复杂日志系统。rename 不是跨文件/任意掉电的绝对事务。断电只承诺尝试恢复最后有效已提交记录，不承诺最后触摸绝不丢失。临时文件不能无条件因 mtime 最新就胜出；记录恢复结果，外部手改与机器恢复规则要分开。多个文件的操作通过可恢复标记/顺序完成，避免「一半改名、一半还在」且无修复路径。

备份数量、日志大小、缓存配额有界。删除缓存前取消在用布局任务，不能删仍打开的共享文件。卡移除后停止新 I/O，挂载代次变化使旧返回失效；保存成功后移卡与未提交后移卡使用不同状态。卡回来后重验原书身份与文件内容。挂载失败不得自动格式化。

## 7. 多端访问与隐私

USB MSC 已实现，固件与电脑不能同时各自挂载同一可写 FAT 卷；先提交并关闭文件、移交所有权，电脑安全弹出后在设备退出并重启，再挂载、扫描和加载。局域网修改也经 store，使用文件变更冲突检查。传输只在用户开启的会话运行；未完成文件不加入正式书库，失败保留原文件。

NVS 仅用于设备身份、凭据、必要硬件绑定等小型例外，不是隐藏配置权威。是否加密需实际配置验证，存 NVS 不自动等于加密。integrations.toml 放非敏感服务信息和 credential_ref，常规备份不含令牌；显式导出另做。不得将 Wi-Fi 密码、令牌、用户 EPUB 或 Flash 备份提交 Git。当前实现把 Wi-Fi 密码和同步账户密钥以明文存在 TF 卡的 `PicoPage/network.toml`、`PicoPage/sync.toml`，便于手工编辑；`FileStore::save_private()` 替换这两个文件时不留 `.bak`，避免旧凭据残留。

## 8. 同步与备份

`progress.json` 描述本地正式位置；devices/<id>/sync 记录该设备/服务/账户确认过的版本与待办。复制卡到其他设备不直接继承上一台设备的上传确认。切换账户也不继续发送旧队列。远端回包不直接改文件，先经 session/policy；「保留本地」不隐式触发覆盖远端。未来按目录同步工具搬运文件时同样可能冲突，不能把文件复制视为自动合并算法。

备份单书：原书 + 伴随目录；必要时另带用到的用户字体。备份阅读环境：所有配置扫描目录 + PicoPage，通常可排除 cache/tmp/logs；凭据单独处理。字体缺失时保留配置并回退。恢复旧版本资料先校验/迁移，不覆盖更新格式。

## 9. 首版存储模块建议子目录

`config`：解析、校验、覆盖合成、保注释写回。`sidecar`：身份/设置/位置与必要资源。`library`：扫描、搜索/排序派生索引。`commit`：临时写、确认、恢复。`cache`：有效性与配额。`sync_state`：本机账户作用域的基线/待办。这些是一个 reader_store 内部职责，不是六个线程。具体测试见 acceptance.md 的 ST/CFG 系列。
