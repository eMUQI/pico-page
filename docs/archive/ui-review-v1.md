# Pico Pages 界面交接包 v1：设计审查与修订清单

日期：2026-10-05  
对象：用户提供的《Pico阅读固件界面设计.zip》  
结论：保留视觉方向和主要页面结构；先修正行为契约、文件式管理入口和状态表达，再作为固件实现基线。

## 1. 审查范围与证据边界

检查了交接包中的 README、tokens、screens、actions、fields、input、copy 和参考 HTML；逐组检查了全部 36 张原始 684 × 1216 PNG，并对正文等关键状态查看原像素图。书库、连接、设置与休眠的 27 个参考 HTML 画面另行离线渲染核对，未修改源文件。

HTML 补充渲染使用本地可用的 Noto CJK 与楷体回退，不能用于判断与原作者字体完全一致的字形和精确换行。原始 PNG 的问题不受这个限制。通用提示 S12 以参考 HTML 与文档核对为主。

本次是静态设计与交接契约审查，不是可运行固件测试；没有验证真实触摸、按钮事件、EPD 波形、残影、功耗、SD 写入或 KOReader 往返同步。动作中的问题指的是文档会导致的实现歧义，不代表某个尚未实现的固件已经出现该运行错误。

| 步骤 | 审查环节 | 状态 |
|---|---|---|
| 1 | S01 书库与单本管理 | 基础列表可保留；缺少文件夹浏览，删除/记录保留需与伴随目录对齐 |
| 2 | S02–S03 阅读与工具 | 沉浸式结构可保留；原图裁字、K2 默认动作与入口布局需调整 |
| 3 | S04 目录与返回 | 层级与当前位置明确；缺目录/读取失败、跳转历史提交需分开 |
| 4 | S05 排版 | 预览与应用分离可保留；全书阻塞重排和默认继承规则需修改 |
| 5 | S06–S07 同步与冲突 | 已区分保存/上传；远端状态、定位质量、取消与冲突策略需补齐 |
| 6 | S08 刷新 | 预设与全刷分离可保留；失败后的屏幕承诺和一次一帧要求需修正 |
| 7 | S09–S10 导入与设置 | 阶段与失败设计可保留；原书/派生文件、配置文件入口与诊断需补齐 |
| 8 | S11–S12 休眠与提示 | 休眠标记清楚；保存失败/唤醒占位/提示输入规则需补齐 |

## 2. 建议保留的设计

黑白为主、方角和明确文字层级符合本项目的目标，无需改成手机式卡片界面。正文默认没有永久顶栏，工具面板按需出现，也值得保留。

“本地保存”和“已上传”有独立表达；“继续此处”不立刻覆盖服务器；删除原书、清除进度、清理缓存分别写出影响。这些方向正确，下面的调整主要是让状态和存储实现真正支持这些承诺。

目录提供当前位置、层级展开与返回跳转前位置；原书无目录时使用阅读顺序回退而不假造章节名。缺图、缺字体、移卡、鉴权失败、不同位置等异常也已有考虑，不需要推倒重画。

## 3. 优先修订

### R01｜先修正文底部半行被裁切

**证据：** 原始 `png/S02-1.png`；参考 `Read Pico 阅读体验.dc.html` 中对应 frame 的正文区域设为 `top:64px; bottom:88px; overflow:hidden`。

最后一行“好心绪。”在页脚上方被截断。这是交付 PNG 已经存在的现象，不是字体回退或固件推测。不能让开发者把隐藏超出部分当成分页方式。

**建议：** 正文分页按完整行框、实际字体度量和页脚保留区结束；最后一行放不下就全部放到下一屏，不把正文或注音/脚注标记裁开。正文下沿与页脚之间增加明确留白。工具面板可以遮盖已有正文，但正常阅读页不能裁字。

**验收：** 28/38/56 px 三种字号、两类中文字体、中英混排与带上标脚注的页面，均无半行、重复或漏字；相邻页能连续接上。

### R02｜书库应补文件夹入口，而非只提供数据库式的平铺书架

**证据：** S01-1、S01-1b、S01-6；`screens.md` 的 S01；`copy.md` 第 188 行固定要求复制到 `books` 文件夹。当前详情仅有进度、同步、占用等，缺少普通可用书籍的完整文件位置。

**建议：** 保留最近阅读和现有书架视图，增加“文件夹”入口，支持当前路径、返回上一级、目录/文件区分及简单排序。列表/封面是展示偏好，不替代文件夹组织。扫描范围来自配置，而非写死一个目录。索引丢失能重建；文件的存在不依赖索引登记。

详情增加原文件路径、伴随目录位置、阅读条件（可打开/需要处理/资源缺失）。若支持在设备内移动或改名，应同时操作书和 `.readpico` 伴随目录；第一版不实现文件管理写操作也可以，但应明确范围。

用户仅移动原书、遗漏伴随目录时，不承诺总能找回进度。内容摘要只能帮助识别仍存在的记录，不能恢复已经不存在的数据。

**验收：** 直接拷入已支持的文件可在文件夹中看到；索引清理后仍能发现它；更改配置扫描根目录后能使用自己的目录命名；同名不同内容不误用进度。

### R03｜设置补“配置文件”入口和加载结果

**证据：** S10-3 只显示空间、设备、诊断与清理缓存；S10-2 以“在手机上修改地址或账户”为主要修改路径。

**建议：** 在“存储与设备”加入轻量“配置文件”页：显示全局配置及连接配置路径，提供“重新加载配置”和加载结果。解析失败要能显示文件名、行/字段、原因，以及当前沿用的有效设置。遇到更高版本配置、只读卡、写入失败时不静默覆盖文件。

不要求在小屏上编辑长文本，不要求新增完整文件编辑器。手机网页仍可作为方便入口，但不是管理普通配置的唯一方式。凭据的真实存放位置另行说明，不把不存在于普通文本里的令牌显示成可直接手改。

**验收：** 在暂停写入/安全维护状态下外部修改配置，重新加载后界面值对应；加载失败不毁掉原文件，不在关机时用旧内存值回写覆盖。

### R04｜“应用排版”不要等待全书排版完成

**证据：** `README.md` 第 35 行；`copy.md` 第 94 行；S05-2 原图写着“正在按新设置排版全书”。

**建议：** 点击应用后优先完成当前位置附近的重排，保留内容锚点，尽快返回正文。其余章节按需或后台分批处理；全书页数暂时未知属于正常状态。把“当前页面准备中”和“后台页数计算中”分成两个状态。

建议文案为“正在应用排版，完成后回到当前内容”，不要在 UI 契约中要求全书先完成。旧排版任务必须能取消或失效，不能在新设置生效后覆盖新页面。

**验收：** 长书改字号不依赖后续未读章节全部处理完；改字号、再改字号、取消、立即跳章等序列不会采用过期结果。

### R05｜本书覆盖、全局默认与未应用预览应有明确规则

**证据：** S05-1、S05-3、S05-4；`actions.md` 的 `SetReadingDefault`；S05-3 字体不可用但“设为阅读默认”仍为可用外观。

**建议：** 默认只存本书发生变化的字段；其余继承全局。把含混的“恢复默认”改为“使用阅读默认”，明确删除本书覆盖而不是恢复固件出厂值。“设为阅读默认”需说明采用的是当前已应用值还是预览值、是否同时应用于本书、会影响哪些未设置单独覆盖的书。

未应用的预览切换到其他标签时，可以保留在此次面板会话中；关闭时取消并提示，或要求显式应用。选一个一致规则，不交给各页面自行判断。

字体不可用时允许选用替代字体；不能把未成功验证的字体直接设为全局默认。对“偏好字体”和“实际使用字体”分别标注，避免当前 S05-3 的字体名和替代字体说明混淆。

### R06｜K2 默认动作需重新决策，建议打开/关闭工具

**证据：** `README.md` 第 36 行、`input.md` 第 34 行明确 K2=立即全刷，并承认三个按键不能打开工具面板。

这不是文件之间的笔误，而是这一版设计主动改变了此前建议的交互。我建议默认 K2=工具/返回，上下键负责翻页；全刷保留在工具中，把 K2=全刷作为可选映射。

这样不用为了偶发全刷牺牲菜单入口，也避免轻触中键就触发一次整屏刷新。若作者明确偏好中键全刷，可以保留该选择，但不要声称它同时实现了按键可达工具。

脚注返回、目录返回、普通面板关闭的 K2 语义也应统一确定。不要依赖尚未核验的按键唤醒能力。

### R07｜工具导航的位置和语义不宜随状态大幅变动

**证据：** S03 最右入口为“全刷”；S04/S05/S06/S08 同组最右格变为“收起”。目录标签栏位于顶部，排版与同步标签栏位于高度不同的底部面板顶部；同步成功/错误之间位置也会变化。

**建议：** 固定工具的四个类别“目录/排版/同步/刷新”，关闭作为独立操作，不替代全刷。全刷只放在刷新页或一个稳定的快捷按钮。

为面板定义有限的布局模板，例如“目录全屏”和“固定高度底部面板”，后者同一标签栏保持固定纵坐标；内部内容变化不推动主导航。可以保留目录全屏例外，但需要明确切换规则。

这是提高操作稳定性的建议，不意味着所有页面都必须相同高度，或必须采用新的视觉语言。

### R08｜同步页显示的是服务端记录，不是另一设备的实时状态

**证据：** S06-4 的第三格是“其他设备 / 无不同位置 / 检查于 10:58”；`fields.md` 只有远端候选、收到时间等字段，未定义读取另一设备实时状态的能力。

**建议：** 最小修改是把第三格改为“远端记录”，写“与本机位置一致 / 有不同位置 / 尚未检查 / 无记录”。展开后显示记录来源设备和时间可信度。不能仅凭一次同步检查断言另一台设备现在已经读到哪里。

普通使用界面还可简化为“本地已保存”和“同步情况”两层，把协议细节放到展开区域；不必每次让用户理解三端状态。

S07-1 的文档要求按钮等权重，PNG 却把“转到另一设备的位置”画成黑底主按钮。两者应统一；建议两个选择同等视觉权重，不预设远端一定更正确。

### R09｜同步缺少几个不可合并的状态

**证据：** `fields.md` 第 10 行把 `unsupported` 指向 S06-6，而该页仍提供“转到附近”；`actions.md` 第 18 行取消同步一律回到离线待同步页；`last_ack` 只有时间和账户作用域。

需要分开：

- **远端没有记录**：不是“不是同一本书”，可以按策略首次上传。只有取得明确的身份冲突证据，才能显示原书不匹配。
- **可近似定位**：才允许显示约百分比跳转；完全不支持、没有可用定位信息时不能画出可执行跳转。
- **联网/服务错误**：包括超时、无法建立连接等，不应都折成登录失效或位置不同。
- **上传确认属于旧位置**：用户同步过程中继续翻页，旧确认不能把新位置标成已上传。确认需要绑定书籍身份、位置修订号、账户和服务范围。
- **取消尚未发送的操作 vs 已在途上传**：后者不能承诺服务器未变化；取消表示不再继续后续步骤，必要时显示“结果待确认”。

“继续此处”还需记录用户对本次远端候选的选择，避免下一次检查立刻重弹；不能关闭提示后又被“休眠前上传”自动覆盖远端，违背提示承诺。

### R10｜统一输入事件规则，避免打开面板又被同一次抬手关闭

**证据：** `input.md` 第 21 行：“打开面板或模态框后，第一次抬手只用于关闭”；第 24 行笼统禁用重排/跳转/同步中的按钮，却有取消动作。

**建议：** 明确一次 pointer 序列的所有权：触发打开的 down/up 由原动作完整消费，不交给新面板；关闭面板的那次触摸也不穿透给正文。不能写成“下一次抬手无条件关闭”。对不同操作逐一规定 busy 状态中仍允许的取消、返回等安全动作，不笼统禁用全部控件。

脚注命中区不能不加约束地统一扩到 88×88：默认正文行距是 38×1.5=57 px，放大范围可能覆盖相邻行或旁边链接。建议按行和邻近命中区裁切扩展，并定义重叠时的确定性选择规则。

### R11｜把“一次交互一次最终帧”改为“无无意义中间帧”

**证据：** `README.md` 第 27 行、阶段验收要求只有一次提交；`screens.md` 同时要求按下态、等待态、取消态、传输阶段与错误提示。

**建议：** 普通瞬时操作尽量合并重绘；长任务允许必要的开始、阶段、完成/错误状态。每个稳定状态只提交一次有效更新，不因旋转动画、每次轮询或重复回调刷屏。按下态可按交互收益合并或省略，不作为每次必须额外提交的一帧。

不能把“每个用户动作只有一次刷新”作为所有功能的验收规则，否则显示加载提示后将无法再显示结果。

### R12｜刷新失败只能保证软件保留上次位置，不能保证屏幕保留完整旧画面

**证据：** S08-4 与 `copy.md` 第 170 行写“已保留上一画面，阅读位置没有改变”。

**建议：** 改为“本地保留上次确认的位置，屏幕内容可能未完整更新”。显示层标记基准帧有效性；恢复成功后才显示状态提示，持续失败时通过已具备的诊断渠道告知。

失败面板是“显示恢复后可呈现的提示”，不能把再次刷新仍可能失败的同一块屏幕当作绝对可靠的告警通道。此项需要显示模块契约确认，不是单纯换文案。

### R13｜原始 EPUB、必需预处理文件和可删缓存须在 UI 中分清

**证据：** S01-2、S09-1、S09-5 把只接受预处理产物写为硬约束；S10-3 只统计原文件、缓存和可用空间。

“设备端不能转换原 EPUB”仍是需技术验证后冻结的实现路线；若首版最终如此，可以写明，但不应让界面阻止原书作为普通文件被保存、发现和备份。未达到阅读条件的书显示“需要处理”，而不是从文件视图消失。

如果离线阅读依赖 `prepared/`，它不是随时可删的普通缓存。空间统计至少能区分原书、必要阅读资源、用户记录、可重建缓存。清理缓存不能使一部之前可离线阅读的书突然要求回电脑重新处理。

复制导入应显示配置确定的目录；`Books`/`books` 命名和导入路径要统一，不把示例路径硬编码到提示中。

### R14｜删除与移卡后的承诺要与文件式存储对齐

**证据：** S01-7 承诺删除后保留进度；S01-4 说“位置已保存在本机，插回存储卡后可继续”；S02-8 将移卡与未保存一起呈现。

**建议：** 明确“删除原书及可重建缓存，但保留伴随目录中的记录”，或者把记录移至明示的可恢复目录；选择一种规则并保持普通文件可见。不能依赖并未设计的隐藏内部权威进度副本。

存储卡不可用不等于最后一次位置未保存：若刚才已成功写入，显示“后续变化暂无法保存”；若真的存在未提交位置，才显示“此处尚未保存”。重启后没有可读取的本地记录时，也不保证知道上次位置。

低电量休眠有“保存成功”和“无法保存”两个分支。不能在低电提示中无条件写“阅读位置已保存”。保存失败应允许重试/明确放弃；不要求用户再翻一页才能触发下一次保存尝试。

## 4. 交接文档中应顺手修正的缺口

### R15｜错误分类与历史提交

`OpenToc` 失败不能一律进入“原书未提供目录”：解析错误、文件丢失、卡不可读分别处理。`RequestSleep` 失败不能统一映射为低电量页：低电是触发/环境状态，不是所有休眠失败的原因。

`JumpToAnchor` 写着“跳转前压入历史”，S04-5 又要求跳转失败时历史不变。建议先暂存跳转起点，目标页呈现成功后提交返回历史；失败或取消则丢弃临时候选，或明确实现回滚。

### R16｜触摸热区和视觉层级

先处理 60 px 高的开关/视图切换热区，再讨论 86 px 与 88 px 的微小差别。视觉控件可以不放大，但要给到足够且不重叠的可点击区域，真机检查边缘可达性。

关键禁用原因、小标签不宜靠 20 px 小字承担全部信息；优先试 22–24 px。删除线容易把“禁用”看成已删除内容，普通禁用可改为正常标签加状态说明，把删除线保留给确实缺失/失效的资源。

正文与主要图标建议从灰阶 0 的实黑开始验证，而非把所有 ink 固定为灰阶 1。是否使用其他灰阶由渲染配置和真机效果决定。网页的高对比滤镜只是辅助检查，不能替代实际的黑白/灰阶转换和面板验证。

### R17｜来源能力无法确认时，不把猜测写成故障结论

配网失败应按真实原因显示“未找到网络 / 无法连接 / 认证失败 / 超时”等。5 GHz 可以作为帮助建议，不能只看 SSID 含“5G”就确定频段；也不宜让“扫描只列可用频段”和默认失败示例全是 5 GHz 形成矛盾。

唤醒文案仍为占位，最终从 `wake_sources` 的真实能力生成，不在 PNG 定稿时固化为“轻触中间按键”。没有 SD 时“导出到 SD”不可用，应给原因或已有的替代诊断入口，不伪装成功。

### R18｜补齐可实现动作与状态

需要给排序、文件夹导航、列表翻屏、目录展开/收起、页脚切换、排版基本/进阶、输入映射、重新加载配置、缓存清理期间状态等控件补动作。可选择由 UI 本地状态处理的纯导航不必都变成跨模块业务动作，但交接必须说明其所有者。

`available_actions` 应成为可用条件的统一来源，避免 screens/actions/input 三处分别写相互冲突的禁用规则。同步状态不能只靠一个混合 enum 同时承担鉴权、远端存在、位置质量和操作阶段。

### R19｜资源完整性

`screens.md` 列出 69 个页面/组件状态，`png/` 实际只有 36 张，覆盖 S02–S08。其余 33 项（S01、S09–S12）有不同程度的 HTML/文字资料，但不符合“每个状态对应 PNG”的交接约定。需要补原像素导出，或准确声明哪些内容仅在 HTML 中提供，不能说这部分完全没有设计。

图标仍为文字符号占位。应补一致的矢量源与固件可使用的资源规格，验证缺字与实际灰阶表现；不要求固件运行时必须解析 SVG。

### R20｜让最终原像素稿由同一套参数生成

HTML、tokens、文字尺寸各维护一份容易漂移。建议让 tokens 成为可追踪的尺寸来源，再导出已核对的原像素图。正文样例由分页测试生成，不再靠 overflow 隐藏；所有动态值仍取 ViewModel，不照抄样图数字。

固定版本的设计包提供导出清单、布局版本与检查日期。审查时原始 PNG 优先判断真实交付效果，HTML 用于理解约束和修订，固件实现不直接复制设计稿业务代码。

## 5. 推荐执行顺序

1. **冻结行为契约：** R02–R06、R08–R15；先确认文件组织、按键、排版生效、保存和同步语义。
2. **修视觉与几何：** R01、R07、R16；修裁字、固定面板模板、热区和小字。
3. **补交接完整性：** R17–R20；补动作/状态、资源与全部导出。

第一轮不用新增卡片主题、统计、词典或复杂文件编辑器。保留已经建立的黑白组件系统，优先把高频阅读路径与真实状态闭合。

## 6. 最小验收场景

- 正常阅读连续翻页，底部完整行衔接，无截断、重复或跳字。
- K2 的默认行为明确，并在正文、面板、脚注、冲突和确认框中一致。
- 字号快速连改后应用，先恢复当前位置；取消不写入预览值；旧任务结果不覆盖新状态。
- 书籍只覆盖字号时，修改全局字体仍能继承，恢复默认能删除本书覆盖。
- 本地保存成功后移卡，与尚未保存时移卡，提示不同；低电量写失败不显示已保存。
- 同步期间翻页，旧上传确认不会把新位置标为已上传。
- 远端无记录、可精确定位、可近似定位、完全不支持和网络失败分别显示正确动作。
- 关闭冲突后不立刻重复弹出，也不被休眠自动上传悄悄覆盖远端。
- 模态打开和关闭均消费触发它的输入序列；脚注扩大热区不抢相邻行的操作。
- 缓存清理后仍可离线阅读，不删除必要预处理文件和伴随记录。
- 外部修改 TOML 后重新加载，失败保留原文件，成功与 UI 设置一致。
- 固件和桌面预览分别验收；后者不用于证明真实波形、残影、功耗或 SD 断电可靠性。
