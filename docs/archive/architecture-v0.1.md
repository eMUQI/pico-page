# Read Pico 阅读固件：程序架构设计 v0.1

日期：2026-10-05  
用途：开发立项、模块划分、接口讨论与实现验收。  
状态：架构提案，不是已完成的固件实现或兼容性测试报告。

## 1. 产品边界与本版决定

### 已确认的需求

主要自用，也会开源，以作者自己的阅读习惯和控制权为优先。首要且第一版只支持 Read Pico，不为尚未存在的其他设备建立通用插件框架。独立设计产品，可以复用现成组件与逻辑，开发框架优先 ESP-IDF。

内容以 EPUB 为主，后续需要 PDF 和 Karakeep 收藏网页；接受在设备外预处理书籍。参考 KOReader 的阅读体验，不照搬其所有设置。输入包括屏幕触摸和电容触摸按键；提供用户可选择的刷新模式。第一版必须能阅读 EPUB 内容并同步 KOReader 进度。

### 本提案采用的工作默认

这些是可调整的设计决定，不将其表述为用户已逐项确认。

| 事项 | v0.1 决定 |
|---|---|
| 首版内容路径 | 用户以 EPUB 为输入，电脑端预处理后导入；设备离线阅读 |
| 设备自主能力 | 字号、字体、行距、页边距在设备上修改并重新排版，不依赖在线服务 |
| 同步方向 | Read Pico 与 KOReader 双向同步，目标是同一处正文，不以百分比相等作为验收 |
| 同步兼容目标 | 优先原生 KOSync，不默认要求用户安装额外 KOReader 插件；可行性必须先验证 |
| 第一版界面 | 中文优先、竖屏优先；屏幕触摸为完整操作路径，电容键覆盖高频操作 |
| 内容组织 | 书库为入口，阅读页为核心，不做书城、推荐流或复杂仪表盘 |
| 软件结构 | 单仓库、模块化单体、显式依赖、少量后台工作任务 |
| UI 技术方向 | 轻量自绘组件与独立正文排版，统一灰阶合成；不移植 KOReader 整套 UI |
| 后续范围 | PDF、Karakeep、批注/词典、自动旋转、完整 OTA 产品体验后置 |

“预处理 EPUB 后阅读”不等于“设备能原生打开任意原始 EPUB”。第一版的支持声明应明确预处理流程和 EPUB 子集，不把两种能力混写。

## 2. 硬件与实现基线

核查的官方仓库说明列出：ESP32-S3、16 MB Flash、8 MB PSRAM、4.7 英寸 1216 × 684 的 16 灰阶屏，触摸屏与三个电容按键区；当前构建说明使用 ESP-IDF v6.1。[S1]

工程以官方可工作的硬件组件为起点，锁定 ESP-IDF、BSP、面板驱动和波形的具体提交或版本。不得将“使用最新分支”作为可复现构建策略。

复用 BSP、PMU、芯片驱动和面板适配，不直接继承演示程序的页面组织。VCOM 与面板上电/下电逻辑沿用已验证的板级路径，不给普通用户提供电压、波形时序之类的调节入口。官方说明 VCOM 在出厂时校准并存于 PMU。[S1]

板级适配仅负责硬件事实。屏幕逻辑方向、阅读手势、刷新偏好等属于上层策略。

## 3. 总体组织

```text
手机/电脑上的 EPUB
        │
        ▼
内容预处理工具 ── 原书 + 阅读包/索引 + 原始位置映射
        │
        ▼
TF 卡 / 显式开启的局域网传输
        │
        ▼
应用控制器（状态、导航、用例）
   ├─ UI：页面、组件、命中区域、输入映射
   ├─ 阅读会话：打开、翻页、目录、恢复、设置
   │    ├─ 文档：章节、内容块、资源、语义锚点
   │    └─ 排版：字体、换行、分页、命中信息
   ├─ 存储：书库、设置、阅读状态、缓存、同步待办
   ├─ 同步：书籍身份 / KOReader 位置适配 / 传输 / 冲突策略
   └─ 系统服务：网络、电源、诊断
        │
        ▼
显示调度：统一合成、刷新策略、帧生命周期
        │
        ▼
Read Pico 板级适配与复用的驱动
```

该图展示职责与运行数据流，不允许模块任意互相调用。核心规则如下：

- `document`、`layout`、位置与同步策略中的纯逻辑部分，不依赖 ESP-IDF 或具体 GUI 库，可以在主机测试。
- UI 只发送语义动作并展示状态快照；不直接保存文件、调用 HTTP 或刷新面板。
- `session` 是阅读位置和阅读历史的唯一业务写入者。网络回包只能提出同步候选，不直接改变当前页面。
- `display` 是面板刷新的唯一入口；所有页面、弹窗和正文都通过它合成。
- `store` 拥有持久化规则，其他模块不能各自写一份“上次进度”。
- `main` 是组装入口，负责注入接口和订阅事件，不放 EPUB 解析或业务实现。

## 4. 模块定义

| 模块 | 负责什么 | 主要输入与输出 | 明确不负责 |
|---|---|---|---|
| `app` | 开机流程、顶层状态、页面导航、用例编排 | Action → 状态快照、异步请求 | 不解析书籍，不直接调用芯片驱动 |
| `platform_read_pico` | 驱动集成、硬件初始化、原始输入、板级供电与唤醒 | 原始硬件事件；设备能力与驱动接口 | 不决定阅读交互、字号或同步策略 |
| `reader_system` | 网络生命周期、配网、休眠协调、设备时间、诊断 | 网络状态、电源请求、资源占用票据 | 不拥有书籍位置；不能绕过显示/存储直接关机 |
| `reader_display` | 灰阶合成、脏区域、刷新策略、帧缓冲、刷新完成通知 | Frame + RefreshIntent → Presented/Failed | 不解析 EPUB，不把尚未显示的页面登记为已读 |
| `reader_document` | 阅读包验证、章节和资源访问、内容模型、位置解析 | BookHandle + Anchor → 内容块/资源/目录 | 不依赖字体大小，不产生本机页码作为永久位置 |
| `reader_layout` | 字体栅格化、中文换行、段落布局、分页、链接命中区 | 内容块 + LayoutSpec → PageLayout | 不保存阅读进度，不调用网络或面板 |
| `reader_session` | 当前书籍、期望/已显示位置、翻页、跳转历史、重排恢复 | ReaderAction + 各模块结果 → ReadingState | 不持有 GUI 对象或 KOSync HTTP 细节 |
| `reader_store` | 书库索引、设置、可靠进度日志、缓存、同步 outbox、导入事务 | 结构化记录/文件流 → 确认或错误 | 不决定哪个冲突进度应该获胜 |
| `reader_sync` | 原书身份、位置转换、KOSync 传输与冲突判定 | 已保存位置 + 远端快照 → 同步候选/确认 | 不读取本机显示页码冒充 KOReader 位置 |
| `reader_ui` | 页面、控件、ViewModel、屏幕和电容键映射 | AppState → DrawList；输入 → ReaderAction | 不直接访问 SD、NVS、HTTP、EPD 驱动 |

另设小型 `reader_contracts` 存放共享值类型和接口声明。它不成为杂项工具库，也不包含可变全局状态。

`reader_system` 内部分 `power`、`network`、`provisioning`、`diagnostics`；`reader_sync` 内部分 `identity`、`locator`、`transport`、`policy`。先保持为子目录，不为每项功能增加一个仓库或运行时服务。

## 5. 四个必须先固定的数据契约

### 5.1 BookIdentity：原书是谁

```text
BookIdentity
  book_id                 内部稳定身份，基于原始文件强摘要
  source_sha256           原始 EPUB 的 SHA-256
  original_filename       原始文件名，仅做展示及兼容匹配的输入
  content_revision        内容与规范化版本
  package_schema_version  阅读包格式版本
  kosync_document_digest  按 KOReader 选定匹配策略生成的标识
  origin                  local_epub / karakeep / future_pdf
  origin_external_id      可空；例如 Karakeep bookmark ID
```

内部强摘要与 KOSync 的标识是不同概念。KOReader 的现有代码支持原书部分 MD5 或文件名 MD5；不能拿完整文件 MD5、SHA-256 或阅读包摘要直接代替。[S2]

默认以原始内容匹配。文件名匹配只作为明确配置的兼容选项，不能自动开启。移动书籍路径不应丢进度；同名不同内容也不能共用进度。

### 5.2 DocumentAnchor：读到哪里

```text
DocumentAnchor
  book_id
  content_revision
  kind                    reflow / fixed_page
  reflow:
    spine_item_id         EPUB 阅读顺序中的资源标识
    source_block_id       与原始内容映射的稳定块标识
    text_offset           明确约定为规范化文本的 Unicode 标量值偏移
    affinity              位于边界之前/之后
    quote_context         可选，迁移或核对用，不作为唯一身份
  fixed_page:             后续 PDF 后端使用
    source_page_index     零基页索引；外部协议由适配器转换
    viewport_or_crop
```

这里是契约草案，不是最终文件编码。UTF-8 字节偏移、UTF-16 单元偏移、Unicode 标量值偏移不得混用。规范化删除空白或合并节点时，需要保留可逆的位置映射。

`DocumentAnchor` 不包含“本机第 37 页”作为永久位置。换字体、字号或屏幕方向后，内容锚点不变，排版页码重新计算。

### 5.3 LayoutKey / PageLayout：这次怎么排

`LayoutKey` 至少包括内容版本、排版引擎版本、字体文件摘要、字号、行距、段距、边距、视口尺寸和文字排版选项。影响栅格化而不影响几何的刷新/灰阶参数单独放入 `RenderProfile`，避免无意义地全部重新分页。

`PageLayout` 包含起止锚点、绘制指令、链接/图片命中区和所属章节。页码是该布局下的派生值；整章或全书分页未完成时，页数允许未知，UI 不伪造总页数。

### 5.4 ReadingRecord / SyncRecord：保存与同步什么

```text
ReadingRecord
  book_id, content_revision
  visible_anchor          最后一次成功显示的正文位置
  local_revision          本机单调递增修订号
  saved_revision          已确认落盘的修订号
  changed_at              可空；附带时钟可信度
  per_book_preferences

SyncRecord
  account_scope           服务地址 + 账户身份
  book_id
  base_remote_snapshot    上次确认的远端版本/内容快照
  pending_local_revision  待上传的本地已保存版本
  acknowledged_revision
  remote_candidate
  mapping_quality         exact / approximate / unsupported
  state                   disabled / ready / pending / syncing /
                          conflict / auth_error / mapping_error / network_error
```

本地保存状态、网络传输状态和定位质量分别建模，不压成一个“成功/失败”字段。

## 6. 对外接口与事件

接口以值类型、只读快照和明确所有权为主。以下是需要固定的语义，不是可以直接编译的 API 代码。

| 接口 | 请求 | 结果 |
|---|---|---|
| DocumentSource | 打开阅读包、读取章节/资源、解析 Anchor | 文档元数据、内容块、结构化错误 |
| LayoutEngine | 从锚点排一屏、相邻分页、重排定位 | PageLayout、分页状态 |
| ReadingRepository | 读取/保存 ReadingRecord | Saved(revision) 或明确保存失败 |
| DisplayPort | 提交 FrameToken 与刷新意图 | Presented(token) 或 Failed(token, reason) |
| PositionCodec | 本地锚点 ↔ KOReader 位置 | 精确映射、明确近似或不支持 |
| SyncTransport | 鉴权、读取/写入进度 | 服务端响应快照与协议错误 |
| PowerCoordinator | 请求休眠、获得/释放活动票据 | 进入休眠或可解释的拒绝/超时 |

关键事件：`BookOpened`、`LayoutReady`、`FramePresented`、`ProgressSaved`、`NetworkChanged`、`SyncCandidateReceived`、`SyncAcknowledged`、`StorageUnavailable`、`SuspendRequested`。

异步结果必须带 `book_id`、会话标识和请求修订号。已经换书、换字号或离开页面后返回的旧结果，不得覆盖新状态。

## 7. 内容处理与格式策略

### 7.1 首版路径

```text
原始 EPUB（保持原样）
  → 验证与安全解包
  → 读取 OPF / spine / nav 或 NCX
  → HTML/CSS 子集规范化
  → 生成按章节或块分片的可重排内容
  → 整理字体、图片与目录资源
  → 生成原始位置映射和 KOReader 兼容映射
  → 验证阅读包
  → 导入设备
```

阅读包不是一组提前分页的图片。电脑承担解包、清洗、资源优化与索引工作；设备仍负责适合当前字号和屏幕的排版。

传输容器可以压缩，设备上的布局应方便分片读取；不要要求每次翻页重新扫描一个大 ZIP。原书和可重建缓存分开保存，清理缓存不删除书籍或阅读进度。

### 7.2 EPUB 首版支持轮廓

必须支持普通可重排 EPUB 的正文、标题、段落、基础强调、列表、目录和中文优先的基础换行规则。自定义字体、字号、行距与边距属于核心阅读能力。

普通插图与脚注按基础能力实现：图片在能力和资源预算内按比例展示；资源超限显示明确占位，不让正文打不开。脚注优先按内部链接跳转并提供“返回正文”，不以复杂悬浮排版为首版前提。

复杂表格、数学公式、嵌入脚本、复杂 CSS、固定版式 EPUB 和特殊矢量资源，不承诺完整还原。需要在预处理报告或文档详情中说明降级，不能悄悄删除内容或将损坏文件当成空书。

正文搜索、划线、批注、词典、朗读和插件系统不列入第一版验收。

### 7.3 后续扩展方式

PDF 是固定页面文档后端，可共享书库、会话、显示和持久化，但不强行通过 EPUB 的流式排版引擎。直接渲染、预处理为页面资源或其他路线需单独做质量/内存验证。

Karakeep 是内容来源，不是页面浏览器，也不是另一种排版引擎。建议先由电脑/自托管内容工具获取收藏内容并形成离线文章包，设备消费同一套流式内容模型。其公开 API 提供书签、列表等资源，使用 Bearer Token；正文和图片的实际可获取性仍需按具体接口验证。[S4]

设备不必首先实现 Karakeep 登录、爬虫、完整 HTML 浏览器或后台常驻下载。以后增加直连同步时，只替换内容来源适配，不改阅读页。

## 8. KOReader 同步设计：首要技术验证项

### 8.1 需要分开的四层

1. **书籍身份**：双方确认是同一原始内容。
2. **位置语义**：本机 Anchor 与 KOReader 实际使用的位置互相转换。
3. **协议传输**：鉴权、上传、下载、超时及重试。
4. **同步策略**：何时应用远端、何时上传本地、怎样处理冲突。

现有 KOSync 请求包含 `document`、`progress`、`percentage`、设备标识等字段；流式文档恢复调用 `GotoXPointer`。[S2][S3] 因而实现 HTTP 客户端，或者只传百分比，都不能等同于完成精确双向同步。

### 8.2 推荐的位置适配路线

在预处理工具侧验证与目标 KOReader/CREngine 版本一致的解析结果，生成原始内容位置与 KOReader XPointer 的映射；设备侧仅保留查询/转换所需的分片索引和薄适配器。

不能根据原始 XHTML 的 DOM 路径猜测 KOReader 的内部路径。需要记录生成映射的工具版本、引擎兼容配置、原书摘要与映射格式版本，并以真实 KOReader 输出作为对照。CREngine 仓库是对应的原始实现参考。[S7]

这一路线目前属于需完成原型验证的架构决定，未证明对任意 EPUB 都成立。首轮应验证节点规范化、空白、脚注、跨章节、图片相邻正文及版本差异。只有实际完成往返定位的文件才能标记为兼容。

默认不依赖配套 KOReader 插件。如果验证后确实需要插件，只增加适配后端，并明确改变了用户安装要求；不能在未告知的情况下把插件作为隐含前提。不得把“以后做一个插件”当作已解决兼容性。

### 8.3 同步算法与边界

- 打开书籍先恢复本地，可异步查询远端；不等待 Wi-Fi 才显示正文。
- 自动接续只考虑本次会话尚未主动移动、远端差异明确、位置可精确转换且策略允许的情形。若用户已开始翻页，只显示待处理提示。
- 断网时先保存本地，并按账户与书籍合并待上传记录。连接恢复后先读远端，再比对上次共同快照；不先盲目清空 outbox 上传旧位置。
- 本地与远端相对基线都改变时判为冲突，用户选择“继续此处”或“转到另一设备的位置”，必要时再明确是否上传本地覆盖远端。
- 不能用“谁的百分比更大谁获胜”：回读也是有效行为。时间戳也不能独立证明优先级，尤其在离线和设备时间不可靠时。
- 远端 XPointer 无法解析时保留本地，不退回第一页。近似定位必须标注并确认，不静默伪装精确同步。
- 推送只使用已显示且已保存的位置，不上传预排版、预取或仅选中但尚未展示的页。
- 收到服务端成功响应后才能标记“已上传”；它不代表另一台 KOReader 已拉取并跳转。
- 切换账户/服务器隔离同步基线与待办，避免把旧账户待办发给新账户。

按已查 API，不把服务端条件写入、原子比较交换或多版本合并视为可用能力。[S3] “先拉后推”仍不能消除两个客户端同时操作的竞态；本机保留近期位置记录和恢复入口，不宣称协议提供强一致性。

对于同一百分比内的微小位置变化，还要验证 KOReader 客户端自身的去重/跳转行为；不通过伪造进度数值规避协议行为。[S2]

## 9. 显示与刷新

### 9.1 策略接口

页面提交 `RefreshIntent`，例如 `PAGE_TURN`、`UI_CHANGE`、`IMAGE_VIEW`、`CLEANUP`、`WAKE_RECOVERY`。显示层结合用户预设、目标区域、前帧可信度、内容灰阶与板级能力选择实际操作。

用户预设为“清晰 / 均衡 / 快速”，默认均衡；另有“立即全刷”。这些名称是本项目的交互语义，不等同于已验证的 Palma 效果。官方示例已有 DU、GL16、GC16 等路径，具体组合和适用条件需真机验证。[S1]

必须区分两个维度：更新范围（整屏/区域）与刷新波形/灰阶策略。不能把“局部刷新”直接等同于某一种黑白快速波形。

### 9.2 帧与状态规则

提交前先协商 `RenderProfile`，使灰阶量化、文字抗锯齿和快速模式匹配；不能先绘制任意 16 灰阶画面，最后盲选仅支持较少灰阶的路径。

面板同一时间只运行一个刷新事务。在途缓冲区保持不可变；还未提交的请求可以合并或替换，但正在驱动的帧不随意中断。

FrameToken 区分正文提交与纯 UI 更新；打开菜单、刷新状态文字或预览样文，不推进正文阅读位置。

维护“已请求、已渲染、已显示”三个位置。只有收到匹配的 `FramePresented` 后，阅读会话才更新已显示位置并触发保存。刷新失败保留上一个确认状态。

启动或恢复时，旧画面状态不可靠就使用清理/初始化策略重建基线；屏幕仍有字不意味着 RAM 中存在正确的上一帧。弹窗关闭后的底层页面也要重新纳入合成和清理区域。

所谓自动清理初版是根据刷新历史和内容变化制定的启发式策略，不是传感器检测到真实残影。UI 不显示“已检测残影”之类没有依据的文案。

## 10. 并发、资源与性能

### 10.1 建议的应用工作任务

| 工作任务 | 唯一责任 | 限制 |
|---|---|---|
| App/UI | 处理语义动作、导航与状态快照 | 不执行长时间解析、网络请求或面板等待 |
| Reader worker | 章节读取编排、排版、字体/图片工作 | 可取消过期任务，按块让出执行 |
| Display worker | 合成并提交面板刷新 | 单写入者，严格缓冲区所有权 |
| Storage worker | 索引、导入与可靠日志写入 | 进度保存优先于大文件导入，写入分块 |
| Network worker | 配网之外的传输与同步请求 | 有界超时、取消、重试，不阻挡保存和休眠 |

这是应用级划分，ESP-IDF 自身仍有系统任务。模块数量不等于 FreeRTOS 任务数量；初版不凭直觉固定核心亲和性或建立每模块一线程模型。

电源协调在 App/System 中运行，不用在底层睡眠回调中做网络请求或大文件写入。中断仅发送轻量通知，所有队列有容量上限。

### 10.2 一次翻页的完整顺序

```text
触摸抬起 / 电容键动作
 → ReaderAction::TurnPage
 → session 更新期望目标
 → reader worker 返回带会话/修订号的布局
 → display 合成并完成面板更新
 → FramePresented
 → session 更新 visible_anchor
 → storage 保存并返回 ProgressSaved
 → sync 合并待上传状态
 → 在网络策略允许时异步同步
```

连续操作可以合并渲染目标，但应保留可解释的翻页意图。刷新忙碌时不能积累无限操作，也不能让后台预取页成为“已读位置”。

### 10.3 内存原则

684 × 1216 的 4-bit 整屏缓冲占 415,872 bytes，约 406.1 KiB；两个这样的缓冲约 812.3 KiB。此为尺寸计算，不含驱动扫描缓冲、历史帧、DMA 描述符、字体、解码器、网络或任务栈。

应先测量复用驱动的真实内存布局，避免在其既有双缓冲之外再无意复制两套整屏。

正文、图片和字体都采用有界分片与缓存；图片优先降低解码尺寸，不整书解压、不缓存全部字形、不在首屏显示前分页整本书。先排当前位置及少量相邻页，剩余工作低优先级进行。

大块非关键缓存倾向放 PSRAM。内部 RAM、DMA 可用堆和最大连续空闲块分别监测。ESP-IDF 文档指出 ESP32-S3 的 PSRAM DMA 存在限制，DMA 描述符不能放入 PSRAM，且带宽竞争需要考虑。[S5]

首次验证可以把“稳定阅读状态 PSRAM 峰值留出约 2 MiB 余量”作为预算目标，而不是已达成指标；网络握手、图片和大字体同时出现的峰值必须单独压测。

记录开书至首帧、缓存翻页、跨章节翻页、修改字号、同步响应、堆峰值和睡眠功耗。毫秒级速度和续航数值在真机测试前不对外承诺。

## 11. 存储、导入与断电恢复

建议分开四类数据：原书/资源、可重建索引与分页缓存、不可随意丢弃的阅读记录、敏感设置/凭据。

首版主存储为 TF 卡。系统设置可放 NVS；当前与最近的阅读位置采用内部存储上的小型带序号/校验日志，完整书库和可重建内容放 TF。NVS 不作为每次触摸都写入的通用数据库。

短时间连续翻页可合并保存，但保存完成以 Storage worker 确认的修订号为准；后台同步只引用已确认版本。突然断电只能保证恢复最后一份完整提交的记录，不能保证尚未落盘的最后一次翻页绝不丢失。

记录包含版本、校验和修订号。使用追加日志或双槽提交，在启动时选择最新的有效记录。不要把一次文件改名当作任意文件系统和跨文件数据的绝对断电事务保证。

导入在临时目录完成检查、容量验证与摘要确认，再发布至书库；中断保留旧书。清理缓存、删除书籍和清除阅读进度为不同操作，删除默认仅涉及本机，不隐式删除远端状态。

TF 卡移除后停止新读取和写入，已显示正文可保留，显示可关闭的说明。系统内置 UI 字体必须能显示错误信息，不能让 SD 字体丢失后连提示也乱码。重新插卡后按内容身份重新验证，不按路径和大小沿用旧位置。

解析器与导入工具对目录穿越、异常压缩膨胀、超大资源、深层嵌套、畸形编码设定限额。实际限额以测试结果和资源预算配置，不直接照抄演示程序。

## 12. 电源与联网

```text
ACTIVE → IDLE → PREPARING_SLEEP → SLEEPING
                  │
                  └→ 若仍有关键操作，限时等待 / 取消非关键操作 / 返回活动态
```

系统服务统一管理活动票据：面板刷新、关键持久化、文件发布等持票时不能切断对应供电。网络重试和后台索引不应无限阻止休眠。

休眠前的逻辑顺序是：冻结新的非必要动作 → 完成必要刷新 → 确认进度保存 → 保存同步待办 → 在明确策略与时限内尝试联网 → 停止网络 → 设置唤醒来源 → 通过 BSP 进入睡眠。具体时序服从面板/PMU 的实际实现。

默认不开常驻轮询。手动同步可主动联网；自动同步只在已连接或用户明确开启自动联网策略时执行。同步失败不让用户一直停留在“正在休眠”。

深睡恢复按重建会话处理，而不是假定继续使用休眠前的内存对象。ESP-IDF 对 Light-sleep 和 Deep-sleep 的 RAM/外设保留行为有明确区别；深睡会关闭大部分 RAM。[S6]

## 13. 技术选择、复用和升级边界

业务可用 C++ 实现值类型、资源所有权和可测试接口；驱动沿用 C 接口。避免在热路径频繁分配零散对象，不引入通用运行时插件系统。

UI 首版采用少量轻量组件：文字、图标、列表、按钮、单选、步进器、提示框、底部工具面板。字体栅格化与正文排版分开封装，先复用已在设备上可工作的基础路径。

若后续采用 LVGL，它只能替换 UI 适配，不应该成为文档、语义锚点或同步状态的所有者。正文不使用“超长 Label + 自动滚动”代替阅读排版引擎。

发布前记录所有第三方组件的版本、来源、修改和许可证。引用算法思路、复制代码、链接代码是不同的工程行为；不能因顶层仓库的许可证就省略子组件声明。CREngine 等组件的使用边界需要在实际选择时核对。[S1][S7]

首版具备串口刷写、恢复入口和可导出的诊断信息。分区布局尽早测算升级空间，完整无线升级 UI 可后置；不因首版界面缺少 OTA 入口而忽略将来升级的存储约束。

凭据不写入日志或可公开导出的阅读包。云端同步校验 TLS；自建服务使用可配置受信任证书，不默认关闭证书验证。局域网传输只在显式进入传输模式时开启，并使用本次会话的访问凭证；退出后关闭服务。

## 15. 实施顺序与验收门槛

| 阶段 | 交付 | 准入/验收条件 |
|---|---|---|
| G0 硬件基线 | 固定版本 BSP、显示/输入/存储/睡眠烟测 | 真机可重复构建运行，诊断和恢复路径可用 |
| G1 位置兼容原型 | 预处理、原书身份、锚点与 KOSync 适配 | 真实 KOReader ↔ 本机双向定位，变字号后仍指向同一正文；失败文件明确标记 |
| G2 阅读闭环 | 书库、正文、目录、设置、保存/恢复 | 离线完整阅读；翻页、跨章节、重启恢复无错书与状态污染 |
| G3 交互与可靠性 | 刷新预设、冲突处理、配网传输、低电/移卡异常 | 所有页面状态可复现，网络失败不阻断阅读，恢复符合已提交记录 |
| G4 首版发布 | 安装包/固件、预处理工具、说明、兼容矩阵 | 用户能从 EPUB 输入走完整流程，声明与实测能力一致 |

位置兼容原型优先于精修书架。G1 未完成不能把“已接通同步服务”当作第一版功能完成。

### 关键测试

测试集包括普通中文/英文书、长章节、同名不同文件、包含插图与脚注的文件、损坏包、资源超限和规范化结构复杂的书。

验证：改字号不丢段落；来回翻页无重字漏字；不同设备字号不同仍定位同一正文；回读不会被更大百分比覆盖；断网期间两端分别阅读后不静默覆盖；旧网络回包不影响新书；显示失败不保存未显示位置；移卡不崩溃；写入中断能恢复有效记录；唤醒不使用失效指针；导入中断旧书仍可读。

位置验证记录源锚点和对应文本，不比较不同设备的页码。保存/同步测试使用故障注入和真实设备回读，不只看成功提示。
