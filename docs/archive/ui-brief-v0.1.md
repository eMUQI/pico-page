# Read Pico 阅读固件：界面设计交接说明 v0.1

日期：2026-10-05  
对象：交互设计师、视觉设计师、固件 UI 开发者。  
配套文件：《Read Pico 阅读固件：程序架构设计 v0.1》。  
状态：设计要求与初始参数，不是已经过真机验证的视觉稿。

## 1. 一句话产品定义

为 Read Pico 设计一套以 EPUB 阅读为中心、能够与 KOReader 接续阅读进度的个人墨水屏阅读器界面。打开后能继续读、必要时容易调整、出错时不丢位置。

它不是手机阅读 App 的灰度版，也不是 KOReader 所有菜单的缩小复制品。第一版不需要书城、推荐流、账号社区、统计仪表盘、桌面小组件或装饰性动画。

## 2. 已确认与工作默认

已确认：主要自用并开源；Read Pico 优先；EPUB 为主要内容；后续需要 PDF 和 Karakeep 网页；可在设备外处理内容；屏幕触摸与电容触摸按键；可切换刷新模式；首版 EPUB 阅读与 KOReader 进度同步。

本说明采用的默认：中文优先、竖屏优先，正文可在设备调整字号等设置；书架使用列表优先；同步按双向接续设计；图像与脚注提供基础展示或明确降级，不扩大为复杂排版编辑器。

尚未确认的字体、视觉细节、手势阈值和刷新周期属于可调整参数。不能将本说明中的初始尺寸当成硬件实测最优值。

## 3. 设计目标与优先级

最高优先级是正文阅读、翻页、恢复阅读位置和同步状态可理解。第二优先级是目录、排版、刷新模式与返回书架。第三优先级是设置、导入和故障恢复。

视觉方向：纸面感、稳定、克制，正文优先，信息层级依靠字号、字重、留白与线条，而不是大量卡片、阴影或颜色。不能为了极简，把返回、同步失败或当前模式隐藏得找不到。

参考 KOReader 的功能路径和阅读控制，不照搬其所有设置层级；参考 Palma 的“用户可选择刷新策略”概念，不复制具体模式名称、效果宣传或性能数值。

## 4. 画布与视觉参数

### 4.1 硬件画布

官方规格为 1216 × 684 像素、4.7 英寸、16 灰阶；本设计以旋转后的 **684 × 1216 竖屏逻辑坐标** 为主画布。[S1]

画稿按 1:1 设备像素标注，不套用手机的 CSS px、dp 或系统状态栏尺寸。横屏作为后续适配约束，不要求首轮为全部页面绘制横屏版本。

最终需要确认显示坐标与触摸坐标变换一致。屏外电容触摸区不占屏幕布局高度，也不要在画稿里虚构屏幕内的三个永久导航键。

### 4.2 初始设计令牌

以下参数用于第一轮稿件与实现对齐，均需在真机上复核。

| 项目 | 初始范围/要求 |
|---|---|
| 基础间距 | 4 / 8 px 步进 |
| 正文左右边距 | 默认约 36 px，可调约 24–52 px |
| 正文字号 | 默认约 36–40 px，提供约 28–56 px 的可选范围 |
| 行距 | 参考 1.35–1.65 倍字号，默认约 1.5；与段距分开 |
| 页面标题 | 约 32–36 px，较正文 UI 标签明显 |
| 常规 UI 标签 | 约 26–30 px |
| 辅助信息 | 约 22–24 px，避免过细字重和极淡灰 |
| 触摸热区 | 以约 88–104 px 的边长/行高为起点；可见图标小于热区 |
| 分隔线 | 约 2 px 起，必要时加深，禁止依赖极淡细线 |
| 图标 | 清晰的实线或轮廓；尽量统一尺寸与视觉重量 |
| 圆角 | 小幅使用，保持一致，不以圆角大卡片组织所有内容 |

字体文件由产品/开发侧选择可用且授权明确的资源。本轮不随设计交付打包字体文件；交付字体名称、来源说明、字重与回退规则。

### 4.3 灰阶与快速模式

主文字用深色，背景以白色为主，灰阶主要用于次要文字和少量分隔。选中、禁用、错误、焦点状态必须同时有文字、图标、边框或反相等区别，不能仅靠两个接近的灰度。

设计师须检查同一界面在正常灰阶与近似黑白表现下是否仍可使用。快速模式的真实灰阶与残影由开发和真机验证，不根据屏幕“支持 16 灰阶”推定所有刷新路径都保留完整灰阶。

避免模糊、透明玻璃、大面积渐变、柔和投影和无意义的整屏深色背景。首次不做深色主题；不是断言硬件不支持，而是缩小首版范围。

## 5. 信息架构

```text
书库
 ├─ 继续阅读 / 最近阅读
 ├─ 本机书籍列表
 ├─ 导入与连接
 ├─ 书籍详情/操作
 └─ 设置

阅读页
 └─ 阅读工具面板
     ├─ 目录
     ├─ 排版
     ├─ 同步状态与操作
     ├─ 刷新模式 / 立即全刷
     └─ 返回书库

设置
 ├─ 网络与传输
 ├─ KOReader 同步账户与策略
 ├─ 显示与刷新
 ├─ 输入与阅读偏好
 ├─ 电源与休眠
 └─ 存储、设备信息与诊断
```

不增加独立“首页 → 书架 → 书籍”的重复层级。冷启动默认进入书库并突出最近阅读；从正常休眠唤醒优先回到原书。自动打开上次书籍可作为偏好，而不是第一轮必须增加的启动选择页。

Karakeep 后续以“文章”来源或筛选出现；首版没有能力时隐藏入口，不在主界面长期摆一个不可点的“敬请期待”。PDF 同理。

## 6. 页面需求与交付清单

| 编号 | 页面/面板 | 必须包含 | 必须设计的状态 |
|---|---|---|---|
| S01 | 书库 | 最近阅读、本机书籍列表、导入、设置 | 正常、空书库、扫描中、TF 不可用、部分书籍不可用 |
| S02 | 正文阅读 | 正文、轻量页脚、触摸区、脚注返回入口 | 正常、首屏准备、跨章等待、图片降级、读完、加载失败 |
| S03 | 阅读工具面板 | 目录、排版、同步、刷新、返回书库 | 展开/关闭、禁用动作、同步有待办 |
| S04 | 目录 | 章节层级、当前章、跳转与返回 | 长目录、目录缺失、加载中、跳转失败 |
| S05 | 排版设置 | 字体、字号、行距、页边距、设置作用域 | 当前值、预览/应用、重排中、字体不可用、恢复默认 |
| S06 | 同步状态与操作 | 本地保存、远端状态、拉取/推送、最近确认信息 | 未配置、离线待同步、进行中、已上传、冲突、鉴权/定位失败 |
| S07 | 同步冲突确认 | 当前位置与另一设备位置、明确选择 | 远端位置可解析、仅近似、时间未知、操作中 |
| S08 | 刷新设置 | 清晰/均衡/快速、当前模式、立即全刷 | 选择、应用、暂不可用、错误说明 |
| S09 | 连接与导入 | 网络状态、配网路径、传输入口/二维码、退出 | 未连接、连接中、失败、会话开启、接收/验证/完成/失败 |
| S10 | 设备设置 | 分组设置、账户/服务地址、存储与设备信息 | 正常、保存失败、不可用项 |
| S11 | 休眠/恢复 | 休眠说明、可靠的唤醒说明、同步待办提示 | 正常、待上传、恢复中、低电量 |
| S12 | 通用提示组件 | 提示、警告、确认、失败后的下一步 | 普通提示、重试、不可恢复、取消/确认 |

S03、S05、S06、S08 可以用同一套面板组件，不要求它们都成为独立全屏页面。S07 是同步面板的明确冲突状态。表中编号用于交接与测试，不代表必须有十二个平行主导航入口。

### S01 书库

优先列表布局。每项以书名为主，作者为辅，可有小封面、已读状态/进度和“继续阅读”。封面不是书名的替代品，无封面要能正常使用。

最近阅读优先置顶，不再重复做一个巨大推荐卡片。列表过长时采用分页或离散滚动，不使用需要连续动画反馈的惯性滚动效果。

长书名最多两行后省略，详情能看到完整标题。容量未知与“0 本书”不同；TF 卡不可用不能显示成“你的书库为空”。

单本详情区分“从本机删除书籍”“清除本机进度”“清理缓存”。破坏性操作需要明确确认，不能默认删除同步服务器上的记录。

### S02 正文阅读

默认无永久顶部工具栏；正文不被浮动按钮长期遮挡。页脚只保留少量信息，例如“本章 3/12 · 全书 38%”。当前章节页数未完成计算时可显示“本章第 3 屏”，不得伪造总页数。

本机页码是当前排版结果，不用它与 KOReader 页码比较。页脚的百分比不是精确同步锚点，也不要增加多位小数制造精确感。

显示错误时尽量保留上一页可读内容。短暂等待不立即切换成整屏加载页；超过提示阈值再显示静态阶段说明，避免提示本身造成多次刷屏。阈值由开发实测决定。

脚注或内部链接跳转后，必须有可见“返回正文/返回原位置”。图片不可显示时给出占位与简短原因，不丢失上下文。

页脚时钟可默认关闭；如提供，不使用秒级跳动。电池/网络状态不需要每一帧重绘。

### S03 阅读工具面板

轻点中部打开，底部工具面板配合必要的顶部返回/标题信息即可。一次只展开一层主要面板，不在阅读区连续叠三层弹窗。

常用动作在一层内可达。按钮使用图标加简短标签；不能要求用户识别一排不常见图标。

关闭面板后回到同一锚点。面板覆盖不应引发正文重新分页，关闭时由显示层处理露出的区域。

### S04 目录

当前章清楚标识，支持必要的层级缩进与折叠。目录标题缺失时展示可解释的回退名称，不虚构真实章节标题。

跳转后保留“返回跳转前位置”的短历史。没有目录的书显示“这本书未提供目录”，而不是笼统“加载失败”。

### S05 排版设置

第一层只包含字体、字号、行距、页边距；段距、首行缩进等少量进阶项可折叠，不做完整 CSS 设置编辑器。

使用步进器或离散选项优先于需要细微拖动的滑杆。连续点击先更新控件和局部样文，用户点击“应用”后对正文进行一次重排；待实测后才考虑停顿自动应用。

同一面板内明确作用域，例如“此书的排版”。全局默认通过独立的“设为阅读默认”动作更新，不因调整一本书就悄悄改变所有书。

应用后保持原正文附近的位置。重排中按钮明确禁用/可取消策略，不允许重复申请形成排版任务堆积。

### S06 同步状态与操作

同步面板要同时回答三件事：本机位置是否保存？是否上传到服务器？是否发现另一设备的不同位置？不要用一个勾号替代所有信息。

提供普通“检查并同步”入口和更明确的“从其他设备接续”“将此处上传”。这些动作的真实覆盖规则由同步策略控制，UI 不直接上传。

只有收到服务端确认才能显示“已上传此处”；不能显示“另一台设备已同步”，因为另一台设备是否已经拉取无法由本机确认。

手动操作失败要给出可理解原因，自动操作失败使用低打扰提示，不强制弹窗打断翻页。

### S07 同步冲突

示例结构（为界面文案，不是真实记录）：

```text
发现不同的阅读位置

此设备
第八章 · 约 38%
本机已保存

另一设备
第七章 · 约 34%
来自 KOReader · 最近收到：10:42

[继续此处]    [转到另一设备的位置]
```

“继续此处”默认仅保留本地并关闭冲突提示，不暗中覆盖远端；需要覆盖时另有明确的“上传此处，替换远端位置”。可以在同一流程中解释结果，但不能让普通关闭操作承担覆盖含义。

另一设备的位置小于本机百分比并不意味着过期；可能是主动回读。时间没有可靠来源时显示“时间未知”，收到记录的时间与实际阅读时间要分开。

远端章名只有在本机实际解析得到时才显示。只有百分比或位置无法解析时，说明信息有限，不编造“第七章”。

精确映射失败时不显示成功状态。允许近似跳转的实验路径必须写“只能定位到附近”，并允许取消。

### S08 刷新设置

三种预设：

| 名称 | 用户侧说明 | 设计限制 |
|---|---|---|
| 清晰 | 优先文字与图像表现 | 不承诺固定毫秒数或完全无残影 |
| 均衡 | 在显示效果和交互之间折中 | 默认项；最终参数由真机调校 |
| 快速 | 优先操作响应，可能减少灰阶或更易留痕 | 切换前说明权衡，不隐藏代价 |

“立即全刷”是独立动作，不是第四种模式。刷新次数/周期等进阶设置可后置，首版不把 DU、GL16、GC16、VCOM 等工程名词放在主选择页面。

切换模式后显示当前选中项即可，不连续展示刷新动画。固件可以基于显示历史做清理；设计不能承诺已自动检测真实残影。

### S09 连接、配网与导入

首版内容入口明确分为“电脑预处理后复制到 TF”和“传输已处理内容”。不能让设备接收原始 EPUB 后假装已经支持设备端转换。

网络、账号和服务地址等长文本尽量通过手机/电脑的辅助配置页输入；设备负责发起、确认和显示结果。首版不要求制作中文输入法。必要的 Wi-Fi 密码输入可使用简单字符键盘，完整方案由配网实现确认。

传输页面包含本次会话的状态与可退出入口，二维码不要包含长期账户密码。二维码在快速模式下也需可扫，必要时切换适合的刷新策略。

导入状态区分“接收文件”“校验内容”“加入书库”。单个文件失败提供重试，不把一切错误显示成“网络异常”。明确“退出将停止传输”的行为；进行中的写入需要取消收尾后再退出。

### S10 设置

设置按用途分组，每组一到两级，避免无边界嵌套。危险动作与普通选项在视觉和位置上分开。

KOReader 配置包含服务地址、账户状态、同步策略；不要假定用户使用官方还是自建服务。凭据默认隐藏，清除/退出账户的影响需要说明，但不能自动删除用户远端账号。

存储显示原书、缓存和可用空间的区别；容量获取失败时显示未知，不填 0。设备信息页可显示固件版本、硬件标识、诊断导出，不把调试日志铺在普通阅读页。

### S11 休眠与唤醒

优先保留正文并显示简洁的休眠标记；也可提供不显示正文的简洁屏保选择，首版无须复杂封面轮播。

如果选择保留正文，必须说明当前已休眠，避免让人以为触摸失灵。唤醒提示以实际支持并测试通过的按键/触摸来源为准，不提前承诺任意触点都能唤醒。

唤醒手势只唤醒，不顺便翻页或触发隐藏按钮。恢复时先返回本地已保存位置；网络查询不能把用户卡在启动界面。

低电量优先保存和提示，不自动开启耗电操作。休眠页可以显示“此处已保存，尚未上传”，但不能为了更新这个状态持续联网或定时刷屏。

## 7. 输入与触摸规则

### 7.1 阅读页触摸分区

初始采用左侧翻前页、右侧翻后页、中部打开工具面板；具体宽度用真机握持测试调整，设计稿需标出热区但不在正式页面绘制分区边框。

左右轻扫作为翻页辅助方式，不要求精准长距离滑动。实际手势阈值和防抖由实现验证。

链接、按钮和图片等显式命中区域优先于阅读页的背景翻页区。一次输入只执行一种操作：滑动不能同时点击脚注，抬手关闭面板不能穿透并翻页。

正文长按不绑定首版必须功能；未来可用于选择文字。重要动作必须有可见入口，不仅靠隐藏长按或双指手势。

### 7.2 三个电容触摸键

官方硬件包含三个电容按键区；实际空间顺序、标识与唤醒行为需要板级确认。[S1] 本设计使用 K1/K2/K3 作为逻辑命名，不将它们擅自描述为机械按键。

| 场景 | K1 | K2 | K3 |
|---|---|---|---|
| 正文阅读 | 上一页 | 打开/关闭工具面板 | 下一页 |
| 书库/目录的翻屏列表 | 上一屏 | 返回上层或关闭面板 | 下一屏 |
| 模态确认框 | 不作用于背后正文 | 安全关闭/取消，若允许 | 不作用于背后正文 |
| 休眠 | 依据真机唤醒能力，不预设全部可用 | 同左 | 同左 |

首版不强求仅靠三个键输入密码或完成所有设置。屏幕触摸是完整操作路径；电容键服务高频翻页和面板操作。

不以短触/长触混合承载大量功能；不依赖实体按压触感确认操作。误触过滤、同时触摸和长按行为要记录在交互稿中。

## 8. 墨水屏特有的状态切换要求

不制作滑入、淡出、翻书动画、旋转加载图标、骨架屏闪动、拖拽跟手缩放等必须连续刷新的效果。面板可直接出现/关闭，进度按阶段或明显变化刷新。

“有响应”不一定意味着马上重绘整屏。一次交互中，状态确认、布局准备和最终刷新应尽量合并，不做一次操作多次闪屏的设计。

必须交付控件按下、选中、禁用、忙碌和错误状态，但允许采用不增加额外刷新负担的实现；例如快速点击使用一次最终状态刷新，不要求独立动画帧。

显示策略是固件职责。设计交付标明建议更新区域、是否需要保证图像/文字质量和是否涉及遮挡恢复；不要替开发硬编码具体波形。

设计稿至少在“正常灰阶”“近似黑白”“小尺寸原像素”三种观看方式下检查。真实残影、闪屏和触摸时延必须用设备确认。

## 9. 统一状态文案

| 场景 | 推荐文案 | 禁止的误导 |
|---|---|---|
| 本地保存完成，离线 | 此处已保存，联网后可同步 | 已同步 |
| 服务器确认上传 | 已上传此处 | 另一台设备已接续 |
| 网络断开 | 暂时无法连接，不影响继续阅读 | 同步成功 / 正在永久等待 |
| 鉴权失败 | 同步登录已失效，请重新配置 | 无网络 |
| 定位无法映射 | 无法准确对应此位置，已保留当前阅读位置 | 已同步但跳到第一页 |
| 两端分别移动 | 两台设备的阅读位置不同，请选择继续位置 | 自动使用进度更大的记录 |
| 原书不匹配 | 无法确认是同一本书，暂未同步 | 按同名文件直接覆盖 |
| 章节准备 | 正在准备这一章 | 无限旋转但无说明 |
| 字体不可用 | 字体不可用，已使用替代字体 | 整页空白或乱码 |
| 图片超出能力 | 图片暂无法显示，正文仍可阅读 | 悄悄删除图片 |
| TF 卡移除 | 存储卡已移除，无法加载后续内容 | 书库为空 |
| 保存失败 | 此处尚未保存，请检查存储 | 已保存 |

本地保存失败属于必须明确告知的状态，但同样不能伪造“数据已丢失”的结论。错误说明同时提供一个最相关的操作，如重试、返回书库或查看设置，不铺满无关按钮。

## 10. UI 与程序的交接契约

设计中每一个可交互控件都标注：所属页面/状态、语义动作、目标热区、可用条件、处理中状态、成功/失败后的去向和建议更新区域。

示例动作：`OpenBook`、`TurnPage`、`OpenToc`、`JumpToAnchor`、`ApplyTypography`、`RequestSync`、`AcceptRemotePosition`、`KeepLocalPosition`、`SetRefreshPreset`、`ForceRefresh`、`RequestSleep`。

UI 不直接拼 KOSync 请求、不推测哪个进度更新，也不直接写设置文件。开发侧提供的状态至少包含：

```text
ReadingViewState
  title / chapter_label
  page_label / percentage_label / pagination_status
  save_state
  sync_state / remote_candidate / mapping_quality
  refresh_preset
  available_actions
  transient_message
```

`percentage_label` 和章名可为空；设计必须覆盖未知状态。控件状态来自真实字段，而不是把设计中的示例数据硬编码到产品。

## 11. 设计师交付物

第一轮先交付阅读页、工具面板、排版面板与同步冲突流程，确定阅读体验后再完成书库、设置和连接。不要从大面积品牌首页或图标风格板开始消耗主要精力。

完整交付需要包含以下六项：

1. 关键用户路径：首次导入并打开、继续阅读、调整排版、两端接续、处理冲突、离线后恢复、休眠唤醒。
2. 684 × 1216 的主要页面视觉稿和关键异常状态，状态使用 S01–S12 编号关联。
3. 组件库及设计令牌：字号、字重、行距、间距、灰阶、边框、图标、按钮/列表/面板状态。
4. 触摸热区与电容键行为标注，明确防穿透、手势冲突和返回逻辑。
5. 开发标注：控件的动作名、字段、可用条件、加载与失败行为、建议更新区域。
6. 可点击的流程原型与原像素 PNG 导出；图标可提供 SVG 源文件，由固件侧转为需要的格式。字体仅提供名称与来源说明，不打包字体文件。

原型只需演示页面和交互关系，不做仿真电泳波形。示例数据使用明确的占位或许可允许的文本，避免整套稿件只用无法验证长书名、长章节和中文标点的短句。

## 12. 验收清单

设计能使用户在正常路径中直接找到继续阅读、目录、排版、同步和返回书库；阅读页的工具界面不会长期占据正文。

每个需要联网的操作都存在离线状态；每个可能等待的动作有明确反馈；每个破坏性动作有清楚的作用范围；不支持的未来功能不占主导航。

长书名、无封面、无目录、未知页数、字体缺失、TF 卡移除、同步冲突、服务不可达和精确定位失败都有对应方案。必须看得到“本地已保存”与“已上传”的区别。

灰阶降级时仍可区分选中和禁用，热区足够大，文字不依赖过细笔画。触摸关闭弹窗不穿透，唤醒不误翻页。

所有主要动作能映射到架构文档的动作或状态，设计未暗示首版拥有原始 EPUB 设备端转换、完整 PDF 渲染、Karakeep 爬虫、实时背景同步等尚未实现的能力。

最终验收包含实际固件和真机检查；仅在 Figma 或手机屏幕上看着舒服，不作为墨水屏效果已经达标的证据。
