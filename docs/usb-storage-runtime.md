# USB 文件传输

默认启动为正常阅读模式，保留 USB Serial/JTAG 烧录和诊断连接。USB 文件传输开关不持久化。

## 操作

1. 将设备连接电脑，在设置的“文件导入”中开启“USB 文件传输”。
2. 等待电脑挂载 TF 卡。设备在准备阶段保存已呈现的阅读位置并关闭卡上的文件；准备失败时不交出卡。
3. 在电脑上管理文件。书籍放入 `Books/`，网页收藏建议放入 `Books/Articles/`，字体放入 `Fonts/`。移动 EPUB 时一并移动同名的 `.epub.picopage/` 目录，以保留进度和单书设置。
4. 在电脑上安全弹出 TF 卡，等待弹出完成。
5. 在设备上选择退出并确认重启。设备重新读取 TF 卡配置与书库，恢复正常 USB 烧录连接。

传输期间暂停阅读、同步、诊断命令和自动休眠。K2 始终全刷当前画面，不退出传输或取消确认；请使用屏幕上的“取消”或“退出并重启”。
电脑未完成安全弹出时不要重启设备或拔线；设备无法判断电脑是否仍有尚未提交的文件系统缓存。

## 所有权与实现

`App::prepare_usb_transfer()` 拒绝未完成的显示、网络和保存事务，成功后释放 EPUB、字体与书库数据。
主循环停止原串口；平台在卸载 FatFs 前，将空卷标或 `NONAME` 卷标设为 `PICO PAGE`，保留其他卷标。卷标写入失败时拒绝交出卡。
平台检查 FatFs 卸载结果，再初始化原始 SDMMC 和 TinyUSB MSC。卷标存于 TF 卡，USB 设备描述符中的 `Pico Page TF Card` 是另一名称。
卡交出后，应用卡扫描和读写路径保持关闭；USB attach、detach、SCSI eject 均不自动挂载本地 FAT。

MSC 使用同步扇区读写，写操作完成后才返回成功；部分扇区写入采用读改写。
边界计算使用 64 位算术，拒绝越界和超出回调返回值范围的请求。移卡或 I/O 失败使介质不可用。
退出先停止接受 I/O、等待当前事务，再停止 USB/SDMMC 并重启，不在当前阅读会话中重新挂载。

Read Pico BSP 未提供独立 VBUS 检测引脚，本实现不以 USB suspend 或连接事件推断电脑已安全弹出。
TinyUSB 和 USB Serial/JTAG 分时使用内部 PHY；传输期间无法通过原串口进行自动烧录。
硬件 BOOT/复位仍作为恢复入口，常规操作使用传输页的退出重启。

## 官方示例核对（2026-10-06）

已对照本机 ESP-IDF 6.1 固定提交 `fff9895c82d744c7237be8847347bdd1b07c6643` 的
[`tusb_msc` 示例](https://github.com/espressif/esp-idf/tree/fff9895c82d744c7237be8847347bdd1b07c6643/examples/peripherals/usb/device/tusb_msc)，
并检查已锁定的 `esp_tinyusb 2.4.0` 实际源码与头文件。USB 协议、描述符、驱动任务和 SDMMC 驱动仍使用官方组件。

- 示例先初始化原始 SD 卡，再安装 TinyUSB；应用与电脑不能同时挂载同一介质。本项目采用相同所有权边界，额外保留阅读进度保存与文件关闭步骤。
- 官方 `tinyusb_msc_driver_config_t.user_flags.auto_mount_off` 可以关闭自动回挂。此前把自动回挂作为无法使用便利层的独立理由并不充分，现予以修正。
- 当前版本 `tinyusb_msc.c` 的 `tud_msc_write10_cb` 在排入延后写入后返回长度；`tusb_write_func` 的介质写入失败仅记日志。项目保留同步回调，将 SDMMC 错误返回 MSC，同时检查范围和部分扇区写入。
- 官方示例的自供电模式需要实际 VBUS 监测 GPIO；不能照搬其他开发板的引脚。现有 BSP 未提供该接线，仍保留手动安全弹出与退出流程，不宣称拔线自动恢复。
- 本轮核对未发现需要替换 USB 协议栈或改动板级引脚的依据，没有额外重写协议层。便利层的构建排除依赖精确版本锁，升级时需重新检查上述回调与构建文件。

用户实际执行退出重启后，串口与 TF 挂载恢复；迁移 EPUB 的设备端 CRC32 与原导出一致。
抽测进度修订号为 3；K2 全刷前后修订号及正文 CRC32 `4bdf5d0e` 均保持一致。
