# 原生 EPUB 内容后端

实现日期：2026-10-05。`reader_document` 供 host 和 ESP-IDF 共用，直接读取原 EPUB；不要求专有阅读包。该组件完成内容读取，不代表真机阅读或 KOReader 位置接续已经验收。

## 接口与职责

`EpubDocument::open()` 打开原书，计算完整 SHA-256 与 KOReader 规则的部分 MD5，读取 container、OPF、spine，以及 EPUB 3 导航或 EPUB 2 NCX。书名、作者和语言来自 OPF；缺少书名时使用文件名。没有可用目录项时以 spine 标识建立入口。

`load_chapter()` 只解压指定 spine XHTML，返回 `Chapter`。失败会清空输出并返回错误；不会把截断内容作为成功章节。ZIP 中其他章节的正文不会被解析，因此未选章节的 XML 错误或章节文本超限不阻止读取当前章。打开时仍会验证整个 ZIP 目录并读取原文件计算摘要。

正文采用 `std::u32string`；段落、文本映射、链接和片段目标中的偏移均为 Unicode 标量索引。普通段落、标题、列表项、预格式文本、内联文本及脚注正文按源顺序读取。`links` 提供本书链接的资源与片段目标；`fragment_offset()` 解析 `id` 的正文目标位置。外部链接会标记 `external`，组件不请求网络。

## 样式与降级

- CSS 文件、样式元素和内联 CSS 不阻止阅读；使用基础正文样式并返回 warning。当前不实现 CSS 选择器、浮动、定位、竖排和样式隐藏。
- 结构标题和列表块保留类别；内联强调的文本保留，但尚未输出独立粗体、斜体样式。
- 表格按行和制表分隔的单元格输出，并返回 warning；不实现表格几何布局。
- `Chapter.images` 提供图片段范围、包内资源与真实媒体锚点；`read_image()` 有界读取 PNG/JPEG。支持 `img` 和无变换、单 `image` 的 SVG 封面包装。图片解码和灰阶缩放见[图片实现](image-runtime.md)。不支持或读取失败时保留明确占位，不清空正文。占位映射到真实媒体元素而非伪造文本；alt 超过 256 标量时截短显示。
- 脚注保留在原文顺序中，入口与目标均可定位；弹出脚注及跳转返回历史由上层实现。
- XHTML `head`、`script`、`style` 不进入正文，脚本不执行。其他未专门排版的元素保留文本。
- 当前要求格式正确的 XML XHTML；允许不含内部子集的 DOCTYPE 声明，但不加载外部 DTD。内部 DTD、自定义/未解析实体、加密/混淆资源、ZIP64 和外部资源作为 manifest 项均明确拒绝。未对 HTML 错误进行浏览器式修复。

## 来源位置

每个保留文本范围对应 `Anchor{resource,node,offset}`。`node` 是当前解析器生成的 `/html[1]/body[1]/p[1]/em[1]/text()[1]` 等本地来源路径，**不是 KOReader XPointer**。路径中的元素同名兄弟编号与文本节点编号从 1 开始。相邻 Expat 字符回调合并为同一节点；子元素、注释与处理指令分隔文本节点，CDATA 边界本身不分隔。偏移针对 XML 实体解码后的文本，不是 UTF-8 字节或 UTF-16 单元。非 BMP 字符占一个标量。

普通 XML 空白连续段折叠为一个空格，块首尾空白删除；NBSP 保留。保留空格对应该连续段的首个源空白；被删除的源空白没有一对一反向映射。`pre` 和 `xml:space="preserve"` 保留空白。块之间插入的换行没有文本来源。媒体占位的 `TextRun.element_reference` 为 true，锚点指向原 XHTML 媒体元素路径，offset 固定为 0；恢复时定位到占位起点，因此纯图片封面也有可保存的来源位置。`anchor_at()` 与 `offset_for()` 不猜测近似文字位置；上层需跳过无来源的分隔符。

`source_nodes` 保留当前章正文中 XML 解码后的原始文本节点（包括节点首尾和纯空白），用于外部位置协议核对；`first_child` 区分父元素的首个文本节点，以识别引擎删除的块首空白。`css_sources` 有界保留内联和本地样式，用于同步层判断空白及 DOM 变化，不改变基础正文排版。普通 CSS、元数据与不含内部子集的 DOCTYPE 不再直接禁用同步。`plain_dom` 遇到媒体、表格、未知元素、正文中的注释/处理指令/CDATA 或其他未核对结构时为 false；缺失、外部或超限样式也会禁用映射。它只是映射前置条件，不自行保证外部引擎兼容。

来源路径和规范化规则仍是当前实现协议。本组件只输出来源锚点；外部 XPointer 转换由 `reader_sync` 独立实现并核对固定 CREngine DOM 版本。真实 KOReader 客户端与服务之间的往返仍须验收，不能把部分 MD5 一致或受限引擎对照当成双向位置接续成功。

## 输入与内存边界

原书通过 `FILE` 随机读回调访问，ZIP 不解压到 TF 卡，也不把整书载入内存。miniz 仅保留 ZIP 中央目录，其所有堆分配合计上限为 2 MiB；XHTML 用解压回调直接送入 Expat。`Chapter` 持有当前章文本和必要映射，上层不应无限保留旧章节。

| 对象 | 当前限额 |
|---|---|
| 原 EPUB | 256 MiB |
| ZIP 目录 | 4,096 项，中央目录 1 MiB；读取前检查 EOCD，拒绝多卷与 ZIP64 |
| ZIP 资源 | 单项声明解压 32 MiB；总声明解压 512 MiB；较大条目压缩比不超过 1,000:1 |
| container、OPF、导航 | 流式解析，每项 XML 16 MiB，沿用通用 XML 的 400,000 元素和深度 64 限制；manifest、spine、封面 guide 引用各 4,096 项，目录 8,192 项，单个标题 32 KiB；OPF 和目录共享 1 MiB 活跃字符串载荷预算（不含容器及分配器开销） |
| 所选章节 XML | 16 MiB；400,000 元素；深度 64。流式解析，这两项限制解析时间而不是内存 |
| 章节分段 | 一段在达到 60,000 标量后的第一个块边界结束；没有块边界时在 120,000 标量处从块内分开。短于此的章节只有一段 |
| 每段记录 | 文本节点、分段各 4,096 个或元数据 256 KiB 时在下一个块边界分段；6,000 个或 448 KiB 时从块内分开 |
| 映射与目标 | 8,192 文本范围与 8,192 源文本节点；片段和链接各 2,048 项；相关字符串合计 512 KiB |
| 路径与属性 | ZIP 名称 511 字节，来源路径 2,048 字节；单元素 64 属性，单属性值 8,192 字节 |
| 映射样式 | 每章合计 256 KiB、256 段样式；本地链接最多 64 项，不请求外部资源 |
| 图片 | 每章最多 256 个引用；每次读取最多 2 MiB 编码数据；CRC 校验失败不返回内容 |

开书不再建立完整 XML 树。OPF 收集原始记录后处理，不依赖 manifest 与 spine 的先后顺序；OPF 解析或预算失败仍使开书失败。目录依次尝试 EPUB 3 nav、NCX、按 spine 生成的目录；目录损坏、超出预算或无有效条目时使用下一来源，不截断目录。取消原样返回，不执行降级。1 MiB 约束的是保留字符串载荷，不能视为峰值堆内存；OPF 阶段同时确认 spine 生成目录所需的 id 和路径副本能够装入共享预算，真机开书峰值与耗时另行测量。

重复/越界 ZIP 路径、符号链接、ZIP 加密和非 STORE/DEFLATE 方法会报错。当前资源预算是软件上限，不是 Read Pico 实测峰值 RAM；标准 C++ 容器分配仍依赖可用堆。

### 分段读取与读取级别（2026-10-06）

`load_chapter` 从 XHTML 起点流式解析，只保留目标段；`Reading` 和 `Layout` 取得该段后停止，`Mapping` 为收集映射信息继续解析。靠后的段仍需处理前缀，因此读取更慢，但正文内存不随章节长度增长。段内偏移从 0 开始，来源锚点（资源、节点路径、节点内偏移）与分段无关，阅读位置的保存和恢复不受影响。`find_chapter_part` 按条件查找包含某个锚点或片段标识的段。分段规则只取决于文档内容，三种读取级别的分段完全一致。

| 级别 | 保留内容 | 用途 |
|---|---|---|
| `Mapping` | 全部，包括各文本节点的原文和样式表；解析到文档末尾以确定整篇的结构和样式 | KOReader 位置换算 |
| `Reading` | 正文、块、图片、链接、片段和分段锚点；不保留节点原文和样式表，不读取外部样式表 | 阅读 |
| `Layout` | 正文、块、图片和分段边界，锚点为空 | 页数统计 |

`Reading` 与 `Layout` 的正文一次预留（不超过 120,000 标量），不做成倍增长；`Reading` 读完后收缩到实际长度。从块内分开的段带 `split_node` 标记，位置换算对这样的段一律拒绝，避免节点原文不完整造成偏移错误。上一段中仍未关闭的元素如果以纯空白文本开头，该节点会带入下一段，因为 KOReader 据此为同一元素后面的文本节点编号。解析过程中每个元素和每段文本前检查 PSRAM 可用量不低于 768 KiB，缓冲增长前按增长后的大小检查；不足时以 `Chapter exceeds available memory` 失败并释放，不让分配失败触发 abort。host 上该检查恒真，可用 `set_chapter_memory_probe` 替换。host 实测（libc++，仅 C++ 堆）：《私有样本 A（版本 1）》最大的一段 `Reading` 占用 0.32 MB、峰值 0.81 MB；《吶喊》0.47 MB、峰值 0.97 MB；600 KB 单块样本 0.49 MB、峰值 0.82 MB。字体、帧缓冲和系统服务的联合内存峰值须在真机验证。

固定来源、独立许可证、配置差异与文件摘要见 [reader_document 第三方记录](../firmware/components/reader_document/third_party/README.md)。直接复用 ZIP/XML 和平台摘要实现，不复制 CrossPoint 应用或 KOReader 引擎代码。
