## 样本管理

合成最小 EPUB 可进仓库；用户自己的书籍在 local 私有目录，样本清单可只留摘要和边界描述。第三方免费可读不自动等于允许随仓库再分发。仓库随附带许可证的内置字体子集；完整测试字体通过固定版本下载脚本取得。额外用户字体不随仓库分发。最小样本应包括同名不同内容、跨章、CJK 与非 BMP 字符、内联/脚注、长段落和异常资源。真实 KOSync 账户/令牌、个人批注和全片备份不能混入测试输出。

## 阅读响应性专项（2026-10-07）

以下数值是工程目标，尚未作为真机实测结果验收。串口诊断输入不能代替实体触摸，编译、host、sanitizer 和桌面 CREngine 对照也不能代替 D/K/V。

| 指标 | 初始目标 | 测量口径 |
|---|---|---|
| 面板空闲时释放输入到应用接收 | P95 ≤ 30 ms，P99 ≤ 100 ms | `input_wait/unqueued`；另测真实手指事件 |
| 位图命中的正文准备 | P95 ≤ 50 ms，P99 ≤ 100 ms | `stage/body_prepare_hit`，包含主线程正文提交准备，不含面板刷新 |
| 解压/解析取消检查 | 约 10–20 ms | `zip/checkpoint_max` 是每次资源解析的最大墙钟间隔，读卡单独观察 |
| 同一图片再次显示 | 无重复 PNG/JPEG 解码 | 对照解码计数与灰阶缓存命中；保留像素质量 |
| 统计干扰 | 翻页时延无明显恶化 | 使用同一本书、同一页段比较统计运行和停止，保留样本量 |

保存完整串口日志后运行：

```sh
python3 tools/summarize_reader_perf.py artifacts/reader-run.log
python3 tools/summarize_reader_perf.py artifacts/reader-run.log --json
```

脚本按是否跨刷新排队分开输入等待，分别汇总复制、面板上电、面板绘制、应用帧完成与后台阶段。旧日志中的 `Frame complete ... save=` 实际是应用帧完成回调的总时间，脚本兼容此格式，不能把它当成纯写卡耗时。新格式使用 `complete=`；进度提交单独记录 `progress_commit`。正文准备记录全部样本；其他 `min_us=20000` 阶段只记录 ≥ 20 ms 的慢样本，其 P95/P99 不能代表完整分布。ZIP 的 `other_us` 包含解压及调用开销；XML 时间包含解析回调和回调触发的内容缓存提交。这些墙钟数据可能包含任务调度，不能冒充纯 CPU 时间，也不能与包含它们的父阶段相加。

至少分别记录普通中文连续翻页、长章节后段恢复、跨章回翻、大 PNG、连续改字号、统计期间触摸、长任务快速连点、保存失败和切书后旧结果返回。每种交互保留原始样本量、P95/P99 及最大值，小样本不能用平均值掩盖长尾。同步还需实际 KOReader 的后段恢复、目录跳转、跨段脚注返回和换字号往返。

资源检查同时记录内部 RAM、PSRAM、各自最大连续块、应用/触摸/内容/网络任务最低剩余栈，以及缓存分项与回收计数。`cache_total` 是已知载荷估计，不是总堆用量或峰值分配承诺。缓存不足后应仍能阅读当前页；输入队列溢出恢复后应仍能保存和休眠。

显示和功耗暂不调整既有波形、240/80 MHz 策略及约 8 秒面板保持窗口。先对比连续翻页、间隔十几秒翻页、长期停留、休眠与唤醒的交互能耗和空闲电流，再决定区域刷新及电源参数。只重绘局部的 CPU 收益不能推导为面板刷新时间按面积等比下降；K2 必须保持可靠的清理全刷。
