# Wi-Fi 传书

设备支持两种 Wi-Fi 传书方式，都可上传书籍（EPUB、UTF-8／GB18030／带 BOM 的 UTF-16 TXT）、字体（TTF、OTF）和锁屏图片（PNG、JPEG）：

- **经设备热点**：不需要路由器或预先配置 Wi-Fi。传书期间，手机连着设备热点，暂时不能上网。
- **经已保存的 Wi-Fi**：设备和手机连同一个网络，手机传书时仍能上网。需要先在「设置 → 网络与传输 → Wi-Fi 设置」中添加网络。

## 经设备热点传书

1. 在设备上打开「设置 → 网络与传输」。未保存 Wi-Fi 时点「Wi-Fi 传书」，已保存时点「经设备热点传书」。设备先保存阅读进度，再开启热点。
2. 用手机扫描热点二维码，或在手机、电脑的 Wi-Fi 设置中连接屏幕显示的热点并输入密码。热点没有互联网连接，请保持连接。iPhone 出现无互联网连接提示时，选择「不连接互联网使用」。
3. 保持连接设备热点，在 Safari 等浏览器中打开 `http://192.168.4.1`，选择一个或多个文件，可以混选。选择后立即开始上传，文件按顺序保存到 TF 卡：书籍到 `Books/`，字体到 `Fonts/`，锁屏图片到 `LockScreens/`。设备按扩展名决定目录。
4. 浏览器逐个显示结果和存入的目录。设备屏幕显示已保存的数量和最近一个文件的名称；这些状态变化只刷新二维码下方的状态区。
5. 在设备上点击「结束传书」。设备关闭热点，重新扫描书库和字体列表，无需重启。新字体随后可在「排版」中选择；设备不会自动改用新字体。

使用键盘时，可按 Tab 聚焦「选择书籍、字体或锁屏图片」，再按 Enter 或空格打开文件选择器。放大文字时，选择入口随文字换行增高。

## 经已保存的 Wi-Fi 传书

1. 在设备上打开「设置 → 网络与传输」，点「经已保存的 Wi-Fi 传书」。连接方式为自动时，设备连接附近信号最强的已保存网络；指定了网络时只连那一个。连接失败时留在本页，页脚显示原因；可以改用设备热点传书。
2. 确认手机或电脑连着屏幕上写明的网络，然后扫描二维码，或在浏览器输入屏幕上的完整地址，例如 `192.168.1.23/k7m2qa`。斜杠后的字母和数字每次会话随机生成，只输入 IP 地址打不开传书页。
3. 之后的上传和结束步骤与经设备热点传书相同。

## 传书页

- 选择后整批列出，每本一行：等待、校验中、上传中（百分比和进度条）、保存并核对、已保存或未上传。
- 同名、格式不支持、超过大小上限或空文件标记为「未上传」，跳过这个文件，继续下一个。
- 锁屏图片在上传前由浏览器读取宽高，单边超过 4096 像素或总像素超过 8 百万（8,388,608）时标记为「未上传」。浏览器读不出宽高的图片照常上传，由设备在准备休眠图片时判断。
- `LockScreens/` 已有 256 张图片时，新的锁屏图片标记为「未上传」；请先整理该文件夹。
- 连接中断、超时或设备存储出错时整批停止，剩余的书标记为「整批已停止」。
- 上传中途中断的文件显示「连接中断，结果未确认。可以点『重试』；若提示已有同名文件，请在设备书库中核对。」，并提供「重试」。重试时若设备已有同名文件，只说明可能是中断前保存的那一份；同名检查不比对内容，请在设备上核对。
- 点「停止上传」中断当前这本，其余不再上传。
- 单个文件的上传时限为 2 分钟加上按 50 KB/s 计算的发送时间，超过后按连接中断处理。
- 文件逐个上传，设备同一时间只接收一个文件。上传过程中和上传结束后都可以继续选择文件，电脑上也可以把文件拖到页面任意位置；新加的文件排在列表末尾，轮到时上传。
- 列表保留本次打开页面以来的全部文件。没有文件在上传时，页面显示已保存与未完成的数量；「继续选择文件」与顶部的选择区作用相同。

## 范围与失败处理

- 书籍（EPUB、UTF-8／GB18030／带 BOM 的 UTF-16 TXT）为 1 字节至 64 MiB，字体（TTF、OTF）至 32 MiB，锁屏图片（PNG、JPG、JPEG）至 2 MiB；不提供下载、删除、覆盖或断点续传。词典与字体许可文本不经 Wi-Fi 上传，用 USB 文件传输或读卡器复制；词典安装见[离线词典](runtime.md#离线词典)。
- TXT 一律作为书籍保存到 `Books/`。
- 「排版」最多列出 `Fonts/` 中的 256 个字体。
- 三类文件的同名文件都不覆盖。需要导入另一个版本时，先在电脑上改名。
- 网络中断、停止上传或结束传书后，当前文件可能已经保存但未收到回包。点「重试」核对：已经保存时会提示已有同名文件。已成功上传的文件保留；未提交的临时文件在正常退出处理程序时删除。
- 断电可能留下未完成的临时文件。重新上传同名书籍时，设备自动清理该目标的临时文件并从头接收，无需改名或手动清理。已保存的正式书籍仍不会被覆盖；临时文件清理失败时，网页明确提示检查存储卡。
- 文件扩展名与传输完整性会检查；EPUB 内容可解析性及 TXT 编码在实际开书时检查。
- TXT 支持 UTF-8（可带 BOM）、GB18030，以及带 BOM 的 UTF-16LE／UTF-16BE；不支持 KOReader 位置同步。无 BOM 时优先尝试 UTF-8，再尝试 GB18030；UTF-16 必须保留 BOM，其他编码可能误判或无法打开。
- 传书会话期间暂停阅读、同步和自动休眠；用完后请点击「结束传书」。电源键会请求结束会话，再按既有流程休眠。
- K2 始终立即全刷当前画面，不取消传输。结束传书会等待正在执行的存储提交返回，不保证瞬时退出。
- 经已保存的 Wi-Fi 传书时，同一网络中的其他设备只要知道屏幕上的完整地址，也能打开传书页。传完请及时结束传书。

## 实现说明

HTTP 服务只在用户开启会话时运行。经设备热点时沿用热点与 DNS 服务；经已保存的 Wi-Fi 时不开热点、不运行 DNS 服务，传书页只在随机路径上提供。上传使用本次会话的随机令牌与自定义请求头，不开放跨域访问；文件名限制为单个文件名，目标目录由设备按扩展名选择，存储层另行检查目标路径。锁屏图片在预检查和上传时各统计一次 `LockScreens/`（最多 2048 个目录项），已满时只拒绝这个文件。浏览器先发送无文件体的预检查请求；会话失效、正式文件同名或临时文件清理失败时，先显示错误，不发送整本书。设备用不同的 HTTP 状态码区分只涉及这一本的拒绝和需要停下整批的错误，见 [板级运行说明](../development/platform-runtime.md)。服务端每次接收最多 2048 字节，复用 `FileStore::begin_import`，执行 CRC32、同步、回读与拒绝覆盖的发布流程。屏幕刷新期间服务端暂停读取，发送端由 TCP 流控等待，刷新结束后继续，这次传输的用时相应变长。
