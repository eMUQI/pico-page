# 开发里程碑与首轮任务

原则：每阶段交付可运行的窄路径和真实证据，不先铺完整 UI 再补可靠性。G0 硬件门槛和 G1 host 工作可以并行；无设备只标硬件待测，不把其他工作全部阻塞。现有实现已覆盖真实内容阅读、持久化、网络传书和手动同步；各阶段是否验收须按 development-status.md 中的版本和证据判断。

## G0 · 真实工程与硬件基线

目标：建立可复现工程，不是产出更多架构图。

- 检查现有仓库与本机工具链，寻找已安装 ESP-IDF/EIM 的真实路径与导出方式。
- 核对并锁定 Read Pico 官方 BSP、显示、PMU、触摸与 SD 依赖；优先做最小构建。
- 在 `firmware/` 建立 ESP-IDF 工程；按现有板级要求配置，不擅自调 VCOM/频率/波形。
- 查清当前分区与将来升级空间，但没有设备信息就不生成声称可安全刷写的分区表。
- 建立 host 构建入口、代码检查和最小 CI（没有建立前不编造可用命令）。
- 记录实际版本、命令、产物路径、退出结果、上游来源与依赖许可证。

验收：真实编译通过才标 build 通过；真机启动/显示/触摸/存储/睡眠另标 hardware 结果。烧录前需要用户授权与当前分区核验；历史批次的备份选择不能作为本次授权。未授权只编译和 host 测试。产物：工程、环境记录、依赖清单、可重现构建/测试命令，不是十个空模块。

## G1a · 可运行核心纵向切片（第一轮与 G0 一起做）

目标：把事件和文件可靠性变成能跑的最小测试。

做一个足够小的 host 路径：输入上下文 → session → recording display → 真实临时目录存储。先用合成内容/锚点；不要等整套 EPUB 引擎和设计全部完成。

至少实现：
- 正文 K2 发 ForceRefresh，像素相同也请求清理，不翻页、不修改已读位置。
- 所有可交互页面 K2 全刷当前画面；关闭/取消使用屏幕控件，正文仍用中部触摸开工具。
- 呈现成功才接受锚点；失败、过期书籍/会话/排版 token 被拒绝。
- 配置从文件读；无效配置保留原文件；cache 清理不碰用户记录与必要 prepared。
- 主机临时目录可写入、重开恢复一份有效记录；恢复机制先小而可测。

验收：IN01–IN04、EV01–EV02、ST01–ST02、CFG01 至少有自动化结果。recording HAL 的通过仅表示接口/状态逻辑正确，不表示面板波形已工作。首轮遇到依赖/硬件阻塞，完成这些独立部分并报告剩余，不以空 mock 返回 success 糊弄完成度。

## G1b · EPUB 与 KOReader 位置兼容验证

目标：先消除最关键内容风险，再大规模实现外围页面。

检查 CrossPoint 的 ProgressMapper/ChapterXPathResolver 及其正文计数、解析依赖和许可。与可选 PapyriX/原生 IDF 路线比较后，选最小内容通路，记录到依赖/架构决策。采用合成 EPUB + 用户自有书籍的私有样本，建立真实 KOReader 输出对照。验证章节内与跨章节定位、空白/内联/中文偏移、换字号后同段定位与回读。

验收：EP01–EP04、SYNC01–SYNC03 的实际适用范围有记录。没有真实 KOReader 运行条件时可以实现 host 转换/解析测试，但往返兼容仍待测。不能把「双方使用同一错误函数生成/解析」当作唯一的兼容性证明。不需要先实现所有同步 UI、全部网络传输或一个完整桌面预处理 App。

## G2 · 本地阅读完整流程

目标：使用当前设计真实读书、改设置、关机后继续。

接入真实文档、字体和显示路径；实现文件夹/书架基本入口、正文、工具、目录、排版、刷新。所有原书、本书配置/进度按 storage.md 保存；必要的配置重新加载用现有组件补入口。原始设计有图用图、有 HTML 用 HTML，纠正裁行等实现问题，不等待重画。

验收：所有 IN/EP/CFG 与基本 ST/DP 门槛；真机至少能打开中文 EPUB、翻页、K2全刷、改字号、重启恢复。不要在 G2 完成报告中声称 G3 网络同步已经完成。

## G3 · 真实同步与可靠性收敛

目标：KOSync 真正双向接续，异常不丢本地位置。

接入实际网络、凭据和位置转换，完善保存/上传/远端候选的状态与界面。实现断网待办、冲突处置、取消在途请求、旧 ACK 过滤、登录失败、近似/不支持定位。加入移卡/满卡/写失败、睡眠协调、刷新失败恢复、传输中断的测试。

验收：SYNC、ST、DP、PW 全系列；必须有至少一组实际 KOReader ↔ Read Pico 双向对照，包括不同字号和一处回读。屏幕、存储、网络分别记录证据，不能只拍一个成功提示。UI 图里的成功状态不能先于真实协议能力上线。

## G4 · 可发布首版

目标：他人按说明可以构建/安装、导入 EPUB 并阅读与接续。

补环境锁定、兼容性清单、已知限制、恢复路径、示例配置、可再分发的测试样本和依赖许可。核对工程代码/UI 参数与原稿，记录所有必要偏离及原因；未实装功能不摆假入口。发布版本/公开仓库/选择项目许可证依用户后续决定，不由本交接包自动执行。验收是有证据的实际功能，不是 README 勾选项。

## 暂不列入首版

PDF/漫画引擎、Karakeep 直连、词典与批注、全部 KOReader 设置、主题市场、插件、统计/成就、多硬件支持、自定义按键设置 UI、完整 OTA 产品体验。可保留接口边界，不提前大规模实现。首版之后计划的设备功能（蓝牙翻页、Wi-Fi 与蓝牙开关、关机、锁屏密码、自定义锁屏、自定义按键、低电量保护、书签、翻页效果、OTA 升级）见 [功能路线图](roadmap.md)。

## 当前实施状态补充（2026-10-06）

已从 G0/G1a 推进到真实内容、阅读界面、持久化及手动同步的可运行初版。G0 的设备门槛、G1b 的完整书籍兼容性、G2 真机视觉/输入、G3 真实客户端双向接续仍待验收；G4 未进入发布。不得把功能代码、桌面通过或引擎对照写成整个阶段硬件验收完成。
