# #104 阅读路径任务看门狗复验

本次从 `66b437a` 开始复验 #104。现行路径未复现旧告警，未修改任务调度、缓存策略或看门狗配置。维护者决定按「当前主线未复现，结束本轮排查」归档关闭 #104。这不表示旧告警根因已查明或风险已全部排除；本文保留证据及未覆盖条件，当前构建再次出现告警时可据此重开。

## 条件与方法

使用同一台 Read Pico、同一张 TF 卡和 USB 供电，生效正文字号均为 46 px。没有换卡，也未发起网络或账号操作；未单独确认射频关闭。TF 型号、老化和物理读写尾延迟未测。沿用 EIM 中已安装的 ESP-IDF 6.1，实际 commit 为 `fff9895c82d744c7237be8847347bdd1b07c6643`；本地 SDK 存在既有链接脚本修改及生成 requirements 文件，不能称为干净官方工具链。BSP 固定为 `5f3406deec33304de8801046db583dec7c49e55b`。

两种设备构建均保持任务看门狗 5 秒、双核 Idle 检查开启、panic 关闭。未连接 OpenOCD，也未增大时限、关闭检查或新增喂狗。Idle 任务被长期阻止执行是任务看门狗的检测对象，单条 API 墙钟和取消检查点间隔均不能直接代替实际 Idle 饥饿时间，见 [ESP-IDF 6.1 看门狗说明](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32s3/api-reference/system/wdts.html#task-watchdog-timer-twdt)。

原样 Diagnostic 交替开关 `status` 轮询，覆盖 3,000 章合成书与两本授权实书。每书五轮，每轮两种轮询条件，各执行开书、向前一页及回翻，共 90 个正文目标帧。关闭轮询仅指命令至目标正文帧的等待区间；准备和保存等待仍查询 `status`。开启时每次响应后再等待 100 ms，不是固定 10 Hz。首开与后续重开分别保留原始身份和缓存证据，不把全部样本称为同一冷热条件的速度对比。

阶段构建加临时固定容量计数，分别记录入口 guard 后的完整缓存回收、压力检查、`status` 总段、画布 CRC、缓存遍历、heap API 总段和两类最大连续块查询。每项最多每秒输出一次自启动以来累计调用数、累计墙钟和最大墙钟，`us` 为累计最大值，不是单次分布。外层计时包含子探针偶发日志和调度等待，父子区间不能相加。实际缺段见下方结果表。各项数值以最后一条已输出累计汇总为截止；退出页面后的不足一秒尾段不保证输出，不能称为全程严格最大值。

封面配对使用同一 3,000 章、3,030 项目录、3,004 个 ZIP 条目的 fixture 的等长独立副本，交替封面活跃／空闲及轮询开／关，每格五次，并核对再次开书。副本仅改变 ZIP comment 和路径，正文条目完全一致；首次打开新副本不等于重启后的全冷缓存，字体缓存仍共享。活跃／空闲条件针对首次开书，后续翻页与再次开书均在封面交还后执行。活跃条件由同一单调时钟的封面 worker 进入、开书分发和封面退出标记确认，匹配任务地址、代次及命令 ID。`count=covers` 仅用于准备，不能单独作为 worker 已执行证据。合成书无图片封面，此条件覆盖 SHA、ZIP 索引、包验证及无封面返回，不覆盖实际封面图片解码。

## 原样诊断结果

90 个目标正文帧均成功；30 次向前操作均改变已保存锚点，30 次回翻均恢复对应开书锚点。输入溢出与诊断回复失败均为零，主机采集没有记录断流或命令超时。完整原始串口中未见任务看门狗、Interrupt WDT、panic 或 abort。

2,023 次 `status` 往返的中位数为 42.481 ms，p95 为 566.032 ms，p99 为 1,630.263 ms，最大值为 1,658.171 ms。该值包含主循环排队、CRC、堆查询、协议输出和主机接收，不能解释为堆扫描耗时。

## 源码定位与结论边界

主线程的 `status` 同步执行画布 CRC、缓存遍历、最大连续块查询和栈水位查询。ESP-IDF 6.1 的 `heap_caps_get_largest_free_block` 经 `multi_heap_get_info_impl` 遍历 TLSF pool。主线缓存回收已按回收 16 KiB 批量复查压力；原有 `cache_reclaim` 计时位于函数中段，漏掉首次压力查询、部分缓存释放及早退，因此本次使用完整路径探针，不重复已有批量化优化。

封面与前台正文共用单个优先级为 1 的内容 worker。开书先请求取消封面，再等待其交还，不是两个内容 worker 同时解析。`OpenMode::Cover` 已跳过目录导航，但仍执行 SHA、ZIP 索引、OPF 及 spine 验证。正常取消检查不自动等同于让出；XML feed 和部分像素循环另有显式 `vTaskDelay(1)`。本次未出现对应看门狗告警，没有据静态风险新增调度或缓存修复。

本次未覆盖原报告中大目录实书的后段重开及大量已存页索引条件。样本不能排除慢 TF、碎片化、强制 EIO 或低内存、异常分配器／heap 锁竞争、极大图片封面和长时间阅读下的风险。没有测量逐核 Idle 最大间隔，不能宣称最长连续不让出已验收。协议输入和驱动帧不证明物理触摸延迟、光学表现、功耗或掉电可靠性。未执行网络账户操作或实际 KOReader 往返，不重跑已完成的 #106 全部性能矩阵。
