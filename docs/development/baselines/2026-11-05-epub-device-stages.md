# 2026-11-05 · EPUB 真机阶段测量

3,000 章合成样本首次打开用时 5.688 秒，其中开书任务 4.213 秒，`epub_open` 3.995 秒。目录 XML 解析在开书过程中占约 2.32 秒。两本实书的首次开书任务分别为 370 和 520 毫秒。两种样本的等待构成不同，后续应分别看大目录开书和实际正文翻页。

## 来源和采集口径

在同一台 Read Pico、同一张 TF 卡和 USB 供电条件下运行主线 `9dd222e`。ESP-IDF 6.1 为 `fff9895c`，含本机已有修改。Read Pico BSP 为 `5f3406de`，交叉编译器为 Xtensa GCC 15.2.0。用 EIM 分别执行 `sh tools/build_firmware.sh stages`、`sh tools/build_firmware.sh` 和 `sh tools/build_firmware.sh diagnostic`。生效的普通对照与阶段版配置只差 `CONFIG_PICO_PAGE_LEGACY_PERF_LOG`。两版保留诊断输入及帧通知。看门狗为 5 秒，检查双核空闲任务，panic 关闭。

样本是 3,000 章原创 EPUB 和两本实书的独立副本，分别约 648、182 和 605 kB。首次打开使用此前未读的书籍身份。普通无轮询轮复用完全相同的测试文件和已生成的缓存。普通轮询轮以 ZIP 注释区分书籍身份，成员内容保持一致。各轮为 46 px，每本书完成重开、向前、回翻和源锚点回读。测试副本的书籍摘要、长度及设备 CRC32 留在私有原始记录中。

端到端计时从串口发出动作前开始，在首个成功的目标正文帧通知处结束，含串口传输、任务调度和驱动刷新。渐进图片补画另行完成。阶段版将每个目标帧配对到 `Frame complete`，分别记录复制、上电与绘制。应用保存与后台缓存写入另记。阶段墙钟可能嵌套或交叠，不能相加或用端到端时间减去面板时间推导解析 CPU 时间。20 ms 门槛的日志只描述已记录的样本。

## 看门狗复测

普通轮询版另完成 30 个目标帧，其中开书 12 次。每次状态应答后等待 100 ms，在动作到正文帧之间共查询 202 次，开书期间查询 158 次。9 次开书前书库状态为 `covers`。该状态表示存在待处理或运行中的封面任务。阶段版也在 15 次重开的计时区间记录到封面任务完成。当前样本覆盖了封面工作与开书相邻的场景，仍缺少同一缓存条件下强制有／无封面任务的配对。

3,000 章合成书在轮询组的四次开书为 6.431–6.499 秒。三个 EPUB 轮次共 126 个成功正文帧，串口未记录任务看门狗、崩溃或显示失败。较长的端到端耗时包含任务调度、存储与刷新。#104 仍需用原问题的工作负载核对任务长时间占用与诊断堆查询。主线已包含 ZIP 成员索引和缓存回收的局部改进（`6ae9c6a`、`11c8aae`）。本次没有在历史构建上用同条件复现，无法把未触发归因于某项改进。
