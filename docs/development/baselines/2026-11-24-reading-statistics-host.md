## 翻页与休眠

同一份候选程序分别开启和关闭采集，另与功能加入前的 `ac688a0` 对照。每种格式、每组配置各运行 6 次，共 384 次翻页、6 次休眠。表中时延单位为毫秒，RSS 为每轮峰值的中位数和范围。

|---|---|---:|---:|---:|---:|
| TXT | 改动前 | 1.302 / 2.116 / 5.242 | 1.212 | 5.235 / 6.621 | 10,146（9,984–10,292） |
| TXT | 关闭 | 1.688 / 49.381 / 64.871 | 1.593 | 7.332 / 8.856 | 10,842（10,732–11,112） |

| EPUB | 改动前 | 0.980 / 1.057 / 1.664 | 0.890 | 5.955 / 10.414 | 11,808（11,536–11,872） |

运行中同时有其他构建与测试，共享 CPU 会放大墙钟尾延迟。输入线程 CPU 时间不含其他工作线程和调度等待。逐轮与全量样本均保留，表内的差异不足以证明设备翻页响应或峰值内存的变化。

## 提交与结果核对

| 样本 | 阅读至休眠的 fsync 次数，关 / 开¹ | 统计目录发布次数，关 / 开¹ | 独立统计提交 P50 / P95 / P99 / 最大（ms） |
|---|---:|---:|---:|
| TXT | 338 / 534 | 0 / 28 | 2.843 / 6.701 / 8.779 / 8.779 |
| EPUB | 338 / 534 | 0 / 28 | 3.251 / 9.436 / 27.972 / 27.972 |

¹ 每轮从启动至休眠帧完成，含必要进度和缓存保存。计入成功的文件及目录 `fsync`，发布次数为目标位于 `PicoPage/data/statistics/` 的成功 `rename`，不含书旁的身份文件。Linux 与 ESP-IDF 对目录同步的处理不同。

每轮 64 次翻页均确认了新的正文帧，逐次保存的锚点与基线相同。每轮开启采集时，休眠后回读得到 520,000 ms，关闭时为 0 ms。所有翻页输入线程的成功 `fsync` 次数均为 0。开启统计后，每轮发布文件次数和同步调用均增加。额外的持久化耗时可见于空闲提交和休眠收尾。开启时另在同一本书上以新的写入者执行 16 次 `FileStore::commit_statistics`，每次提交一条 45 秒增量，回读确认总量再增加 720,000 ms。每种格式共 96 次独立提交，此阶段在 RSS 与阅读流程计数之后。

## 条件与复现

- Linux x86_64，GCC 14.2，CMake 3.31.6，Release（`-O3 -DNDEBUG`）。受控存储和异步内容 worker 均启用。测量前采样 4 秒，选择可用核心中空闲时间占比最高的 CPU，所有进程均固定在该核心。每一轮使用独立的 overlay 工作区测试卡，清空应用进度和缓存，操作系统页缓存保持正常。基线、关闭和开启遍历全部六种先后顺序。
- 从同一章首起，连续前翻 32 次、后翻 32 次，按 8 页一组，在后 4 页的翻页前推进既有预取。每次已呈现的正文向测试统计时钟推进 8 秒。输入开始到成功确认帧、请求到确认休眠画面、文件提交采用独立的真实单调时钟。Linux RSS 取当前进程地址空间 `/proc/self/status` 的 `VmHWM`。脚本按 nearest-rank 汇总全部样本，没有耗时阈值。
- 样本由仓库脚本生成。`sample.txt` SHA-256 前缀 `634c35fe42063713`，`long-chapter.epub` 为 `ea760994157eed9e`。文楷 v1.520 为 38 px。改动前与未提交候选的探针可执行文件 SHA-256 前缀分别为 `d443282005a2f999`、`a58375ad483b957e`。
- 构建前和完成测量后均核对组件、顶层构建入口及探针源码摘要，同一份文件清单的 SHA-256 前缀为 `80106cec28de4307`。

以下命令复现候选构建的一组 TXT 对照。将输入替换为同目录的 `long-chapter.epub` 可测 EPUB。

```sh
python3 tools/setup_fonts.py
cmake -S . -B build/perf-host -DCMAKE_BUILD_TYPE=Release
cmake --build build/perf-host --target reading_statistics_bench document_fixtures_target --parallel 4
mkdir -p .local/statistics-bench/cards
for mode in off on; do
  TMPDIR="$PWD/.local/statistics-bench/cards" build/perf-host/reading_statistics_bench \
    build/perf-host/document-fixtures/sample.txt .local/card/Fonts/LXGWWenKai-Regular.ttf "$mode" 64 \
    > ".local/statistics-bench/$mode.log"
  python3 tools/summarize_reader_perf.py --json ".local/statistics-bench/$mode.log"
done
```

原始日志、每轮命令与程序摘要保存在忽略目录 `.local/verification/reading-statistics/performance/`。真实设备待测项目包括输入到面板完成的尾延迟、内部 RAM 与 PSRAM 低水位、任务栈余量、TF 提交次数与耗时、请求至硬件休眠时延，以及功耗和意外唤醒。启用已有性能日志时，`reading_statistics_commit` 阶段可用于统计提交次数和时长。[阅读统计验收项](../acceptance.md#本机阅读统计)

## 同日统计提交优化

将已交付版本（探针 `a58375ad483b957e`）与优化版本（`f3a9799076deb6ef`）重新在同机交替测量。每种格式、每个版本各测采集开启和关闭 8 轮，每组 512 次翻页、8 次休眠。两侧使用相同的测试卡初始内容、38 px 字体、8 秒模拟停留、64 次真实翻页和休眠流程。

| 样本 | 版本 | 采集 | 翻页 P95 / P99 / 最大（ms） | 休眠中位数（ms） | 每轮峰值 RSS 中位数（KiB） | 同日提交 P50 / P95（ms） |
|---|---|---|---:|---:|---:|---:|
| TXT | 优化前 | 关闭 | 0.896 / 1.659 / 29.474 | 3.603 | 11,008 | — |
| TXT | 优化前 | 开启 | 0.867 / 1.653 / 3.706 | 5.338 | 10,576 | 2.177 / 4.874 |
| TXT | 优化后 | 关闭 | 0.958 / 3.186 / 8.678 | 4.098 | 10,940 | — |
| TXT | 优化后 | 开启 | 1.058 / 5.225 / 22.930 | 4.713 | 10,386 | 1.002 / 1.362 |
| EPUB | 优化前 | 关闭 | 0.681 / 0.790 / 3.233 | 3.792 | 11,844 | — |
| EPUB | 优化前 | 开启 | 0.660 / 0.852 / 0.950 | 5.712 | 12,308 | 2.036 / 2.967 |
| EPUB | 优化后 | 关闭 | 0.677 / 0.831 / 3.546 | 3.776 | 11,808 | — |
| EPUB | 优化后 | 开启 | 0.766 / 2.694 / 9.983 | 4.953 | 12,134 | 1.032 / 1.497 |

独立提交每轮有 16 条。探针传入 `progress_percent = -1`，优化版本在这一情况下还省去读取保存进度签名的工作。携带百分比的更新仍校验保存进度，阅读至休眠的测量覆盖应用实际调用路径。表中取同日后续 15 条，各 120 个样本。首条写入另一个日期，单独保留在原始记录中。两种格式、两个版本的所有运行均核实相同的逐页锚点，休眠后开启组回读 520,000 ms、关闭组 0 ms；独立提交后另增 720,000 ms。

两种格式的写入计数相同。开启采集后，每轮从启动至休眠的统计目录发布次数从 28 降至 17，文件及目录的 `fsync` 从 534 降至 457，其中休眠收尾从 24 降至 17。关闭采集时，两种版本都为 338 次 `fsync`。同日提交的中位耗时约减半。跨日期的首笔提交在两侧各有 8 个样本，TXT 中位耗时为 2.094 → 1.972 ms，EPUB 为 1.957 → 2.071 ms。

开启采集时，两种格式的合并翻页 P99 均比优化前高。逐轮差异较大，TXT 的单轮 P99 中位数为 1.446 → 1.068 ms，EPUB 为 0.778 → 0.886 ms。主机数据验证了普通提交的收益，翻页尾延迟需要扩大样本并做设备对照。

单独用 `strace -f -yy` 跟踪 TXT，在一个已有目录、已有日期的独立提交中，文件数据的成功 `fsync` 为 2 → 1 次，成功 `rename` 为 2 → 1 次。已有祖先目录的同步为 10 → 5 次，发布后包含目录的同步为 2 → 1 次。系统调用路径与各阶段原始输出保存在 `.local/verification/statistics-optimization/`。普通翻页输入线程的成功 `fsync` 均为 0。

使用上文命令，在两个版本间交替执行开启和关闭组即可复测。两种构建在同一核心顺序运行，计时期间没有同时进行的项目构建。Linux overlay 记录包含目录同步，实体 TF 写入时延、面板完成、低功耗交接和电流仍待 Read Pico 对照。

### 翻页独立复测

对同一对二进制再次启用采集，使用另一个空闲核心，按预先生成的随机顺序成对比较。TXT、长章 EPUB 和 `large-toc-small.epub` 各 32 对，每个版本各有 16 次先运行，两个版本在对内相邻执行。每侧每个样本均确认 2,048 次翻页，已保存锚点和有效阅读总量逐轮相同。

| 样本 | 版本 | 翻页 P95 / P99（ms，墙钟） | 输入线程 CPU P95 / P99（ms） | 位图命中 / 未命中 P99（ms，墙钟） |
|---|---|---:|---:|---:|
| TXT | 优化前 | 0.862 / 1.182 | 0.818 / 1.104 | 0.594 / 1.313 |
| TXT | 优化后 | 0.854 / 1.441 | 0.794 / 1.224 | 2.636 / 1.441 |
| EPUB 长章 | 优化前 | 0.662 / 1.422 | 0.618 / 1.239 | 0.803 / 1.724 |
| EPUB 长章 | 优化后 | 0.649 / 0.822 | 0.590 / 0.757 | 0.736 / 0.847 |
| EPUB 跨章 | 优化前 | 3.517 / 11.877 | 0.437 / 0.965 | — / 11.877 |
| EPUB 跨章 | 优化后 | 2.076 / 10.501 | 0.367 / 0.875 | — / 10.501 |

以下先在每一对内计算优化后减去优化前的翻页分位数，再取 32 个差值的中位数。负数表示该分位耗时降低。每轮仅 64 次翻页，按 nearest-rank 计算的单轮 P99 等于该轮最大值。

| 样本 | 配对 P50 差值（ms） | 配对 P95 差值（ms） | 配对 P99 差值（ms） | P99 较低 / 较高 / 持平（对） |

复测中，TXT 的合并 P99 增加 0.259 ms，长章 EPUB 降低 0.600 ms。两个版本的两类样本各有 384 次位图命中、1,664 次未命中。跨章样本的 64 次翻页在 33 个正文资源之间往返，全部未命中已预绘的正文位图，优化后合并 P95 降低 1.441 ms。跨章的墙钟尾延迟明显长于输入线程自身 CPU 时间，其中也包含等待异步内容任务和系统调度的时间。

全部 192 轮共 12,288 次翻页，期间没有并行的项目构建或测试。三个样本的长尾变化方向不同，实体面板与 TF 卡仍需独立验证。完整的运行顺序、逐轮锚点、缓存命中及计时保存在 `.local/verification/statistics-optimization/confirmation/`。
