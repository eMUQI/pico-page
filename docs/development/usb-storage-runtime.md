# USB 文件传输

默认启动为正常阅读模式，保留 USB Serial/JTAG 烧录和诊断连接。USB 文件传输开关不持久化。

正常阅读模式只枚举串口，不挂载 TF 卡。浅睡眠硬件交接时断开串口，并在周期 PMU 事件处理期间保持断开；最终退出睡眠后恢复原 USB 配置，请求电脑重新枚举，已有串口句柄需重新打开。准备阶段取消不操作 USB；SDK 拒绝入睡不标记已睡眠，退出时恢复原配置，不追加重连等待。睡眠中插线仍须按电源键唤醒。板级配置关闭启动阶段的 BBPLL 重新校准（`CONFIG_ESP_SYSTEM_BBPLL_RECALIB`）：ESP-IDF 在非 CPU 复位后的应用启动早期会为此关闭再开启 BBPLL，而 USB Serial/JTAG 的 PHY 时钟来自 BBPLL；该校准只针对 ESP-IDF v5.2 之前构建的 bootloader。诊断无回复、USB 设备未枚举和 TF 卡未挂载是不同现象；检查 TF 卡前须先确认已开启文件传输。

## 操作

1. 将设备连接电脑，在设备上打开「设置 → 网络与传输」，点「开启 USB 传输」。设备随后保存已呈现的阅读位置并关闭卡上的文件；准备失败时不交出卡。
2. 等待电脑挂载 TF 卡。
3. 在电脑上管理文件。书籍放入 `Books/`，网页收藏建议放入 `Books/Articles/`，字体放入 `Fonts/`。移动 EPUB 时一并移动同名的 `.epub.picopage/` 目录，以保留进度和单书设置。
4. 在电脑上安全弹出 TF 卡，等待弹出完成。
5. 在设备上选择退出并确认重启。设备重新读取 TF 卡配置与书库，恢复正常 USB 烧录连接。

传输期间暂停阅读、同步、诊断命令和自动休眠。K2 始终全刷当前画面，不退出传输或取消确认；请使用屏幕上的「取消」或「退出并重启」。电脑未完成安全弹出时不要重启设备或拔线；设备无法判断电脑是否仍有尚未提交的文件系统缓存。

## 所有权与实现

`App::prepare_usb_transfer()` 拒绝未完成的显示、网络和保存事务，成功后释放 EPUB、字体与书库数据。主循环停止原串口；平台在卸载 FatFs 前，将空卷标或 `NONAME` 卷标设为 `PICO PAGE`，保留其他卷标。卷标写入失败时拒绝交出卡。平台检查 FatFs 卸载结果，再初始化原始 SDMMC 和 TinyUSB MSC。卷标存于 TF 卡，USB 设备描述符中的 `Pico Page TF Card` 是另一名称。卡交出后，应用卡扫描和读写路径保持关闭；USB attach、detach、SCSI eject 均不自动挂载本地 FAT。

开启传输时，主循环依次呈现三帧：在「网络与传输」页显示准备提示，切换到传输页，再显示启动结果。三帧均为不清屏的整屏更新；交出 TF 卡前仍等待前两帧成功呈现。帧呈现失败后显示基准失效，下一帧按全刷重画。K2 的全刷不受影响。

MSC 使用同步扇区读写，写操作完成后才返回成功；部分扇区写入采用读改写。边界计算使用 64 位算术，拒绝越界和超出回调返回值范围的请求。移卡或 I/O 失败使介质不可用。退出先停止接受 I/O、等待当前事务，再停止 USB/SDMMC 并重启，不在当前阅读会话中重新挂载。

Read Pico BSP 未提供独立 VBUS 检测引脚，本实现不以 USB suspend 或连接事件推断电脑已安全弹出。TinyUSB 和 USB Serial/JTAG 分时使用内部 PHY；传输期间无法通过原串口进行自动烧录。硬件 BOOT/复位仍作为恢复入口，常规操作使用传输页的退出重启。

TinyUSB 接管前保存 Serial/JTAG 的 pad、内外 PHY 选择和 RTC PHY 路由；卸载成功后，在重启前恢复原值。ESP32-S3 的软件重启会保留 USB 外设状态，不能依靠重启将 OTG 自动切回 Serial/JTAG，参见 [ESP-IDF #9826](https://github.com/espressif/esp-idf/issues/9826)。该恢复不依赖诊断控制台驱动，Release 和 Diagnostic 使用相同路径；原本关闭的 pad 保持关闭，重复退出不再操作 PHY。

TinyUSB 初始化在创建任务前同步失败时恢复原 PHY；启动超时、状态冲突或协议栈仍在运行时，无法确认驱动任务已停止，不切换 PHY，保留失败后的重启入口。卸载失败同样不交还 PHY，只有后续卸载成功才恢复；SDK 的部分失败会留下无法重试卸载的状态，不能保证重试恢复。这些状态仅为固定大小的静态快照，操作在原主循环的 USB 交接中执行，不新增任务、堆分配或等待。host 故障注入覆盖初始化失败、超时、卸载失败及重试，真实串口重新枚举的验收见 PW06。

## 与官方示例的差异

对照 ESP-IDF 6.1 固定提交 `fff9895c82d744c7237be8847347bdd1b07c6643` 的 [`tusb_msc` 示例](https://github.com/espressif/esp-idf/tree/fff9895c82d744c7237be8847347bdd1b07c6643/examples/peripherals/usb/device/tusb_msc)，并检查已锁定的 `esp_tinyusb 2.4.0` 实际源码与头文件。USB 协议、描述符、驱动任务和 SDMMC 驱动仍使用官方组件。

- 示例先初始化原始 SD 卡，再安装 TinyUSB；应用与电脑不能同时挂载同一介质。本项目采用相同所有权边界，额外保留阅读进度保存与文件关闭步骤。
- 官方 `tinyusb_msc_driver_config_t.user_flags.auto_mount_off` 可以关闭自动回挂，自动回挂不是弃用便利层的理由。
- 当前版本 `tinyusb_msc.c` 的 `tud_msc_write10_cb` 在排入延后写入后返回长度；`tusb_write_func` 的介质写入失败仅记日志。项目保留同步回调，将 SDMMC 错误返回 MSC，同时检查范围和部分扇区写入。
- 官方示例的自供电模式需要实际 VBUS 监测 GPIO；不能照搬其他开发板的引脚。现有 BSP 未提供该接线，仍保留手动安全弹出与退出流程，不宣称拔线自动恢复。
- 核对未发现需要替换 USB 协议栈或改动板级引脚的依据，没有额外重写协议层。便利层的构建排除依赖精确版本锁，升级时需重新检查上述回调与构建文件。
