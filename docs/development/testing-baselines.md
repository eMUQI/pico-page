# 版本测试基准

本页规定周期性版本测试的记录口径。工程验收目标仍见[验收清单](acceptance.md)，构建入口见[环境说明](environment.md)；基准记录实际观察到的结果，不替代未执行的硬件专项。

## 测量记录

新的公开测量报告与 JSON 放在 `docs/development/baselines/`，文件名使用日期与提交标识，不覆盖旧记录。开源前的历史测量保存在归档仓库，不随本仓库发布；其中的提交号不能在本仓库检出。

## 固定记录项

后续测试使用独立目录和不可覆盖的日期／提交标识，记录以下信息：

- 拉取后的完整 commit、工作区原有差异、测试期间新增修正及其补丁；原始提交失败与修正后通过分开记录。
- 每种实际构建模式的版本、镜像字节数、SHA-256、来源记录、生效 sdkconfig、IDF／BSP／编译器版本及工具链本地差异。
- 设备身份、实测分区、卡与文件系统、供电和无线状态；公开记录使用匿名设备标识，身份原值与 Flash 元数据留在私有目录。
- 书籍匿名编号、内容摘要、测试起点、字体及排版、刷新模式和全刷间隔、缓存与统计任务状态；不提交个人书籍、源锚点原文、账户或完整原始日志。
- 每项的执行命令、结果、样本数、P50／P95／P99／最大值、资源采样、异常和未测项，以及私有原始文件的摘要清单。

公开报告与 JSON 放在 `baselines/`；原始字节、逐次操作、截图、安装副本、工具脚本和敏感条件放在 `.local/<基准标识>/`。公开结果不得依赖私有文件才能理解结论，私有证据不得因下一轮测试而覆盖。

结构化结果包含 `schema_version` 与 `kind`，新格式在报告中说明字段含义。

## 可重复的测试顺序

| 编号 | 工作负载 | 判定与边界 |
|---|---|---|
| B01 | host Debug、开启实际 BSP 波形测试的完整 CTest；独立 ASan/UBSan 开启事件跟踪；CI 路径选择测试 | 核对实际注册项目与 Node 条件，保留完整日志；macOS 不支持的 LSan、Linux 专属故障注入另列 |
| B02 | 标准及 Release／Performance／Diagnostic 构建 | 核对模式开关、来源、镜像尺寸和目标槽；构建成功不等于设备已安装 |
| B03 | 设备身份、分区和镜像校验，安装后启动、TF 与首帧 | 只执行明确授权的安装，保留独立读回校验；不复用历史偏移 |
| B04 | 章节九组工作负载 | 同一设备、书籍、起点、动作顺序与排版；验证保存锚点往返、驱动确认、资源释放和完整事件 |
| B05 | 卡上现有书籍开书与退出、图片采用及保存收尾 | 保留实际样本清单；样本集合变化时不直接比较总耗时；开书不等于整书全部章节或图片通过 |
| B06 | K2、设置、引导重看、字体预览取消／应用、轻扫、水波纹和电源菜单 | 区分注入输入、画布及驱动结果与实体触摸、光学效果 |
| B07 | 现有 Wi-Fi、传书服务、同步服务、更新检查与重启恢复 | 成功、取消、网络失败分别记录；HTTP 往返不等于实际 KOReader 客户端接续或 OTA 槽切换 |
| B08 | 真实 CREngine 位置对照、原书普通／顺序解析摘要对照、图片缓存冷／热探针 | 明确 host 计时及不支持的映射边界，不推断设备性能 |

在无人值守且不能自动恢复的条件下，不进入需要实体按键才能退出的模式。USB 操作以当次授权与自动恢复条件为准，TF 访问遵守固件既有文件所有权规则。电流、面板光学、真实断电、换卡、慢卡、实体电源键与实际 KOReader 接续分别保留待测状态。

### 九组章节工作负载 v1

使用专用测试目录中的九份副本。匿名样本 A 为长章节书，B 为 714 个 spine 项的书，C 为英文短章书；每本有三个固定边界。私有 `seeds.json` 保存源位置与内容身份，报告只公开匿名编号。

每组从已确认保存的固定起点开始：前进到末屏并跨界，执行五次后退／前进往返，检查返回起点和再次进入首屏的保存锚点，再前进若干页并返回同一位置，最后退出书库并等待任务交还。B 的首组与 C 的首组各前进 40 页再返回，其余组各 6 页；A 的第三组跨界前停留 8 秒，B／C 的第二组停留 4 秒。固定测量动作共 388 次翻页；重新定位、K2、开书与退出单独标注。

保留已有进度时，先通过正常 K1 操作回到起点，并核对已保存锚点；不满足起点断言时停止该组，不能将任意当前位置套入历史比较。每组测量前的 K2 另记为准备动作，其耗时不混入普通翻页。全刷计数起点不同导致的帧类型差异必须在比较中剔除或分组。

缓存分成首次未缓存、磁盘命中、保留内容、预准备命中和无需章节任务。没有清缓存的开书不能宣称冷启动；准备动作已触达的章节不能宣称首次进入。派生缓存格式升级后，准备轮不保证可选全书统计完成；按每个动作前后已知／未知总页数单独匹配，并保留未匹配的完整分布。`count` 标签不等于活动 worker，不能据此假定后台工作相同。完整原始日志及由事件派生的全部样本均保留，使用 `tools/summarize_reader_perf.py` 汇总，不使用只记录慢样本的阶段推断总体分布。

## 历史比较与判定

只有设备、内容、源位置、排版、模式、缓存和工作负载可比时，才解释性能变化。优先比较两批共同动作；普通翻页、跨界、预准备命中和完整清屏分开。父子阶段耗时不能相加，串口命令发送至驱动完成的时间不能改称实体触摸或光学时延。

画布分块导出期间继续排空诊断 trace；内存事件副本是否启用不影响排空。采集前后确认帧号及 CRC，截止前等待相关任务交还。出现采集缺口时保留原始记录，修正工具后仅复采受影响范围，分别记录工具来源；不以行为成功覆盖不完整 trace。

新版本出现的新失败、事件缺口、保存锚点不符、显示恢复或资源持续下降须单列。均值下降不能抵消新增失败或长尾；小样本的 P99 常等于最大值。无法保持同条件时保留方向性观察和限制，不输出确定的提升／退化结论。历史结果保持原样，新批次增加记录，不改写旧基准。
