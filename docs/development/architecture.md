# Pico Page 程序架构 · 当前实现基线

首先服从 [当前决定](../planning/decisions.md)。本文件同时说明已实现的组件边界和设计契约；职责名称不要求各自对应一个组件或任务。历史 v0.1 的冲突决定以本文为准，实际验收见[开发状态](../development-status.md)。

## 1. 结构

模块化单体固件 + 按需使用的主机内容工具。单仓库，先只支持 Read Pico。正文、排版、位置、同步策略的纯逻辑可在 host 编译；平台与 UI 是适配层。

```text
用户输入（屏幕 / 电容键）
           ↓
上下文输入映射 → app / reader_session（唯一阅读状态所有者）
                   ├─ reader_document：原书 / 派生内容 → 内容块、资源、锚点
                   ├─ reader_layout：内容 + 排版参数 → PageLayout
                   ├─ reader_display：合成、刷新 → Presented / Failed
                   ├─ reader_store：读写文件、提交确认、缓存与索引
                   └─ reader_sync：位置编解码、网络传输、远端候选

reader_ui：渲染只读状态 + 提交语义动作；不是上述业务的所有者
reader_system：网络生命周期、时间、休眠协调、诊断
platform_read_pico：官方 BSP / PMU / 屏幕与输入驱动的受控适配
```

这是职责图，不表示任意模块可以互相调用。外部 KOSync 是进度服务，不是书籍存储或完整备份服务；Karakeep 是后续来源，不是设备内浏览器。

### 板级构建边界

`firmware/CMakeLists.txt` 负责 ESP-IDF 工程、产品版本和 SDK 版本约束，固定接入 `firmware/board/board.cmake`。板级目录负责目标芯片、更新目标参数、默认配置、BSP 固定版本、补丁构建副本及 TinyUSB 组件裁剪；`platform_read_pico` 继续负责运行时驱动适配。`tools/setup_bsp.sh` 与板级 CMake 共用 `firmware/board/bsp-revision.txt`，构建命令和产物路径见[环境说明](environment.md)。

### 已实现的运行时边界

```text
firmware/board/board.cmake       选择目标、配置、BSP 和链接实现
firmware/main/app_main.cpp        仅调用 runtime::run()
firmware/components/
├── reader_runtime               ESP-IDF 应用循环、网络工作任务、显示/电源/USB 编排
├── reader_app                   页面、阅读用例、内容工作任务
├── reader_core                  Session、Display、帧和值类型
├── reader_input                 释放手势、长按、休眠准备输入策略
├── reader_document / reader_graphics / reader_dictionary
├── reader_store / reader_sync / reader_console
├── platform_contract            显示、输入、存储、电源、系统、网络和更新端口
└── platform_read_pico           端口实现及 BSP、面板尺寸、采样器和驱动互斥状态
```

`firmware/board/profile.cmake` 定义设备标识、更新清单地址和构建目标的 OTA 槽大小，固件与 host 入口共同选择它。`platform_contract` 生成只含这些常量的 `pico_page/build_profile.h`，共享更新逻辑不再写死板名；下载后端仍核对实际分区，构建常量不替代设备分区检查。

`reader_runtime` 和 `reader_console` 只编译依赖 `platform_contract`，由板级 CMake 使用 ESP-IDF 的 `idf_component_add_link_dependency` 在链接阶段接入 `platform_read_pico`。仅把实现加入 `COMPONENTS` 不足以保证静态库解析顺序；板级同时负责这两个消费者的链接关系。实现的 BSP 依赖为私有依赖，不经契约传给消费者。`reader_input` 的纯策略位于 `pico_page::input`，只使用平台事件值，现有 core/app 测试直接使用它。采样器的 `TouchMoves` 事件合并工具属于 `platform_read_pico` 私有实现，provider 不依赖应用输入策略。

契约按能力拆为 `pico_page/platform_*.h`，`pico_page/platform.h` 是聚合入口；不包含 ESP-IDF、FreeRTOS 或 BSP 头文件，不持有全局可变状态。现有 `DisplayBackend`、Frame/FrameResult 和 Session 仍负责请求、结果及可见位置。同步 `platform::present()` 借用画布到返回；应用任务以 `try_begin_display()` 非阻塞申请呈现，成功后无论准备或刷新是否成功都调用 `finish_display()`，丢弃尚未获准的帧时调用 `cancel_display()`。实现仍以原有原子门协调网络接收和显示，显示请求优先级不变。

`card_mount_path()` 返回当前平台配置的卡路径，即使挂载失败也用于构造错误界面；它不授予文件访问权限，只有 `card_root()` 非空才表示可用挂载。应用入口不再写死 `/sdcard`。诊断输入按应用画布尺寸验证坐标，不读取面板实现常量。`display_info()` 在平台初始化前即可无副作用地返回竖屏尺寸；正常启动和初始化失败后的诊断入口均在应用初始化、首帧呈现前校验画布宽高。不匹配时记录错误并停止该入口，未确认 OTA 镜像沿用拒绝路径，不尝试用错误尺寸绘制错误页。此检查在 Release 中有效，既有 `present()` 长度校验仍保留。

本次整理不新增任务、队列、画布或持久格式，不改变保存时机、取消交接、波形、锁顺序和资源预算。`reader_runtime` 明确属于 ESP-IDF 运行环境；共享组件中的条件式堆分配、计时和内容 worker 仍保留既有 SDK 实现。当前 684 × 1216 布局、图片缓存几何与产品更新渠道也保持既有约束。这些边界允许独立增加平台实现，但不宣称已有任意分辨率、其他芯片或 S31 的兼容性。

host 构建逐个编译契约公共头文件；`architecture` 测试约束应用组件不能依赖 Read Pico 实现，显示仲裁测试调用生产端口并与真实网络侧状态交错。固件构建验证板级装配、SDK 依赖和静态链接；真机行为继续按[验收清单](acceptance.md)核对。

### 增加第二块板之前的工作

现有 OTA 镜像只校验芯片、运行中固件的项目名和请求版本；manifest 的板名校验不等于镜像含独立板卡身份。增加第二块板之前必须设计镜像板卡标识和已发布固件的升级兼容路径；不能直接改 `project_name`，否则当前固件会拒绝不同项目名的候选镜像。

届时再按实际依赖考虑 `platform_esp_idf` 与板级实现的拆分。当前网络传输依赖显示仲裁，USB MSC 含 SD 引脚和卡所有权交接，不能把整块代码直接视为与硬件无关。选板入口、通用／板级 defaults、分区文件归属和消费者链接方式也随第二个实际实现验证，不在本轮引入未验证的多板选择开关。`architecture` 测试已校验当前 profile 的更新大小限制与已发布分区表的两个 OTA 槽一致；运行时仍检查实际目标槽。

## 2. 模块与所有权

| 模块 | 拥有/负责 | 禁止 |
|---|---|---|
| `app` | 启动、导航、用例编排 | 堆入 EPUB/驱动实现 |
| `platform_contract` / `reader_core` 值类型 | 平台端口声明与帧、事件等公共值 | BSP 类型、杂项工具和全局可变状态 |
| `platform_read_pico` | BSP、PMU、原始输入、硬件能力 | 用户排版/同步策略；篡改工厂校准 |
| `reader_system` | 网络、电源协调、时间可信度、诊断 | 绕过保存/显示直接切断电源 |
| `reader_display` | 合成、刷新调度、缓冲生命周期、基准帧状态 | 决定阅读位置、直接保存进度 |
| `reader_document` | 书籍身份、目录、内容块、资源、源位置映射 | 以本机页码作为永久位置 |
| `reader_dictionary` | StarDict 索引、只读文件、dictzip 按块解压和有界选词候选；由内容 worker 调用，应用负责选区与释义面板 | 修改原词典、正文进度或显示画布 |
| `reader_layout` | 字形、换行、段落、分页、命中区域 | HTTP、持久化或面板控制 |
| `reader_session` | 当前书、期望/已显示位置、短历史、排版会话 | 持有 GUI 控件、绕过 store 写文件 |
| `reader_store` | 普通文件权威、提交、书库扫描、可重建索引、同步记录 | 选择哪个冲突进度获胜 |
| `reader_sync` | 身份/位置编解码、协议、冲突策略 | 网络回包直接切页；上传未保存位置 |
| `reader_ui` | 页面、控件、状态呈现、语义输入 | 直接访问 SD/NVS/HTTP/EPD |

先按目录/组件建立边界，不要求每个模块都成为任务或有独立仓库。首轮可以只实现 contracts/session/store 与 recording display，不生成十套空框架。

### 2026-10-07 阅读响应性实现

固件启用 `ReaderApp` 的受控存储与异步内容模式。host 保留同步模式用于既有行为对照；异步回归单独启用与固件相同的调度入口。以下为当前代码事实，不代表真机延迟验收完成。

- 主应用仍独占 Session、当前正文、主字体和显示画布。`ContentJob` 每项工作独占自己的解析器、字体和输出缓冲，或独占借用阅读／统计会话中的资源；只在完成标记发布后转移结果，工作任务不修改在途显示缓冲。固件在应用初始化、网络启动前预留一个内容 worker：内部栈 32768 字节、优先级 1、无绑核，指针请求队列容量 1、非阻塞入队，满时返回启动失败；最多一项运行、一项排队。worker 与队列保留至固件复位，空闲时阻塞等待；阅读／统计会话可保留书籍句柄，任务只在执行期间访问它们。每项工作完成后释放局部资源，发布完成后不再访问该 `ContentJob`。取消仍需等完成，必要保存继续执行既有不可中断提交。初始化失败释放队列，后续请求可重试。可选任务的内部余量检查扣除已经预留的栈，不重复计入栈预算。
- 章节与后台统计解析共用协作检查点。固件沿用 XML 分块解析累计约 20 ms 及统计页间阻塞让出 1 tick，使低优先级 Idle 任务有机会执行；这不是单次解析或 I/O 的时限。面板扫描前，主循环通过 `prepare_frame()` 请求正在执行的 Chapter／Pagination 暂停并按请求代次轮询确认，连续帧不能复用旧确认；等待期间继续处理输入，不启动面板。刷新成功或失败均通过 `complete_frame()` 恢复任务；取消解除暂停，但资源仍须等完成后回收。休眠须等待提示帧完成后才能进入后续准备。
- 前台开书、详情、跨章/分段跳转、图片及位置换算使用可取消请求。正文图片未准备好时先呈现文字和固定占位，成功刷新并短暂停留后再建立请求、让出可选资源，保持阅读输入可用；PSRAM 空闲不足冷解码门槛加 256 KiB 时，建立图片请求（含图片查看）前按缺口裁剪正文、界面字形缓存，被裁字形按需重新栅格化；已准备好的当前页/预取位图直接显示。新请求先取消旧工作，等旧任务退出再启动；结果依任务代次校验。同步另校验账户和已保存快照。位置映射任务启动失败时最多尝试 3 次，后两次通过主循环轮询间隔至少 50 ms；不阻塞输入、不重发 HTTP，也不保证能解决持续内存不足。耗尽后留在同步面板，区分内部内存不足与任务创建失败，清除可用候选及上传资格，重新检查和明确确认后才能上传。
- 进度提交持有不可变的已显示版本快照，完成只确认该版本。切书等待保存成功；失败保留旧会话。USB、休眠等存储所有权交接仍先等待任务退出和进度提交，不能在写入中卸载卡。
- 章节内容缓存按文件实际字节数及各文本、记录、字符串的实际分配量检查内存，沿用解析器的安全余量；坏缓存或内存不足时回退原书。顺序跨章／分段和回翻请求携带已验证书籍的内容身份与目标资源，先校验缓存摘要、资源、分段及记录；命中时不重新建立 ZIP 索引或解析 OPF／目录。最近成功呈现的页边界最多保留 64 个不同跨度，重复呈现同一跨度不占用新条目，避免回翻挤出仍需使用的路径。末页边界按章节、分段、末段标记和返回栏几何匹配，读取后还核对分段长度，再跳过从分段开头的回翻排版；修改排版或书籍沿用页历史失效规则。
- 异步开书与跨章保留当前分段和最近离开分段各一份有界序列化缓存，均为不可变共享载荷；快速回翻可在落盘前复用。磁盘缓存完整校验命中后，读取缓冲直接移交这两个既有槽位，保持相同容量核算和回收门槛，不重复复制或提交已落盘载荷。正文成功呈现并完成必要保存后，复用内容 worker 提交当前尚未落盘的缓存。顺序加载遇到已有前缀缓存时不重复序列化和写入；存在性仅用于省略可选写入，实际读取仍完整校验，锚点搜索会补齐缺口并修复遇到的坏缓存。取消、切书或内存压力可丢弃派生数据，写入失败不影响正文和权威进度；前台解析因内存不足失败且仍保留相邻载荷时，释放可选载荷后只重试一次。正文发起的未准备好跨章／分段加载先保留原画面，超过 1 秒尚未完成时，worker 在检查点确认暂停后才显示一次准备提示；面板完成后继续解析，取消可结束暂停。快速完成直接提交目标正文，不新增任务或队列。
- 空闲时先完成必要保存，再提交待写章节缓存、准备当前分段内下一页的布局、字形和正文位图。当当前页或已预排的下一页到达分段末尾时，复用内容 worker 的可选任务槽准备相邻一个分段，跳过非线性 spine 项，不解析整书、不解码下一章图片。只保留已完成的 Reading 正文及源锚点；跨界时校验书籍、请求代次、章节与分段，转移结果后由主应用排版和显示，预准备自身不推进进度。输入可取消未完成工作，旧任务确认结束后才释放；失败或资源准入不足时沿用前台加载。准入前先释放可选分页会话，再复用统计的 PSRAM 总量与连续块预算、解析器余量和可选任务的内部 RAM 余量，完成载荷计入 4 MiB 缓存目标；内存压力先回收顺序阅读会话，再回收相邻预准备和旧章节载荷。随后继续分页索引和全书统计。
- 内容块以强书籍身份和规范化版本定位，保留源锚点、图片、链接和片段目标；源结构精确换算仍使用原 EPUB。分页索引包含强字体身份、算法版本和几何条件，短期访问页历史独立保留非标准入口与返回栏高度。
- 当前正文像素、下一页像素与按目标几何缓存的图片分别复用。书库封面按可见批次准备后合并更新。正文补图复用单个内容任务槽，结束后校验书籍、请求代次、章节/分段、页起点和排版；只更新图片矩形，以带区域的 Overlay 帧提交，不增加阅读修订。输入待处理时不启动或应用补图；正在显示的帧保持不可变。菜单打开后取消正文补图，恢复未完成的正文页时重新调度；旧任务确认结束后才释放和启动新任务。图片预览也在工作任务中解码；面板缓存缺失时允许显示原有图片不可用状态，不在 UI 绘制中重启解码。
- 可选驻留载荷采用 4 MiB 目标及 PSRAM 空闲/连续块门槛，优先回收远处索引、不可见封面、预取与低价值字形。此目标不包括分配器、FreeType 内部对象和工作任务临时副本，不是全系统内存硬保证。

同一受控存储会话中的异步开书和顺序跨分段复用一个 `ChapterSession`：开书完成时将文件、ZIP 和 XML 游标交给它，主应用只保留元数据、spine 和目录的只读快照；快照分配未通过内存准入时保留原路径。章节任务优先读取缓存，未命中时复用已验证文档，长 XHTML 顺序下一段继续解压和解析；到下一章保留包信息并重建单个章节游标。回翻与随机锚点定位重置顺序游标，保留同书已验证的包信息；换书、排版变更、离开阅读、资源压力及存储交还会结束可选会话。只有当前执行的任务可以访问解析器；排队前或运行中取消均在发布完成前关闭文件，应用等待完成后才启动后续任务或交还 TF 卡。续读失败先释放游标，再沿用原读取器；64 KiB 未完成 XML 标记限制仅约束续读输入，不能拒绝原路径能够读取的正文。文档和解析器的可计量载荷计入缓存目标，Expat 内部池和分配器开销由实际堆余量监测，不能把载荷统计当作内存硬上限。

首次随机定位、失去游标或低内存回退后的长 XHTML 后段仍从资源开头解压；相邻预准备和顺序续读减少边界等待，但不保证所有冷跨章无停顿。缓存目标的序列化和摘要仍在章节 worker 内完成。解压/XML、分页和图像处理均有取消检查，但单次阻塞 SD 调用不能被抢断，图片输出逐行检查取消，缓存摘要计算后、开始可选缓存提交前再检查一次；缓存摘要计算也仍是有界整块操作，已开始的缓存提交按原协议完成。首个未命中文本页的字体打开、单页排版/绘制和配置提交仍有主任务工作；不能仅据工作任务存在就承诺所有输入都在 10–20 ms 内完成。阶段日志与[验收矩阵](acceptance.md)用于确定设备上的剩余最长等待。正文补图通过既有 BSP 的 `epd_hl_update_area` 提交区域；其他正文帧沿用整屏更新，K2 与基准失效仍全刷。波形和电源窗口保持原值；区域刷新的灰阶、残影、时延及能耗须真机测量。

### 正文整页图片缓存

固件异步内容 worker 的 `gray-v1` 缓存仍保存 684×1216 的 4 位灰度画布和 32 字节十六进制 MD5。热读取按最多 16 KiB 一块直接填入 worker 独占、尚未发布的结果画布，并增量校验摘要；完整校验通过后才交还结果。损坏、截断或取消时丢弃部分画布，释放读取句柄，未取消时按原冷解码预算回退原书。写入从结果画布借用分块视图，使用已有临时文件、同步及重命名协议，不创建整屏字符串副本；失败仍可使用本次已准备的图片。读写分块之间检查取消，单次文件操作及最终提交不能抢断，不据块大小承诺毫秒上限。热路径准入为一份画布加 256 KiB 余量，并检查最大连续块；前台字形回收及冷解码预算保持原值。host 同步绘制对照路径保持原实现，本条仅描述异步 worker。

## 3. 关键数据

### BookIdentity

内部内容身份基于未修改原书文件的强摘要。另存原文件名、来源、内容规范化版本。KOSync 的文档标识单独保存/生成，不能拿 SHA-256 或阅读包摘要冒充其部分 MD5。路径是当前位置，不是内容身份；同名不同内容必须隔离。同内容的多个路径可共享可重建缓存，但各自伴随记录不静默合并；KOSync 可能仍把它们视为同书。

### DocumentAnchor

与字号/视口无关：阅读顺序中的资源标识 + 稳定源块/节点 + 有明确单位的文本偏移。当前偏移工作默认是 Unicode 标量值；接入现有引擎时必须说明 UTF-8 字节、UTF-16 单元、标量值与空白规范化的转换。位置格式的兼容性以真实 KOReader 源位置对照为准。原始 EPUB 结构映射、规范化规则和版本是位置兼容的一部分，不只复制某一个 XPath 函数。UTF-8、GB18030、UTF-16LE／BE TXT 使用固定字节目标、字符边界分段和段内 Unicode 标量偏移保存本地位置；编码分别使用独立的内容修订。当前没有 KOReader TXT 位置适配。

固定页文档以后使用源页索引与视口/裁切信息，不强行借用 EPUB 的段落偏移。页面编号、百分比属于派生显示，允许未知，不承担唯一身份。

UTF-16LE／BE TXT 以 BOM 选择解码器，分段索引记录原文件字节边界，保留代理对和 CRLF。开书 worker 按实际验证的编码读取进度和书签，已验证快开保留编码与原字节索引，不将 UTF-16 当作 UTF-8。

章节内容缓存使用 `content-reading-v4`，页索引兼容标记使用 `pagination-v5`，使 HTML 正文适配前生成的缓存按未命中重建。`epub-native-v1` 权威进度修订保持不变；缓存失效不删除原书、进度或设置。

### LayoutSpec / LayoutKey / PageLayout

LayoutKey 包含内容与引擎版本、字体摘要/样式、字号、行距、边距、视口和影响几何的设置。灰阶/刷新偏好单独作为 RenderProfile；仅颜色策略改变不必重分页。PageLayout 包含起止锚点、绘制指令和与绘制共享的链接/图片命中区。正文在完整行之间分页；末行放不下进入下一屏，不裁半行、不重字漏字。总页数未完整计算时显式未知或标注估计。

### OperationContext / FrameToken

每次异步操作带 `book_id`、会话代次、排版代次、请求 ID；必要时再加存储挂载代次和账户作用域。旧结果不因「任务成功了」就被采用。FrameToken 区分正文与纯 UI 更新。

### ReadingRecord / SyncRecord

ReadingRecord 包含最后成功呈现的锚点、内容版本、写入者及本地修订、保存确认。本地计数只在同一写入者/会话规则内比较，不能跨设备直接按计数大小裁决。SyncRecord 按设备、账户/服务和书籍隔离，含基线、待上传的已保存版本、远端候选、确认版本。本地保存、传输、远端记录存在性、定位质量分别建模。原稿 `last_ack` 需补 `book_id`、`local_revision`、`account_scope`、对应锚点/摘要。

## 4. 一次正文翻页

```text
ReaderAction::TurnPage
→ session 请求目标
→ worker 返回有效 PageLayout
→ display 呈现并确认对应 FrameToken
→ session 更新 visible_anchor
→ store 提交并确认 saved_revision
→ sync 合并该已保存版本的待办
```

排版成功但刷新失败：不推进已显示位置。显示成功但保存失败：可以继续显示，明确「尚未保存」，不上传此版本。菜单、状态条、样文预览和 K2 全刷不会推进正文锚点或增加正文修订号。目录/脚注跳转先暂存起点，目标正文呈现成功再提交返回历史；失败或取消不污染历史。

## 5. K2 与输入路由

`map_input(context, input) -> Action` 是唯一映射入口。正文：K1/K3 翻页，K2 ForceRefresh；工具通过中部触摸打开。所有可交互页面的 K2 均发 ForceRefresh，只重刷当前画布；关闭、取消、确认由屏幕控件承担。自定义按键按 [功能路线图](../planning/roadmap.md) R7 实现；开工前保持静态默认表。K1/K2/K3 不增加组合键或长按；电源键长按菜单按 R1、D34 实现，真机时序待测。

全刷是明确用户操作：即使帧缓冲与上次相同也必须执行有效清理刷新，不能被差分优化跳过。刷新事务忙碌时按原稿忽略重复 K2，不中断在途波形，也不积累无限请求。触发面板打开/关闭/唤醒的一次输入序列有唯一所有者，不将尾部抬手交给下一层。

## 6. 内容路径与组件复用

首版验收优先验证普通中文 EPUB、换字号恢复和 KOReader 源位置往返。优先研究 CrossPoint/PapyriX 的章节/位置/缓存代码，记录平台耦合与许可，再确定最小路径。原生解析或配套预处理先做一条，不同时做两套完整引擎。保留原书；规范化/转换不得丢失同步需要的源映射。必须预处理才能离线读时，其产物属于必要资源，不是可随意删除的缓存。

首版范围：正文、标题、基础强调/列表、目录、基础中英混排、字体/字号/行距/边距；插图和脚注在有界资源内提供基础路径或明确降级。复杂样式不承诺完整还原。PDF、Karakeep、词典/批注/脚本等后置，不用「格式已识别」冒充可阅读。

## 7. 同步契约

identity / locator / transport / policy 四部分分开。优先原生 KOSync；参考的源码入口见 references.md。不要只实现 HTTP 然后把核心定位列为以后补。

打开书只恢复本地，不自动联网或查询。首版同步仅由用户明确触发，远端回包只给候选，不强跳。断网先保存；联网先拉远端并与上次基线比较，不盲推旧 outbox。两边都改变时提示；不按最大百分比或不可信时间戳自动覆盖。没有远端记录不等于原书不匹配。mapping=unsupported 不提供「跳到附近」。近似定位先说明并确认，失败保留本地；不得退到第一页后报告成功。

「继续此处」仅保留本地，并记录对该候选的处置；不能随后由休眠上传暗中覆盖同一冲突。显式「上传并替换」走单独确认，服务器未实现条件写入时仍要承认竞态并保留恢复信息。取消在途上传不能保证服务端未变化，记录结果待确认，再拉取核对。确认成功只对应发送时的版本；期间又翻页则当前版本仍待上传。同步服务成功不等于其他设备已经接续，UI 显示「远端记录」，不推断对方实时状态。

## 8. 显示、内存与任务

Display 提供意图（翻页/UI/图片/手动清理/恢复）而不是把波形常量散布各页面。灰阶与更新范围是两个维度；用户模式名称不等于 Palma 的已验证效果。板级初始化、工厂 VCOM、供电时序沿用锁定且已核查的路径，不盲用别的屏幕实现。

维护基准帧 valid/unknown；刷新失败保留软件已确认锚点，但物理屏幕可能部分更新。Read Pico 的行队列欠载在电源状态正常时，等待驱动结束供数并解除扫描回调后，保留目标画布，执行一次完整清屏和从白底重画；清屏与重画均成功才确认显示，重试失败仍使基准失效并进入错误页。恢复复用既有驱动画布，不新增任务或图像缓冲；恢复期间不能抢断波形或改写在途目标。同步面板在网络等待期间保留一次等待画面，网络阶段通知只更新状态，不触发额外刷屏；完成/失败、明确取消和 K2 仍沿用各自显示事务。错误提示只能在屏幕能恢复呈现后显示；不能承诺坏屏一定能显示自身错误。同一时刻只有一个面板刷新；在途 buffer 不可变。减少重复整屏复制，优先复用驱动现有缓冲。

684×1216×4bit = 415872 bytes，约 406.1 KiB，仅是一个像素缓冲计算，不是总内存预算。实际内部堆、PSRAM、DMA 能力与最大连续块需分别测量，网络/字体/图像峰值要单测。正文/图片/字体缓存有上限，不整书解压或一次缓存所有中文字形。

任务先按工作类型安排：app/UI、阅读计算、显示、文件 I/O、网络；不预设每模块一任务。解析器/缓存对象在后台工作时只有一个拥有者；协作式取消并等待退出，不能强删后复用。前台当前页优先于未读章节预计算，进度保存优先于长导入；所有队列有界。

固件更新沿用上述分工：清单解析、版本比较和安装前判断是可在 host 测试的纯逻辑；界面发动作，网络 worker 独占无线电，平台层独占应用槽写入、启动槽切换和首次启动确认。请求带序号，取消后迟到结果丢弃；下载校验完成不等于安装成功。下载、续传、显示互斥与回滚规则统一见[固件更新实现](platform-runtime.md#固件更新)。

## 9. 休眠、恢复与诊断

自定义锁屏沿用内容 worker、独占输出画布与显示事务的分工。请求休眠时固定恢复来源，提示呈现后才开始网络和存储收尾；取消须等在途刷新和 worker 交还资源。绘制及显示完成回调不扫描、解码或提交文件。文件、缓存、内存、取消预算和恢复规则统一见[自定义锁屏实现](platform-runtime.md#自定义锁屏)，页面反馈见[UI 说明](ui-implementation.md#电源与休眠)。

立即休眠、等待图片及自动休眠共用上述输入规则。板级交接在采样器锁内丢弃触摸队列，并抑制当前触摸直至释放；触摸中断不取消交接，PMU 事件确认和唤醒源检查仍照常执行。取消后的恢复期间仅保留电源键意图，触摸队列溢出的重置事件不能清除长按菜单请求。

休眠协调器冻结非必要请求，等待/取消有界工作，确认必要呈现与保存，保存待办，结束网络并通过 BSP 设置真实唤醒来源。网络失败不能无限阻止休眠。保存失败有独立分支；不能因低电量就声称已保存。深睡按重新构造对象处理。无卡时仍能使用内置错误字体呈现提示；不自动格式化挂载失败介质。设备刷写须获授权，并核对实际分区和 OTA 槽大小。

## 10. 预期工程组织与验收

`firmware/main` 组装；`firmware/components` 放当前所需组件；`tools/host` 复用纯逻辑；`tools` 预处理/开发工具；`tests` 合成样本、对照、故障注入与真机步骤。第三方代码锁版本并留许可/修改记录。只有完成可运行实现与对应测试，模块才算交付。首版门槛和具体验收项见[验收矩阵](acceptance.md)。硬件与外部项目线索见 [references.md](../planning/references.md)，旧架构来源见 archive。

后台 EPUB 解压输出按 4,096 字节喂给 XML 解析器；设备分支在块边界检查自上次让步是否已经过 20 ms，达到后阻塞一个调度 tick，再检查取消。后台分页在页边界同样阻塞一个 tick，避免连续 CPU 计算饿死低优先级空闲任务。该检查点不限制单次解压、XML 调用或 TF I/O 的墙钟耗时，保留原看门狗配置与所有权规则。

## 阅读应用的源码组织

`reader_app/app.cpp` 保留公开 API 与部分应用协调，`app_impl.h` 定义唯一的 `ReaderApp::Impl` 状态及共享内联辅助函数。实现按书库、正文、内容任务、绘图、书签与目录、设置、Wi-Fi、同步、固件更新、传输、电源和输入分到 `app_*.cpp`；这些是同一组件的翻译单元，不是新增任务或状态所有者。host 与固件共用同一份源文件列表。

### 2026-10-23 词典检索核心候选

`reader_dictionary` 在 host 与 ESP32-S3 编译同一实现，独立实现 StarDict 记录与 dictzip 头，链接 `reader_document` 已有的 miniz；不复制或链接外部阅读器的应用代码。`Dictionary` 由单一执行者持有，所有公开方法同步执行文件操作，内容 worker 已具备目录元数据扫描、索引准备、候选查询和读取指定义项的工作种类；设备菜单、请求派发与结果面板通过 `app_dictionary.cpp` 接入。

`open` 流式核对原始索引数量、顺序与数据边界，建立每 256 条一个偏移的内存稀疏表；成功后才发布对象状态，失败关闭候选文件。精确查询包括普通与压缩同义词表，单批最多返回 32 个不同目标，调用者可按最后一个 ordinal 继续；不截掉重复词头的后续义项。释义字段保留原格式类型，HTML／Pango／XDXF 的基础显示转换由 `dictionary_text` 处理。原始单条解码上限为 128 KiB，超限明确失败；显示文本按游标分段解码和分页，不一次生成整条 UTF-32 文本。

索引表每套最多 8,192 个 32 位检查点，普通与同义词索引分别有界；dictzip 每文件最多 4,096 个块和一个末尾偏移，解码缓冲不超过 65,536 字节。正文与同义词解码缓冲交替保留，解压状态使用可检查失败的堆分配；压缩输入以 4 KiB 分块，解析与解压循环调用取消回调。读取仍可能阻塞于单次 stdio／TF I/O，检查间隔不是取消时限。ESP 分配前保留既有阅读路径的 768 KiB PSRAM 余量，并检查最大连续块；实际峰值与时间待目标设备测量。

释放或卸载存储前必须结束同步操作并销毁 reader，应用取消须沿用既有 worker 完成交还协议。单项核心与后台测试不能替代 [实施计划](../planning/dictionary-plan.md) 中的完整交互验收。

### 2026-10-23 词典准备与缓存接入

`Dictionary::open_prepared` 通过 FileStore 建立或复用稀疏索引；`Verification` 仅缓存当前挂载作用域已完整核对的源摘要，不持有打开的文件。每次新作用域的首次准备读取元数据、索引及同义词的完整 SHA-256；同一作用域重开可跳过全量扫描，但仍检查缓存载荷摘要、结构和当前正文边界。重新扫描、USB、换卡与源替换清除验证对象，应用通过挂载身份与 `DictionarySession` 管理验证作用域。

`.ifo.gz` 在 16 KiB 上限内展开；`.idx.gz` 使用 32 KiB 环与 4 KiB 输入流式解压，完整验证单个 gzip 成员的 CRC、长度及可选头校验。暂存索引最大 64 MiB，写入后同步并分段读回 SHA-256，再由 FileStore 发布；正文不全量展开。多成员 gzip 明确拒绝。新增 `Sha256Digest` 复用 reader_document 已有 host OpenSSL／固件 PSA 后端，没有增加第三方代码或任务。字体、画布、正文进度仍不属于词典核心。

`ReaderSettings.dictionary_enabled` 按顺序保存已启用词典相对标识；设备管理通过现有 TOML 快照比较与提交协议写入，外部修改冲突或提交失败时保留旧生效设置。

### 2026-10-23 词典选区基础与内容 worker

`PositionedGlyph.advance` 保存排版时的宽度，`text_hit` 与 `selection_boxes` 只使用当前页的字形和行几何，不访问字体或文件；空白、图片和页边不产生文字命中。选区使用章节分段内的 Unicode 标量半开区间。`initial_selection` 限定在可见范围内选取一个汉字或 Latin 单词；`selection_candidates` 生成包含触点的有界中文候选，或原词、ASCII 大小写、规范化软连字符／撇号与有限英语屈折候选。手动选区只生成其原始文本；候选不是确定词根，仍须真实索引命中。上层多词典调度必须先完成原词／大小写轮，再进行词形回退轮。

`dictionary_job.cpp` 在原 ContentJob 执行者内工作，不创建额外任务。扫描仅解析元数据，不准备索引；每个准备／读取任务只打开一套词典，查询任务依次打开请求内最多 32 套词典，同一时刻只持有一套文件，所有文件在任务发布完成之前关闭。查询返回命中候选、最多 32 个词条描述及首个义项的字段，后续义项由 ordinal 按需读取。`DictionarySession` 仅保留最多 32 套的验证状态，由正在执行的任务独占；应用须在旧任务完成后于 USB、挂载变化或重新扫描时替换它。

词典任务复用内部 RAM 准入与暂停／取消检查点，并参加扫描前暂停协调。应用调度处理旧结果拒绝、关闭、必要保存及休眠／USB 的交还路径。失败保留明确状态，未收录与 I/O、格式或资源错误分开。请求与结果不借用正文、字体或画布；持续拖选与释义转换由下述应用路径衔接。

### 2026-10-23 词典管理、释义与应用生命周期

`app_dictionary.cpp` 接入管理页、单页长按查询、词典切换、义项续批、释义分页及展开／关闭。一次查词只派发一项 worker 任务：候选按原词／大小写先于屈折、中文较长先于较短排序，任务按全局启用顺序逐个打开词典，每个词典最多打开一次；同一起点的中文候选由短到长查询，词典中没有以某候选开头的更长词头时跳过同起点的更长候选，最终取优先级最高的命中；后续词典只查严格更优的候选，同等候选保留较早词典，最优候选已命中或无更优候选时立即结束。结果与原「长度优先、词典顺序其次」逐轮查询一致，但不再为每个长度和词典重复打开文件、读取校验稀疏索引及呈现读取面板。挂载级 `DictionarySession` 复用验证状态，并以最多 32 项记录来源 `open_prepared` 返回的 InvalidFormat／Unsupported；同一挂载会话内来源只能经 USB 或换卡改变，二者都会重置会话，因此后续查词直接复用该失败，明确重试重新读取已记录坏来源，重新扫描重置会话。仅当前 worker 访问会话，I/O、资源不足、取消及单条词条错误不记录。其他词典由用户按需切换。前后导航将当前来源之前／之后的来源按方向交给同一查询任务，命中第一套可用释义即结束，跳过未收录及失败来源；结果来源标识映射回全局启用序号。查询期间保留旧释义和分页，全部无结果时恢复旧结果并禁用该方向，成功后才切换来源。旧释义字段最多 128 KiB，与新查询字段存在有界重叠，不缓存所有来源全文。应用另保留最多 32 项已知来源打开错误供管理页显示，只接收当前查询代次及正文位置的结果；成功或明确重试移除对应记录，重新扫描及挂载变化清除全部记录。必要进度保存先于词典任务启动；完成结果校验 foreground 代次、当前页面及章节／分段／正文起点，关闭先恢复既有底图，旧 worker 完成后再释放。

`dictionary_text` 将 `m/t` 保留为文本与分隔字段，将基础 `h/g/x` 转换为段落、列表和强调，Pango 字段保留原始换行与空白；跳过脚本、样式及 head 内容，不执行或加载外部资源。命名实体复用 document 的既有表，未知实体保留字面值并标记简化；畸形结构、无效 Unicode 与超深嵌套明确失败。解码游标只保存字段／字节偏移、最多 64 层标记及少量状态；每次输出最多 4,096 个 Unicode 标量，失败不推进游标。原始单条字段仍受 128 KiB 解码上限约束，没有整份 UTF-32 副本。核心读取结果通过 `omitted_fields` 标记安全跳过的未知或二进制字段；应用在当前词条的释义分页期间保留该状态并显示不完整提示，没有支持字段时仍返回 Unsupported。

`DictionaryPage` 在原 worker 中使用独立字体排版，保留下一页游标；向前翻页不重排此前全文。应用最多保留最近 128 个游标，超过历史窗口的返回从本词条布局起点有界重放，期间可取消。页码与游标仅在新页排版成功后更新，失败保留当前有效页。展开／收起以当前页的解码 Unicode 标量偏移重建布局；该锚点将其前一页截短，新页从相同文本位置开始。重建在原 worker 中逐页执行，仍使用 4,096 标量块和有界页数；请求携带锚点，后续回翻重放沿用同一边界。新布局、历史及页码仅在成功后提交，失败保留旧页，不增加整屏副本或任务。应用绘制复用现有字体与正文底图，不增加长期整屏画布；词头和面板名称使用当前正文字体，避免界面字体子集遗漏繁体或生僻字，缺字与简化格式在面板提示。现有 32 KiB worker 栈不变，分页另做 PSRAM 余量与最大块准入；实际内存峰值与最长 TF 阻塞仍待设备测量。

重新扫描以新 `DictionarySession` 替换验证作用域，旧任务通过自身共享所有权完成退出；挂载身份失效、休眠和 USB 收尾清除验证状态。运行中的词典任务收到休眠或 USB 接管请求后先取消，只有完成后才继续交还文件；休眠等待状态包含该任务，避免把正常等待误判为失败。长按电源可取消查询并待资源交还后打开电源菜单，取消菜单保留可退出的词典状态。持续接触与端点拖选已接入；host 与客户端对照的范围见开发状态，真机专项尚未完成，不代表 P2/P3 设备验收通过。

### 2026-10-23 持续选词输入

平台 `EventPhase` 和核心 `Phase` 增加 Move。采样任务在原 16 项事件队列中最多保留一个移动通知，`TouchMoves` 保存对应接触的最新坐标与范围；Begin／End／Cancel 不合并，队列重置同步清除移动槽。采样、接收与睡眠清理共用既有控制器互斥量，主循环用零等待尝试获取，不能因控制器 I/O 超时阻塞接收。`ReleasedTap` 保留原始按下点，用累计移动范围判断长按，Move 不释放输入所有权。

长按成立后，主循环保留物理接触与逻辑序号，直到真实 End／Cancel；普通点击和轻扫仍在释放后分派。应用在刷新忙时只更新待呈现选区，`poll_background` 在面板完成且不处于休眠反馈时刷新最新范围或提交一次查询；不改写在途画布。拖选使用已有字形几何，空白与行间位置吸附到最近文字，图片和页脚不参与选词。选区复用正文底图；新增状态为有界偏移、序号与标志，不新增任务、长期画布或文件读取。

重新调整选区先取消旧查询并使其代次失效。InputReset、移卡和电源事件取消接触；系统取消延后绘制，避免在休眠反馈或电源菜单接管前创建冲突帧。端点释放后使用手选原文精确查询，旧自动候选不得覆盖。桌面 SDL 入口保留右键长按模拟并传递 Move／End，失去焦点取消接触。真实触摸采样、长按反馈与面板时延仍需设备测量。

### 2026-10-24 词典来源选择

来源列表是 Dictionary 视图的临时状态，复用已有元数据扫描、启用列表和输入分发。取消扫描使旧代次失效并恢复原释义，完成结果不覆盖新状态。由查词进入管理页时保留正文与选区，设置未变时恢复原释义，改变后重新查询可用的启用来源；该管理入口的错误／电源返回来源仍为阅读。常规设置入口保持原行为。
