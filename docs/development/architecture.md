# Pico Page 程序架构

本文说明组件边界、所有权和跨组件契约；产品取舍以[当前决定](../planning/decisions.md)为准，验收状态见[开发状态](../development-status.md)。职责名称不要求各自对应一个组件或任务；以源码中的实际组件和调用链定位实现。

## 1. 结构

模块化单体固件，加按需使用的主机工具。单仓库，只支持 Read Pico。正文、排版、位置和同步策略的纯逻辑可在 host 编译，平台与 UI 是适配层。

```text
用户输入（屏幕 / 电容键）
           ↓
上下文输入映射 → app / reader_session（唯一阅读状态所有者）
                   ├─ reader_document：原书 → 内容块、资源、锚点
                   ├─ reader_layout：内容 + 排版参数 → PageLayout
                   ├─ reader_display：合成、刷新 → Presented / Failed
                   ├─ reader_store：读写文件、提交确认、缓存与索引
                   └─ reader_sync：位置编解码、网络传输、远端候选

reader_ui：渲染只读状态 + 提交语义动作，不拥有上述业务
reader_system：网络生命周期、时间、休眠协调、诊断
platform_read_pico：官方 BSP / PMU / 屏幕与输入驱动的受控适配
```

这是职责图，不表示任意模块可以互相调用。KOSync 是进度服务，不是书籍存储或备份服务。

### 组件与构建

```text
firmware/board/board.cmake       选择目标、配置、BSP 和链接实现
firmware/main/app_main.cpp       只调用 runtime::run()
firmware/components/
├── reader_runtime               ESP-IDF 应用循环、网络工作任务、显示/电源/USB 编排
├── reader_app                   页面、阅读用例、内容工作任务
├── reader_core                  Session、Display、帧和值类型
├── reader_input                 释放手势、长按、休眠准备输入策略
├── reader_document / reader_graphics / reader_dictionary
├── reader_store / reader_sync / reader_console
├── platform_contract            显示、输入、存储、电源、系统、网络和更新端口
└── platform_read_pico           端口实现及 BSP、采样器和驱动互斥状态
```

`firmware/CMakeLists.txt` 负责 ESP-IDF 工程、产品版本和 SDK 版本约束；`firmware/board/` 负责目标芯片、默认配置、BSP 固定版本、补丁构建副本和 TinyUSB 裁剪；`tools/setup_bsp.sh` 与板级 CMake 共用 `firmware/board/bsp-revision.txt`。`firmware/board/profile.cmake` 定义设备标识、更新清单地址和 OTA 槽大小，`platform_contract` 据此生成 `pico_page/build_profile.h`；构建常量不代替运行时的实际分区检查。

`reader_runtime` 和 `reader_console` 编译时只依赖 `platform_contract`，由板级 CMake 用 `idf_component_add_link_dependency` 在链接阶段接入 `platform_read_pico`；仅把实现加入 `COMPONENTS` 不足以保证静态库解析顺序。实现的 BSP 依赖是私有依赖，不经契约传给消费者。

契约按能力拆为 `pico_page/platform_*.h`，`pico_page/platform.h` 是聚合入口；不包含 ESP-IDF、FreeRTOS 或 BSP 头文件，不持有全局可变状态。同步的 `platform::present()` 借用画布直到返回；应用任务以 `try_begin_display()` 非阻塞申请呈现，成功后无论成败都调用 `finish_display()`，丢弃未获准的帧时调用 `cancel_display()`。

`card_mount_path()` 即使挂载失败也用于构造错误界面，不授予文件访问权；只有 `card_root()` 非空才表示可用挂载。`display_info()` 在平台初始化前即可返回竖屏尺寸；启动入口在应用初始化和首帧前校验画布尺寸，不匹配时停止，不尝试用错误尺寸绘制。

host 构建逐个编译契约公共头文件；`architecture` 测试约束应用组件不依赖 Read Pico 实现，并校验 profile 的更新大小与已发布分区表一致。

### 增加第二块板之前

现有 OTA 镜像只校验芯片、项目名和版本；清单的板名校验不等于镜像含板卡身份。增加第二块板前必须设计镜像板卡标识和已发布固件的升级路径，不能直接改 `project_name`，否则当前固件会拒绝候选镜像。网络传输依赖显示仲裁，USB MSC 含 SD 引脚和卡所有权交接，不能直接视为与硬件无关。在第二个实际实现出现前，不引入多板选择开关。

## 2. 模块与所有权

| 模块 | 拥有／负责 | 禁止 |
|---|---|---|
| `app` | 启动、导航、用例编排 | 堆入 EPUB 或驱动实现 |
| `platform_contract` / `reader_core` 值类型 | 平台端口声明与帧、事件等公共值 | BSP 类型、杂项工具和全局可变状态 |
| `platform_read_pico` | BSP、PMU、原始输入、硬件能力 | 排版或同步策略；改写工厂校准 |
| `reader_system` | 网络、电源协调、时间可信度、诊断 | 绕过保存或显示直接切断电源 |
| `reader_display` | 合成、刷新调度、缓冲生命周期、基准帧状态 | 决定阅读位置、直接保存进度 |
| `reader_document` | 书籍身份、目录、内容块、资源、源位置映射 | 以本机页码作为永久位置 |
| `reader_dictionary` | StarDict 索引、dictzip 按块解压、有界选词候选 | 修改原词典、正文进度或显示画布 |
| `reader_layout` | 字形、换行、段落、分页、命中区域 | HTTP、持久化或面板控制 |
| `reader_session` | 当前书、期望与已显示位置、短历史、排版会话 | 持有 GUI 控件、绕过 store 写文件 |
| `reader_store` | 普通文件权威、提交、书库扫描、可重建索引、同步记录 | 决定哪个冲突进度获胜 |
| `reader_sync` | 身份与位置编解码、协议、冲突策略 | 网络回包直接切页；上传未保存位置 |
| `reader_ui` | 页面、控件、状态呈现、语义输入 | 直接访问 SD、NVS、HTTP 或 EPD |

`reader_app/app.cpp` 保留公开 API，`app_impl.h` 定义唯一的 `ReaderApp::Impl` 状态；实现按功能分到 `app_*.cpp`，它们是同一组件的翻译单元，不是独立任务或状态所有者。

## 3. 内容任务与阅读响应

固件启用 `ReaderApp` 的受控存储与异步内容模式；host 保留同步模式作行为对照，异步回归单独启用与固件相同的调度入口。

- **所有权**：主应用独占 Session、当前正文、主字体和显示画布。每个 `ContentJob` 独占自己的解析器、字体和输出缓冲，或独占借用阅读／统计会话的资源；只在完成标记发布后转移结果，不修改在途显示缓冲。
- **内容 worker**：在应用初始化、网络启动前预留一个，最多一项运行、一项排队，非阻塞入队，满时返回启动失败；worker 与队列保留到复位。每项工作完成后释放局部资源，发布完成后不再访问该任务。取消请求后仍需等待完成；必要保存是不可中断的提交。可选任务的内存余量检查不重复计入已预留的栈。
- **协作检查点**：章节与统计解析在块边界检查耗时，超过阈值时让出一个调度 tick，让低优先级 Idle 任务运行；分页在页边界同样让出。检查点不限制单次解压、XML 调用或 TF I/O 的耗时，也不改看门狗配置。面板扫描前主循环通过 `prepare_frame()` 请求正在执行的 Chapter／Pagination 暂停，并按请求代次确认（连续帧不能复用旧确认）；刷新完成后 `complete_frame()` 恢复。
- **前台请求**：开书、详情、跨章／分段跳转、图片和位置换算使用可取消请求。新请求先取消旧工作，等旧任务退出再启动；结果按任务代次校验，同步另校验账户和已保存快照。图片请求前按冷解码预算的缺口裁剪字形缓存。位置映射任务启动失败时有限次重试，不阻塞输入、不重发 HTTP；耗尽后清除候选和上传资格。
- **保存**：进度提交持有不可变的已显示版本快照，完成只确认该版本。切书等待保存成功，失败保留旧会话。USB、休眠等存储交接先等待任务退出和进度提交。
- **章节缓存与续读**：章节缓存按实际分配量检查内存，坏缓存或内存不足时回退原书。顺序跨章和回翻请求携带已验证的内容身份与目标资源，先校验缓存再使用，命中时不重建 ZIP 索引或重新解析 OPF。同一存储会话中，开书与顺序跨分段复用一个 `ChapterSession`（文件、ZIP 和 XML 游标），随机定位重置游标，换书、改排版、离开阅读、资源压力和存储交还结束会话。续读的输入限制不能拒绝原路径能读取的正文。
- **派生缓存提交**：保留当前与最近离开分段各一份不可变缓存，快速回翻可在落盘前复用。正文成功呈现并完成必要保存后，再由内容 worker 提交未落盘的缓存。取消、切书或内存压力可丢弃派生数据；写入失败不影响正文和权威进度。
- **跨章等待**：未准备好的跨章先保留原画面，超时后 worker 在检查点确认暂停，才显示一次准备提示；快速完成则直接显示目标页。
- **空闲工作**：依次为必要保存、提交待写缓存、准备下一页的布局与位图、在接近分段末尾时预准备相邻一个分段（跳过非线性项，不解码下一章图片），然后才是分页索引和全书统计。预准备自身不推进进度；输入可取消未完成工作；失败时沿用前台加载。
- **正文补图**：复用单个内容任务槽，完成后校验书籍、请求代次、章节／分段、页起点和排版，只更新图片矩形并以 Overlay 帧提交，不增加阅读修订。输入待处理时不启动或应用补图；菜单打开后取消，恢复正文时重新调度。
- **重开**：应用仍持有且文件身份有效的 EPUB 复用已解析的书脊与目录，并重新核对 ZIP 资源；身份失效后完整重算摘要，摘要匹配时仍可复用不可变阅读索引。OPF 清单按块分配，分配失败时开书可重试，封面任务按暂时失败处理。
- **内存目标**：可选驻留载荷有总量目标和 PSRAM 空闲／连续块门槛，优先回收远处索引、不可见封面、预取和低价值字形。该目标不含分配器、FreeType 内部对象和任务临时副本，不是全系统内存保证。

单次 TF 调用不能被抢断，首次随机定位或低内存回退后的长章后段仍从资源开头解压；不能仅凭存在工作任务就承诺所有输入都在固定时间内响应。设备上的最长等待由阶段日志和[验收矩阵](acceptance.md)确定。

### 正文整页图片缓存

`gray-v1` 缓存保存整屏 4 位灰度画布和摘要。热读取分块填入 worker 独占、未发布的结果画布并增量校验，完整通过后才交还；损坏、截断或取消时丢弃部分画布，未取消时按冷解码预算回退原书。写入借用结果画布的分块视图，沿用临时文件、同步和重命名协议；失败仍可使用本次图片。热路径准入检查总余量和最大连续块。

## 4. 关键数据

**BookIdentity**：内容身份基于未修改原书文件的强摘要，另存文件名、来源和内容规范化版本。KOSync 文档标识单独生成，不能用 SHA-256 冒充其部分 MD5。路径是当前位置，不是身份；同名不同内容必须隔离；同内容的多个路径可共享可重建缓存，但各自的伴随记录不静默合并。

**DocumentAnchor**：与字号和视口无关，由阅读顺序中的资源标识、稳定源块／节点和有明确单位的文本偏移组成，偏移默认是 Unicode 标量值；与 UTF-8 字节、UTF-16 单元和空白规范化之间的转换必须明确。位置兼容性以真实 KOReader 源位置对照为准。TXT 使用固定字节目标、字符边界分段和段内 Unicode 标量偏移，各编码使用独立的内容修订；没有 KOReader TXT 位置适配。页码和百分比是派生显示，允许未知。

TXT 由 BOM 选择 UTF-16 解码器，分段索引记录原文件字节边界，保留代理对和 CRLF。浅睡恢复在 worker 中校验原文件完整 SHA-256，摘要相同才复用会话中的编码、目录和分段索引。章节缓存与页索引按各自格式与算法版本校验，旧版本按未命中重建；版本号见[内容后端](document-runtime.md#html-正文兼容与-txt-编码)。缓存失效不删除原书、进度或设置。

**LayoutKey / PageLayout**：LayoutKey 包含内容与引擎版本、字体摘要与样式、字号、行距、边距、视口和影响几何的设置；刷新偏好单独作为 RenderProfile，只改颜色策略不重分页。PageLayout 包含起止锚点、绘制指令和与绘制共享的链接／图片命中区。正文在完整行之间分页，不裁半行、不重字漏字；总页数未完整计算时显式未知。

**OperationContext / FrameToken**：每次异步操作带 `book_id`、会话代次、排版代次和请求 ID，必要时加挂载代次和账户作用域。旧结果不因任务成功就被采用。FrameToken 区分正文与纯 UI 更新。

**ReadingRecord / SyncRecord**：ReadingRecord 包含最后成功呈现的锚点、内容版本、写入者与本地修订、保存确认；本地计数不能跨设备直接比较大小。SyncRecord 按设备、账户／服务和书籍隔离，包含基线、待上传的已保存版本、远端候选和确认版本；ACK 记录 `book_id`、`local_revision`、`account_scope` 和对应锚点。

## 5. 一次正文翻页

```text
ReaderAction::TurnPage
→ session 请求目标
→ worker 返回有效 PageLayout
→ display 呈现并确认对应 FrameToken
→ session 更新 visible_anchor
→ store 提交并确认 saved_revision
→ sync 合并该已保存版本的待办
```

排版成功但刷新失败时不推进已显示位置。显示成功但保存失败时可以继续显示，明确「尚未保存」，不上传此版本。菜单、状态条、预览和 K2 不推进正文锚点或修订。目录和脚注跳转先暂存起点，目标正文呈现成功后才提交返回历史。

## 6. 输入路由

`map_input(context, input) -> Action` 是唯一映射入口；按键与触摸的默认映射见[界面说明](ui-implementation.md#输入与刷新)。全刷是明确的用户操作，即使帧缓冲与上次相同也必须执行清理刷新；刷新忙碌时忽略重复 K2，不中断在途波形，不积累请求。触发面板打开、关闭或唤醒的输入序列有唯一所有者，尾部事件不交给下一层。

## 7. 内容路径

`reader_document` 直接读取原始 EPUB 和 TXT，不要求预处理阅读包；正文有界分段，缓存是可重建的派生数据，持久位置使用源锚点。解析与资源限制见[内容后端](document-runtime.md)，原书模式见[原书排版](original-layout.md)。核心发布验收包含普通中文 EPUB、换字号恢复和实际 KOReader 往返，不能由缓存或解析器测试代替。

## 8. 同步契约

identity、locator、transport、policy 四部分分开；兼容范围、拒绝条件和账户作用域见[同步说明](sync-runtime.md)。HTTP 成功不代表位置可以精确接续。

打开书只恢复本地，不联网。同步只由用户触发，远端回包只是候选，不强制跳转。联网时先拉取远端并与上次基线比较，不盲推旧 outbox；两边都改变时提示，不按最大百分比或不可信时间戳覆盖。没有远端记录不等于原书不匹配。映射不支持时不提供「跳到附近」，换算失败保留本地，不能退到第一页后报告成功。

「留在这里」只保留本地并记录对该候选的处置，不能随后由休眠上传暗中覆盖。「上传并替换」需要单独确认；服务器不支持条件写入时承认竞态。取消在途上传不能保证服务端未变化，记录结果待确认并重新拉取。确认只对应发送时的版本。

## 9. 显示、内存与任务

Display 接收意图（翻页、UI、图片、手动清理、恢复），波形常量不散布在各页面。灰阶与更新范围是两个维度。板级初始化、工厂 VCOM 和供电时序沿用锁定且已核查的路径。

基准帧有 valid／unknown 状态；刷新失败时保留软件已确认的锚点，但物理屏幕可能部分更新。行队列欠载的恢复规则见[平台适配](platform-runtime.md#像素刷新和输入)。同一时刻只有一个面板刷新，在途缓冲不可变；网络阶段通知只更新状态，不额外刷屏。错误提示只能在屏幕可以恢复呈现后显示。

一份整屏 4bpp 像素缓冲为 415,872 字节，这不是总内存预算。内部堆、PSRAM、DMA 能力和最大连续块分别测量；正文、图片和字体缓存都有上限，不整书解压或缓存所有中文字形。

任务按工作类型划分：app/UI、内容计算、显示、文件 I/O、网络，不预设每模块一个任务。后台工作中的解析器和缓存对象只有一个拥有者；取消是协作式的，等待退出后才复用资源。前台当前页优先于预计算，进度保存优先于长导入，所有队列有界。

固件更新沿用相同分工：清单解析、版本比较和安装判断是可在 host 测试的纯逻辑；界面发动作，网络 worker 独占无线电，平台层独占应用槽写入、启动槽切换和首次启动确认。见[固件更新实现](platform-runtime.md#固件更新)。

## 10. 休眠与恢复

休眠协调器冻结非必要请求，等待或取消有界工作，确认必要呈现与保存，结束网络，再通过 BSP 设置唤醒来源。请求开始时固定恢复来源；提示呈现后才开始网络和存储收尾；取消须等在途刷新和 worker 交还资源。网络失败不能无限阻止休眠；保存失败有独立分支。无卡时用内置字体显示提示；不自动格式化挂载失败的介质。输入与硬件交接规则见[平台适配](platform-runtime.md#tf-卡和电源)，锁屏资源见[自定义锁屏](platform-runtime.md#自定义锁屏)。

## 11. 词典

- `reader_dictionary` 在 host 与固件编译同一实现，复用 `reader_document` 的 miniz；`Dictionary` 由单一执行者持有，文件操作同步执行。
- 扫描、索引准备、查询和读取义项都在内容 worker 内执行；同一时刻只打开一套词典，任务发布完成前关闭全部文件；请求与结果不借用正文、字体或画布。
- 索引、解压缓冲、单条字段和分页游标都有固定上限，超限明确失败；解析与解压循环检查取消，单次 TF 读取不能抢断。
- 已验证的索引摘要按挂载作用域保存在 `DictionarySession`，重新扫描、USB 和换卡替换该会话。
- 应用只接收当前查询代次和正文位置的结果；关闭面板先恢复正文底图，旧任务完成后再释放资源。
- 长按选词使用触摸 Move 事件；采样队列最多保留一个移动通知，Begin／End／Cancel 不合并；刷新忙时只更新待呈现选区。

## 12. 工程组织

`firmware/main` 调用 `reader_runtime` 入口；`firmware/board` 选择板级配置；`firmware/components` 包含共享组件与平台适配；`tools/host` 提供桌面运行入口；`tools` 包含构建、验证与诊断工具；`tests` 包含合成样本、对照和故障注入。第三方代码锁定版本并记录许可与修改。只有完成可运行实现与对应测试，模块才算交付。
