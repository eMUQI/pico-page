# 公开发布检查

本文维护以新仓库、单个初始提交公开源码的迁移步骤。旧仓库历史留作私有存档，不随源码工作树公开。文件整理、构建通过与公开发布是不同状态。

## 本地整理

- 当前代码许可为 GPL-3.0-or-later，附加 ESP-IDF 二进制库链接许可；保留各第三方组件声明，分发义务见[许可说明](../../LICENSING.md)与[依赖审查](dependency-review.md)。水波纹按维护者提供的官方允许使用确认原样保留。
- 历史交接清单、旧文档归档、设备过程记录及未引用截图不进入公开工作树。当前文档引用的合成画面放在 `docs/images/`，原始设计保持不变。
- 公开状态集中在[开发状态](../development-status.md)。性能报告仅保留匿名或合成样本、必要测量条件及其限制；设备身份、备份摘要、凭据和私人正文仅保留在私有证据中。
- `python3 tools/check_handoff.py` 检查公开文档和示例，不依赖私有交接清单。

## 发布前仍需核对

- `docs/design/original/reference/*.dc.html` 及配套脚本属于设计工具导出资料；公开前核对适用导出条款和资源权利，不从文件存在或本项目 GPL 推定第三方授权。
- 逐组件完成二进制分发义务核对，准备与发布固件对应的完整源码、补丁、构建步骤及必要安装资料；保留 FreeType、epdiy、字体、Unicode 与网站素材的独立声明。组件清单用 `esp-idf-sbom` 按发布构建生成，2026-11-06 的清单与许可核对见[依赖审查](dependency-review.md#固件-sbom-组件清单2026-11-06)；随固件发布的许可汇编尚未生成。
- 扫描待导出的工作树及图片元数据。上游版权邮箱、公开作者邮箱和明确的合成测试凭据可以保留；实际凭据、设备身份、本机绝对路径和个人书籍不得进入公开提交。未提供私人书库目录时，不宣称已完成与私人书库逐本比对。
- CI 继续使用现有私有 runner，是否切换及切换时机由维护者另行决定，不作为本次整理或发布的前置条件。仓库迁移时核对 runner 的仓库关联、工作流触发范围和 PR 权限。

## 仓库与发布迁移

下列步骤涉及远端仓库、权限或生产发布，须由维护者明确授权并在每步完成后独立读回。

1. 保存私有源仓库、需要迁移的 Issue、正式 Release 附件及部署配置。确认最终源码工作树没有私有资料；本机快照不得复制进公开目录。
2. 将原仓库改名并保持私有，再创建目标公开仓库。导出已审阅的工作树，在独立空目录初始化 Git，仅创建一个初始提交；作者使用 `wulu <wulu@wulu.zone>`，核对作者、提交者和文件清单。不要推送原私有历史。
3. 在导出目录准备固定资源，执行 host Debug／CTest、固件构建、文档回归及文档检查。核对实际注册测试、版本来源与有效配置；单提交导出会改变来源记录，不能把旧提交构建的固件标成新提交构建。
4. 迁移当前正式版本的 Release，保留原附件字节与来源声明，核对清单、镜像长度和 SHA-256。使用[版本管理](versioning.md)与[固件托管](firmware-hosting.md)中的现行流程，不重用过时的 SSH 部署步骤。
5. 按新仓库的实际身份更新 GitHub OIDC 信任条件、上传角色和 Pages 配置。新建同名仓库的仓库 ID 会变化，不能仅凭名称沿用旧主体；核对 `tools/cos-publisher-trust.json`、工作流中的角色配置及最小权限。私有仓库原 Secrets 不会因同名新建而自动迁移。
6. 推送后检查 Actions，确认普通 PR 只执行验证，只有受信任 main／Release 能发布。确认源码可匿名访问后，再添加网站源码与完整许可入口。完成固件上传和网站部署后，独立读回官网清单、安装页、更新日志和部署标识，与正式 Release 附件比较。
7. 按需迁移仍有效的问题，修正文档中旧仓库的 Issue／PR 引用，确认不再暴露私有历史后再结束迁移。

本地整理完成不代表上述远端步骤已经执行，也不替代设备或实际 KOReader 验收。
