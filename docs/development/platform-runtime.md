# Read Pico 运行时适配

平台适配位于 `firmware/components/platform_read_pico/`；阅读用例由 `reader_app` 完成，ESP-IDF 应用循环与任务交接由 `reader_runtime` 编排。本页维护平台接口、资源交还、锁屏与 OTA 的运行规则；当前验证结果和待验收项统一见[开发状态](../development-status.md)。

## 接口与所有权

`platform_contract` 的 `pico_page/platform.h` 聚合按能力拆分的接口；板级构建选择单个 Read Pico 实现。`initialize()` 记录显示和输入的调用任务，`present()`、`poll()`、`refresh_card()` 和 `sleep()` 拒绝其他任务调用。显示提交为同步调用；调用方必须在返回前保持输入像素不变。平台层不持有阅读锚点、不保存进度、不解释 K2 的产品动作。网络接口另有独立的单一任务所有者，可由工作任务串行调用，避免阻塞显示和输入任务。

| 接口 | 当前行为 |
|---|---|
| `initialize(error)` | 初始化官方 EPD 板级后端、PMU、工厂 VCOM、触摸和 TF；TF 错误不阻止错误页面显示 |
| `display_info()` | 无需初始化即可返回 684 × 1216 竖屏尺寸，不访问硬件或分配缓冲；运行入口先核对应用画布再初始化应用／呈现 |
| `panel_ready()` | 指示显示驱动是否已取得有效工厂 VCOM 并完成缓冲初始化；不代表物理显示已验收 |
| `card_mount_path()` | 返回配置路径 `/sdcard`，不表示挂载成功或授权访问 |
| `card_root()` / `card_error()` | 返回当前有效的 `/sdcard` 挂载点或空指针及原因 |
| `refresh_card(error)` | 调用方关闭所有文件后显式重新挂载；无格式化路径 |
| `present(packed, size, full_clean, error)` | 接收 684×1216 竖屏 4bpp 帧，执行波形并报告驱动返回值和电源状态 |
| `presentation_gate` | 面板帧与网络接收步骤的原子门控，可在任意任务使用。面板扫描期间接收 Wi-Fi 数据会使驱动的行队列欠载，HTTPS 工作任务和传书接收循环只在取得网络侧后读取；待呈现帧优先于下一次读取 |
| `poll(event, error)` | 按下、释放、取消及电源短按、长按、拔卡事件；无事件时返回 `EventKind::None` |
| `finish_power(error)` | 调用方停止全部文件消费者后关闭面板电源并尝试卸载 TF 卡；失败不恢复读写 |
| `power_off(error)` | 校验 PMU 主机 EN 控制能力，暂停触摸并停放 IO 扩展器后调用官方协作关机接口；失败时恢复外设并返回原因，文件保持关闭 |
| `battery()` | 返回最近一次有效 PMU 状态快照；读失败时 `valid=false` |
| `set_performance(high)` | 持有或释放 CPU 最高频率锁；释放后空闲频率为 80 MHz。`present()` 总是先恢复最高频率 |
| `sleep(error)` | 关闭面板高压，配置睡眠 GPIO，停放 IO 扩展器并使触摸深睡；ESP32-S3 浅睡返回后先恢复扩展器，再复位触摸 |

平台在第一次调用浅睡 API 前保存 USB Serial/JTAG 的引脚与电阻配置，关闭上拉、下拉和 USB 引脚功能。ESP-IDF 6.1 会在每次浅睡返回时恢复入睡前的引脚状态，因此保存关闭状态可避免周期 PMU 事件处理期间重新连接电脑；同一次逻辑睡眠的后续尝试沿用首次快照。最终结束睡眠后，在释放触摸锁后恢复原电阻、软件覆盖和引脚配置；触摸或电源清理失败也执行恢复。只有至少一次浅睡调用返回 `ESP_OK` 才标记已睡眠，并保证断开间隔不少于 100 ms；计入睡眠及清理耗时，仅等待不足部分。准备阶段在浅睡 API 前取消不操作 USB；仅被拒绝或失败的尝试恢复原配置，不追加重连等待，不能据此保证 SDK 硬件交接期间没有短暂断开。现有串口句柄需重新打开。USB 已持有 TF 卡时平台拒绝休眠，原本关闭的串口 PHY 保持关闭，不在 TinyUSB MSC 模式操作 Serial/JTAG PHY。电脑恢复连接的实际效果仍待真机验证。

`initialize()` 的非 TF 错误返回 `false`。工厂值不可读时，屏幕保持断电，此时只能通过日志报告错误。触摸初始化失败但 `panel_ready()` 为真时，调用方可以显示错误页。初始化失败后不能在同一次启动中重复分配 BSP；修复条件后需要重新启动。

## 初始化和校准

适配层直接组合锁定 BSP 的公开入口，不调用 `read_pico_init()`。初始化顺序为：

1. `epd_init()` 运行官方板级初始化。IO 扩展器自检期间 SY_EN 和 VCOM_EN 保持低电平。
2. `read_pico_pmu_init()` 建立 PMU 协议和主机就绪握手；系统时间尚未设置时，尝试读取有效 RTC 恢复 UTC 时间，失败仅记录日志。
3. 最多三次 `read_pico_pmu_vcom_get()` 读取工厂 VCOM；上游验证有效标志、500–2500 mV 范围和 10 mV 步长。
4. 将读取结果交给 `sy7636a_set_vcom()`。此时电源未启用，仅更新显示电源驱动的 RAM 配置。
5. 初始化官方波形和显示缓冲；首次 `present()` 才开启面板高压。

官方 `board_init()` 中的 1290 mV 是传给 `sy7636a_init()` 的 RAM 默认值；后者只注册 I2C 设备并配置低电平输出，不启用面板、不写 VCOM 寄存器。适配层在第一次上电前用工厂值替换它。没有调用 `read_pico_pmu_vcom_set()`、工厂校准页、PMU 配置写入或标定保存入口。

板级自检和 EPD 缓冲分配仍使用上游 `ESP_ERROR_CHECK` / `assert`；这些底层失败会中止启动，不能由适配层转换为屏幕提示。

## RTC 与系统时间

沿用官方 BSP `5f3406deec33304de8801046db583dec7c49e55b` 的 CW32 PMU 协议：`TIME_GET` 返回 UTC Unix 秒及 `time_synced`，`TIME_SYNC` 接收 4 字节小端 UTC 秒。启动时只有系统时间早于 2024-01-01 才读取 RTC；本次命令成功、响应为 OK、`time_ok` 为真、`time_synced` 为 1，且时间在 2024-01-01 至 2099-12-31 范围内才调用 `settimeofday()`。保留已有有效系统时间，不以较旧 PMU 值覆盖。响应长度校验应用于构建副本，见 [BSP 审查](bsp-review.md#rtc-响应校验与接入2026-10-11)。

STA 取得 IP 后，由既有网络 worker 初始化 SNTP，连接和传书不等待校时。明确的「校准」请求沿用 Wi-Fi 操作槽与取消标志，复用或按配置建立 STA 后重新启动 SNTP，最多等待 10 秒新的同步信号；已有有效系统时间不能替代本次成功。超时、取消和初始化失败均不设置虚构时间，TLS 调用仍可使用已有有效时间。临时连接完成后释放，手动保持的连接继续保留；不增加任务、队列、联网重试或定时刷屏。

SNTP 回调只设置一个原子待写标志，不访问 PMU。应用主循环在网络工作结束、无待处理输入或显示、无内容或保存任务、必要进度已保存且空闲至少 2 秒后，调用 `persist_clock()`；USB、休眠请求和电源菜单期间不执行。写入使用执行时的系统时间，不使用排队前的旧秒值。成功响应后读取 RTC，确认有效且与提交值相差 0–4 秒才记录成功；失败仅记录日志并结束本次尝试，下一次真实 NTP 回包可再次触发。不新增任务、队列、配置文件或 NVS 状态，不改变阅读进度。立即关机或一直没有空闲边界时，待写值可能尚未落入 RTC。

PMU 命令仍由应用任务串行执行。每次尝试最多调用一次 `TIME_SYNC` 和一次 `TIME_GET`，沿用 BSP 内部最多三轮命令重试及每次 I²C 调用 100 ms 超时；它们是不可抢断的同步调用，不能把空闲门槛视为响应时限。正常命令各含 30 ms 等待，故写入与读回至少包含两次等待；故障时可能明显延长，实际耗时、内部重试、输入队列压力和内存峰值仍待真机验证。主循环开始写回后出现的新输入由原输入采样队列保留。

官方 PMU 文档注明复位后 `time_synced=0`，LSI 约有 ±1–2% 误差；接入 RTC 不构成完全断电保时或长期精度保证。ESP32 浅睡沿用系统时钟，不在每次唤醒重复读取 PMU。PMU 失效时仍能离线阅读；无有效系统时间时页脚显示「—」，网络流程继续按原规则要求可用时间才进行 TLS。

## 像素、刷新和输入

契约只描述调用语义；当前 Read Pico 的 Gray16 使用默认 GL16 的 37 相，Gray8 使用 30 相的 8 级 GL16，全清理使用 GC16。`hold_unchanged_footer` 的当前布局边界是竖屏 `y >= 1128`，正文更新与方向效果保留该区域相同非白像素，白→白仍按源波形维护；清屏和恢复忽略保持标志。该边界随显示配置适配，不能从当前契约推断其他分辨率已可用。

网络 worker 在持有显示／Flash 锁时成对调用 `guard_flash_io()`，避免 Flash cache 暂停打断触摸、PMU 和卡检测的 I²C 事务。输入采样器在接触附近加快采样、空闲时由中断唤醒；Flash 操作或休眠持有控制器锁时暂停。K1/K2/K3 在平台事件里是逻辑辅助键标识，Read Pico 将下方电容区域映射到它们。`TouchMoves` 只合并当前序列的移动事件，由采样队列锁序列化；应用长按、轻扫和休眠输入规则由 `reader_input` 解释。

输入帧每行 342 字节，偶数 x 位于低半字节，奇数 x 位于高半字节，0 为黑色、15 为白色。平台将竖屏坐标变换为官方 1216×684 原生缓冲：`native_x = y`、`native_y = 683 - x`，对应上游 `EPD_ROT_INVERTED_PORTRAIT`。触摸控制器的显示区坐标直接采用竖屏坐标。

首次呈现、上次刷新失败后的恢复和 `full_clean=true` 均调用 `epd_clear_checked()` 的物理黑白清理周期，再执行 `MODE_GC16` 全像素更新。该路径禁用前导保持跳过，不检查图像是否相同。普通更新按请求使用全屏或限定区域，正文波形可选择默认波形或 Gray8；全刷与恢复始终建立完整基准。每次更新检查面板 PGOOD、故障状态、VCOM 读回值和波形返回值；失败后基准帧失效，下次执行清理恢复。健康供电下发生行队列欠载时，把像素时钟降为 12 MHz，并对同一目标最多执行一次清屏和 GC16 重画；仅在恢复成功后确认呈现，重试失败则报告失败。

构建时应用的 epdiy 补丁提供 `epd_clear_checked()`，适配层检查清屏和后续 GC16 的结果及电源状态；仍无法读取像素确认成像，真机检查不可省略。默认时钟为官方初始化使用的 18 MHz。更新后 8 秒无新帧时，由 `poll()` 关闭面板高压。

三个电容键不是 ESP32 GPIO 按键，识别区域来自同一 commit 的 `main/ui/ui_menu.h`：触摸原始 y ≥ 1300，K1/K2/K3 的 x 分别为 `[0,160)`、`[160,320)`、`[320,480)`。显示区为 x < 684、y < 1216；中间未定义区域不触发动作。这些边界来自上游硬件实现，尚未在用户设备上实测。

一次触摸序列仅有一个递增序号，不生成长按或自动重复。多点触摸、跨越按键区域和 I2C 读取失败取消当前序列，并等待全部释放后重新接收输入。开机、拔卡、电源动作和唤醒期间也等待释放，避免输入尾部进入下一页面。拔卡或电源事件打断已有序列时，先返回该序列的 `Cancel`，下一次轮询再返回系统事件。I2C 失败时，调用方仍需处理随失败返回的 `Cancel`。

## TF 卡和电源

普通挂载使用 `read_pico_sd_start_probe()` / `read_pico_sd_remount()`，保持上游的 SDMMC 接线、超时重试及介质失效锁存。挂载最多等待 5 秒。`read_pico_sd_get_info()` 检测移除后，即使卡重新插入也要求显式重新挂载。普通探测不创建目录、复制演示资源或格式化；上游的演示目录创建仅属于格式化函数，适配层不调用它。卡移除检查间隔为 500 ms；文件读写自身的错误仍由 `store` / 内容层处理。

睡眠前调用方必须完成显示事务、进度保存及网络停止。当前采用保留 RAM 和挂载状态的浅睡，不切断主电源、不进入 ESP 深睡、不重新挂载仍有打开文件的介质。触摸芯片深睡期间，触摸和 K1/K2/K3 都不承担唤醒；唤醒来源仅为 PMU 电源键通过官方 `READ_PICO_IOE_INT_GPIO` 传播的中断。PMU 有未确认事件时一直拉低 CW_INT（FCA9555 P0.2），运行期约每 30 秒的电池采样等非按键事件也会唤醒 ESP32-S3；此时先确认全部 PMU 事件，再读 IO 扩展器清中断，因为 CW_INT 释放本身也是一次输入变化。清中断后再读一次 PMU 队列：若有事件在确认与清中断之间到达，CW_INT 会保持低电平且不再产生新边沿，浅睡将无法再被唤醒，因此队列不为空时继续处理。进睡前的空闲检查使用同一判断。没有电源键事件时重新浅睡；唤醒后读取 PMU 失败时每 20 ms 重试，中断线或 PMU 队列 2 秒内仍不空闲、或 PMU 仍读取失败才报告睡眠失败。`esp_light_sleep_start()` 在唤醒线已为低时返回 `ESP_ERR_SLEEP_REJECT`，平台按立即唤醒处理并等待 20 ms，不当作睡眠失败。按 D43，触摸队列、待处理触摸中断和触摸 IRQ 电平在第一次入睡前及入睡后均不取消休眠；板级交接在采样器锁内清空触摸队列，抑制当前接触直至释放，再设置触摸芯片待机。触摸芯片深睡后须复位才恢复，真机上每次浅睡唤醒都会在其中断线（GPIO43）记录一次下降沿，这类信号只计数，不作为 PMU 唤醒源。唤醒后先恢复触摸，并消费唤醒按键的后续事件。休眠返回约 1 秒后，`poll()` 输出一行 `Light sleep:` 汇总，包含唤醒次数、被拒次数、PMU 重试次数、触摸线边沿与低电平次数、首个 PMU 错误和结束原因；更早的输出落在 USB 重新枚举之前，电脑收不到。

取消锁屏后，主循环先恢复页面并排空准备期间的触摸和电容键，不保留或重放这些接触，只保留电源键意图。长按请求菜单时，如果原网络工作任务或无线电尚未退出，保留菜单意图并继续屏蔽输入，等待安全交还后打开菜单，不中断仍持有文件和无线电的任务；菜单若还在等待页脚恢复或锁屏 worker，屏蔽保持到菜单显示。Wi-Fi 重连请求须等页面恢复与电源意图处理完成；电源菜单及其资源等待阶段继续保留请求，取消菜单后才可派发。加速度计只初始化并关闭采样，不启用拿起唤醒。读取电池失败、PMU 未设置电池有效位或电量超出协议范围时，不把快照作为有效电量；没有新增电量校准或 PMU 阈值设置。

### 睡眠 GPIO 与外设恢复

`SleepIo` 在应用任务、既有触摸采样锁内执行，调用方先等待显示与文件任务结束并处理保存结果。BSP 探卡／挂载工作仍忙时拒绝浅睡，忙状态独立于拔卡后的错误快照；没有其他生产者能在这次主任务交接期间重新启动探卡。浅睡前只改墨水屏时钟／控制／数据线及 TF CLK（GPIO38）的睡眠方向、下拉和 SLP_SEL，运行时 SDMMC 配置不变；没有新增卸载、重新挂载或卡供电切换。电源键、触摸中断及 I²C 引脚不在下拉清单中。仅在真正进入 ESP 浅睡时切换为睡眠配置，唤醒后由硬件恢复运行配置；配置失败则不入睡。

面板电源关闭且 SY_EN／VCOM_EN 输出锁存均为低时，先完整读取并保存 FCA9555 输出及方向；读失败或 PMU／PGOOD／卡检测方向不符时拒绝停放。触摸深睡后，Port1 输出锁存先置高，再改为输出；面板 MODE 拉低。浅睡保持 CW_INT 输入，沿用既有 PMU 确认、清中断及队列复查协议；仅最终关机把 CW_INT 预置低后改为输出，不能用于浅睡。

直接写扩展器期间不调用 BSP 的输出设置器，保留其运行期输出缓存。取消、唤醒、准备失败及 PMU 关机失败都先恢复保存的方向与输出，再通过 BSP 复位触摸；恢复 CW_INT 输入后才允许恢复其输出锁存，避免驱动 PMU 中断线为高。失败写入可能已生效，因此保留原快照，不能从半停放状态重新取样；恢复失败保留待办，采样器跳过控制器读取，呈现与轮询在锁内重试，恢复完成前不操作面板。触摸复位失败同样保留重试状态。成功终止关机后外设继续停放，主循环不恢复应用工作。

本批沿用 `5f3406deec33304de8801046db583dec7c49e55b` BSP 与原有五个补丁，另加只读的 SD 忙状态补丁，低功耗方案移植自上游 `a2a63a6a2c606540be72156a6567392d948d65fc`，来源和许可见 [BSP 审查](bsp-review.md#2026-10-26--睡眠-io-停放移植)。无新任务、队列或文件访问；正常路径不分配堆内存，错误信息沿用 `std::string`，寄存器快照和触摸恢复状态固定大小。额外事务沿用 FCA9555／CST836U 驱动的 100 ms I²C 超时，触摸复位包含 10 ms 低电平及 50 ms 启动等待；单次驱动调用不可取消，新增步骤不构成整条休眠路径的硬时限。资源与功耗的真机结果按 PW02／PW04 验收，host 故障注入不证明实际电流改善。

### 电源键菜单与关机、重启（2026-10-08）

PMU `KEY_LONG` 打开菜单，`KEY_SHORT` 仍进入浅睡；同次长按的重复及后续短按被消费。启动或唤醒时先等待电源键释放，不改 PMU 阈值。持续按住仍可能触发硬件强制关机。网络、USB、诊断传输或内容任务进行中提示先结束任务。菜单取消恢复原页面、草稿和同步候选。菜单的打开、取消、本地保存失败页和「先结束任务」提示使用不清屏的整屏更新；帧呈现失败后显示基准失效，下一帧按全刷重画。关机、重启的结果画面仍全刷。

触摸采样器随释放事件携带本次接触的坐标范围；电源菜单要求所有已采样位置都在原按钮内，滑出后再移回也取消。派发仍等待松手；呈现前开始的输入及打开菜单时已按住的输入被消费。点击关机/重启直接保存 TF 卡上的已呈现位置和最近阅读记录，不启动云端同步、不再二次确认。本地保存失败仅提供「仍然关机/重启」和「返回」。此时未清除同步状态，返回后原同步操作仍有效。保存成功或明确跳过后，停止内容工作、尝试全刷结果画面、关闭文档与字体，再尝试卸载 TF 卡。最终呈现或卸载失败不恢复应用，也不阻止 `esp_restart()` 或 PMU 断电请求。`finish_power()` 即使卸载失败也关闭面板电源；所有文件消费者停止后才允许继续断电。

关机使用 `PMU_CAP_HOST_EN_CONTROL` 与锁定 BSP 的 `read_pico_pmu_power_off()`：`HOST_REQUEST_OFF` → `SHUTDOWN_READY`，BSP 自带 logical-off 回退和有界轮询。不支持或命令失败时，以内置字体尝试呈现硬件关机提示，保留真实的本地保存结果；随后关闭面板电源，停止应用及存储操作，不重新挂载 TF 或恢复阅读现场。USB 供电下命令成功仍可能保持主机供电，因此成功后同样停止应用工作。

长按响应时间、硬件强制关机时序、真实断电电流、USB 供电表现与重启恢复仍待设备验收。

## 显式网络会话

`connect_network()`、`http_request()`、`disconnect_network()` 在独立网络任务中串行执行。应用先显示连接状态，再分派用户明确发起的同步请求。打开书籍、翻页和启动不会自动联网。睡眠前应用必须等待网络任务结束并断开网络，不在传输中切断其对象或电源。

小响应 HTTPS 请求共用 25 秒单调时钟期限；GET 遇连接、响应头或未完成响应的传输失败时，关闭旧连接、丢弃部分响应，等待 250 ms 后最多重试一次，不重新开始期限。HTTP 错误状态、超限响应和本地校验失败不重试；PUT／POST 不自动重发，发送后失败仍要求重新查询远端。取消会结束等待和后续尝试，但不能抢断正在执行的 SDK 调用／TLS 清理，因此该期限不是整条路径的严格墙钟保证。失败诊断只记录阶段、错误码和 socket errno，不记录 URL、凭据或正文。

`connect_network()` 接收网络名称和密码，不读文件。应用在分派同步/手动连接前读取目标凭据快照；网络 worker 使用应用传入的凭据快照；`PicoPage/network.toml` 的解析在 host 上有测试。最多保存 5 个网络，名称不重复：

```toml
schema_version = 2
selected_ssid = "YOUR_2_4_GHZ_NETWORK" # 指定只连这个网络；省略本行或写空串表示自动

[[wifi]]
ssid = "YOUR_2_4_GHZ_NETWORK"
password = "YOUR_NETWORK_PASSWORD"
last_connected = 1791300000   # 可选：最近一次连上的 Unix 秒数，设备记录

[[wifi]]
ssid = "ANOTHER_NETWORK"
password = ""                 # 开放网络
```

旧格式 `schema_version = 1` 加单个 `[wifi]` 表仍可读取，按一个没有连接时间的条目处理；设备下次写入该文件时改为 schema 2。文件不存在表示未配置。上面仅为格式说明，没有创建含凭据的工作区文件。该文件包含明文秘密，不属于普通阅读配置或公开示例，应从 Git、诊断导出和常规分享备份中排除。`integrations.toml` 仍只放非敏感配置；账户凭据由同步模块的独立本地文件管理。读取限制为 4 KiB，只接受上述两种结构；内容无效时设备不改写该文件，解析错误不输出原文或解析器片段。Wi-Fi 驱动使用 RAM 配置并关闭 NVS 保存，不把密码写入 Flash；断开时释放 Wi-Fi 驱动。

连接方式由 `network.toml` 根字段 selected_ssid 决定（D37）：
- 没有该字段、字段为空串，或所写名称已不在已保存网络中：**自动**。worker 扫描一次（最多 10 秒），用 `provision::connection_order()` 取出在附近的已保存网络，按信号从强到弱逐个连接，第一个连上的就用。附近没有已保存网络时不尝试连接。全部失败时先报密码被拒的那个网络，其次报最后一次失败。
- 字段为已保存的网络名：**指定**。只连这个网络，不扫描、不改用其他网络；失败后由用户选择重试或本次改用自动。
- 已经在线时（手动保持或同步事务未结束），新任务直接使用当前连接，不重新选网。

添加网络不写 selected_ssid；忘记被指定的网络时把它写成空串，即回到自动。连接候选在应用任务上从 TF 卡读出并复制进请求；worker 不为选网读卡。成功连接仍可更新末项和有效时间下的 last_connected（至少相差一小时），不修改连接方式。同步/手动连接的历史记录由应用在无卡写任务的空闲边界提交；连接、TLS 和等待用户决定不持有 TF 文件。设备界面和电脑脚本（`tools/setup_network.py`）修改时都保留注释、原文和连接方式，不会因为添加或更新网络而指定它；不支持安全修改的语法或提交前的外部变更会拒绝写入。旧固件不识别 selected_ssid，会拒绝配置；并且旧固件把缺少该字段的文件理解为「使用末项」。降级前需备份并处理此字段。

自动方式的最长等待：一次扫描 10 秒，加上每个候选最多 20 秒（最多 5 个）。扫描与每次连接之间都检查取消标记。

worker 保留两类原子取消标记：手动保持、完整同步事务；没有使用者时停止驱动。GET 成功后保留至用户处置，最多两分钟；PUT 复用同一事务，结束/失败/取消后释放，手动保持不受影响。worker 串行处理请求，持有无线时每 200 ms 检查标记、期限和连接丢失；无线已释放时阻塞等待新队列消息；手动保持只重连原网络一次，不重新扫描，失败等待用户操作。热点期间手动保持意图暂停，退出不新建 STA；点「立即连接」才恢复。休眠/关机清除全部标记并等待 radio_active 归零。状态快照队列最多四个指针，满时删除最旧累积快照；UI 消费最新状态，不轮询 RSSI 或按秒重绘。网络任务仍为 16 KiB 栈、优先级 3、无固定亲和性；请求/响应队列各一项，无新增任务。

关联/取得 IP 的等待限时为 20 秒；按关联事件区分连接超时与 DHCP 超时。同步请求随后最多等待 10 秒 SNTP 时间同步（`synchronize_clock()`），默认服务器为 `pool.ntp.org`。每次连接首次校时即使已有 RTC 时间，也等待真实 NTP 回包；同一连接已成功校时后不再重复等待。超时而已有有效系统时间时允许继续 HTTPS，仍启用证书日期校验；没有可用系统时间时拒绝 HTTPS。只有真实 NTP 回包触发 RTC 写回，单纯连接 Wi-Fi、保存凭据或 RTC 恢复不会冒充网络校时成功。扫描、连接与对时的事件等待每 100 ms 检查取消；扫描总等待上限 10 秒。驱动初始化/停机和已有连接断开的最多 2 秒等待不由此抢断。经已保存 Wi-Fi 传书只在局域网内传输，不等待对时。此版本支持开放网络或 WPA2 及以上个人网络，不提供企业认证。失败时 `ConnectFailure` 给出停在哪一步（启动、关联、取地址、对时）和驱动原因编号。连接失败显示实际驱动原因编号，不按 SSID 猜测频段或密码错误。worker 另把失败归为三类交给界面（`LinkFailure`）：不在附近（驱动原因 201、210–212）、密码被拒（2、14、15、202、204）、其他。界面只用它决定下一步的按钮，例如只有密码被拒时主按钮才是「重新输入密码」。

HTTP 只接受 HTTPS GET/PUT/POST，使用 ESP-IDF 系统证书包和主机名验证，不自动跟随重定向。mbedTLS 的动态内存从 PSRAM 分配（`CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC`），因为主内部堆容不下常驻的 Wi-Fi 驱动再加一个 TLS 会话；设备未启用 Flash 加密，PSRAM 中的会话数据不加密。自签证书服务在未安装可信证书前会失败，当前没有关闭 TLS 验证的入口。请求体最大 16 KiB，响应体最大 32 KiB，头字段数量和值长度也有限制。连接/头部操作有 10 秒 I/O 超时，读取操作使用最多 5 秒 I/O 超时，并在操作之间检查 25 秒会话期限；期限检查不会强杀正在执行的驱动调用。传输失败清空不完整响应；HTTP 状态码由同步层单独解释。失败的 PUT/POST 可能已经由服务端处理，调用方必须保留「结果待确认」状态，不能直接重试覆盖。调用方可以传入共享原子取消标志。工作任务在连接、发送和读取边界检查它，不会从其他任务关闭仍在使用的 HTTP 对象。取消不能撤销已经到达服务端的写入，也不会强制中断正在进行的驱动调用。

## 在设备上添加网络和验证账户

手机配置会话已删除（D37）；`start_portal_server()`、配置网页和表单解析不再存在。流程和界面见 [Wi-Fi、键盘与同步](ui-implementation.md#wi-fi键盘与同步)。

- 扫描：`WifiOperation::Kind::Scan`。worker 启动站点接口并扫描一次，返回最多 20 个名称、信号强度和是否开放，随后释放无线。
- 添加或更新密码：`WifiOperation::Kind::Join`。worker 用键盘输入的凭据建立一条独立连接，成功或失败后都释放无线。应用任务只在连接成功、且用户没有取消时，用 `save_network_edit()` 把网络写入 `network.toml`，并记录连接时间。取消后迟到的成功结果按请求编号丢弃，不写卡。已满 5 个时只接受已保存网络的密码更新。
- 立即连接：`WifiOperation::Kind::Connect`，按连接方式选网，成功后由手动保持标记维持到断开或休眠。
- 验证同步账户：与同步请求走同一条路径（联网、对时、`GET /users/auth`）。应用任务只在返回 200 时写 `sync.toml`；401/403、其他状态码、联网失败和取消都不写。密码明文只在本次流程的内存中，写入的是它的 MD5。
- 移除同步账户：确认后删除 `PicoPage/sync.toml`（`FileStore::remove_private()`），不联网。

键盘输入期间不使用无线，也不读写 TF 卡。密码草稿在流程结束、休眠或成功保存后清除。

## Wi-Fi 传书会话

- 经设备热点：`start_access_point()` 以 APSTA 模式开启热点，名称为 `PicoPage-` 加 MAC 末两字节，WPA2，每次会话随机生成 8 位密码，最多 2 台设备，地址 192.168.4.1；另有一个任务在 UDP 53 端口把所有 A 记录查询答为热点地址。`start_upload_server()` 在 `GET /` 提供传书页，其他路径 303 跳转到它。
- 经已保存的 Wi-Fi：按连接方式选网，已经在线时复用当前连接；不开热点，也不运行名称服务。会话中若站点连接失效，传书服务结束，设备返回「网络与传输」并显示断线原因。`start_upload_server()` 只在 `GET /<6 位随机路径>` 提供传书页，其余路径返回提示页；设备屏幕的二维码和文字地址都包含这段路径。连接失败时不进入会话页，网络页显示原因。
- 两种方式都在页面中注入本次会话的 32 位十六进制令牌；`POST /check`、`POST /upload` 必须带该令牌。拒绝时按原因返回状态码：400（文件名）、409（同名，或 `LockScreens/` 已满）、413（大小）、415（格式）只涉及这一个文件，传书页继续下一个；403（会话无效）、500、503、507 等停下整批。
- 上传/校验 handler 在有效令牌鉴权后及处理结束时通过回调记录单调活动时间及阶段；无效令牌、已取消或正在停服的请求不更新活动时间，两者与 worker 的到期检查共用会话锁。即使短请求在两次轮询间完成也重新计时；handler 运行时不按空闲到期，结束后 10 分钟无活动才结束服务。传书会话暂停自动休眠；电源键请求休眠时结束会话，先由文件事务回滚或完成提交，stop_portal_server() 返回后才释放网络及卡。取消/失败不增加已保存数；已进入提交边界的完整文件仍以真实提交结果为准。
- 停服由单一网络 worker 执行，不持有会话锁。`httpd_stop()` 返回失败时保留服务器句柄、回调上下文及其锁，拒绝新上传，每秒重试；只有 SDK 确认 handler 已退出才清除借用状态并返回。重复启动也先完成旧服务停服，注册失败沿用同一收尾。持续失败时 worker 保持停服流程，不释放网络或卡，不发出已结束事件；SDK 内部等待与重试均无总时限。依据固定 ESP-IDF v6.1 的 `httpd_main.c`，停止失败发生在发送关闭命令前，句柄仍有效；成功返回前等待 HTTP 任务退出。
- 目标目录和大小上限由 `portal_server.cpp` 中按扩展名的表决定：书籍 `Books/` 64 MiB，字体 `Fonts/` 32 MiB，锁屏图片 `LockScreens/` 2 MiB。接收和回读的缓冲与文件大小无关（2048 字节栈缓冲、4096 字节堆缓冲）；接收循环每次 `httpd_req_recv()` 前取得 `presentation_gate` 的网络侧，待呈现帧或刷新进行中时不读取，由 TCP 流控让发送端等待，面板刷新结束后继续；发送端停滞时，单次读取最多占用门控 `recv_wait_timeout`（5 秒），随后该次上传失败；锁屏图片另在 HTTP 任务中列一次目录，文件名列表在堆上。提交阶段的同步和两次回读不检查取消，耗时随文件大小增长。
- 每个文件提交并回读校验后，HTTP 任务回调网络任务，设备状态区更新为「已保存 N 个文件 · 最近：文件名」。文件名过长时设备截短显示；完整的逐个结果可在浏览器中查看。会话结束后，应用任务重新列出 `Fonts/` 并让自定义休眠图片重新准备。

预算（按输入上限推得，未在真机测量）：HTTP 任务栈 8 KiB，DNS 任务栈 4 KiB（其中收发缓冲 528 字节），网络任务沿用原有 16 KiB；二维码两个 407 字节缓冲。Wi-Fi 驱动在 APSTA 下和 TLS 握手占用的内部 RAM 没有数字，必须在真机上读 `status` 的 `internal`、`largest_internal`。固件比版本 E 增加 103,008 字节。

已知限制：连接其他信道的网络时热点会跟着换信道，手机可能短暂掉线；连接等待可取消，但驱动调用、HTTP I/O 和文件提交期间只能在返回后的安全边界退出。热点密码在射频开启前生成，`esp_random()` 此时是伪随机数，另混入了点击时刻。

## 书籍封面休眠

进度保存和后台资源交还完成后，应用释放正文位图、预读、统计与书库缩略图缓存，并复用图片路径按缺口裁剪字形缓存。封面 worker 沿用正文图片的冷解码预算，输出画布按目标尺寸检查最大连续块，EPUB 图片读取按实际压缩图大小检查内存；不按允许的最大图片大小预留连续块。资源不足仍回退书名，下次休眠请求重新尝试。

已声明的封面图片发生暂时读取或内存分配失败时，保留该错误，不继续用正文探测结果将其改判为无封面。休眠封面使用 `PPCOVER4` 缓存头，使旧版误写的无封面记录重新生成；不改书籍、配置或进度。

有效热缓存以 16 KiB 分块读入独占输出画布，不再同时保留整份缓存字符串。冷解码与热缓存均向应用移交已完成的图片；应用校验任务代次、当前书籍和有效休眠请求后接收，绘制阶段不再读 TF 缓存。可选缓存提交失败不丢弃本次图片，取消、唤醒和图片使用结束后释放输出。冷路径保留输出、缩放后的解码像素和实际大小的压缩图片；缓存提交前释放压缩图片，提交仍可能使用一份输出大小的序列化缓冲。684×1040 的单份输出为 355,680 字节。

书籍封面与自定义图片共用 20 秒取消预算及后台文件所有权协议，单次 TF 读取、写入与同步不能抢断，该预算不代表整个休眠流程的耗时上限。验证边界见 [PW05](acceptance.md#显示电源和设计)；应用休眠画面、实体浅睡与电源键唤醒分别记录。

## 自定义锁屏

本节维护锁屏文件、缓存、准备预算与失败回退；控件和布局见[自定义锁屏界面](ui-implementation.md#自定义锁屏)。实际验收状态见[开发状态](../development-status.md)。

- 将 PNG、JPG、JPEG 放入 TF 卡根目录 `LockScreens/`，在「设置 → 电源与休眠 → 自定义图片 → 选择图片 / 轮播」选择模式，返回后保存设置。
- 仅扫描根目录，不递归；忽略隐藏文件和符号链接。最多 256 张图片、2048 个目录项，超出时提示整理目录，不使用不完整列表。按文件名的 UTF-8 字节顺序轮播，建议使用 `01-`、`02-` 前缀。
- 原图上限 2 MiB、单边 4096 像素、总计 8 百万像素；建议直接使用 684×1216 图片。等比缩放居中，不裁切。默认透明区域和空白区域填白；开启「叠加当前画面」且 PNG 含透明像素时，两者均保留底图。不透明 PNG 和 JPEG 的空白区域仍填白。全屏显示图片，不另叠加书名、页码或唤醒文字。
- 「叠加当前画面」只在自定义图片模式显示，默认关闭；设置通过全局 `power.sleep_overlay` 布尔值保存，指定图片和轮播共用，单书不可覆盖。选图与开关只修改草稿，点击「保存设置」生效；「预览」按当前草稿显示，开启叠加时以进入预览前的设置画面为底，顶部和底部保留预览操作区。预览不推进轮播，失败返回电源页显示提示。
- 全局 `power.sleep_screen="custom"` 启用；`power.sleep_image=""` 表示轮播，非空时为 `LockScreens/` 下的图片文件名。单书不能覆盖。锁屏成功呈现后，文件名先保留在内存；下一次锁屏任务（唤醒后的空闲预准备，或下一次休眠准备）把它保存到 `PicoPage/data/last-lock-screen.txt`，再选择下一张，休眠前不等待这次保存。保存失败只写诊断日志，由后续任务重试；保存前重启或断电，下次重复显示一张。重启后从已保存的文件名之后继续，清缓存不重置记录。
- 转换使用现有内容 worker，在清醒且空闲时准备下一张，只保留 `PicoPage/cache/lockscreens/current` 一张转换缓存；缓存使用 `PPLOCK4`：无透明像素时保持 4 位灰阶；含透明像素的 PNG 保存灰度 8 位与 Alpha 8 位，最大载荷 1,663,488 字节，单份约 1.59 MiB，原子替换期间旧缓存加临时文件约 3.18 MiB，不随历史文件名累积。旧缓存按需重建；缓存与叠加开关无关，开关切换可直接复用。原图不修改，缓存通过原图 SHA-256、文件名、大小、修改时间、转换版本及像素摘要校验。
- 开启叠加时，在显示空闲、必要保存及旧 worker 交还后，将当前画面复制到独立锁屏输出缓冲；正文底图清除整条阅读页脚，书库和设置底图恢复准备提示前的页脚；该缓冲随后由内容 worker 独占，主画布和在途帧均不修改。worker 在读取块、目标行和缓存提交前检查取消和剩余预算，混合后转换为 16 级灰阶；完成后移交主应用显示，取消或失败丢弃未呈现输出。PNG 保留整张画布的透明留白，不自动去白、不加阴影。
- 休眠时先保存进度、交还背景资源，再读取原图摘要并校验缓存；缓存缺失、损坏或原图改变时，由内容 worker 补做转换。轮播按顺序跳过确定损坏、空文件、格式不支持或超限的图片，最多检查一轮；指定模式不替换为其他图片。取消、超时、内存不足、读卡失败与原图在转换期间改变均停止本次尝试，不当作坏图继续扫描。
- 准备共用 20 秒取消预算，包括等待在途自定义图片任务及后续缓存读取、转换和轮播候选；空闲预准备同样最多 20 秒。空闲预准备每轮最多尝试 3 次，失败后至少间隔 5 秒，耗尽后等待显式休眠、预览、设置变化、唤醒或存储会话重置；显式休眠仍保留自己的准备机会。失败类别控制重试及坏图跳过，诊断文案不参与判断。请求被接受后，先在原页页脚显示一次「正在准备休眠，按电源键取消」，提示呈现后再执行网络和存储收尾及图片准备，保留其余画面和交互上下文。从请求休眠到进入浅睡（含立即休眠与自动休眠），仅再短按电源键取消；触摸和 K1/K2/K3 均忽略，K2 不全刷，不把这些输入重放到原页。长按电源键仍请求电源菜单；取消时恢复页脚，等待在途刷新与 worker 交还资源后打开菜单。提示最多暂存 30,096 字节页脚像素，资源不足或缓冲分配失败时省略提示；不新增 worker、栈或整屏快照。正在执行的 TF I/O 和存储提交须安全退出，预算不是整条休眠路径的硬上限。
- 转换成功但缓存提交失败时，本次仍显示已准备的图片，下次重新准备；原因只写诊断日志，不显示提示。目录为空、指定图片不存在、轮播全部不可用或预算内无法准备时，才使用简洁屏保；此时唤醒后的原页面只显示一次页脚结果提示，不进入通用错误页、不取消正文图片准备；具体原因保留在诊断日志。休眠请求开始时固定唤醒目的地，从书库休眠仍回书库，从正文休眠恢复正文；锁屏失败和提示不得改变目的地。暂不新增图片格式或更改官网图集。

### 锁屏执行与资源

冷 PNG 逐块读取并将最终采样直接合成到独占画布，透明缓存只用行缓冲写入临时文件；不保留整份压缩图或整屏透明层，Adam7 重访行由临时文件承接。冷缓存轮播可能在部分合成后发现坏图，因此保留未修改的背景，并为当前候选使用一份 415,872 字节输出；下一候选从原背景重新开始，避免重复叠加。指定图片和有效热缓存直接复用背景输出。输入块为 4,096 字节、缓存行 1,368 字节、行标记 1,216 字节，解码后回读与不透明压缩另使用 8 行共 10,944 字节缓冲，减少 TF 小块读写，不新增任务或栈；源坐标表按已验证尺寸有界分配，沿用 pngle 的扫描行与字典。源文件单次读取、行读写和最终同步不能抢断，完成前的任何失败均不提交显示。

提示保留期间暂缓接收会替换原页的后台结果；取消恢复仅向原来源页恢复暂存像素，不覆盖已出现的错误或网络收尾页面。休眠目的地在请求开始时固定，不在准备重入时重算。绘制与显示完成回调不扫描、解码或提交文件；等待页脚刷新与 worker 交还后再打开已请求的电源菜单。

### 分区与前提

当前 `expected_image()` 校验 ESP32-S3 芯片标识、合法镜像／应用描述头、与正在运行的固件一致的 `project_name` 及请求版本；前缀共 288 字节。镜像本身没有独立板卡身份校验，manifest 的 `board` 检查不能防止未来两块同芯片、同项目名设备的镜像被错误配置到同一渠道。支持第二块板前须补镜像身份和兼容迁移设计；本轮保持项目名与 OTA 路径不变。

- 分区布局为 `firmware/partitions.build.csv`：`ota_0`、`ota_1` 两个 4 MiB 应用槽和 `otadata`，与第一台设备出厂时读回的布局条目相同。升级只写入另一个槽，再切换启动槽；联网更新不修改分区表、bootloader、NVS 或工厂 VCOM/PMU 校准。
- 电脑安装按 D41 使用 release 全量镜像：擦除整片闪存后从 `0x0` 写入本项目 bootloader、分区表和应用，NVS 与 otadata 保持擦除状态，从 `ota_0` 启动。其他固件可能采用不同布局，只写应用不能保证槽位置、容量和回滚前提。安装与恢复仍按 INST01–INST03 逐项验收，历史成功不代表完整验收。
- 没有整片安装、仍保留出厂 bootloader 和分区表的设备，`ota_1` 中现有的内容未确认。第一次升级会覆盖它，首次真机验证前需读取并记录该槽的应用信息。
- 全量镜像由 `tools/ota_manifest.py --full` 合并，脚本核对其中的 bootloader（ESP32-S3、16 MiB 闪存）、分区表（`ota_0` 位于 `0x10000`、两个 4 MiB 槽、有 otadata）和应用（与联网更新镜像逐字节相同）。不要直接使用构建日志输出的烧录参数。
- 开发时只写应用仅适用于分区表与 `partitions.build.csv` 一致的设备。设备经联网更新切换到 `ota_1` 以后，写入前必须读取 otadata 确认当前启动槽，并写入该槽；只写 `0x10000` 不再保证更新正在运行的固件。
- 应用槽为 4 MiB。新固件必须小于槽容量，安装前按清单中的大小和实际分区大小各检查一次，不沿用历史剩余比例。

### 联网更新

请求带序号，取消后迟到结果丢弃；显示失败沿用恢复流程，只有实际显示完成才推进呈现序号。

- 入口为「设置 → 固件更新」。用户点「检查更新」后设备才联网读取清单，用完按现有规则断开。没有保存 Wi-Fi 时按钮改为「先设置 Wi-Fi」，Wi-Fi 开关关闭时改为「先打开 Wi-Fi」，两者都进入 Wi-Fi 设置。
- 缓存在 TF 卡上的清单只用于显示。需要联网复核时，更新首页或更新日志页的安装入口在 Wi-Fi 已关闭或没有保存网络时进入 Wi-Fi 设置，不发出检查或下载请求。本次开机后没有从服务器读到过清单时，点「下载并安装」先重新读取一次：服务器给出的仍是同一个镜像时，按最新清单检查是否需要数据格式确认，确认完成或无须确认后才下载；有变化则显示新的清单并要求再次确认。下载地址和摘要因此始终来自服务器，不来自卡上的文件。
- 清单是一份 JSON：`manifest`（格式版本，目前为 1）、`board`（`read_pico`）、`version`、`published_at`、`url`、`size`、`sha256`、`data_schema`（`progress`、`config` 两个整数）和 `notes`（Markdown 更新日志）。清单只描述一个版本。格式不符、`board` 不符或版本带构建元数据时，按读取失败处理。清单由 `tools/ota_manifest.py` 生成，随镜像作为 GitHub Release 附件，不提交到仓库；发布与部署按[固件托管](firmware-hosting.md)校验。没有任何发布时清单地址返回 404，设备提示「更新服务器上还没有发布固件」。
- 版本比较按[版本管理](versioning.md)的规则：清单版本不高于当前版本时显示「已是最新版本」，不提供降级。当前是开发构建（版本带 `+`）时无法比较，界面写明后允许换成清单中的发布构建。
- 安装条件按顺序判断：电量不低于 20% 或正在充电，电量读数无效且未充电时不安装；没有同步、传书或书籍加载在进行；清单的 `data_schema` 任一项低于本机时拒绝安装，否则任一项高于本机时需要用户在下载前确认，取消后不下载。本次检查和缓存联网复核均遵守此规则，开发构建保留说明且不豁免确认，格式未提高时不增加确认。本机的进度格式版本为 2（进度记录用 1，清除进度的标记用 2），配置为 1。R8 实现后，电量下限改用 R8 的提醒值。
- 下载时边收边写入空闲的应用槽，不经过 TF 卡。写入前先核对镜像开头的芯片型号、项目名 `pico_page` 和版本；写完核对长度、整个文件的 SHA-256，并由 ESP-IDF 校验写入槽内的镜像摘要。任一项不符就丢弃，启动槽不变。下载期间不休眠，电源键短按不响应；可以在屏幕上取消。
- 下载读取允许连续 30 秒无数据，收到数据后重新计时；临时读取超时继续轮询，连接失败或正文提前结束时最多追加 3 次重连，探测、预擦除后的建连及续传中的失败共用该重连预算，并保留 20 分钟下载执行时限。重连只从同次调用内已成功交给 OTA 句柄的字节偏移继续，使用 HTTP Range，并要求响应为 `206`、`Content-Range` 的起点与总长度及剩余正文长度均匹配；忽略 Range、范围不符或摘要不符时终止。整个镜像仍只做一次累计 SHA-256 校验，不保存重启后的下载状态。取消或退出后不再续传。SDK 建连单步仍可能阻塞至 10 秒，清理须等待显示与网络门控交还，不能把轮询间隔当作整条路径的取消时限。
- 校验通过后由用户点「重启并安装」。此时再次检查电量，不满足时不重启。设备先保存阅读位置，再切换启动槽，切换成功后才写入安装记录并重启。安装记录因此只在新固件确实获得过一次启动机会时存在；启动槽没有切换成功，或在切换之前断电时，重启后仍是当前固件，不提示启动失败，也不跳过该版本。选「稍后」时不切换启动槽；已校验的镜像只在本次开机期间有效，关机或重启后需要重新下载。
- 新固件首次启动时，板级初始化、应用初始化和首屏显示都成功后才确认有效；确认写入失败时立即放弃该镜像并回到旧固件。无卡或挂载失败不计入（2026-10-12 用户确认）。确认前复位、断电或任一步失败，bootloader 回到旧固件。
- 重启后显示一次结果：安装成功时显示版本和更新日志；回到旧版本时提示更新没有完成，并跳过这个版本，直到清单出现更高的版本；清单改为另一个高于当前固件的版本时照常提供。安装记录和已跳过的版本保存在 `PicoPage/cache/update.json`，「清理全部缓存」会一并清除。

### 资源与时限

- 执行上下文：检查和下载都在网络工作任务上运行，显示和输入仍由应用任务处理。进度每 5% 局部刷新一次。
- 内存：下载使用一块 4 KiB 的内部 RAM 缓冲和 4 KiB 的 HTTP 接收缓冲；TLS 会话沿用现有配置，从 PSRAM 分配。TCP 接收窗口为 32 KiB，接收邮箱为 25 项，每个连接的接收内存仍有界。清单响应沿用现有的 32 KiB 上限，更新日志只保留前 8 KiB。
- Flash 操作与面板刷新互斥：先验证首段的芯片、项目和版本并关闭探测连接，再按 64 KiB 块预擦除镜像占用范围（尾部向上对齐且不超过槽大小），块间让出调度并检查取消；擦除后重新建连，再次核对首段身份，之后按最多 4 KiB 写入。擦除、写入和最终镜像回读校验均持有既有显示/Flash 锁，并通过既有输入锁与完整 I²C 事务错开，期间输入采样及轮询可能延后。下载期间暂时关闭 Wi-Fi 省电，结束时恢复原模式。
- HTTPS 与显示通过原子门控错开：待呈现帧优先于下一次 SDK 传输调用；应用任务遇到在途调用时保留待呈现帧，继续处理输入并在后续主循环重试。握手、请求头、响应头及正文均经此门控，显示失败沿用原有恢复流程，不改变波形、供电、任务优先级或 TLS 内存位置。
- 取消与时限：连接使用 10 秒等待配置；连接建立后改为 50 毫秒 socket 轮询，重试间检查取消和阶段截止时间，下载读取的无数据等待预算为 30 秒，整次下载预算仍为 20 分钟。50 毫秒不是 DNS、TLS 计算或整条取消路径的硬上限；已进入的 SDK 调用及单个 Flash 块操作须返回后才能观察取消。休眠提示仍需呈现后才开始网络收尾。
- 失败回退：任何失败或取消都不改启动槽，当前固件继续使用；空闲槽留下不可启动的内容，下次下载时重写。
- 同设备、同镜像的局域网与公网耗时、内存采样和显示回归记录见 [历史开发状态](../archive/development-status-20261024.md) 的 2026-10-18「OTA 吞吐与 HTTPS 显示互斥」。状态采样最低余量不等于瞬时峰值内存，有限样本不替代长时间稳定性验证。

### 失败恢复

- 整片安装的设备使用本项目 release 构建的 bootloader，回滚由 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` 提供。没有整片安装的设备仍是出厂 bootloader：2026-10-12 对设备原始 bootloader 备份反汇编，启动槽选择函数包含把新镜像标为待确认、把未确认即复位的镜像标为放弃的写入。两种 bootloader 的回滚都没有在真机上验证。
- 新固件卡住而没有复位时，bootloader 不会自行介入。用户长按电源键强制断电后再开机，设备回到旧固件。
- 两个槽都无法启动时，恢复方法是用 USB 连接电脑重新整片安装。芯片 ROM 的下载模式不依赖闪存中的内容。
- 升级不修改 TF 卡上的书籍、配置和进度。新固件读取旧版本的配置文件时，按现有 schema 规则兼容。
- 新固件在被确认有效之前，不得把配置、进度或书签迁移到旧固件不能读取的新 schema。需要迁移时，在确认有效之后进行，或保留旧固件仍能读取的版本，确保回滚后可以继续阅读。

### 安全说明

- 设备未启用 Secure Boot，固件不验证发布者签名。清单中的 SHA-256 只能发现传输或写入错误；能控制下载地址或其域名的人可以安装任意固件。文档必须说明这一点。发布签名等后续范围见[路线图 R11](../planning/roadmap.md#r11--ota-升级)。

验收：见 [验收](acceptance.md) OTA01–OTA06。真机记录升级前后的启动槽与版本。
