# Read Pico 运行时适配

平台适配位于 `firmware/components/platform_read_pico/`；阅读用例由 `reader_app` 完成，ESP-IDF 应用循环与任务交接由 `reader_runtime` 编排。本页说明平台接口、硬件约束、资源交还、锁屏与 OTA 的运行规则。页面行为见[界面说明](ui-implementation.md)，验证状态见[开发状态](../development-status.md)，具体超时、缓冲大小和边界值以源码为准。

## 接口与所有权

`platform_contract` 的 `pico_page/platform.h` 聚合按能力拆分的接口，板级构建选择单个 Read Pico 实现。`initialize()` 记录显示和输入的调用任务，`present()`、`poll()`、`refresh_card()` 和 `sleep()` 拒绝其他任务调用。显示提交是同步调用，调用方在返回前必须保持输入像素不变。平台层不持有阅读锚点、不保存进度、不解释 K2 的产品动作。网络接口有独立的单一任务所有者，由工作任务串行调用。

| 接口 | 语义 |
|---|---|
| `initialize(error)` | 初始化官方 EPD 板级后端、PMU、工厂 VCOM、触摸和 TF；TF 错误不阻止显示错误页 |
| `display_info()` | 无需初始化即可返回竖屏尺寸，不访问硬件 |
| `panel_ready()` | 显示驱动已取得有效工厂 VCOM 并完成缓冲初始化；不代表物理显示已验收 |
| `card_mount_path()` / `card_root()` / `card_error()` | 配置路径、当前有效挂载点或空指针及原因 |
| `refresh_card(error)` | 调用方关闭所有文件后显式重新挂载；没有格式化路径 |
| `present(...)` | 接收竖屏 4bpp 帧，执行波形并报告驱动结果和电源状态 |
| `presentation_gate` | 面板帧与网络接收步骤的原子门控，见下文 |
| `poll(event, error)` | 按下、释放、取消，电源短按、长按和拔卡事件 |
| `finish_power(error)` | 调用方停止全部文件消费者后关闭面板电源并尝试卸载 TF；失败不恢复读写 |
| `power_off(error)` | 校验 PMU 主机 EN 控制能力，停放外设后调用官方协作关机；失败时恢复外设并返回原因 |
| `battery()` | 最近一次有效 PMU 状态快照；读失败时 `valid=false` |
| `set_performance(high)` | 持有或释放 CPU 最高频率锁；`present()` 总是先恢复最高频率 |
| `sleep(error)` | 关闭面板高压、配置睡眠 GPIO、停放 IO 扩展器、触摸深睡，然后 ESP32-S3 浅睡 |

`initialize()` 的非 TF 错误返回 `false`。工厂 VCOM 不可读时屏幕保持断电，只能通过日志报告。触摸初始化失败但 `panel_ready()` 为真时，调用方可以显示错误页。初始化失败后不能在同一次启动中重复分配 BSP，修复后需重启。

## 初始化和校准

适配层直接组合锁定 BSP 的公开入口，不调用 `read_pico_init()`：

1. `epd_init()` 运行官方板级初始化，IO 扩展器自检期间 SY_EN 和 VCOM_EN 保持低电平。
2. `read_pico_pmu_init()` 建立 PMU 协议和主机就绪握手；系统时间尚未设置时尝试从 RTC 恢复。
3. 最多三次 `read_pico_pmu_vcom_get()` 读取工厂 VCOM，上游校验有效标志、范围和步长。
4. 把读取结果交给 `sy7636a_set_vcom()`；此时电源未启用，只更新驱动的 RAM 配置。
5. 初始化官方波形和显示缓冲；首次 `present()` 才开启面板高压。

官方 `board_init()` 中的 1290 mV 只是 `sy7636a_init()` 的 RAM 默认值，不写 VCOM 寄存器；适配层在第一次上电前用工厂值替换。项目不调用 `read_pico_pmu_vcom_set()`、工厂校准页或任何 PMU 标定写入。板级自检和 EPD 缓冲分配沿用上游 `ESP_ERROR_CHECK` / `assert`，这些失败会中止启动，无法转换为屏幕提示。

## RTC 与系统时间

沿用锁定 BSP 的 CW32 PMU 协议：`TIME_GET` 返回 UTC Unix 秒及 `time_synced`，`TIME_SYNC` 接收 4 字节小端 UTC 秒。启动时只有系统时间早于 2024-01-01 才读取 RTC；命令成功、`time_ok` 为真、`time_synced` 为 1 且时间在 2024–2099 年范围内才调用 `settimeofday()`，不以较旧的 PMU 值覆盖已有有效时间。响应长度校验以补丁形式应用于构建副本，见 [BSP 审查](bsp-review.md#构建补丁)。

STA 取得 IP 后由网络 worker 初始化 SNTP，连接和传书不等待校时。主动校准复用或按配置建立 STA，启动一次新的 SNTP 并在等待预算内接收新样本；worker 检查取消后才应用样本，临时连接结束后释放。

每次成功应用 SNTP 样本后以原子变量通知应用任务。应用主循环在网络工作结束、无待处理输入或显示、无内容或保存任务、必要进度已保存并空闲一段时间后，才写入 RTC 和 TF 卡。RTC 写入后读回确认；TF 卡记录通过 store 提交，休眠、关机或移交 USB 前在必要保存后也会尝试提交。SNTP 回调不访问 PMU 或 TF 卡；写入失败只记录日志，下次有效回包后再写。

PMU 命令由应用任务串行执行，沿用 BSP 内部的命令重试和 I²C 超时；它们是不可抢断的同步调用，空闲门槛不是响应时限。主循环开始写回后出现的新输入由输入采样队列保留。

PMU 复位后 `time_synced=0`，LSI 有约 ±1–2% 误差；RTC 不提供完全断电保时或长期精度保证。浅睡沿用系统时钟，不在每次唤醒读取 PMU。没有有效系统时间时拒绝 HTTPS。

## 像素、刷新和输入

当前 Gray16 使用默认 GL16，Gray8 使用 8 级 GL16，全清理使用 GC16。`hold_unchanged_footer` 的边界随当前显示布局确定，不能推断其他分辨率已可用；清屏和恢复忽略保持标志。

输入帧为竖屏 4bpp，偶数 x 在低半字节，0 为黑、15 为白。平台把竖屏坐标变换到官方原生缓冲，对应上游 `EPD_ROT_INVERTED_PORTRAIT`；触摸控制器的显示区坐标直接采用竖屏坐标。

首次呈现、上次刷新失败后的恢复和 `full_clean=true` 调用 `epd_clear_checked()` 的物理黑白清理周期，再执行 `MODE_GC16` 全像素更新，不检查图像是否相同。普通更新按请求使用全屏或限定区域。每次实际面板更新都检查 PGOOD、故障状态、VCOM 读回值和波形返回值；失败后基准帧失效，下次执行清理恢复。健康供电下发生行队列欠载时，降低像素时钟并对同一目标最多执行一次清屏和 GC16 重画，恢复成功才确认呈现。

普通更新在像素转换后比较驱动的目标缓冲与已确认缓冲；基准有效且整帧相同时直接返回成功，不开启高压、不扫描，仍经成功回调完成，使相同像素对应的新正文锚点可以确认。比较在既有显示事务内执行，不新增任务、堆分配或整屏副本。区域更新后只以驱动实际提交的像素为基准。

`epd_clear_checked()` 来自构建时应用的 epdiy 补丁。驱动无法读取像素确认成像，光学效果必须在真机检查。更新后一段时间无新帧时，由 `poll()` 关闭面板高压。

三个电容键不是 GPIO 按键，识别区域来自上游 `main/ui/ui_menu.h`：触摸原始 y 坐标超过显示区的下方区域按 x 分为 K1/K2/K3，中间未定义区域不触发动作。显示区以外、按键以外的位置不产生事件。

网络 worker 持有显示／Flash 锁时成对调用 `guard_flash_io()`，避免 Flash cache 暂停打断触摸、PMU 和卡检测的 I²C 事务。输入采样器在接触时加快采样、空闲时由中断唤醒；Flash 操作或休眠持有控制器锁时暂停。`TouchMoves` 只合并当前序列的移动事件；长按、轻扫和休眠输入规则由 `reader_input` 解释。

一次触摸序列只有一个递增序号，平台不生成长按或自动重复。多点触摸、跨越按键区域和 I²C 读取失败取消当前序列，并等待全部释放后再接收输入；开机、拔卡、电源动作和唤醒期间同样等待释放。系统事件打断已有序列时，先返回该序列的 `Cancel`，下一次轮询再返回系统事件。

## TF 卡和电源

普通挂载使用 `read_pico_sd_start_probe()` / `read_pico_sd_remount()`，保留上游的 SDMMC 接线、超时重试和介质失效锁存。`read_pico_sd_get_info()` 检测到移除后，即使卡重新插入也要求显式重新挂载。普通探测不创建目录、不复制演示资源、不格式化。文件读写错误由 `store` 和内容层处理。

休眠前调用方必须完成显示事务、进度保存和网络停止。当前采用保留 RAM 和挂载状态的浅睡，不进入深睡，不重新挂载仍有打开文件的介质。触摸芯片深睡期间触摸和 K1/K2/K3 不承担唤醒，唤醒源只有 PMU 电源键经 `READ_PICO_IOE_INT_GPIO` 传播的中断。

PMU 有未确认事件时持续拉低 CW_INT（FCA9555 P0.2），周期性的电池采样等非按键事件也会唤醒芯片。处理顺序必须是：先确认全部 PMU 事件，再读 IO 扩展器清中断（CW_INT 释放本身也是一次输入变化），然后再读一次 PMU 队列。若有事件在确认与清中断之间到达，CW_INT 会保持低电平且不再产生边沿，浅睡将无法被唤醒，因此队列不空时继续处理；进睡前的空闲检查使用同一判断。没有电源键事件时重新浅睡；中断线或 PMU 队列持续不空闲、或 PMU 持续读取失败才报告睡眠失败。唤醒线已为低时 `esp_light_sleep_start()` 返回 `ESP_ERR_SLEEP_REJECT`，按立即唤醒处理，不当作失败。

触摸芯片深睡后须复位才能恢复；每次浅睡唤醒都会在触摸中断线上出现一次下降沿，只计数，不作为唤醒源。板级交接在采样器锁内清空触摸队列并抑制当前接触直至释放；触摸队列和触摸中断不取消休眠（D43）。唤醒后先恢复触摸，并消费唤醒按键的后续事件。休眠返回约 1 秒后 `poll()` 输出一行 `Light sleep:` 汇总（唤醒、拒绝、PMU 重试、触摸线边沿、首个错误和结束原因）；更早的输出落在 USB 重新枚举之前，电脑收不到。

USB Serial/JTAG：第一次调用浅睡 API 前保存其引脚与电阻配置并关闭上拉、下拉和 USB 引脚功能。ESP-IDF 6.1 每次浅睡返回时恢复入睡前的引脚状态，保存关闭状态可避免周期 PMU 事件期间重新连接电脑；同一次逻辑睡眠沿用首次快照。最终结束睡眠后，在释放触摸锁后恢复原配置；只有至少一次浅睡返回 `ESP_OK` 才保证断开足够时间，让主机识别重新枚举。浅睡 API 前取消不操作 USB。USB 已持有 TF 卡时拒绝休眠，不在 TinyUSB MSC 模式操作 Serial/JTAG PHY。现有串口句柄需重新打开。

取消休眠后，主循环先恢复页面并排空准备期间的触摸和电容键，只保留电源键意图。长按请求菜单时，若网络任务或无线电尚未退出，保留菜单意图并继续屏蔽输入，安全交还后再打开菜单。Wi-Fi 重连请求等页面恢复与电源意图处理完成后才派发。加速度计只初始化并关闭采样，不启用拿起唤醒。PMU 未设置电池有效位或电量超出协议范围时，不把快照当作有效电量。

### 睡眠 GPIO 与外设恢复

`SleepIo` 在应用任务、触摸采样锁内执行，调用方先等待显示与文件任务结束并处理保存结果。BSP 探卡或挂载工作仍忙时拒绝浅睡。浅睡前只改墨水屏时钟、控制、数据线及 TF CLK 的睡眠方向、下拉和 SLP_SEL；运行时 SDMMC 配置、卡供电和挂载状态不变。电源键、触摸中断和 I²C 引脚不下拉。只在真正进入浅睡时切换为睡眠配置，配置失败则不入睡。

面板电源关闭且 SY_EN、VCOM_EN 输出锁存均为低时，先完整读取并保存 FCA9555 的输出与方向；读失败或关键方向不符时拒绝停放。触摸深睡后 Port1 先置高再改为输出，面板 MODE 拉低。浅睡保持 CW_INT 为输入；只有最终关机才把 CW_INT 预置低后改为输出，浅睡不能这样做。

直接写扩展器时不调用 BSP 的输出设置器，保留其运行期输出缓存。取消、唤醒、准备失败和 PMU 关机失败都先恢复保存的方向与输出，再通过 BSP 复位触摸；恢复 CW_INT 输入后才恢复其输出锁存，避免把 PMU 中断线驱动为高。失败的写入可能已生效，因此保留原快照，不从半停放状态重新取样；恢复失败保留待办，恢复完成前不操作面板。成功关机后外设保持停放。

该方案移植自上游 `a2a63a6a2c606540be72156a6567392d948d65fc`，另加只读的 SD 忙状态补丁，来源见 [BSP 审查](bsp-review.md#睡眠-io-停放)。不新增任务、队列或文件访问；额外寄存器事务沿用驱动的 I²C 超时，单次驱动调用不可取消，新增步骤不构成整条休眠路径的硬时限。

### 电源键菜单与关机、重启

PMU `KEY_LONG` 打开菜单，`KEY_SHORT` 进入浅睡；同次长按的重复及后续短按被消费。启动或唤醒时先等待电源键释放，不改 PMU 阈值；持续按住仍可能触发硬件强制关机。网络、USB、诊断传输或内容任务进行中时提示先结束任务。菜单相关画面使用不清屏的整屏更新，呈现失败后基准失效；关机、重启的结果画面全刷。

触摸采样器随释放事件携带本次接触的坐标范围，菜单要求所有采样位置都在原按钮内。选择关机或重启后直接保存已呈现位置和最近阅读记录，不启动云端同步。本地保存失败时只提供「仍然关机／重启」和「返回」，返回后原同步状态仍有效。保存成功或明确跳过后，停止内容工作、尝试全刷结果画面、关闭文档与字体，再尝试卸载 TF 卡；最终呈现或卸载失败不恢复应用，也不阻止 `esp_restart()` 或断电请求。所有文件消费者停止后才允许断电。

关机使用 `PMU_CAP_HOST_EN_CONTROL` 与 BSP 的 `read_pico_pmu_power_off()`（`HOST_REQUEST_OFF` → `SHUTDOWN_READY`，含 logical-off 回退和有界轮询）。不支持或命令失败时，以内置字体显示手动关机提示并保留真实的保存结果，随后关闭面板电源、停止应用和存储操作，不重新挂载或恢复现场。USB 供电下命令成功仍可能保持主机供电，因此成功后同样停止应用工作。

## 显式网络会话

`connect_network()`、`http_request()`、`disconnect_network()` 在独立网络任务中串行执行，只服务用户明确发起的操作；打开书、翻页和启动不联网。休眠前应用等待网络任务结束并断开网络，不在传输中切断其对象或电源。

`connect_network()` 接收名称和密码，不读文件；应用在分派前读取凭据快照传给 worker。`PicoPage/network.toml` 最多保存 5 个不重名的网络：

```toml
schema_version = 2
selected_ssid = "YOUR_2_4_GHZ_NETWORK" # 指定只连这个网络；省略本行或写空串表示自动

[[wifi]]
ssid = "YOUR_2_4_GHZ_NETWORK"
password = "YOUR_NETWORK_PASSWORD"
last_connected = 1791300000   # 可选：最近一次连上的 Unix 秒数，设备记录

[[wifi]]
ssid = "ANOTHER_NETWORK"
password = ""                 # 开放网络
```

旧格式 `schema_version = 1` 的单个 `[wifi]` 表仍可读取，设备下次写入时改为 schema 2。该文件含明文密码，应排除在 Git、诊断导出和分享备份之外；同步凭据单独保存在 `PicoPage/sync.toml`。内容无效时设备不改写文件，解析错误不输出原文。Wi-Fi 驱动关闭 NVS 保存，不把密码写入 Flash，断开时释放驱动。设备界面和 `tools/setup_network.py` 修改时都保留注释与连接方式；无法安全修改的语法或提交前的外部变更会拒绝写入。旧固件不识别 `selected_ssid` 并会拒绝该配置，降级前需处理此字段。

连接方式由 `selected_ssid` 决定（D37）：

- 字段缺失、为空串或名称不在已保存网络中：**自动**。扫描一次，用 `provision::connection_order()` 取出附近的已保存网络，按信号从强到弱逐个连接，第一个成功的即采用；附近没有已保存网络时不尝试。全部失败时优先报告密码被拒的网络。
- 字段为已保存的网络名：**指定**。只连该网络，不扫描、不改用其他网络。
- 已在线时（手动保持或同步事务未结束），新任务直接使用当前连接。

添加网络不写 `selected_ssid`；忘记被指定的网络时把它写成空串。连接候选由应用从 TF 卡读出复制进请求，worker 不读卡；连接时间在无卡写任务的空闲边界提交。扫描和每次连接之间都检查取消。

worker 保留两类原子取消标记：手动保持和完整同步事务，没有使用者时停止驱动。GET 成功后连接保留至用户处置（有时限），PUT 复用同一事务。手动保持只重连原网络一次，不重新扫描。热点期间手动保持意图暂停，退出后不自动新建 STA。休眠和关机清除全部标记并等待无线电退出。状态快照队列有界，满时丢弃最旧的累积快照；界面只消费最新状态，不轮询 RSSI。

关联和取得 IP 分别计时，区分连接超时与 DHCP 超时。同步请求随后等待一次真实 NTP 回包（默认 `pool.ntp.org`），同一连接已成功校时后不再等待；超时而已有有效系统时间时允许继续 HTTPS 并校验证书日期。只有真实 NTP 回包触发 RTC 写回。经已保存 Wi-Fi 传书只在局域网内传输，不等待校时。支持开放网络和 WPA2 及以上个人网络，不支持企业认证。`ConnectFailure` 给出失败阶段（启动、关联、取地址、校时）和驱动原因编号；`LinkFailure` 把失败归为不在附近、密码被拒和其他三类，界面只用它决定下一步按钮，不按 SSID 猜测原因。

HTTP 只接受 HTTPS GET／PUT／POST，使用 ESP-IDF 系统证书包和主机名验证，不跟随重定向，没有关闭 TLS 验证的入口。mbedTLS 动态内存从 PSRAM 分配（`CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC`），因为内部堆容不下常驻 Wi-Fi 驱动加 TLS 会话；设备未启用 Flash 加密，PSRAM 中的会话数据不加密。请求体、响应体、头字段数量和长度都有上限。小响应请求共用一个单调时钟期限；GET 的传输失败关闭旧连接、丢弃部分响应后最多重试一次，不重新开始期限；HTTP 错误、超限和本地校验失败不重试。PUT／POST 不自动重发，发送后失败要求重新查询远端。取消在连接、发送和读取边界检查，不能撤销已到达服务端的写入，也不抢断正在执行的 SDK 调用，因此期限不是整条路径的墙钟保证。失败诊断只记录阶段、错误码和 socket errno，不记录 URL、凭据或正文。

`presentation_gate` 让面板帧与网络接收步骤互斥：面板扫描期间接收 Wi-Fi 数据会使驱动行队列欠载，因此 HTTPS 工作任务和传书接收循环只在取得网络侧后读取，待呈现帧优先于下一次读取。

## 在设备上添加网络和验证账户

流程和界面见 [Wi-Fi、键盘与同步](ui-implementation.md#wi-fi键盘与同步)。

- 扫描：`WifiOperation::Kind::Scan`，扫描一次后释放无线。
- 添加或更新密码：`WifiOperation::Kind::Join`，用键盘输入的凭据建立独立连接，结束后释放无线。应用只在连接成功且用户未取消时用 `save_network_edit()` 写入 `network.toml`；取消后迟到的成功结果按请求编号丢弃。
- 立即连接：`WifiOperation::Kind::Connect`，按连接方式选网，由手动保持标记维持到断开或休眠。
- 验证同步账户：与同步请求同一路径（联网、校时、`GET /users/auth`），只有返回 200 才写 `sync.toml`，写入密码的 MD5。
- 移除同步账户：删除 `PicoPage/sync.toml`（`FileStore::remove_private()`），不联网。

键盘输入期间不使用无线，也不读写 TF 卡。

## Wi-Fi 传书会话

- 设备热点：`start_access_point()` 以 APSTA 模式开启 WPA2 热点，名称为 `PicoPage-` 加 MAC 末两字节，每次会话随机生成密码，限制连接数；另一任务在 UDP 53 把所有 A 记录查询答为热点地址。`start_upload_server()` 在 `GET /` 提供传书页，其他路径跳转到它。热点密码在射频开启前生成，此时 `esp_random()` 是伪随机数，因此另混入点击时刻。
- 已保存的 Wi-Fi：按连接方式选网或复用当前连接，不开热点、不运行名称服务；传书页只在随机路径下提供，屏幕上的二维码和地址包含该路径。站点连接失效时结束服务并显示原因。
- 两种方式都在页面中注入本次会话的随机令牌，`POST /check`、`POST /upload` 必须携带。只涉及单个文件的拒绝（文件名、同名或目录已满、大小、格式）返回对应状态码，传书页继续下一个；会话无效或服务器错误停止整批。
- 有效令牌的上传和校验请求在鉴权后及结束时记录活动时间，无效令牌不延长会话；handler 运行时不按空闲到期，结束后一段时间无活动才结束服务。传书会话暂停自动休眠；电源键请求休眠时结束会话，文件事务回滚或提交完成、`stop_portal_server()` 返回后才释放网络和卡。
- 停服由网络 worker 执行。`httpd_stop()` 失败时保留服务器句柄、回调上下文和锁，拒绝新上传并重试；只有 SDK 确认 handler 已退出才释放。依据固定 ESP-IDF v6.1 的 `httpd_main.c`，停止失败发生在发送关闭命令前，句柄仍有效。持续失败时不释放网络或卡，也不发出结束事件。
- 目标目录和大小上限按扩展名由 `portal_server.cpp` 的表决定（书籍 `Books/`、字体 `Fonts/`、锁屏图片 `LockScreens/`）。接收与回读使用固定缓冲，与文件大小无关；每次 `httpd_req_recv()` 前取得 `presentation_gate` 的网络侧，刷新期间由 TCP 流控让发送端等待；发送端停滞超时则该次上传失败。提交阶段的同步和回读不检查取消，耗时随文件大小增长。
- 每个文件提交并回读校验后更新设备状态区；会话结束后重新列出 `Fonts/` 并让自定义休眠图片重新准备。

连接其他信道的网络时热点会跟着换信道，手机可能短暂掉线。驱动调用、HTTP I/O 和文件提交期间只能在返回后的安全边界退出。

## 书籍封面休眠

进度保存和后台资源交还后，应用释放正文位图、预读、统计与书库缩略图缓存，并按缺口裁剪字形缓存。封面 worker 沿用正文图片的冷解码预算，按实际图片与目标尺寸检查内存，不按允许的最大图片预留连续块；资源不足时回退书名，下次休眠请求重新尝试。

已声明的封面图片发生暂时读取或分配失败时保留该错误，不用正文探测结果改判为无封面。休眠封面使用 `PPCOVER4` 缓存头，使旧版误写的无封面记录重新生成。热缓存分块读入独占输出画布。冷解码与热缓存都向应用移交已完成的图片，应用校验任务代次、当前书籍和休眠请求后接收，绘制阶段不再读 TF；缓存提交失败不丢弃本次图片。

书籍封面与自定义图片共用 20 秒取消预算和后台文件所有权协议。单次 TF 读写和同步不能抢断，该预算不代表整个休眠流程的耗时上限。

## 自定义锁屏

本节说明文件、缓存、准备预算与失败回退；界面见[自定义锁屏界面](ui-implementation.md#自定义锁屏)，用户步骤见[使用指南](../user/runtime.md)。

- 只扫描 TF 卡根目录 `LockScreens/` 中的 PNG、JPG、JPEG，不递归，忽略隐藏文件和符号链接；图片数量和目录项有上限，超出时提示整理目录而不使用不完整列表。轮播按文件名的 UTF-8 字节顺序。
- 原图的文件大小、单边像素和总像素有上限。图片等比缩放居中，不裁切；空白和透明区域默认填白，开启叠加且 PNG 含透明像素时保留底图。
- 全局 `power.sleep_screen="custom"` 启用；`power.sleep_image=""` 表示轮播，非空时为图片文件名；`power.sleep_overlay` 控制叠加。三者都不能单书覆盖。
- 轮播记录：锁屏成功呈现后文件名先保留在内存，由下一次锁屏任务（唤醒后的空闲预准备或下一次休眠准备）写入 `PicoPage/data/last-lock-screen.txt` 后再选下一张；休眠前不等待该写入。写入失败只写日志并由后续任务重试；写入前断电时下次重复显示一张。清缓存不重置记录。
- 转换使用内容 worker，清醒且空闲时准备下一张，只保留 `PicoPage/cache/lockscreens/current` 一份缓存（`PPLOCK4`）：无透明像素时为 4 位灰阶，含透明像素时为 8 位灰度加 8 位 Alpha。原子替换期间旧缓存与临时文件同时存在，TF 卡空间需容纳两份。缓存与叠加开关无关，通过原图 SHA-256、文件名、大小、修改时间、转换版本和像素摘要校验。
- 开启叠加时，在显示空闲、必要保存及旧 worker 交还后，把当前画面复制到独立的锁屏输出缓冲，正文底图清除整条阅读页脚；该缓冲随后由内容 worker 独占，主画布和在途帧不修改。worker 在读块、目标行和缓存提交前检查取消与剩余预算，失败或取消丢弃未呈现输出。
- 休眠时先保存进度、交还后台资源，再校验缓存；缓存缺失、损坏或原图改变时由 worker 补做转换。轮播跳过确定损坏、空文件、不支持或超限的图片，最多检查一轮；指定模式不换图。取消、超时、内存不足、读卡失败和原图在转换中改变都停止本次尝试，不当作坏图继续。
- 准备共用 20 秒取消预算；空闲预准备每轮尝试次数和重试间隔有限，耗尽后等待显式休眠、预览、设置变化、唤醒或存储会话重置。失败类别决定重试与跳过，诊断文案不参与判断。
- 准备提示只暂存页脚像素，资源不足时省略提示；不新增 worker、栈或整屏快照。
- 转换成功但缓存提交失败时仍显示本次图片，下次重新准备。目录为空、指定图片不存在、轮播全部不可用或预算内无法准备时才使用简洁屏保。休眠目的地在请求开始时固定，锁屏失败和提示不改变目的地。

### 锁屏执行与资源

冷 PNG 逐块读取，最终采样直接合成到独占画布；透明缓存只用行缓冲写入临时文件，不保留整份压缩图或整屏透明层，Adam7 重访行由临时文件承接。冷缓存轮播可能在部分合成后才发现坏图，因此保留未修改的背景，下一候选从原背景重新开始，避免重复叠加；指定图片和有效热缓存直接复用背景输出。源坐标表按已验证的尺寸有界分配，沿用 pngle 的扫描行与字典。单次读取、行读写和最终同步不能抢断，完成前的任何失败都不提交显示。

提示保留期间暂缓接收会替换原页的后台结果；取消只向原来源页恢复暂存像素，不覆盖已出现的错误或网络收尾页面。绘制与显示完成回调不扫描、解码或提交文件。验收标准见 [PW07](acceptance.md#显示电源和设计)。

## 固件更新

本节说明设备升级、分区前提、下载校验、取消与回滚；发布流程见[固件托管](firmware-hosting.md)，界面见[固件更新界面](ui-implementation.md#固件更新)，后续范围见[路线图 R11](../planning/roadmap.md#r11--ota-升级)。

### 分区与前提

- `firmware/partitions.build.csv` 定义双 7 MiB 布局（`ota_0`、`ota_1`、`otadata`）。固件校验设备的应用槽与选槽分区，布局不符时阻止联网更新并提示电脑重装。联网更新只写入另一个应用槽，校验后切换启动槽。
- 从双 4 MiB 切换时按 D41 和 D50 完整重装：电脑擦除内部 Flash，从 `0x0` 写入配套 bootloader、分区表和应用，NVS 与 otadata 为擦除态，设备从 `ota_0` 启动。见[分区迁移方案](../planning/ota-partition-migration.md)。
- 打包校验 ESP32-S3、16 MiB Flash 的 bootloader，与项目标识匹配的分区表，以及与联网更新镜像逐字节相同的应用。
- 开发时只写应用的方式只适用于实际分区与构建布局一致的设备，写入前读取 otadata 确定活动槽。见[固件开发指南](../../firmware/README.md#硬件与写入边界)。

### 升级来源

双 7 MiB 固件读取 `https://picopage.wulu.zone/firmware/ota-v2/manifest.json`，双 4 MiB 设备的旧地址固定提供 0.6.2。清单的 `url` 指向单一下载源。HTTPS 校验证书，收到重定向即终止。

### 联网更新

- 请求带序号，取消后迟到结果丢弃；只有实际显示完成才推进呈现序号。
- 用户点按检查后才联网。卡上缓存的清单只用于显示；本次开机没有从服务器读到清单时，安装前先重新读取，镜像相同才继续，有变化则显示新清单并要求再次确认。下载地址和摘要因此始终来自服务器。
- 新布局清单必须包含 `manifest: 2`、`board: "read_pico"`、`layout: "ota7"`、`version`、`published_at`、`url`、`size`、`sha256`、`data_schema`（`progress`、`config`）和 `notes`，可选 `notes_i18n`；布局、格式或板型不符以及版本带构建元数据时拒绝。清单由 `tools/ota_manifest.py` 生成。服务器返回 404 时提示尚未发布固件。
- 版本按[版本管理](versioning.md)比较，不提供降级；开发构建（版本带 `+`）无法比较，允许换成发布构建。
- 安装条件依次为：电量不低于 20% 或正在充电（读数无效且未充电时不安装）；没有同步、传书或书籍加载在进行；`data_schema` 任一项低于本机时拒绝，任一项高于本机时下载前须确认。本机进度格式版本与配置版本以源码常量为准。
- 下载时边收边写入空闲应用槽，不经过 TF 卡。擦除前核对镜像开头的芯片型号、项目名 `pico_page_ota7` 和版本；双 4 MiB 固件只接受 `pico_page`。写完核对长度和整文件 SHA-256，并由 ESP-IDF 校验槽内镜像摘要；任一项不符即丢弃，启动槽不变。下载期间不休眠。
- 无数据等待、重连次数和总执行时间都有上限。重连只从已交给 OTA 句柄的字节偏移继续，使用 HTTP Range，要求响应为 `206` 且 `Content-Range` 的起点、总长度和剩余长度都匹配；否则终止。整个镜像只做一次累计 SHA-256，不保存跨重启的下载状态。
- 用户确认重启安装时再次检查电量；先保存阅读位置，再切换启动槽，切换成功后才写安装记录并重启。启动槽未切换成功或切换前断电时，重启后仍是当前固件，不提示失败、不跳过版本。选「稍后」时已校验的镜像只在本次开机有效。
- 新固件首次启动时，板级初始化、应用初始化和首屏显示都成功后才确认有效，无卡或挂载失败不计入；确认写入失败时立即放弃该镜像。确认前复位、断电或任一步失败，bootloader 回到旧固件。
- 重启后显示一次结果；回到旧版本时跳过该版本，直到清单提供更高的版本。安装记录和已跳过版本保存在[固件更新缓存](storage.md#4-身份移动删除)，清理全部缓存时一并清除。

### 资源与时限

- 检查和下载在网络工作任务上运行，显示和输入仍由应用任务处理，进度按固定间隔局部刷新。
- 下载使用固定大小的内部 RAM 缓冲和 HTTP 接收缓冲，TLS 会话从 PSRAM 分配，TCP 接收窗口与邮箱有界；清单响应沿用通用上限，更新日志只保留开头部分。
- Flash 操作与面板刷新互斥：先验证首段身份并关闭探测连接，再按块预擦除镜像占用范围，块间让出调度并检查取消；擦除后重新建连并再次核对首段，然后分块写入。擦除、写入和最终回读校验都持有显示／Flash 锁，并与 I²C 事务错开，期间输入采样可能延后。下载期间暂时关闭 Wi-Fi 省电，结束后恢复。
- HTTPS 握手、请求头、响应头和正文都经 `presentation_gate`，待呈现帧优先于下一次 SDK 传输调用。
- 连接建立后改为短间隔 socket 轮询，在重试间检查取消和截止时间；该间隔不是 DNS、TLS 计算或整条取消路径的上限，已进入的 SDK 调用和单个 Flash 块操作须返回后才能观察取消。
- 任何失败或取消都不改启动槽；空闲槽留下不可启动的内容，下次下载时重写。

### 失败恢复

- 整片安装的设备使用本项目构建的 bootloader，回滚由 `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` 提供。未整片安装的设备仍是出厂 bootloader；对其备份的反汇编显示启动槽选择包含待确认和放弃逻辑。
- 新固件卡住而不复位时 bootloader 不会介入；长按电源键强制断电后再开机即回到旧固件。
- 两个槽都无法启动时，用 USB 连接电脑重新整片安装；芯片 ROM 下载模式不依赖闪存内容。
- 升级不修改 TF 卡上的书籍、配置和进度。新固件确认有效前，不得把配置、进度或书签迁移到旧固件不能读取的 schema；需要迁移时在确认有效之后进行，或保留旧固件可读的版本。

### 安全说明

设备未启用 Secure Boot，固件不验证发布者签名。清单中的 SHA-256 只能发现传输或写入错误；能控制下载地址或其域名的人可以安装任意固件。验收见 [OTA01–OTA07](acceptance.md#固件更新)。
