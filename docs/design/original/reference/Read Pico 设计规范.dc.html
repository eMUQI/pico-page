命中规则
1. 显式命中区（脚注、链接、图片、按钮）优先于背景翻页区。
2. 一次输入只执行一个动作：滑动不触发脚注，抬手关闭面板不穿透成翻页。
3. 打开面板或模态框后，第一次抬手只用于关闭，不传给下层。
3a. 阅读页 K2 = 立即全刷。刷新事务进行中时忽略，不排队；有返回条时也不执行返回。
4. 唤醒输入只唤醒，被吞掉，不传给任何页面。
5. 正文长按首版不绑定功能；重要动作都有可见入口。
6. 重排中、跳转中、同步中的按钮禁用，不会排队提交。

7 · 状态字段需求
在 ReadingViewState 和 SyncRecord 已有字段的基础上，画板还用到下面这些信息，需要开发侧确认能否提供。
字段
用途
available_actions[].disabled_reason
禁用项下面显示的原因：需联网、需存储卡、屏幕正忙等
sync_progress { stage, stage_count }
S06-3 的阶段显示：连接 → 读取远端 → 上传
remote_candidate { chapter_label?, percentage, received_at, read_time_reliable }
S07 的远端卡片：章名可为空，“最近收到”和“阅读时间未知”分开显示
last_ack { at, account_scope }
“最近一次上传确认”以及当前服务和账户
jump_history[≤3] { label, anchor }
返回条和目录首行
typography { applied, pending, preview_status, reflow_status }
区分“已应用”“预览中”“重排中”“字体不可用”
library_item.status
ok / missing / needs_reprocess / corrupt，对应 S01-5 的三类原因
library_item.cover { available, decode_ok }
卡片模式和休眠封面；不可用时回退到文字封面
storage { state, books_bytes?, cache_bytes?, free_bytes? }
存储卡不可用和空书库分开显示；读不到时显示“未知”
transfer.items[] { name, stage, progress?, error_kind }
S09-5 的逐文件三阶段和失败原因
wifi { state, ssid, band, fail_reason }
只支持 2.4 GHz；fail_reason 区分密码错误、找不到网络、超时、无地址
wake_sources[]
休眠画面的唤醒文案，以板级确认结果为准
8 · 已知偏差与待验证
1. 20px 小标签和禁用原因低于交接说明中辅助信息 22px 的下限。建议真机检查后统一提到 22px，代价是部分格子需要变宽。
2. 目录行高 86px，略低于 88px 的热区起点。若真机误触多，每屏少放一行。
3. 浅灰分隔线（#cfcfcf）在近似黑白下会消失。列表行靠留白和行高仍然能分开，但快速模式下要实际看一遍。
4. 唤醒文案、K1/K2/K3 的实际排列，待板级确认。
5. 提示阈值、自动全刷间隔、翻页区宽度、扫描计数的刷新频率都是占位值，由实测确定。
6. 图标仍是文字符号，需要统一绘制成 SVG 源文件。
