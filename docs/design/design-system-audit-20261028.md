## 结论与范围

检查基线为 `main 1ce9c1de85450654f8c1d158727a17bf7fee13b0`，开始时工作区干净。依据为 [D46](../planning/decisions.md)、[设计系统](system/README.md)、[tokens](system/tokens.json)、各组件说明与 [UI 实现说明](../development/ui-implementation.md)。本次只记录差异，不修改实现、设计规则或原始设计，也不代表已经完成 D46 迁移。

设计系统列出的六类待实施规则均仍存在。额外发现包括危险操作推荐方向、紧凑控件热区、按钮式选择器状态、字号角色和反馈位置；另有设计系统总则与组件细则之间的冲突，需要先明确适用范围。以下按问题类别归并，不把同一绘制函数的每个调用重复计算为独立缺陷。

三名 Sol 子代理分别检查通用绘制与设置、书库与阅读及词典、网络与电源等系统页面；主代理复核证据，检查规范与静态预览、官网共享样式，并从当前源码生成和查看代表性 host 画面。覆盖包括 `reader_app` 的通用绘制、书库、详情与确认、正文与工具、目录与书签、排版与字体、词典、引导与帮助、设置、网络键盘、同步、传输、更新和电源相关入口。传书网页和官网仅核对本地源文件，不宣称线上界面已验收。

优先级「高」表示优先处理可能误导危险操作的样式；「中」表示交互辨认、触控或迁移范围问题；「低」表示局部视觉与文案一致性。全部条目状态均为待处理或待澄清。

## 补充差异

### A1 · 高：保存失败后的电源页推荐了危险操作

`firmware/components/reader_app/app_impl.h:384–388` 在保存失败后明确提示「继续可能丢失最后一段阅读进度」，但「仍然关机／仍然重启」使用黑底推荐样式，「返回」为白底框。与设计系统「危险操作以实线框表达，推荐取消」相反。此处已有明确后果说明，本次发现是推荐方向错误，不是发现会自动丢失数据的新执行路径。

后续应让安全返回承担推荐样式，危险操作保留明确名称与实线框。本次以源码分支确认，未注入保存失败或执行设备关机。

### A2 · 中：多个实际热区低于 88 px

`firmware/components/reader_app/app_impl.h:1214–1221` 的 `button()` 按传入高度直接注册热区，没有额外扩展。以下不是仅有视觉框较小，而是实际可点高度较小：

| 页面／控件 | 高度 | 代码位置（`firmware/components/reader_app/`） |
|---|---|---|
| 书库排序、列表、卡片 | 60 px | `app_library.cpp:340–342` |
| 书籍详情的清除进度、删除原书入口 | 76 px；危险按钮组件规定 96 px | `app_library.cpp:471–472` |
| 字体选择上一／下一页、取消／选用 | 64／80 px | `app_settings.cpp:95–102` |
| 设置页底部更新、帮助、关于行 | 82 px | `app_settings.cpp:306–310` |
| 帮助中的说明项与按键示例 | 72 px | `app_settings.cpp:359,363` |
| 词典管理启停、排序、翻页和底部操作 | 60／68／80 px | `app_dictionary.cpp:66–85` |
| 词典选词时查词／取消、下一词条，以及重试、来源翻页、管理入口 | 44／64／80 px | `app_dictionary.cpp:297–298,343,357,362–363,370,389–393` |
| 键盘辅助操作清空、显示／隐藏、恢复默认 | 60 px | `app_wifi.cpp:237–239` |

依据为设计系统「触控目标高度至少 88 px」及 Button 组件的尺寸规则。后续需要同时核对相邻热区间隔和页面可用空间，不能简单扩大后制造重叠。书库、字体选择、电源设置已有本次截图；其他为源码确认。未测实际漏点率。

排版 80 px 参数格、56 px 收起条、词典 72 px 图标与 44 px 选区端点具有明确专项规则，放入 S2 待澄清，不混入上表的普通按钮整改范围。

### A3 · 中：按钮式选择器仍用黑底表示状态

`firmware/components/reader_app/app_power.cpp:45–48,53,65` 用黑底分别表示当前休眠样式、叠加开关开启和「保存设置」。自定义图片且开启叠加时，一页同时有三处黑底，其含义并不相同。本次 [电源设置截图](../images/design-system-audit-20261028/power-settings.png) 已确认。`app_impl.h:2941–2942` 的锁屏图片选择也使用同类表达。

这超出已知清单仅点名的 `choice()` 外框／标签迁移。需按 D46 补充选择器状态方案，避免只改通用单选行后仍保留旧语义；不能把所有选中黑底都替换为不可用样式。

### A4 · 中：字号迁移不能只搜索五个旧字号

设计系统已知清单列出 30／26／25／23／22 px，但还存在其他非四档 UI 字号及四档内的角色错用：

| 类型 | 示例证据（`firmware/components/reader_app/`） | 处理边界 |
|---|---|---|
| 大标题／状态 34、36、40 px | `app_wifi.cpp:33`、`app_power.cpp:60`、`app_impl.h:377,384,410,3118`、`app_library.cpp:53,322` | 普通状态、数值、确认页标题需要按角色归档；终态标题是否例外见 S3。 |
| 普通说明误用 20 px | `app_impl.h:1202` 的 ValueRow 第二行；`app_dictionary.cpp:338–339` 的提示 | 即使数值属于四档，也不符合 `description=24 px` 的角色要求。 |
| 词典普通提示 21 px | `app_dictionary.cpp:296` | 不在四档或已列旧字号中。 |
| 键盘输入与字符键 34 px | `app_wifi.cpp:224,246` | 与键宽、ASCII 可辨认性一并核对，不能机械全局替换。 |

阅读专用的 30／22 px 顶栏、正文排版字号、40 px 步进符号和绘图用的「Aa」不能因数值相同而误归为普通 UI 文案。词头与词典名称已规定使用当前正文字体，但字体族不等于字号豁免；它们与欢迎品牌文字、更新版本字样的专项边界见 S3。

### A5 · 低：装饰分隔线使用额外灰阶

`firmware/components/reader_app/app_settings.cpp:92` 的字体列表分隔线为灰阶 9、默认 1 px；`app_dictionary.cpp:386` 的词典来源分隔线为灰阶 10。设计系统规定列表装饰分隔线使用 2 px `rule`（灰阶 12），设备基本色板不包含 9／10。本次字体选择截图可见该细线。

这里是绘图颜色参数差异，不把字体抗锯齿、封面、正文图片生成的其他灰阶算作色板违规，也不推断这些装饰线会造成操作失败。帮助图 `app_impl.h:2857,2864–2865` 的灰阶 9 分隔另需明确教学图是否例外。

### A6 · 低：书库设置提示未使用统一页脚区

`firmware/components/reader_app/app_impl.h:3029–3031` 在 y 1012 画分隔线、y 1044 绘制 `notice()`，而共通反馈与 FooterBar 规定从 y 1120 起显示提示。影响视图／文件夹排序更改后的提示及保存失败反馈位置。此项源码确认，尚未追加该状态截图；需与该页面空间安排一起处理，不改变保存失败语义。

### A7 · 低：传书网页仍有一处旧引号

`firmware/components/platform_read_pico/upload_page.h:29` 的结果说明使用弯引号包围「结束传书」，未采用直角引号。仅属文案一致性；本次检索的设备 UI 与帮助未发现「存储卡」残留。传书网页使用 CSS 像素，不套用设备的 88 px 热区和四档设备字号。
