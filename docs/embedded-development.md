# Pico Page 嵌入式开发规则

本文规定修改固件及共享核心时的检查方法，不表示这些要求已经全部实现或验收。产品语义服从 [当前决定](decisions.md)，数值目标和测试编号以 [验收矩阵](acceptance.md) 为准。按本次涉及的路径读取对应章节；只改文案不需要执行整套硬件测试。

## 1. 先定位执行路径，再选择实现

开工前确认实际调用链、构建条件和状态所有者。当前入口主要在 `firmware/main/app_main.cpp`；共享阅读流程在 `reader_app`，硬件适配在 `platform_read_pico`。具体以当前源码为准。架构中的 session/display/system 是职责，不是必须新建的一组 FreeRTOS 任务。

涉及资源或异步行为的改动，先回答五个问题：在哪里执行，谁拥有数据，最多占多少资源，什么时候可以停止，失败后用户停在哪个可恢复状态。简单变更在交接中写清即可。

| 变更对象 | 开工时额外检查 |
|---|---|
| 阅读、分页、图片 | `reader_app/content_job.*`、对应解析/图形路径及缓存；前台与后台是否复用同一对象 |
| 存储、USB、同步 | store 提交协议、挂载所有者、网络回调、已保存快照和账户作用域 |
| 显示、触摸、PMU | `platform_read_pico`、所用 BSP 源码、引脚/中断/供电/时序及当前硬件证据 |
| 构建、依赖、配置 | 实际 IDF/BSP 版本、依赖锁、已有补丁、最终 sdkconfig 和各目标是否包含改动 |

不为「架构完整」新增空组件、通用硬件插件层或每模块一任务。不做与本次目标无关的大规模搬迁；确需拆分时按状态所有权、资源生命周期和可测试边界拆分，保留行为回归，而不是只按文件行数。

## 2. 响应性：优先级、工作分片和取消

用户当前要看的正文、必要保存与安全状态切换优先于可选预取、封面、统计。后台任务不能因低优先级就无限占用共享文件锁、字体锁、总线或全部内存；这些资源同样会阻塞前台。输入采样仍在运行，不等于应用能及时执行输入。

新增长工作必须区分计算片段和阻塞 I/O：计算片段设置可检查取消的边界；单次 SD、网络或驱动调用记录其超时、返回条件和无法抢断的部分。不能以「每轮最多 N 页/字符」推定固定毫秒上限。进度显示与取消入口必须真实可用；不要反复刷新墨水屏来伪装后台已让出。

分片之间保留可安全复用的解析上下文、字体、已完成结果和游标。现有 `PaginationSession` 是阅读统计复用的入口之一，不要退回每小批都重新验书、开字体和解析章节；也不能为了复用让前台与后台同时修改同一个非线程安全对象。缓存键或代次变化后应结束旧会话。

取消遵循明确的生命周期：

```text
请求取消 → 工作任务观察取消 → 停止访问借用资源/安全完成不可中断提交
         → 发布结束状态 → 所有者校验代次 → 接收或丢弃结果 → 释放资源
```

取消标志不是结束确认；`shared_ptr` 只管理寿命，不管理互斥。`ContentJob` 的完成发布/读取协议不得弱化。其析构会等待任务，因此在输入路径直接销毁未结束任务前必须检查可能的等待时间。普通交互宜保留对象并轮询结束，不强删任务，也不把 join/wait 藏在「轻量」回调或析构中。

等待超时不能授权释放仍被使用的文件、锁、DMA 缓冲或会话。超时后按操作性质保持拒绝状态、报告失败或进入已设计的安全恢复路径；低电量紧急收尾另遵循路线图，不能套用无限等待。

对队列明确容量、入队失败处理、合并策略和所有权。累计状态可保留最新快照，正文翻页依 D14 仅保留一次后续翻页，取消/释放等控制事件需要可靠送达或可恢复的状态重置。阻塞等待新任务的空闲 worker 可以无限等待；用户操作、停机交接、网络请求不能由此无限等待。

## 3. 内存：按能力和同时存活峰值核算

不要把 PSRAM 剩余量当成系统还可创建任务或启动外设的证据。分别检查内部 RAM、PSRAM、满足驱动要求的内存能力、最大连续块、最低剩余堆和最低剩余栈。能力堆统计可能有交集，不把不同 capability 查询结果直接相加当成总内存。

一次变更的峰值应覆盖同时存活的全部对象：

```text
稳定驻留数据 + 新工作输入/输出 + 旧对象等待移交的重叠量
+ 解压/解码/字体/TLS 临时分配 + 容器扩容的旧块与新块
+ 任务栈/队列/驱动分配 + 记录明确的余量
```

现有缓存载荷估计不是全系统承诺。容量预算使用实际 capacity 和嵌套对象，而不只看元素数量。重点检查图片缩放前的原始像素、UTF-32 文本、字形缓存、整个字符串副本和按值捕获的大型请求。大数组、大对象不随手放任务栈；也不先把所有任务栈翻倍再查原因。

使用堆分配、STL、RAII 或固定池取决于生命周期和可测预算，不作一刀切禁止。初始化时可预留确定规模的缓冲；有界容器可减少扩容，但不能按外部未经验证的长度直接 reserve。检查实际分配/任务创建/驱动返回值；事前检查 free heap 不是分配成功保证。同时核查目标的异常和分配器配置，不能假设 `new`/容器分配失败一定返回空指针或一定可 catch。错误反馈路径避免再次依赖同等规模分配。

ESP32-S3 的 PSRAM DMA 能力不能照搬旧 ESP32 的结论：需逐驱动确认缓冲、描述符、对齐、缓存同步和寿命要求；不写「全部 DMA 缓冲均可放 PSRAM」或「PSRAM 一律不能 DMA」。涉及 cache-disabled 路径时还要核对代码和被引用数据的实际位置，不能只给入口加 IRAM 属性。依据见文末对应芯片和 IDF 版本的官方说明。

资源紧张优先回收可重建且不在途的低价值数据。降级可以是不预取、暂缓总页数、封面占位、图片按现有错误状态回退；不能丢正文、覆盖权威进度或让错误/退出界面不可用。有效长章节按 D17 分段读取，不以扩大单章缓冲或拒绝整章作为内存方案。

## 4. FreeRTOS、ISR 和共享对象

新建或调整任务时记录入口、优先级、亲和性、栈大小及单位、持有资源、唤醒机制、退出与清理者。IDF 任务创建 API 的栈参数按字节解释，不能照抄其他 FreeRTOS 移植的 word 数值。任务数量和频繁创建/销毁的代价应计入资源与延迟；改成长驻 worker 也须先说明回收和空闲策略。

`taskYIELD()` 不等于让 Idle 或低优先级任务获得执行时间。分析实际就绪状态、亲和性与持锁情况；对等待用事件/通知/队列，对计算设计分片和真正的阻塞让出。不要盲目增加 delay 掩盖竞争。仅关闭本核中断或暂停本核调度不是双核共享数据的互斥方案。

ISR 不做文件访问、解析、格式化日志、动态分配或等待互斥锁。使用适用的 FromISR API，正确处理是否需要切换任务。短临界区只保护必要状态，耗时操作移到区外；定义锁顺序，不能持有应用状态锁等待可能回调应用的网络、显示或任务退出。

RTOS 队列按固定字节复制条目，不直接把带 `std::string`、容器、智能指针的对象作为字节载荷。使用可复制的小值消息，或传递有明确所有者的指针/句柄。成功入队、失败、覆盖旧条目、取消、关闭队列分别确定谁释放；不能让异步请求持有已失效的栈引用或临时对象。

解析器、字体 face、文件游标和画布的线程安全由所用实现决定。共享对象优先单一所有者加消息；必须共享时建立同步及可证明的寿命边界。`volatile` 不代替原子、内存序或互斥。

看门狗报警先记录任务、栈、等待对象及最长阶段。不得以关看门狗、无条件喂狗、提高优先级或绑定另一核心作为未定位问题的修复。合法长操作需要更大预算时，记录依据、恢复边界和压力测试。

## 5. 显示事务和输入序列

沿用显示所有者和 FrameToken 的边界。工作任务输出已完成的内容/像素，不能改写正在提交或由驱动读取的画布。显示 API 返回所代表的完成程度必须从驱动契约确认，不把「提交队列成功」当成「物理刷新完成」。正文只有成功呈现后才能推进 visible anchor。

失败或未知的前帧不能继续作为差分刷新基准；复位、休眠恢复、波形失败后走既有基准重建路径。默认 K2 全刷绕过像素相同优化，不改变锚点/进度修订，也不取消草稿、退出传输或操作远端。刷新过程不中断波形；不要把 D14 的一次连续翻页扩展为任意动作积压。

优化前分别测量输入排队、内容准备、像素转换/复制、上电、波形执行和完成回调。局部 CPU 重绘不代表面板时间或能量按面积缩小；不以换波形、改 PCLK/VCOM 或缩短供电窗口掩盖软件等待。工厂校准不得改写；新模式须验证灰阶、残影、恢复、输入与能耗。

一次触摸从按下到释放由同一上下文拥有；打开面板、唤醒或进入图片查看后吞掉该序列不应再触发的尾部事件。异常移除/队列溢出要清理接触状态，避免永久长按或输入穿透。输入坐标、旋转、安全区和绘制命中几何共用约定。

## 6. 文档、字体、图片和派生缓存

EPUB/TXT/字体/图片/缓存都是需要校验的输入。检查资源路径越界、压缩与展开尺寸、截断、嵌套深度、数量、图像尺寸乘法、偏移加法和 32 位类型转换；循环必须前进且可结束。对非法结构和不受支持的资源返回具体错误，对有效长正文使用流式/分段路径。不要为通过样本默默截断正文、漏字或把解析失败显示成正常空白页。

文本位置明确区分 UTF-8 字节、UTF-16 单元、Unicode 标量与源节点偏移。归一化、空白折叠、分段和字体度量变化都要检查边界；同一布局用于绘制和链接/图片命中。分页必须前进，跨页/跨段无重复或遗漏；脚注返回和不同排版下恢复使用源锚点，不使用本机页码。

缓存分层，不把所有设置拼成一个万能键：

| 缓存 | 兼容性至少考虑 |
|---|---|
| 解析内容 | 强内容身份、规范化/解析版本、资源与分段信息 |
| 页边界 | 内容版本、布局算法、字体及度量、影响几何的全部设置 |
| 字形/位图/图片 | 输入身份、渲染算法及目标几何、影响像素的参数 |

改变颜色不应无故重算全部页码；改变影响换行的字体或几何不能误命中旧页边界。字体被同名替换、原书同名不同内容、USB 外部修改、损坏缓存和旧格式都要有确定的失效路径。更改缓存格式时显式版本化；损坏缓存作为 miss，不采用残缺值，也不删除权威记录。

缓存验收必须证明：冷路径正确、热路径实际减少工作、资源门槛在目标设备可达到、无法命中仍可阅读。记录命中/未命中/回收/因资源不足跳过的计数。不要把文件大小与时间戳冒充足以跨会话证明内容未变的强身份。读入迟到缓存时不得覆盖当前会话更完整的计算结果。重启复用时核验兼容性，不无条件整书重算。

## 7. 文件提交、USB 和网络边界

以 [存储实现](store-implementation.md) 和 [USB 运行说明](usb-storage-runtime.md) 的协议为准。不要把已有提交替换成直接覆盖主文件，也不把 host 的 rename/fsync 行为假定为 FAT 掉电保证。临时文件、备份、已提交记录各有角色；恢复只采用验证过的记录，保存失败不能确认新修订。配置语法错误、未知 schema、卡满、只读、短写、拔卡均不得触发自动格式化或清空用户文件。

切书/休眠/USB/同步前处理已显示位置的保存；普通翻页按 D15 延后保存，不无故每页 fsync。缓存失败与权威保存失败分开处理。读回校验和文件提交不能宣称覆盖 TF 控制器所有掉电行为；掉电试验只用授权的可丢弃介质/测试副本。

USB 原始块设备与本机文件系统不得同时拥有卡。交接前停止扫描、解析、缓存、保存及相关上传生产者，排空或拒绝待处理工作，等待文件与缓冲安全释放，再按平台流程卸载/移交。回来时按既有流程重启或重新挂载，重读文件并失效旧句柄/缓存身份；新挂载代次拒绝旧结果。不能把「已发出取消」当成可卸载的条件。失败时保持明确的单一所有者和恢复入口。

网络工作不在 UI 同步等待；请求、DNS/连接/TLS/传输/收尾均有可说明的边界。账号、服务、书籍、已保存修订与请求关联，ACK 只能确认实际上传的快照。取消已经发送的写请求只能停止本地等待，不能保证远端未改变；必要时重新查询。重试有次数/退避边界，关闭会话后不留下重试风暴或持有卡的回调。TLS 校验和凭据隐私不因调试关闭。

## 8. 电源、休眠、唤醒和固件更新

板级变更先读实际 PMU/扩展器协议和所固定的 BSP，确认中断的电平/边沿、有效极性、读清还是写清、FIFO 与状态有效标志；同时考虑任意两次操作之间新事件到达。不能只读「队列为空」，也不能只看 IRQ 高低就宣称进入睡眠的条件已满足。不得用屏蔽全部中断、固定等待或忽略所有非按键事件替代确认协议。

电池采样/充电等事件需要按协议处理，但不等于用户要求点亮阅读界面。修复唤醒要测试长于相关周期事件的停留、按键唤醒、事件同时到达、线保持有效及重复睡眠。触摸采样器进入待机与恢复期间不得访问失效控制器；唤醒首个输入不穿透翻页。

正常用户休眠与低电量保护不混成一条无限等待保存流程。按路线图处理保存失败、用户选择及保护性收尾；必要工作有边界，但不得超时后继续让未结束任务操作已断电外设。屏保转换/网络收尾不能无限阻止保护动作；回退状态真实，不能把「显示关机字样」描述为主机已断电。

功耗结论记录供电方式、USB/充电状态、无线状态、调试/日志条件、停留与唤醒次数。测量空闲电流和单次交互能耗，不能只拿 API 返回成功或降低 CPU 频率证明更省电。清理 PM 锁、定时器、面板电源和无线生命周期时遵循所有权，并检查每条失败分支。

OTA 仅在该任务被明确安排时实现，并遵循 R11：核对设备真实分区、镜像兼容性、电量前提、版本/schema 兼容和确认有效时机。不能以本地构建分区表替代实测，也不能假定 bootloader 已支持自动回滚。沿用既有「不改工厂校准、bootloader 和分区表」等范围限制。

## 9. 构建与依赖可复现

使用 [环境说明](environment.md) 和现有构建脚本；核查当前机器，不照抄旧机器的安装路径与成功记录。记录实际 IDF 版本/commit/dirty 状态、BSP/依赖锁和生效配置。改 defaults 不代表已有 sdkconfig 已跟随变化；从构建日志、生成配置与产物检查目标和功能开关。

涉及 `ESP_PLATFORM`、入口或驱动的变更必须尝试固件构建；host 不包含的源文件不能由 CTest 证明可编译。依赖不可用时可单独验证隔离逻辑，但禁用组件或替换版本的特殊构建必须独立标注，不能冒充标准入口。锁文件、补丁和许可证一起更新，不直接修改下载目录并遗失修改来源。

检查应用镜像大小和目标分区适配；必要时对比 ELF/map 中内部 RAM 与静态占用。编译成功不授权烧录。安装需当前适用授权、真实设备身份与分区核对；摘要校验只证明写入一致，不证明屏幕、触摸、持久化、睡眠、功耗或 KOSync 已验收。

## 10. 按风险选择测试，按证据描述结果

构建与测试命令见根 AGENTS 和 [环境说明](environment.md)。主机 Debug 回归、ASan/UBSan、固件构建、设备行为和实际 KOReader 往返分别记录。host 测试要覆盖固件使用的异步模式，不能只验证默认同步路径。检查 `ctest -N` 注册数和条件依赖，不能以用例未注册获得「全绿」。

| 涉及的改动 | 至少选择的异常/边界 |
|---|---|
| 分页/分段/缓存 | 长章后段、跨段往返、字体替换、改设置再取消、坏缓存、重启复用 |
| 并发/任务/队列 | 旧结果迟到、取消后退出、快速输入、队列满、任务创建失败、回调与关停交错 |
| 分配/图片/字体 | 内存不足、连续块不足、尺寸/偏移溢出、释放后访问、大图与正文共存 |
| 保存/USB/上传 | 卡满/只读/短写、提交各阶段失败、卸载交接、外部改文件、远端结果未知 |
| 显示/输入 | 刷新失败、基准失效、相同像素 K2、一次后续翻页、唤醒/面板切换的序列尾部 |
| 电源/OTA | 保存失败、网络/屏保超时、周期事件唤醒、重复睡眠、失败后的供电/句柄状态；OTA 按 R11 |

纯逻辑用可重复的合成样本与故障注入。不能为赶进度降低断言、移除失败测试、禁用关键组件或静默跳过资源。没有设备仍完成 host 可验证内容；把其余列为待验证候选，不把待测项等同于失败或通过。

性能沿用 [响应性专项](acceptance.md) 和 `tools/summarize_reader_perf.py`，不另造硬编码全局目标。比较同版本配置、同页段、相同缓存冷/热状态，并注明统计任务运行/停止、样本数、P95/P99 与最大值。软件等待和面板物理刷新分开；真实触摸与串口注入分开。阶段仅记录慢样本时，其分位数不是完整分布；包含子阶段的墙钟耗时不能再与子阶段直接相加。日志本身的开销也要受控，不在每字形/中断热路径刷日志。

交接至少包含：改了什么、保持的不变量、执行上下文/资源变化、真实命令与结果、未测项和下一步。当前摘要与历史记录区分；稳定决定回写权威文档，临时推断不升级为已确认硬件事实。
