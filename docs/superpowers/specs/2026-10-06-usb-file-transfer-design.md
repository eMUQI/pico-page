# USB 文件传输设计

> 后续决定：2026-10-06 用户将 K2 更新为所有可交互页面全刷；下文涉及 K2 取消/关闭的历史约定已被 docs/decisions.md 覆盖。

日期：2026-10-06。状态：用户已确认设计；实现候选已烧录，真机文件传输验收进行中。

实现采用同步 MSC 回调；初始化失败后维持独占错误页，由退出流程统一释放资源并重启。实际验证见 [运行记录](../../usb-storage-runtime.md)。

## 已确认的目标

用户希望在设置中手动开启 USB 文件传输，使电脑直接管理 TF 卡里的书籍、网页文章、字体和配置。默认维持正常阅读及现有 USB Serial/JTAG 烧录连接。用户已接受关闭传输模式时重启。开关只表示当前运行状态，不写入 NVS 或 TF 卡；每次正常启动均关闭。

## 交互

沿用现有设置页面和按钮样式，将「文件导入」入口接入 USB 文件传输页面，提供默认关闭的开关。开启前提示「传输期间暂停阅读，请在电脑安全弹出后退出」。保存成功、文件关闭、存储交接及 USB 初始化完成后才显示开启状态。传输页显示「USB 文件传输中」，保留「退出并重启」操作。

退出前以确认界面提示先在电脑安全弹出；取消为安全选项，K2 取消确认而非立即重启。首版不承诺自动识别所有桌面系统的安全弹出行为，也不把 USB suspend 当作弹出。拔线不自动重挂 TF 卡；用户退出后重启，重新读取配置、字体和书库。USB 模式内禁用阅读、同步、普通文件导入和自动休眠；正常阅读中的 K2 全刷不变。

## 存储与 USB 所有权

正常状态：固件持有 TF 文件系统，现有 Serial/JTAG 使用内部 PHY。进入过程：主循环阻止新任务；已有网络工作、显示事务、USB 导入或未结束输入存在时提示稍后重试。保存当前已显示位置，失败时保留原会话并拒绝切换。关闭 EPUB、字体、目录及其他 TF 文件句柄；传输界面使用内置字体，不能再从 TF 取字。确认卸载成功后，才初始化由 USB MSC 独占的 SD 块设备；不格式化、不重建分区。停止诊断串口驱动并将内部 PHY 交给 TinyUSB。首版仅 MSC，不增加 CDC 复合设备。

USB 状态下不运行原 ReaderApp 的读卡路径；主循环仅处理传输页输入、显示和 USB 状态。所有 SD 读写范围、长度、偏移、错误码由 MSC 适配层校验；处理移卡及不完整扇区请求。退出时停止接受新 MSC 请求，等待在途 I/O 结束，断开 USB，再重启。正常重启恢复 Serial/JTAG 和应用启动路径；需要真机确认端口重新枚举与烧录恢复。不烧写 eFuse，不改变 bootloader、分区、NVS 或工厂校准。

## 现有代码约束与改动位置

- `reader_app/app.cpp` 已有设置、文件导入和保存逻辑，可复用入口；新增准备交接与传输状态接口。
- `app_main.cpp` 已协调网络、输入、显示、导入和休眠；在同一主循环完成所有权转换，拒绝旧网络结果重新访问卡。
- `platform_read_pico` 负责 SD 卸载、块设备及 TinyUSB 生命周期；传输页面继续走既有 display 提交确认。
- `reader_console` 新增明确关闭接口，确保原串口驱动不在 MSC 模式访问 USB PHY。
- 当前固定 BSP 将 `sdmmc_card_t` 隐藏在 `read_pico_sd.c`；其 `read_pico_sd_sync()` 即使卸载失败也返回成功，不能直接作为交接成功依据。需要可传播卸载错误的窄接口。以仓库管理的最小适配补丁构建，保留固定上游原件及摘要核验，不直接修改 `.local` 上游检出，也不复制第二套完整 BSP。
- 采用官方 `esp_tinyusb` MSC，选择与 ESP-IDF 6.1 相容的固定版本；实现前记录来源、依赖和许可证。Read Pico 的供电/VBUS 检测路径须核实，不能猜测 GPIO 或仅凭 USB suspend 判定拔线。

## 失败处理

保存或显示失败：停留正常模式并明确提示，不交出卡。关闭句柄/卸载失败：不启动 MSC；若已无法恢复应用会话，显示错误和重启入口，禁止继续访问未知状态的卡。MSC 初始化失败：确保 USB 不再持有卡后提供错误及重启入口；不能显示「传输中」。传输中移卡：返回介质不可用，禁止自动重新格式化或将新卡接入旧会话。未安全弹出即拔线/强制重启：不能保证电脑尚未提交的写入；设备不得宣称所有电脑写入已保存。电脑删除或移动当前书籍后，重启正常显示书库，不回写旧内存配置或旧进度覆盖电脑改动。

## 验证与交付

复用现有 host 测试，增加必要的所有权/失败门控用例：保存失败不交接、忙碌不交接、交接后无应用读卡、K2 不误退出。执行 host CTest、必要 sanitizer 检查、完整固件构建及交接检查；不新增独立测试框架。真机验证默认串口、开启后磁盘枚举、新增/读取/重命名测试文件及摘要、安全弹出、退出重启、字体和书库重新加载、进度恢复与 USB 烧录连接恢复。先以单个测试文件验证磁盘读写，确认后再整理既有文件。

## 方案取舍

采用运行中手动进入、退出后重启，减少退出时重建应用和文件句柄的复杂度。不采用 MSC 常驻加 CDC 的复合模式，避免更改默认烧录连接；不采用退出后热恢复，避免首版增加另一套恢复流程。
