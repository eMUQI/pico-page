# 功能路线图

本文列出首版范围之外、已确定要做的设备功能。条目只表示计划，均未实现；
实现前不在界面显示可用入口。阶段与验收门槛见 [开发里程碑](milestones.md)，
已确认的产品决定见 [当前决定](decisions.md)（D29、D30）。

这些功能不改变首版验收：EPUB 离线阅读与 KOReader 双向位置接续仍优先。
每项实现时沿用现有规则：按键使用默认映射（K2 全刷）时，各项功能不改变 K2 的行为；R7 实现后按用户映射执行，
规则见 R7；设置写入 TF 卡上的 TOML 文件，
NVS 不保存权威配置；新页面用现有组件和视觉风格，不借机重设计。

## R1 · 关机

目标：在设备上主动断电，与现有的“短按电源键浅睡”区分。

- 入口放在“设置 → 电源与休眠”，使用屏幕按钮并二次确认。不新增电源键长按或组合键；
  板级 PMU 现有的硬件强制关机操作保持不变。
- 关机前按休眠流程处理：保存当前已呈现的正文位置，等待文件提交完成，结束网络任务，
  然后显示关机画面并全刷，最后请求 PMU 断电。
- 用户主动关机时，保存失败或网络任务未能结束则先不断电，显示失败原因，由用户选择重试或仍然关机；
  不得在保存失败时提示“已保存”。
- 低电量保护（R8）调用关机时不等待用户选择：收尾步骤有时间上限，超时或失败后仍然断电或休眠。
  画面如实显示保存结果；结果未明的上传记为远端状态未知。
- 开机后按现有启动流程从文件恢复书库或正文。

前提：当前使用的 PMU 接口只有初始化、读取、轮询、事件确认和 VCOM 读取，
未发现主机发起断电的命令。需要先查阅官方 BSP 与 PMU 协议。没有该命令时（D32）：
完成上述保存步骤后显示关机画面，画面提示用户使用硬件关机操作；不用深睡冒充断电。

验收：真机断电后电流降到关机水平；重新开机后进度与关机前一致；用户主动关机时保存失败后保持开机并提示，
用户明确选择“仍然关机”后可以断电，且画面不显示已保存；低电量保护在收尾失败或超时后仍断电或休眠。

## R2 · Wi-Fi 开关

目标：用户可以禁止设备使用 Wi-Fi。

- 当前 Wi-Fi 只在同步、传书和配网时临时开启，结束后释放驱动。开关关闭后，
  这些入口显示“Wi-Fi 已关闭”，并提供跳转到开关的按钮；不得静默失败或显示连接中。
- 开关保存在 `PicoPage/settings.toml`，手工编辑文件同样生效。
- 关闭开关时若有网络任务在进行，先按现有取消流程结束任务，再释放驱动；
  不得在上传中途切断后标记已上传。
- 关闭 Wi-Fi 不删除已保存的网络和同步账户。

验收：开关关闭后无法发起任何网络请求；重启后开关状态保持。上传请求已发出后才取消时，服务器可能已经收到更新，
此时把远端状态记为未知，下次同步前重新查询或交给用户处置，不显示“未上传”或“已上传”。

## R3 · 蓝牙开关

目标：用户可以单独开启或关闭蓝牙，与 Wi-Fi 开关互不影响。

- 与 R6 一起实现；R6 完成前不显示蓝牙开关。
- 开关保存在 `PicoPage/settings.toml`。关闭时断开遥控器并停止蓝牙控制器，保留已配对设备记录。
- 默认关闭，避免未使用遥控器的用户承担额外耗电。

验收：关闭后遥控器无法翻页且设备不再广播或扫描；重新开启后已配对遥控器可以重连。

## R4 · 自定义锁屏

目标：休眠画面可以使用用户自己的图片，支持轮播或指定一张。

- 用户把图片放入 TF 卡根目录 `LockScreens/`（D25）。支持的格式在实现时根据解码器确定，
  先考虑与正文图片相同的 JPEG 和 PNG。
- “设置 → 电源与休眠”的休眠画面选项在现有“书籍封面、保留正文、简洁屏保”之外增加“自定义图片”，
  其下选择“轮播”或“指定图片”。
  - 轮播：每次进入休眠时按文件名顺序换下一张；顺序位置记录在 `PicoPage/` 下的普通文件中。
  - 指定：从图片列表选择一张；该图片被删除或无法解码时回退到简洁屏保，并在下次唤醒时提示。
- 转换为 684×1216 灰阶的结果放入 `PicoPage/cache/`；清理缓存后重新生成，原图不修改。
- 转换在设置图片时或唤醒期间提前准备。进入休眠时缓存未就绪（例如首次选择后或清理缓存后），
  只允许有限的转换时间；超时则本次使用简洁屏保，下次唤醒后再准备缓存。不得因转换延误休眠或让面板停在中间状态。

验收：轮播在连续多次休眠中按顺序更换；指定图片在重启后保持；删除图片、损坏图片、
空目录、缓存未就绪均回退到可显示的画面。

## R5 · 锁屏密码

目标：开机和每次从休眠唤醒后，输入 4 位数字密码才能进入书库或正文（D32）。

- 密码只防止他人随手使用设备，不保护数据：书籍、进度和配置仍以明文存放在 TF 卡上，
  取出 TF 卡即可读取。界面与文档必须说明这一点。
- 设置时输入两次确认。设备只保存加盐摘要，写入 `PicoPage/` 下的配置文件，不保存明文，不写 NVS。
- 输入界面使用屏幕数字键盘，输满 4 位后自动校验。按键只执行全刷，不作为确认或删除键。
- 锁定期间不响应翻页、蓝牙遥控器和 USB 传输；USB 连接电脑时不得在解锁前开放 TF 卡。
- 忘记密码时，在电脑上删除对应配置项或文件即可清除密码；文档写清操作步骤。
- 连续输错时可以加等待时间，但不清除任何数据。

验收：未解锁时无法进入书库、正文和 USB 传输；删除配置项后不再要求密码；
错误次数和等待时间不影响已保存的进度。

## R6 · 蓝牙翻页

目标：使用蓝牙翻页器或遥控器翻页。

- ESP32-S3 只支持低功耗蓝牙（BLE），不支持经典蓝牙。只能连接 BLE HID 设备；
  只支持经典蓝牙的翻页器无法使用，兼容列表按实测记录。
- 设备作为 BLE HID 主机连接遥控器，协议栈和 HID 主机组件在实现前做依赖审查，记录版本与许可证。
- 遥控器按键进入现有的集中上下文动作映射，固定为上一页、下一页，不映射全刷，
  也不在 R7 中开放自定义（D32）。遥控器翻页与触摸、按键翻页走同一路径，遵守 D14 和 D15。
- 配对界面放在“设置”中，列出扫描到的设备并显示连接状态；配对记录写入 `PicoPage/` 下的文件。
  蓝牙协议栈自身的绑定密钥由其管理，不把阅读配置放入 NVS。

需要先测量的风险：

- 固件体积：当前应用槽剩余约 23%，需确认加入 BLE 协议栈后的大小。
- 内存：协议栈常驻内存与正文排版、图片解码同时使用时的余量。
- Wi-Fi 共存：同步或传书期间蓝牙连接是否稳定。
- 功耗与休眠：当前浅睡只由 PMU 电源键唤醒。保持蓝牙连接会增加待机耗电，
  遥控器能否唤醒设备需单独设计；默认休眠时断开遥控器，唤醒后重连。

验收：至少一款 BLE 翻页器在正文中稳定翻页；连续翻页不丢失；断开后自动重连；
休眠后耗电与关闭蓝牙时的差异有实测记录。

## R7 · 自定义按键

目标：用户为机身 K1、K2、K3 分别指定动作，三个键在所有页面使用同一套映射（D30）。

可选动作共四个：上一页、下一页、全刷、回到主页。不提供“返回”（D32）。默认映射与现行规则相同：
K1 上一页、K2 全刷、K3 下一页。不改动映射时，设备行为与现在完全一致。

### 配置

- 映射保存在 `PicoPage/settings.toml`，例如：

  ```toml
  [keys]
  k1 = "prev_page"   # prev_page | next_page | refresh | home
  k2 = "refresh"
  k3 = "next_page"
  ```

- 某个键的值无效时，该键使用默认动作；不改写原文件，在按键设置页显示哪一项无效。
- 设备上新增“设置 → 按键”页，每个键从四个动作中选择一项，另有“恢复默认”。
  沿用现有设置页的列表和选项组件，点击“保存设置”后生效。
- 多个键可以选择同一动作。没有键映射到“全刷”时，设置页提示正文可从工具中的刷新面板全刷，
  其他页面将无法用按键全刷。

### 动作在各页面的含义

映射对所有页面相同，动作的具体效果由当前页面决定。不适用的动作被忽略，不产生其他效果。

| 动作 | 正文 | 书库、目录等列表 | 工具、排版等面板 | 其他页面 |
|---|---|---|---|---|
| 上一页 / 下一页 | 翻页，遵守 D14、D15 | 上一屏 / 下一屏 | 忽略，不操作背后的正文 | 有分页时翻屏，否则忽略 |
| 全刷 | 与现行 K2 相同：绕过像素比较全刷当前画面，刷新中忽略重复请求，不改变位置与修订号 | 同左 | 同左 | 同左 |
| 回到主页 | 保存已呈现位置后回到书库首页并全刷（D13、D15） | 回到书库首页 | 关闭面板，按正文规则回到书库首页 | 见下方受保护页面 |

受保护页面中，“回到主页”被忽略，只能用屏幕控件操作；翻页与全刷照常：

- 冲突处置与确认对话框：按键不执行确认或取消。
- USB 传输：按键不退出传输，避免电脑写入中途断开。
- 同步、传书、配网等网络任务进行中：取消使用屏幕上的取消控件。
- 锁屏密码输入（R5）。

### 不变的规则

- 按键不承担唤醒；唤醒来源仍由板级能力决定。
- 不增加按键长按或组合键。长按书库条目进入详情、长按正文图片进入查看保持不变。
- 动作经集中的上下文动作映射分派，页面只接收动作，不直接读取按键编号。
- 蓝牙遥控器不使用这套映射（见 R6）。

验收：默认映射下现有输入测试全部通过；每个动作在每类页面上有 host 测试；
受保护页面中“回到主页”不改变状态；无效配置值不覆盖文件；真机上三个键按新映射工作。

## R8 · 低电量保护

目标：电量过低时先保存进度，避免突然断电丢失刚读到的位置。

- 两级阈值，写在 `PicoPage/settings.toml`。默认提醒 20%、保护 5%（D32），真机测量电量读数后再调整：
  - 提醒：电量低于提醒值时，在状态栏或下一次页面切换时提示一次，不打断阅读。
  - 保护：电量低于保护值时，保存已呈现的正文位置，结束网络任务，显示“电量过低，请充电”画面并全刷，
    然后按 R1 断电；R1 不可用时进入休眠。收尾有时间上限，保存或取消网络任务失败也不阻止断电或休眠，
    避免电池耗尽时设备仍在运行。
- 只依据有效的 PMU 电量快照判断。读数无效、超出范围或正在充电时不触发保护。
  为避免读数抖动误触发，需要连续多次低于保护值才执行。
- 保存失败时仍显示低电量画面，但画面不得声称进度已保存。
- 同步上传或 USB 传输进行中：先按现有流程结束任务，不在上传中途标记已上传。

前提：当前电量百分比直接来自 PMU，没有本项目的校准；电压与百分比的对应关系需要在真机放电过程中记录。

验收：用可控电量读数的 host 测试覆盖阈值、抖动、充电和读数无效；真机低电量时进度已保存，
重新充电开机后从原位置继续。

## R9 · 书签

目标：在正文中标记位置，之后从列表跳回。

- 在正文工具中增加“加书签”和“删除书签”，当前页已有书签时显示为删除。
  书签列表放在目录页中，沿用现有列表组件；每条显示章节名、页码或百分比和创建时的页首文字摘要。
- 当前页有书签时，在页面角落显示小标记。位置和样式在实现时用现有视觉元素确定，记录与原稿的差异。
- 书签保存在原书旁的 `.picopage/bookmarks.json`，与 `progress.json` 一样记录 `book_id` 和 `content_revision`，
  每条书签记录锚点、摘要和本书内递增的序号，列表按序号排序。创建时间为可选字段，只在设备有可信时间
  （例如联网对时后）时填写，并记录时间来源；离线时不写入虚构时间。
  打开书时校验身份字段：与当前原书不符（例如同名替换为另一本书）时不显示、不跳转这些书签，并提示。
  在新书第一次添加书签时，旧文件改名为 `bookmarks.<book_id 前缀>.<序号>.json` 保留在同一目录，
  序号取不与已有文件冲突的最小值，不覆盖已有归档；再为新书创建新文件；
  旧文件不删除，原书恢复后可以手工改回原名。锚点使用与 `progress.json` 相同的格式，
  因此改字号或排版后仍指向同一段落；页码只作为展示值，重新排版后重算。
- 跳转到书签与目录跳转相同：页面成功呈现后才更新阅读位置。
- 清理缓存不删除书签。移动书籍时与进度一样，需要一并移动 `.picopage/` 目录。
- KOReader 同步只传阅读进度，书签不会同步到 KOReader，界面不显示同步状态。
- 不包含批注、高亮和摘录；这些仍按既定决定后置。

验收：添加、删除、跳转书签；改字号后跳转到同一段落；同名替换原书后旧书签不被使用，且可以为新书添加书签、
旧文件仍保留；同一位置反复换书时每次归档都不覆盖已有文件；离线添加的书签不含虚构时间；
文件损坏时保留原文件并提示，不影响阅读进度。

## R10 · 可选翻页效果

目标：正文翻页时可以选择过渡效果，默认无效果。

- 墨水屏无法显示连续动画，效果只能用少量局部刷新帧实现，例如按翻页方向擦除或滑入。
  具体效果和适用范围待用户决定，在真机上试验后只保留残影和耗时可以接受的效果。
- 用户提到出厂固件有翻页效果可以参考。先确认出厂固件是否有公开源码及其许可证；
  未审查前只参考可观察到的行为，不复制代码或波形参数。
- 设置放在排版或刷新设置中，保存在 `PicoPage/settings.toml`，可在单书设置中覆盖。
- 效果只改变显示过程，不改变翻页结果：效果帧不计为已呈现页面，最终页面成功显示后才更新阅读位置。
- 效果进行中的翻页输入按 D14 处理：最多补执行紧接着的一次翻页；可直接跳过剩余效果帧，显示目标页。
- K2 或映射到全刷的按键照常全刷当前页，不播放效果。现有的自动全刷间隔和刷新模式不变。
- 若某个效果在某种刷新模式下残影明显，该组合不提供选项，不在界面上留下无效的选择。

验收：开启效果后连续翻页不丢失；翻页耗时与无效果时的差异有实测记录；进度只在最终页呈现后保存。

## R11 · OTA 升级

目标：不连接电脑，在设备上安装新固件。

### 分区与前提

- 设备实测分区已有 `ota_0`、`ota_1` 两个 4 MiB 应用槽和 `otadata`，当前固件运行在 `ota_0`。
  升级只写入另一个槽，再切换启动槽；不修改分区表、bootloader、NVS 或工厂 VCOM/PMU 校准。
- `ota_1` 中现有的内容未确认。第一次升级会覆盖它，实现前需读取并记录该槽的应用信息。
- 本地构建使用的 `partitions.build.csv` 只有单个应用槽，只用于编译和大小检查。
  实现 OTA 前需让构建配置与实测布局一致，但不得用它生成的完整烧录命令覆盖设备分区。
- 应用槽剩余约 23%。新固件必须小于 4 MiB，安装前检查。

### 升级来源

1. TF 卡：用户把固件文件放到 `PicoPage/update/`，在“设置”中选择安装。不需要网络，先实现。
2. 联网下载：从用户在配置文件中指定的地址下载，例如项目的发布页面。依赖 Wi-Fi 开关（R2），
   使用 HTTPS 并校验证书，不关闭 TLS 验证。是否实现及下载地址待定。

### 安装流程

- 安装前：显示当前版本与新版本；电量须不低于 20% 或正在充电，电量读数无效且未充电时不安装；
  保存阅读进度并结束网络任务。R8 实现后，此下限改用 R8 的提醒值。
- 校验：检查 ESP-IDF 镜像头与内置 SHA-256、芯片型号和项目名 `pico_page`；任一项不符就不写入。
  下载或读取中断时不切换启动槽，当前固件继续使用。
- 写入完成并再次校验后才切换启动槽，然后重启。
- 版本比较：当前应用版本来自 `git describe`，不同分支或未提交改动的构建之间无法可靠比较新旧。
  实现 OTA 前需定义单调递增的构建号或受约束的版本号，写入应用描述。新版本不高于当前版本，
  或任一方无法比较时，提示并需用户确认才安装。
- 降级：旧固件会拒绝较新 schema 的进度和新增配置字段（见 [数据存储](storage.md)）。固件需在应用描述中声明
  能读取的最高 schema；安装前与 TF 卡上权威文件的 schema 比较，旧固件无法读取时拒绝安装并列出不兼容的文件。
  无法判断时按不兼容处理。
- 新固件首次启动后完成自检（显示、触摸），再标记为有效。TF 卡可以被取出或暂时挂载失败，
  无卡是支持的状态，不计入固件有效性；挂载错误按现有流程单独显示。

### 失败恢复

- 自检失败后自动回到旧槽需要两个条件：现有 bootloader 启用了应用回滚，且新镜像由应用在自检后确认有效，
  而不是在进入 `app_main` 前自动确认。两者都需读取现有 bootloader 与本项目构建配置后确认；
  不为此替换 bootloader。条件不满足时，不承诺自检失败后自动回滚。
- 未启用回滚时，新固件无法启动的恢复方法是用 USB 连接电脑重新写入应用。文档写清该步骤。
- 升级不修改 TF 卡上的书籍、配置和进度。新固件读取旧版本的配置文件时，按现有 schema 规则兼容。
- 新固件在被确认有效之前，不得把配置、进度或书签迁移到旧固件不能读取的新 schema。
  需要迁移时，在确认有效之后进行，或保留旧固件仍能读取的版本，确保回滚后可以继续阅读。

### 安全说明

- 设备未启用 Secure Boot，固件不验证发布者签名；能放入 TF 卡或控制下载地址的人可以安装任意固件。
  文档必须说明这一点。是否增加发布签名校验待定。

验收：TF 卡升级成功并保留进度；损坏文件、错误芯片或错误项目的镜像被拒绝且当前固件不变；
写入中断电后设备仍从旧槽启动；真机记录升级前后的启动槽与版本。
