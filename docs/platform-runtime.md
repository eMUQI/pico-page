# Read Pico 运行时适配

更新日期：2026-10-11。实现位于 `firmware/components/platform_read_pico/`。本页记录当前代码和编译检查；屏幕、TF 卡、输入及睡眠仍需真机验证。

## 接口与所有权

`pico_page/platform.h` 提供单个 Read Pico 实例。`initialize()` 记录显示和输入的调用任务，`present()`、`poll()`、`refresh_card()` 和 `sleep()` 拒绝其他任务调用。显示提交为同步调用；调用方必须在返回前保持输入像素不变。平台层不持有阅读锚点、不保存进度、不解释 K2 的产品动作。网络接口另有独立的单一任务所有者，可由工作任务串行调用，避免阻塞显示和输入任务。

| 接口 | 当前行为 |
|---|---|
| `initialize(error)` | 初始化官方 EPD 板级后端、PMU、工厂 VCOM、触摸和 TF；TF 错误不阻止错误页面显示 |
| `panel_ready()` | 指示显示驱动是否已取得有效工厂 VCOM 并完成缓冲初始化；不代表物理显示已验收 |
| `card_root()` / `card_error()` | 返回当前有效的 `/sdcard` 挂载点或空指针及原因 |
| `refresh_card(error)` | 调用方关闭所有文件后显式重新挂载；无格式化路径 |
| `present(packed, size, full_clean, error)` | 接收 684×1216 竖屏 4bpp 帧，执行波形并报告驱动返回值和电源状态 |
| `poll(event, error)` | 按下、释放、取消及电源短按、长按、拔卡事件；无事件时返回 `EventKind::None` |
| `finish_power(error)` | 调用方停止全部文件消费者后关闭面板电源并尝试卸载 TF 卡；失败不恢复读写 |
| `power_off(error)` | 校验 PMU 主机 EN 控制能力，调用官方协作关机接口，失败时返回原因 |
| `battery()` | 返回最近一次有效 PMU 状态快照；读失败时 `valid=false` |
| `set_performance(high)` | 持有或释放 CPU 最高频率锁；释放后空闲频率为 80 MHz。`present()` 总是先恢复最高频率 |
| `sleep(error)` | 关闭面板高压、使触摸进入深睡、ESP32-S3 浅睡；PMU 电源键唤醒后恢复触摸 |

实际浅睡眠返回后，平台在释放触摸锁后将 USB Serial/JTAG 的 D+/D- 上拉和下拉暂时关闭，让出 100 ms，再恢复原电阻配置与软件覆盖状态，请求电脑重新枚举。现有串口句柄需重新打开。取消入睡时不执行；唤醒后的触摸或电源清理失败也先恢复 USB。USB 已持有 TF 卡时平台拒绝休眠，不在 TinyUSB MSC 模式操作 Serial/JTAG PHY。此路径已完成代码与构建检查，电脑恢复连接的实际效果待真机验证。

`initialize()` 的非 TF 错误返回 `false`。工厂值不可读时，屏幕保持断电，此时只能通过日志报告错误。触摸初始化失败但 `panel_ready()` 为真时，调用方可以显示错误页。初始化失败后不能在同一次启动中重复分配 BSP；修复条件后需要重新启动。

## 初始化和校准

适配层直接组合锁定 BSP 的公开入口，不调用 `read_pico_init()`。初始化顺序为：

1. `epd_init()` 运行官方板级初始化。IO 扩展器自检期间 SY_EN 和 VCOM_EN 保持低电平。
2. `read_pico_pmu_init()` 建立 PMU 协议和主机就绪握手；系统时间尚未设置时，尝试读取有效 RTC 恢复 UTC 时间，失败仅记录日志。
3. 最多三次 `read_pico_pmu_vcom_get()` 读取工厂 VCOM；上游验证有效标志、500–2500 mV 范围和 10 mV 步长。
4. 将读取结果交给 `sy7636a_set_vcom()`。此时电源未启用，仅更新显示电源驱动的 RAM 配置。
5. 初始化官方波形和显示缓冲；首次 `present()` 才开启面板高压。

官方 `board_init()` 中的 1290 mV 是传给 `sy7636a_init()` 的 RAM 默认值；后者只注册 I2C 设备并配置低电平输出，不启用面板、不写 VCOM 寄存器。适配层在第一次上电前用工厂值替换它。没有调用 `read_pico_pmu_vcom_set()`、工厂校准页、PMU 配置写入或标定保存入口。

板级自检和 EPD 缓冲分配仍使用上游 `ESP_ERROR_CHECK` / `assert`；这些底层失败会中止启动，不能由适配层转换为屏幕提示。

## RTC 与系统时间

沿用官方 BSP `5f3406deec33304de8801046db583dec7c49e55b` 的 CW32 PMU 协议：`TIME_GET` 返回 UTC Unix 秒及 `time_synced`，`TIME_SYNC` 接收 4 字节小端 UTC 秒。启动时只有系统时间早于 2024-01-01 才读取 RTC；本次命令成功、响应为 OK、`time_ok` 为真、`time_synced` 为 1，且时间在 2024-01-01 至 2099-12-31 范围内才调用 `settimeofday()`。保留已有有效系统时间，不以较旧 PMU 值覆盖。响应长度校验应用于构建副本，见 [BSP 审查](bsp-review.md#rtc-响应校验与接入2026-10-11)。

SNTP 回调只设置一个原子待写标志，不访问 PMU。应用主循环在网络工作结束、无待处理输入或显示、无内容或保存任务、必要进度已保存且空闲至少 2 秒后，调用 `persist_clock()`；USB、休眠请求和电源菜单期间不执行。写入使用执行时的系统时间，不使用排队前的旧秒值。成功响应后读取 RTC，确认有效且与提交值相差 0–4 秒才记录成功；失败仅记录日志并结束本次尝试，下一次真实 NTP 回包可再次触发。不新增任务、队列、配置文件或 NVS 状态，不改变阅读进度。立即关机或一直没有空闲边界时，待写值可能尚未落入 RTC。

PMU 命令仍由应用任务串行执行。每次尝试最多调用一次 `TIME_SYNC` 和一次 `TIME_GET`，沿用 BSP 内部最多三轮命令重试及每次 I²C 调用 100 ms 超时；它们是不可抢断的同步调用，不能把空闲门槛视为响应时限。正常命令各含 30 ms 等待，故写入与读回至少包含两次等待；故障时可能明显延长，实际耗时、内部重试、输入队列压力和内存峰值仍待真机验证。主循环开始写回后出现的新输入由原输入采样队列保留。

官方 PMU 文档注明复位后 `time_synced=0`，LSI 约有 ±1–2% 误差；接入 RTC 不构成完全断电保时或长期精度保证。ESP32 浅睡沿用系统时钟，不在每次唤醒重复读取 PMU。PMU 失效时仍能离线阅读；无有效系统时间时页脚显示「—」，网络流程继续按原规则要求可用时间才进行 TLS。

## 像素、刷新和输入

输入帧每行 342 字节，偶数 x 位于低半字节，奇数 x 位于高半字节，0 为黑色、15 为白色。平台将竖屏坐标变换为官方 1216×684 原生缓冲：`native_x = y`、`native_y = 683 - x`，对应上游 `EPD_ROT_INVERTED_PORTRAIT`。触摸控制器的显示区坐标直接采用竖屏坐标。

首次呈现、上次刷新失败后的恢复和 `full_clean=true` 均调用 `epd_clear_checked()` 的物理黑白清理周期，再执行 `MODE_GC16` 全像素更新。该路径禁用前导保持跳过，不检查图像是否相同。普通更新按请求使用全屏或限定区域，正文波形可选择默认波形或 Gray8；全刷与恢复始终建立完整基准。每次更新检查面板 PGOOD、故障状态、VCOM 读回值和波形返回值；失败后基准帧失效，下次执行清理恢复。健康供电下发生行队列欠载时，把像素时钟降为 12 MHz，并对同一目标最多执行一次清屏和 GC16 重画；仅在恢复成功后确认呈现，重试失败则报告失败。

构建时应用的 epdiy 补丁提供 `epd_clear_checked()`，适配层检查清屏和后续 GC16 的结果及电源状态；仍无法读取像素确认成像，真机检查不可省略。默认时钟为官方初始化使用的 18 MHz。更新后 8 秒无新帧时，由 `poll()` 关闭面板高压。

三个电容键不是 ESP32 GPIO 按键，识别区域来自同一 commit 的 `main/ui/ui_menu.h`：触摸原始 y ≥ 1300，K1/K2/K3 的 x 分别为 `[0,160)`、`[160,320)`、`[320,480)`。显示区为 x < 684、y < 1216；中间未定义区域不触发动作。这些边界来自上游硬件实现，尚未在用户设备上实测。

一次触摸序列仅有一个递增序号，不生成长按或自动重复。多点触摸、跨越按键区域和 I2C 读取失败取消当前序列，并等待全部释放后重新接收输入。开机、拔卡、电源动作和唤醒期间也等待释放，避免输入尾部进入下一页面。拔卡或电源事件打断已有序列时，先返回该序列的 `Cancel`，下一次轮询再返回系统事件。I2C 失败时，调用方仍需处理随失败返回的 `Cancel`。

## TF 卡和电源

普通挂载使用 `read_pico_sd_start_probe()` / `read_pico_sd_remount()`，保持上游的 SDMMC 接线、超时重试及介质失效锁存。挂载最多等待 5 秒。`read_pico_sd_get_info()` 检测移除后，即使卡重新插入也要求显式重新挂载。普通探测不创建目录、复制演示资源或格式化；上游的演示目录创建仅属于格式化函数，适配层不调用它。卡移除检查间隔为 500 ms；文件读写自身的错误仍由 `store` / 内容层处理。

睡眠前调用方必须完成显示事务、进度保存及网络停止。当前采用保留 RAM 和挂载状态的浅睡，不切断主电源、不进入 ESP 深睡、不重新挂载仍有打开文件的介质。触摸芯片深睡期间，触摸和 K1/K2/K3 都不承担唤醒；唤醒来源仅为 PMU 电源键通过官方 `READ_PICO_IOE_INT_GPIO` 传播的中断。PMU 有未确认事件时一直拉低 CW_INT（FCA9555 P0.2），运行期约每 30 秒的电池采样等非按键事件也会唤醒 ESP32-S3；此时先确认全部 PMU 事件，再读 IO 扩展器清中断，因为 CW_INT 释放本身也是一次输入变化。清中断后再读一次 PMU 队列：若有事件在确认与清中断之间到达，CW_INT 会保持低电平且不再产生新边沿，浅睡将无法再被唤醒，因此队列不为空时继续处理。进睡前的空闲检查使用同一判断。没有电源键事件时重新浅睡；唤醒后读取 PMU 失败时每 20 ms 重试，中断线或 PMU 队列 2 秒内仍不空闲、或 PMU 仍读取失败才报告睡眠失败。`esp_light_sleep_start()` 在唤醒线已为低时返回 `ESP_ERR_SLEEP_REJECT`，平台按立即唤醒处理并等待 20 ms，不当作睡眠失败。触摸中断只在第一次入睡前取消休眠：触摸芯片深睡后须复位才恢复，真机上每次浅睡唤醒都会在其中断线（GPIO43）记录一次下降沿，入睡后的这类信号只计数。唤醒后先恢复触摸，并消费唤醒按键的后续事件。休眠返回约 1 秒后，`poll()` 输出一行 `Light sleep:` 汇总，包含唤醒次数、被拒次数、PMU 重试次数、触摸线边沿与低电平次数、首个 PMU 错误和结束原因；更早的输出落在 USB 重新枚举之前，电脑收不到。

取消锁屏后，主循环先恢复页面并派发保留的输入，再允许 Wi-Fi 重连请求进入网络 worker。电源菜单及其资源等待阶段保留 Wi-Fi 请求，取消菜单后才可派发。保留的触摸在页面恢复后继续检查长按阈值；书库条目和正文图片达到阈值时即执行，消费同一序列，实际松手不重复触发。队列已有输入时先处理队列。加速度计只初始化并关闭采样，不启用拿起唤醒。读取电池失败、PMU 未设置电池有效位或电量超出协议范围时，不把快照作为有效电量；没有新增电量校准或 PMU 阈值设置。

### 电源键菜单与关机、重启（2026-10-08）

PMU `KEY_LONG` 打开菜单，`KEY_SHORT` 仍进入浅睡；同次长按的重复及后续短按被消费。启动或唤醒时先等待电源键释放，不改 PMU 阈值。持续按住仍可能触发硬件强制关机。网络、USB、诊断传输或内容任务进行中提示先结束任务。菜单取消恢复原页面、草稿和同步候选。菜单的打开、取消、本地保存失败页和「先结束任务」提示使用不清屏的整屏更新；帧呈现失败后显示基准失效，下一帧按全刷重画。关机、重启的结果画面仍全刷。

触摸采样器随释放事件携带本次接触的坐标范围；电源菜单要求所有已采样位置都在原按钮内，滑出后再移回也取消。派发仍等待松手；呈现前开始的输入及打开菜单时已按住的输入被消费。点击关机/重启直接保存 TF 卡上的已呈现位置和最近阅读记录，不启动云端同步、不再二次确认。本地保存失败仅提供「仍然关机/重启」和「返回」。此时未清除同步状态，返回后原同步操作仍有效。保存成功或明确跳过后，停止内容工作、尝试全刷结果画面、关闭文档与字体，再尝试卸载 TF 卡。最终呈现或卸载失败不恢复应用，也不阻止 `esp_restart()` 或 PMU 断电请求。`finish_power()` 即使卸载失败也关闭面板电源；所有文件消费者停止后才允许继续断电。

关机使用 `PMU_CAP_HOST_EN_CONTROL` 与锁定 BSP 的 `read_pico_pmu_power_off()`：`HOST_REQUEST_OFF` → `SHUTDOWN_READY`，BSP 自带 logical-off 回退和有界轮询。不支持或命令失败时，以内置字体尝试呈现硬件关机提示，保留真实的本地保存结果；随后关闭面板电源，停止应用及存储操作，不重新挂载 TF 或恢复阅读现场。USB 供电下命令成功仍可能保持主机供电，因此成功后同样停止应用工作。

长按响应时间、硬件强制关机时序、真实断电电流、USB 供电表现与重启恢复仍待设备验收。

## 显式网络会话

`connect_network()`、`http_request()`、`disconnect_network()` 在独立网络任务中串行执行。应用先显示连接状态，再分派用户明确发起的同步请求。打开书籍、翻页和启动不会自动联网。睡眠前应用必须等待网络任务结束并断开网络，不在传输中切断其对象或电源。

`connect_network()` 接收网络名称和密码，不读文件。应用在分派同步/手动连接前读取目标凭据快照；网络 worker 使用应用传入的凭据快照；`PicoPage/network.toml` 的解析在 host 上有测试。最多保存 5 个网络，名称不重复：

```toml
schema_version = 2
selected_ssid = "YOUR_2_4_GHZ_NETWORK" # 指定只连这个网络；省略本行或写空串表示自动

[[wifi]]
ssid = "YOUR_2_4_GHZ_NETWORK"
password = "YOUR_NETWORK_PASSWORD"
last_connected = 1791300000   # 可选：最近一次连上的 Unix 秒数，设备记录

[[wifi]]
ssid = "ANOTHER_NETWORK"
password = ""                 # 开放网络
```

旧格式 `schema_version = 1` 加单个 `[wifi]` 表仍可读取，按一个没有连接时间的条目处理；设备下次写入该文件时改为 schema 2。文件不存在表示未配置。上面仅为格式说明，没有创建含凭据的工作区文件。该文件包含明文秘密，不属于普通阅读配置或公开示例，应从 Git、诊断导出和常规分享备份中排除。`integrations.toml` 仍只放非敏感配置；账户凭据由同步模块的独立本地文件管理。读取限制为 4 KiB，只接受上述两种结构；内容无效时设备不改写该文件，解析错误不输出原文或解析器片段。Wi-Fi 驱动使用 RAM 配置并关闭 NVS 保存，不把密码写入 Flash；断开时释放 Wi-Fi 驱动。

连接方式由 `network.toml` 根字段 selected_ssid 决定（D37）：
- 没有该字段、字段为空串，或所写名称已不在已保存网络中：**自动**。worker 扫描一次（最多 10 秒），用 `provision::connection_order()` 取出在附近的已保存网络，按信号从强到弱逐个连接，第一个连上的就用。附近没有已保存网络时不尝试连接。全部失败时先报密码被拒的那个网络，其次报最后一次失败。
- 字段为已保存的网络名：**指定**。只连这个网络，不扫描、不改用其他网络；失败后由用户选择重试或本次改用自动。
- 已经在线时（手动保持或同步事务未结束），新任务直接使用当前连接，不重新选网。

添加网络不写 selected_ssid；忘记被指定的网络时把它写成空串，即回到自动。连接候选在应用任务上从 TF 卡读出并复制进请求；worker 不为选网读卡。成功连接仍可更新末项和有效时间下的 last_connected（至少相差一小时），不修改连接方式。同步/手动连接的历史记录由应用在无卡写任务的空闲边界提交；连接、TLS 和等待用户决定不持有 TF 文件。设备界面和电脑脚本（`tools/setup_network.py`）修改时都保留注释、原文和连接方式，不会因为添加或更新网络而指定它；不支持安全修改的语法或提交前的外部变更会拒绝写入。旧固件不识别 selected_ssid，会拒绝配置；并且旧固件把缺少该字段的文件理解为「使用末项」。降级前需备份并处理此字段。

自动方式的最长等待：一次扫描 10 秒，加上每个候选最多 20 秒（最多 5 个）。扫描与每次连接之间都检查取消标记。

worker 保留两类原子取消标记：手动保持、完整同步事务；没有使用者时停止驱动。GET 成功后保留至用户处置，最多两分钟；PUT 复用同一事务，结束/失败/取消后释放，手动保持不受影响。worker 串行处理请求，持有无线时每 200 ms 检查标记、期限和连接丢失；无线已释放时阻塞等待新队列消息；手动保持只重连原网络一次，不重新扫描，失败等待用户操作。热点期间手动保持意图暂停，退出不新建 STA；点「立即连接」才恢复。休眠/关机清除全部标记并等待 radio_active 归零。状态快照队列最多四个指针，满时删除最旧累积快照；UI 消费最新状态，不轮询 RSSI 或按秒重绘。网络任务仍为 16 KiB 栈、优先级 3、无固定亲和性；请求/响应队列各一项，无新增任务。

关联/取得 IP 的等待限时为 20 秒；按关联事件区分连接超时与 DHCP 超时。同步请求随后最多等待 10 秒 SNTP 时间同步（`synchronize_clock()`），默认服务器为 `pool.ntp.org`。每次连接首次校时即使已有 RTC 时间，也等待真实 NTP 回包；同一连接已成功校时后不再重复等待。超时而已有有效系统时间时允许继续 HTTPS，仍启用证书日期校验；没有可用系统时间时拒绝 HTTPS。只有真实 NTP 回包触发 RTC 写回，单纯连接 Wi-Fi、保存凭据或 RTC 恢复不会冒充网络校时成功。扫描、连接与对时的事件等待每 100 ms 检查取消；扫描总等待上限 10 秒。驱动初始化/停机和已有连接断开的最多 2 秒等待不由此抢断。经已保存 Wi-Fi 传书只在局域网内传输，不等待对时。此版本支持开放网络或 WPA2 及以上个人网络，不提供企业认证。失败时 `ConnectFailure` 给出停在哪一步（启动、关联、取地址、对时）和驱动原因编号。连接失败显示实际驱动原因编号，不按 SSID 猜测频段或密码错误。worker 另把失败归为三类交给界面（`LinkFailure`）：不在附近（驱动原因 201、210–212）、密码被拒（2、14、15、202、204）、其他。界面只用它决定下一步的按钮，例如只有密码被拒时主按钮才是「重新输入密码」。

HTTP 只接受 HTTPS GET/PUT/POST，使用 ESP-IDF 系统证书包和主机名验证，不自动跟随重定向。mbedTLS 的动态内存从 PSRAM 分配（`CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC`），因为主内部堆容不下常驻的 Wi-Fi 驱动再加一个 TLS 会话；设备未启用 Flash 加密，PSRAM 中的会话数据不加密。自签证书服务在未安装可信证书前会失败，当前没有关闭 TLS 验证的入口。请求体最大 16 KiB，响应体最大 32 KiB，头字段数量和值长度也有限制。连接/头部操作有 10 秒 I/O 超时，读取操作使用最多 5 秒 I/O 超时，并在操作之间检查 25 秒会话期限；期限检查不会强杀正在执行的驱动调用。传输失败清空不完整响应；HTTP 状态码由同步层单独解释。失败的 PUT/POST 可能已经由服务端处理，调用方必须保留「结果待确认」状态，不能直接重试覆盖。调用方可以传入共享原子取消标志。工作任务在连接、发送和读取边界检查它，不会从其他任务关闭仍在使用的 HTTP 对象。取消不能撤销已经到达服务端的写入，也不会强制中断正在进行的驱动调用。

## 在设备上添加网络和验证账户

手机配置会话已删除（D37）；`start_portal_server()`、配置网页和表单解析不再存在。流程和界面见 [UI 实现](ui-implementation.md) 第 21 节。

- 扫描：`WifiOperation::Kind::Scan`。worker 启动站点接口并扫描一次，返回最多 20 个名称、信号强度和是否开放，随后释放无线。
- 添加或更新密码：`WifiOperation::Kind::Join`。worker 用键盘输入的凭据建立一条独立连接，成功或失败后都释放无线。应用任务只在连接成功、且用户没有取消时，用 `save_network_edit()` 把网络写入 `network.toml`，并记录连接时间。取消后迟到的成功结果按请求编号丢弃，不写卡。已满 5 个时只接受已保存网络的密码更新。
- 立即连接：`WifiOperation::Kind::Connect`，按连接方式选网，成功后由手动保持标记维持到断开或休眠。
- 验证同步账户：与同步请求走同一条路径（联网、对时、`GET /users/auth`）。应用任务只在返回 200 时写 `sync.toml`；401/403、其他状态码、联网失败和取消都不写。密码明文只在本次流程的内存中，写入的是它的 MD5。
- 移除同步账户：确认后删除 `PicoPage/sync.toml`（`FileStore::remove_private()`），不联网。

键盘输入期间不使用无线，也不读写 TF 卡。密码草稿在流程结束、休眠或成功保存后清除。

## Wi-Fi 传书会话

- 经设备热点：`start_access_point()` 以 APSTA 模式开启热点，名称为 `PicoPage-` 加 MAC 末两字节，WPA2，每次会话随机生成 8 位密码，最多 2 台设备，地址 192.168.4.1；另有一个任务在 UDP 53 端口把所有 A 记录查询答为热点地址。`start_upload_server()` 在 `GET /` 提供传书页，其他路径 303 跳转到它。
- 经已保存的 Wi-Fi：按连接方式选网，已经在线时复用当前连接；不开热点，也不运行名称服务。会话中若站点连接失效，传书服务结束，设备返回「网络与传输」并显示断线原因。`start_upload_server()` 只在 `GET /<6 位随机路径>` 提供传书页，其余路径返回提示页；设备屏幕的二维码和文字地址都包含这段路径。连接失败时不进入会话页，网络页显示原因。
- 两种方式都在页面中注入本次会话的 32 位十六进制令牌；`POST /check`、`POST /upload` 必须带该令牌。拒绝时按原因返回状态码：400（文件名）、409（同名）、413（大小）、415（格式）只涉及这一本，传书页继续下一本；403（会话无效）、500、503、507 等停下整批。
- 上传/校验 handler 在开始和结束时通过回调记录单调活动时间及阶段，两者与 worker 的到期检查共用会话锁。即使短请求在两次轮询间完成也重新计时；handler 运行时不按空闲到期，结束后 10 分钟无活动才结束服务。传书会话暂停自动休眠；电源键请求休眠时结束会话，先由文件事务回滚或完成提交，stop_portal_server() 返回后才释放网络及卡。取消/失败不增加已保存数；已进入提交边界的完整文件仍以真实提交结果为准。
- 每本书提交并回读校验后，HTTP 任务回调网络任务，设备状态区更新为「已保存 N 本 · 最近：书名」。书名过长时设备截短显示；完整的逐本结果可在浏览器中查看。

预算（按输入上限推得，未在真机测量）：HTTP 任务栈 8 KiB，DNS 任务栈 4 KiB（其中收发缓冲 528 字节），网络任务沿用原有 16 KiB；二维码两个 407 字节缓冲。Wi-Fi 驱动在 APSTA 下和 TLS 握手占用的内部 RAM 没有数字，必须在真机上读 `status` 的 `internal`、`largest_internal`。固件比版本 E 增加 103,008 字节。

已知限制：连接其他信道的网络时热点会跟着换信道，手机可能短暂掉线；连接等待可取消，但驱动调用、HTTP I/O 和文件提交期间只能在返回后的安全边界退出。热点密码在射频开启前生成，`esp_random()` 此时是伪随机数，另混入了点击时刻。

早期平台接入阶段只编译网络调用路径，未连接真实服务或开启设备热点。后续设备及同步证据见开发状态，不以这条历史结论描述当前验证范围。
