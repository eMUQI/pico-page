# Read Pico 运行时适配

日期：2026-10-06。实现位于 `firmware/components/platform_read_pico/`。
本页记录当前代码和编译检查；屏幕、TF 卡、输入及睡眠仍需真机验证。

## 接口与所有权

`pico_page/platform.h` 提供单个 Read Pico 实例。`initialize()` 记录显示和输入的调用任务，
`present()`、`poll()`、`refresh_card()` 和 `sleep()` 拒绝其他任务调用。
显示提交为同步调用；调用方必须在返回前保持输入像素不变。
平台层不持有阅读锚点、不保存进度、不解释 K2 的产品动作。
网络接口另有独立的单一任务所有者，可由工作任务串行调用，避免阻塞显示和输入任务。

| 接口 | 当前行为 |
|---|---|
| `initialize(error)` | 初始化官方 EPD 板级后端、PMU、工厂 VCOM、触摸和 TF；TF 错误不阻止错误页面显示 |
| `panel_ready()` | 指示显示驱动是否已取得有效工厂 VCOM 并完成缓冲初始化；不代表物理显示已验收 |
| `card_root()` / `card_error()` | 返回当前有效的 `/sdcard` 挂载点或空指针及原因 |
| `refresh_card(error)` | 调用方关闭所有文件后显式重新挂载；无格式化路径 |
| `present(packed, size, full_clean, error)` | 接收 684×1216 竖屏 4bpp 帧，执行波形并报告驱动返回值和电源状态 |
| `poll(event, error)` | 按下、释放、取消及电源短按、长按、拔卡事件；无事件时返回 `EventKind::None` |
| `finish_power(error)` | 调用方停止全部文件消费者后关闭面板电源并尝试卸载 TF 卡；失败不恢复读写 |
| `power_off(error)` | 校验 PMU 主机 EN 控制能力，调用官方协作关机接口，失败时返回原因 |
| `battery()` | 返回最近一次有效 PMU 状态快照；读失败时 `valid=false` |
| `set_performance(high)` | 持有或释放 CPU 最高频率锁；释放后空闲频率为 80 MHz。`present()` 总是先恢复最高频率 |
| `sleep(error)` | 关闭面板高压、使触摸进入深睡、ESP32-S3 浅睡；PMU 电源键唤醒后恢复触摸 |

`initialize()` 的非 TF 错误返回 `false`。工厂值不可读时，屏幕保持断电，
此时只能通过日志报告错误。触摸初始化失败但 `panel_ready()` 为真时，调用方可以显示错误页。
初始化失败后不能在同一次启动中重复分配 BSP；修复条件后需要重新启动。

## 初始化和校准

适配层直接组合锁定 BSP 的公开入口，不调用 `read_pico_init()`。
初始化顺序为：

1. `epd_init()` 运行官方板级初始化。IO 扩展器自检期间 SY_EN 和 VCOM_EN 保持低电平。
2. `read_pico_pmu_init()` 建立 PMU 协议和主机就绪握手。
3. 最多三次 `read_pico_pmu_vcom_get()` 读取工厂 VCOM；上游验证有效标志、500–2500 mV 范围和 10 mV 步长。
4. 将读取结果交给 `sy7636a_set_vcom()`。此时电源未启用，仅更新显示电源驱动的 RAM 配置。
5. 初始化官方波形和显示缓冲；首次 `present()` 才开启面板高压。

官方 `board_init()` 中的 1290 mV 是传给 `sy7636a_init()` 的 RAM 默认值；
后者只注册 I2C 设备并配置低电平输出，不启用面板、不写 VCOM 寄存器。
适配层在第一次上电前用工厂值替换它。没有调用 `read_pico_pmu_vcom_set()`、工厂校准页、
PMU 配置写入或标定保存入口。

板级自检和 EPD 缓冲分配仍使用上游 `ESP_ERROR_CHECK` / `assert`；
这些底层失败会中止启动，不能由适配层转换为屏幕提示。

## 像素、刷新和输入

输入帧每行 342 字节，偶数 x 位于低半字节，奇数 x 位于高半字节，0 为黑色、15 为白色。
平台将竖屏坐标变换为官方 1216×684 原生缓冲：`native_x = y`、`native_y = 683 - x`，
对应上游 `EPD_ROT_INVERTED_PORTRAIT`。触摸控制器的显示区坐标直接采用竖屏坐标。

首次呈现、上次刷新失败后的恢复和 `full_clean=true` 均调用 `epd_clear()` 的物理黑白清理周期，
再执行 `MODE_GC16` 全像素更新。该路径禁用前导保持跳过，不检查图像是否相同。
普通更新采用 `MODE_GL16` 全像素路径，使上游白底补偿覆盖未变化像素。
每次更新检查面板 PGOOD、故障状态、VCOM 读回值和波形返回值；失败后基准帧失效，下次执行清理恢复。
供数队列不足时把后续像素时钟降为官方支持的 12 MHz；没有把失败帧确认成成功。

`epd_clear()` 在锁定版本中返回 `void`，不能单独确认清理周期的驱动结果。
适配层随后检查 GC16 返回值及电源状态，但仍无法读取像素确认成像；真机检查不可省略。
默认时钟为官方初始化使用的 18 MHz。更新后 8 秒无新帧时，由 `poll()` 关闭面板高压。

三个电容键不是 ESP32 GPIO 按键，识别区域来自同一 commit 的 `main/ui/ui_menu.h`：
触摸原始 y ≥ 1300，K1/K2/K3 的 x 分别为 `[0,160)`、`[160,320)`、`[320,480)`。
显示区为 x < 684、y < 1216；中间未定义区域不触发动作。
这些边界来自上游硬件实现，尚未在用户设备上实测。

一次触摸序列仅有一个递增序号，不生成长按或自动重复。
多点触摸、跨越按键区域和 I2C 读取失败取消当前序列，并等待全部释放后重新接收输入。
开机、拔卡、电源动作和唤醒期间也等待释放，避免输入尾部进入下一页面。
拔卡或电源事件打断已有序列时，先返回该序列的 `Cancel`，下一次轮询再返回系统事件。
I2C 失败时，调用方仍需处理随失败返回的 `Cancel`。

## TF 卡和电源

普通挂载使用 `read_pico_sd_start_probe()` / `read_pico_sd_remount()`，
保持上游的 SDMMC 接线、超时重试及介质失效锁存。挂载最多等待 5 秒。
`read_pico_sd_get_info()` 检测移除后，即使卡重新插入也要求显式重新挂载。
普通探测不创建目录、复制演示资源或格式化；上游的演示目录创建仅属于格式化函数，适配层不调用它。
卡移除检查间隔为 500 ms；文件读写自身的错误仍由 `store` / 内容层处理。

睡眠前调用方必须完成显示事务、进度保存及网络停止。
当前采用保留 RAM 和挂载状态的浅睡，不切断主电源、不进入 ESP 深睡、不重新挂载仍有打开文件的介质。
触摸芯片深睡期间，触摸和 K1/K2/K3 都不承担唤醒；唤醒来源仅为 PMU 电源键通过官方
`READ_PICO_IOE_INT_GPIO` 传播的中断。PMU 有未确认事件时一直拉低 CW_INT（FCA9555 P0.2），
运行期约每 30 秒的电池采样等非按键事件也会唤醒 ESP32-S3；此时先确认全部 PMU 事件，再读 IO 扩展器清中断，
因为 CW_INT 释放本身也是一次输入变化。清中断后再读一次 PMU 队列：若有事件在确认与清中断之间到达，CW_INT 会保持低电平且不再产生新边沿，
浅睡将无法再被唤醒，因此队列不为空时继续处理。进睡前的空闲检查使用同一判断。
没有电源键事件时重新浅睡；中断线或 PMU 队列 2 秒内仍不空闲才报告睡眠失败。
唤醒后先恢复触摸，并消费唤醒按键的后续事件。
加速度计只初始化并关闭采样，不启用拿起唤醒。
读取电池失败、PMU 未设置电池有效位或电量超出协议范围时，不把快照作为有效电量；
没有新增电量校准或 PMU 阈值设置。

### 电源键菜单与关机、重启（2026-10-08）

PMU `KEY_LONG` 打开菜单，`KEY_SHORT` 仍进入浅睡；同次长按的重复及后续短按被消费。
启动或唤醒时先等待电源键释放，不改 PMU 阈值。持续按住仍可能触发硬件强制关机。
网络、USB、诊断传输或内容任务进行中提示先结束任务。菜单取消恢复原页面、草稿和同步候选。

触摸采样器随释放事件携带本次接触的坐标范围；电源菜单要求所有已采样位置都在原按钮内，
滑出后再移回也取消。派发仍等待松手；呈现前开始的输入及打开菜单时已按住的输入被消费。
点击关机/重启直接保存 TF 卡上的已呈现位置和最近阅读记录，不启动云端同步、不再二次确认。
本地保存失败仅提供“仍然关机/重启”和“返回”。此时未清除同步状态，返回后原同步操作仍有效。
保存成功或明确跳过后，停止内容工作、尝试全刷结果画面、关闭文档与字体，再尝试卸载 TF 卡。
最终呈现或卸载失败不恢复应用，也不阻止 `esp_restart()` 或 PMU 断电请求。
`finish_power()` 即使卸载失败也关闭面板电源；所有文件消费者停止后才允许继续断电。

关机使用 `PMU_CAP_HOST_EN_CONTROL` 与锁定 BSP 的 `read_pico_pmu_power_off()`：
`HOST_REQUEST_OFF` → `SHUTDOWN_READY`，BSP 自带 logical-off 回退和有界轮询。
不支持或命令失败时，以内置字体尝试呈现硬件关机提示，保留真实的本地保存结果；
随后关闭面板电源，停止应用及存储操作，不重新挂载 TF 或恢复阅读现场。
USB 供电下命令成功仍可能保持主机供电，因此成功后同样停止应用工作。

长按响应时间、硬件强制关机时序、真实断电电流、USB 供电表现与重启恢复仍待设备验收。

## 显式网络会话

`connect_network()`、`http_request()`、`disconnect_network()` 在独立网络任务中串行执行。
应用先显示连接状态，再分派用户明确发起的同步请求。打开书籍、翻页和启动不会自动联网。
睡眠前应用必须等待网络任务结束并断开网络，不在传输中切断其对象或电源。

`connect_network()` 接收网络名称和密码，不读文件。网络任务用 `provision::load_networks()` 读取 TF 卡的
`PicoPage/network.toml`（该解析在 host 上有测试）。最多保存 5 个网络，名称不重复：

```toml
schema_version = 2

[[wifi]]
ssid = "YOUR_2_4_GHZ_NETWORK"
password = "YOUR_NETWORK_PASSWORD"
last_connected = 1791300000   # 可选：最近一次连上的 Unix 秒数，设备记录

[[wifi]]
ssid = "ANOTHER_NETWORK"
password = ""                 # 开放网络
```

旧格式 `schema_version = 1` 加单个 `[wifi]` 表仍可读取，按一个没有连接时间的条目处理；
设备下次写入该文件时改为 schema 2。文件不存在表示未配置。
上面仅为格式说明，没有创建含凭据的工作区文件。
该文件包含明文秘密，不属于普通阅读配置或公开示例，应从 Git、诊断导出和常规分享备份中排除。
`integrations.toml` 仍只放非敏感配置；账户凭据由同步模块的独立本地文件管理。
读取限制为 4 KiB，只接受上述两种结构；内容无效时设备不改写该文件，解析错误不输出原文或解析器片段。
Wi-Fi 驱动使用 RAM 配置并关闭 NVS 保存，不把密码写入 Flash；断开时释放 Wi-Fi 驱动。

联网前网络任务先扫描一次（只保存一个网络时省略），按信号强弱依次尝试附近的已保存网络；
附近没有任何已保存网络时，只尝试列表最后的网络。设备成功连接后将该网络移到列表末尾；
有有效系统时间且记录时间与当前相差至少一小时时，同时更新 `last_connected`。
列表顺序或连接时间变化时，设备在原 TOML 文本上修改对应条目并比较提交，保留注释和未改动格式；
手机端增删网络或替换密码也只修改相关条目。无法安全保留原文件语法，或保存前检测到外部修改时，设备停止写入并提示失败。
电脑端 `tools/setup_network.py` 添加网络或替换密码时也保留原文件的注释和未改动格式；不支持安全修改的写法会提示并停止写入。
没有有效时间时不填写虚构的时间。

取得 IP 的等待限时为 20 秒。同步请求随后最多等待 10 秒 SNTP 时间同步（`synchronize_clock()`），
默认服务器为 `pool.ntp.org`；没有可用系统时间时拒绝 HTTPS，不关闭证书日期校验。
经已保存 Wi-Fi 传书只在局域网内传输，不等待对时。
此版本支持开放网络或 WPA2 及以上个人网络，不提供企业认证或设备文字输入界面。
失败时 `ConnectFailure` 给出停在哪一步（启动、关联、取地址、对时）和驱动原因编号。
连接失败显示实际驱动原因编号，不按 SSID 猜测频段或密码错误。

HTTP 只接受 HTTPS GET/PUT/POST，使用 ESP-IDF 系统证书包和主机名验证，不自动跟随重定向。
自签证书服务在未安装可信证书前会失败，当前没有关闭 TLS 验证的入口。
请求体最大 16 KiB，响应体最大 32 KiB，头字段数量和值长度也有限制。
连接/头部操作有 10 秒 I/O 超时，读取操作使用最多 5 秒 I/O 超时，并在操作之间检查 25 秒会话期限；
期限检查不会强杀正在执行的驱动调用。传输失败清空不完整响应；HTTP 状态码由同步层单独解释。
失败的 PUT/POST 可能已经由服务端处理，调用方必须保留“结果待确认”状态，不能直接重试覆盖。
调用方可以传入共享原子取消标志。工作任务在连接、发送和读取边界检查它，
不会从其他任务关闭仍在使用的 HTTP 对象。取消不能撤销已经到达服务端的写入，
也不会强制中断正在进行的驱动调用。

## 手机配置会话

用户在设置中开启后，网络任务运行一次会话，流程和界面见 [UI 实现](ui-implementation.md) 第 13、15 节。

- `start_access_point()`：APSTA 模式，热点名 `PicoPage-` 加 MAC 末两字节，WPA2，每次会话随机生成 8 位密码，
  最多 2 台设备，地址 192.168.4.1。启动后扫描一次周围网络，最多 20 个名称及信号强度。
- `start_portal_server()`：`esp_http_server` 在 80 端口提供 `GET /` 和 `POST /save`，最多 3 个连接，
  表单正文上限 4096 字节；其他路径 303 跳转到配置页。另有一个任务在 UDP 53 端口把所有 A 记录查询答为热点地址，
  使手机连上热点后把配置页当作登录页弹出。
- 每次提交只带一个动作（`action`）：
  - `wifi_add`：表单非空 `ssid` 表示从扫描列表选择，先 `connect_network()` 连接并取得 IP 地址，成功后保存；
    空 `ssid` 配合 `manual` 表示手动填写，校验名称和密码格式后直接保存到 `network.toml`，不操作连接。
    未开启的手机热点也可手动填写；同名网络替换密码，已满 5 个时拒绝新名称。
    仅成功连接时提供连接时间；直接保存传入 0，新网络不记录连接时间，同名更新保留原连接时间。
  - `wifi_delete`：从 `network.toml` 删除该网络，不联网验证。
  - `account`：按扫描结果连接已保存的网络，对时，再用 `GET /users/auth` 验证同步账户，通过后只写 `sync.toml`。

  Wi-Fi 与账户分别写入，一项失败不回滚、也不改动另一项。配置页在处理中显示当前阶段，每 2 秒刷新。
  手机热点先保存并在设备上结束配置，再开启手机的 2.4 GHz 热点，使用同步或经已保存的 Wi-Fi 传书触发连接。
  从列表选择的网络验证时，APSTA 保留设备热点，但信道可能随站点连接变化，手机可能短暂断开。
  手机提交前和验证中提示看设备屏幕；设备显示连接、验证后保存、未验证直接保存及失败原因。
  结果在当前会话的设备画面和 `PageState` 中保留，手机重连设备热点后打开配置页可再次查看。
- 会话在用户点“结束配置”、10 分钟没有提交、配置页被错误页取代或按下电源键时结束，随后释放 Wi-Fi 驱动。

## Wi-Fi 传书会话

- 经设备热点：与配置会话相同的热点和名称服务，`start_upload_server()` 在 `GET /` 提供传书页。
- 经已保存的 Wi-Fi：`scan_networks()` 后按上述顺序连接已保存的网络，不开热点，也不运行名称服务。
  会话中若站点连接失效，传书服务结束，设备返回“网络与传输”并显示断线原因。
  `start_upload_server()` 只在 `GET /<6 位随机路径>` 提供传书页，其余路径返回提示页；
  设备屏幕的二维码和文字地址都包含这段路径。连接失败时不进入会话页，网络页显示原因。
- 两种方式都在页面中注入本次会话的 32 位十六进制令牌；`POST /check`、`POST /upload` 必须带该令牌。
  拒绝时按原因返回状态码：400（文件名）、409（同名）、413（大小）、415（格式）只涉及这一本，
  传书页继续下一本；403（会话无效）、500、503、507 等停下整批。
- 每本书提交并回读校验后，HTTP 任务回调网络任务，设备状态区更新为“已保存 N 本 · 最近：书名”。
  书名过长时设备截短显示；完整的逐本结果可在浏览器中查看。

预算（按输入上限推得，未在真机测量）：HTTP 任务栈 8 KiB，DNS 任务栈 4 KiB（其中收发缓冲 528 字节），
网络任务沿用原有 16 KiB；配置页固定部分约 1.9 KB，20 个网络名称转义后最多再加约 4.2 KB；
二维码两个 407 字节缓冲。Wi-Fi 驱动在 APSTA 下和 TLS 握手占用的内部 RAM 没有数字，必须在真机上读 `status` 的
`internal`、`largest_internal`。固件比版本 E 增加 103,008 字节。

已知限制：连接其他信道的网络时热点会跟着换信道，手机可能短暂掉线；`connect_network()` 进行中不能取消，
点“结束配置”后最长要等约 30 秒，当前连接尝试结束后不再尝试后续网络；热点密码在射频开启前生成，
`esp_random()` 此时是伪随机数，另混入了点击时刻。

本轮只编译网络调用路径，没有读取真实 Wi-Fi/账户凭据，没有向真实同步服务发请求，也没有在真机上开过热点。
