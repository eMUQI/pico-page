# G1a 文件存储实现

`reader_store` 提供 C++17 的 `pico_page::FileStore`，同一源码用于 host 与 ESP-IDF。公开类型与行为见 `firmware/components/reader_store/include/pico_page/store.h`。当前实现进度保存/恢复、配置读取与受限写回、最近书籍记录和缓存清理；不建立数据库、隐藏 NVS 权威或后台扫描任务。

## 进度提交与恢复

调用者传入卡根目录、卡根相对书籍路径及已核实的原书 `book_id` / `content_revision`。store 不根据文件名推断内容身份，也不负责计算原书摘要。临时文件不参与恢复。

保存顺序：

1. 校验记录、路径与现有主记录/恢复备份的身份和版本。
2. 写 `progress.json.tmp`，完成文件 `fsync` 和关闭，重新读取并核对全部字段。
3. 当主记录有效时，将该已提交记录写入并验证 `progress.json.bak.tmp`，替换备份。如果主记录损坏或缺失而使用备份恢复，保留这份备份，不重写唯一有效副本。
4. 移除旧主文件，将验证过的临时文件重命名为 `progress.json`，再读回核对。
5. 只有所有适用步骤成功才返回准确的 `ReadingRecord`。失败结果没有确认记录；发布后验证失败仍可能留下有效主文件，下次加载会重新校验。

ESP-IDF FatFs 的 `rename` 不覆盖已有目标。host 和固件都执行「保留另一份有效记录 → 删除目标 → 重命名」协议，不能称为无间隙的 POSIX 原子替换。主文件缺失或损坏时可读取有效 `.bak`，并标明恢复来源；发现不支持的新 schema 或身份不符时返回明确错误，不静默采用旧备份或重写新格式。同一写入者不能回写更低的修订；不同写入者之间不比较计数大小。相同记录的保存重试也重新完成写入、文件同步和发布验证，不因读回字节相等而直接返回成功。每次保存都重新同步伴随目录的父目录，避免上次创建目录后的同步失败被「目录已存在」掩盖。仅有备份可恢复时，重试保留该备份并按同一流程修复主文件。

主机对发布目录执行 `fsync`；ESP-IDF FAT VFS 不提供目录文件描述符，因此只执行文件 `fsync`。真实 TF 卡掉电、移卡、满卡和控制器缓存行为尚待真机验证，不承诺保存最后一次触摸。当前类要求单一文件 I/O 执行者，挂载/卸载与 USB 文件所有权移交由调用者串行协调。没有实现挂载代次或异步队列；不能据此标记 ST08 已通过。

普通进度记录的 `schema_version` 为 1；清除进度的墓碑记录为 2，包含 `state: "cleared"`；`local_revision` 使用十进制字符串，避免 double 丢失 uint64 精度。`anchor.offset` 为 Unicode 标量偏移数字。读取最多 16 KiB，检查字段、UTF-8、整数范围、版本及身份。此格式是 G1a 的最小实现，未宣称冻结 EPUB 源位置映射或 KOReader 兼容格式。

## TOML 配置

读取顺序：内置默认 → `PicoPage/settings.toml` → `<完整书名>.picopage/settings.toml`。本书只叠加出现的字段，因此只有字号覆盖时，重新加载仍继承全局字体变化。缺失文件采用上层值；语法、UTF-8、类型、范围、未知字段或新 schema 错误时整层回退，返回文件路径、字段或解析器行号及原因，保留原文件。

当前支持：`reader.font`、`font_weight`、`font_size_px`、`line_height`、`margin_x_px`、`paragraph_gap_lines`、`indent_chars`，以及 `display.refresh_preset`、`display.balanced_full_refresh_pages`、`display.fast_full_refresh_pages`，后两项的取值范围均为 1–30 页。全局另支持 `library.roots`、`library.view`、`library.sort`、`library.folders`、`network.wifi_enabled`、`power.auto_sleep_minutes`、`power.sleep_screen`、`power.sleep_image` 与 `power.sleep_overlay`。`network.wifi_enabled` 为布尔值，默认 `true`；单书不可覆盖。关闭后禁止同步、账号验证和两种 Wi-Fi 传书，保留网络及同步账户文件。配置无效时网络入口拒绝启动，修正原文件后可重试。`power.auto_sleep_minutes` 是无输入后自动休眠的分钟数，范围 0–240，默认 10，0 表示关闭；单书配置中出现 `power` 表按未知字段处理。设备设置页可保存自动休眠时长和休眠画面；也可在 TF 卡上编辑，启动或开书时读取。`power.sleep_screen` 接受 `cover`、`reading`、`simple`、`custom`。`power.sleep_image` 为空字符串时轮播；非空时只接受 `LockScreens/` 根目录的 PNG/JPEG 文件名，禁止路径跳转。`power.sleep_overlay` 为布尔值，默认 `false`，开启后将透明 PNG 叠加在休眠前当前画面上；图片与开关均为全局配置。字号当前界限为 12–96 px，行高 1–3，水平边距 0–160 px；这些是输入校验界限，不是已经完成的视觉范围验收。文件最多 32 KiB，扫描根最多 16 项。段距为 0–1 行，默认 0；首行缩进为 0–2 字，默认 2。旧配置缺少这两个字段时采用默认值。用户 TOML 中 `/Books` 表示卡根目录，输出内部规范化为 `Books`，不会访问 host `/Books`。字体偏好原样保留；字体可用性和运行时回退由字体/渲染模块处理。

`reader.font_weight` 接受 `light`、`regular`、`medium`、`bold`，默认 `regular`；字体文件选择和单字重字体的合成加粗见 [图形运行说明](graphics-runtime.md)。`library.sort` 接受 `recent`、`name`、`name_desc`，默认 `recent`；`library.folders` 接受 `first`、`recent`，默认 `first`，仅在最近阅读排序下决定文件夹置顶或跟随其最近子书。后两项只允许全局保存。

`settings_snapshot()` 捕获全局和本书的原始字节及其有效值。`apply_settings()` 在写入前比较两层原文，外部修改、创建或删除文件均返回 `ExternalChange`。语法、版本或字段无效时拒绝保存，不把读取阶段的回退值覆盖到原文件。写回接受上述阅读和显示字段；全局配置还可写 `library.view`、`library.sort`、`library.folders`、`network.wifi_enabled` 和 `power` 字段。`library.roots` 通过此接口只读。

写回根据 TOML 解析器的源行列定位值，仅替换发生变化的单行值，保留字段顺序、空白及注释。删除覆盖时保留该行注释；新增字段插入对应表，缺少表时新增表。行内表、多行字符串及无法确认范围的表示法返回明确失败，保留原文件。变更后的完整文本再次经过相同语法和字段校验，然后执行临时文件同步、逐字节读回、备份及发布。普通读取不自动恢复设置备份，避免有意删除的配置或覆盖项被旧备份重新启用；`.bak` 可供手工恢复。

本书写回仅处理相对快照发生变化的值；新值等于全局值时删除对应覆盖。`clear_book_settings()` 写入有效的无覆盖状态，保留 schema 和注释。保存全局配置不会删除或改写其他书的显式覆盖。面板预览、保存后重新排版及 UI 状态由应用层完成，不能用 store 的通过结果代替视觉验收。该比较协议仍要求单一可写文件系统所有者；不支持电脑与固件同时挂载并写同一 FAT 卷。

## 最近书籍

`save_last_book()` 将现存原书的安全卡根相对路径写入 `PicoPage/data/last-book.txt`，使用同一临时写入、同步、备份和读回确认流程；调用方只能在正文成功显示后调用。`load_last_book()` 拒绝路径穿越、控制字符、无效 UTF-8、符号链接和不存在的书籍。记录损坏或缺失时可恢复有效已提交 `.bak`，不采用 `.tmp`。修复坏主文件时保留已有备份，不让损坏内容覆盖唯一有效恢复副本。该文件只记录最近书籍；正文位置仍由各书 `progress.json` 管理，清理缓存不会删除它。

同一次 `save_last_book()` 另维护 `PicoPage/data/recent-books.txt`：`PPRECENT1` 版本行之后，每行是 Unix 秒数、制表符和卡根相对路径。最多保留 128 本、文件上限 144 KiB；新打开的书移到首位，不依赖系统时间排序。未校时记作 0，日期显示另检查当前时钟和未来时间。两份文件各自采用现有提交协议，不组成跨文件事务；最近列表提交失败会报告「最近阅读记录未保存」，不能据此宣称列表已更新，正文进度仍由原有提交结果决定。列表读取可恢复有效 `.bak`，主副本均无效时保留文件并返回错误。打开同一本书的新会话也更新记录，普通翻页不重复写入最近列表。

最近列表不是位置权威，也不用于上传同步。移动书后旧路径不会自动改名；实际书库扫描只匹配当前存在的条目。删除文件不会让历史路径变成书库条目。超出 128 本或缺少历史记录的旧书按书名排序；存在进度主文件或备份的书不标成未读，其日期保持未知。清缓存保留最近列表。

## 缓存边界

大图缓存可通过 `save_cache(name, payload, prefix, suffix)` 顺序写入头部、既有载荷和尾部校验值，避免为拼接再分配整份载荷。三个缓冲仅在同步调用期间借用，完成后沿用临时文件、同步及发布协议；各段写入失败均不发布部分内容。透明锁屏的 `PPLOCK4` 文件格式和校验规则不变，缓存失败仍不影响本次已准备图片的使用。

有界缓存读取使用 `open_cache` 持有单个只读句柄，由调用者提供逐行缓冲；路径、普通文件和长度上限在打开前后核对，精确读取拒绝越界与截断，重读仍使用同一文件并核对长度。调用者负责格式及内容摘要，失败时不得发布部分输出。句柄由单一 worker 拥有，须在清缓存、卸载或交接 TF 前释放。

冷 PNG 转换使用受 2 MiB 上限约束的 `CacheWriter`，在同一个临时文件句柄上分行读写。Adam7 可重访已写入行；解码完成后的读回以最多 8 行为一批，不透明载荷在同一批缓冲中向前压缩，避免每行独立寻址和读写；调用方负责初始化完整载荷，提交前核对文件长度、截断到实际格式长度并同步，再沿用缓存发布协议。读、写或提交失败后不发布不完整缓存，退出清理临时文件。该文件是可重建缓存，不是配置或进度的权威记录；发布失败后允许缓存缺失，下次从原图重建。原图由有界文件句柄读取，转换前后核对身份；解码结束后先释放输入句柄，再打开原图做末尾 SHA-256，转换最多同时占用两个文件句柄，避免挤占阅读会话和字体占用的八文件板级配额；文件系统与 USB 的所有权边界不变。

章节内容缓存读取在打开文件并核对长度上限后，按实际长度检查内存准入；解码的文本和各类记录分别核对分配量并预留确定容量，避免按 2 MiB 文件上限预留。序列化先计算实际大小，再一次分配；摘要、强书籍身份和 `content-reading-v3` 格式校验保持不变。异步前台加载将目标分段的编码结果延后至正文成功呈现和必要保存完成后，由已有内容 worker 写入；定位目标时经过的前缀分段仍在内容 worker 中同步缓存，保证后续锚点搜索可以连续命中目标，中途取消或资源紧张时可以丢弃，后续从原书重建。缓存仍使用临时文件、同步落盘和重命名发布，单次文件提交不能抢断；没有降低用户配置和阅读进度的提交要求。

`clear_cache()` 仅移除 `PicoPage/cache` 下的内容，保留目录本身；不接触原书、伴随进度/设置、用户封面、`prepared` 或 `PicoPage/data`。host 拒绝根/路径上的符号链接；缓存内部链接只删除链接本身。嵌套清理最多 32 层，遇到错误返回失败，可能已清除部分缓存。生成的封面缓存位于此缓存目录内，会一并清除；调用前必须停止使用缓存的任务。协议不支持另一进程同时改动挂载目录；不将 TOCTOU 检查冒充并发写入隔离。

## Host 验证

紧凑的 `tests/store_test.cpp` 使用真实临时目录和文件，检查：

- 保存确认、超过 double 精度的修订往返；坏主文件和缺失主文件恢复；临时文件不被采用。
- 内容身份不匹配和新 schema 拒绝覆盖；路径穿越和符号链接隔离。
- 临时/备份路径受阻时不确认保存；子进程 `RLIMIT_FSIZE` 产生实际短写与 `EFBIG` 后保留已提交主记录。
- TOML 语法/字段/UTF-8/版本错误回退，原文不改写；全局和本书字段继承。
- 单行配置写回保留注释，跨层外部修改阻止保存，删除覆盖恢复继承，行内表拒绝破坏性改写。
- 最近书籍路径验证、备份恢复、保存失败与清理缓存后的保留。
- 缓存清理保留原书、设置、进度、封面、prepared 与链接目标。

`tests/store_sync_test.cpp` 仅在测试编译单元替换 `fsync`，其余操作仍使用真实文件；验证发布目录同步失败、文件同步失败、创建伴随目录后父目录同步失败，在持续失败和重试时均不返回保存确认，恢复同步后才成功；另验证只有备份时的相同记录重试。最近书籍复用同样的文件同步和发布失败检查，并覆盖坏主文件修复时保留旧备份。
